# GuguChat 对话窗口设计规范

适用于桌面端和 Web 共用的咕咕对话窗口。IM 采用同一份消息语义，按渠道能力呈现文字、图片和交互。窗口材质、主题和公共控件遵循[前台设计规范](frontend-design.md)。

## 窗口与消息

- 紧凑模式用于快速问答，展开模式用于阅读长回复和查看历史。切换时保持当前会话和阅读位置，重新打开时恢复用户上次使用的模式。
- 紧凑模式默认最高约半屏，新回复可随内容增长到视口高度的 85%，并保留顶部和悬浮球边距。超出的消息在窗口内滚动。
- 用户消息在右侧，咕咕的消息在左侧。使用主题令牌区分两者，暗色模式下保证正文、链接和状态文字可读。
- 每个运行（Run）只在结束后显示一次时间戳，放在最后一条消息底部。没有 Run 标识的独立消息按自身时间显示。
- 正文、工具摘要、交互和对象卡按消息时间线排列。用户停在最新消息时跟随新增内容，向上阅读时保留当前视口。
- 工具摘要、工具标题和生成状态左对齐，使用与助手气泡一致的缩进。折叠按钮宽度随内容收紧，输入与输出卡片保留助手气泡的内容宽度。

## Markdown

- 正文以可复制的 Markdown 为基础。先写结论或下一步，再补必要细节。较长内容按主题分段，段落尽量控制在 150–200 个汉字以内。分割线用于相对独立的章节，引用块用于摘录和引文，列表用于可扫描的要点。
- 同类对象的字段对比优先用表格。紧凑窗口中，宽表只在自身容器内横向滚动。代码块保留语言、换行和复制入口。
- 流程、关系和状态变化适合用 Mermaid，数学表达适合用 TeX。依据用户的语意选择呈现方式。图表须有可读标签，公式和图表在渲染完成前可保留可读的源码。
- 流式输出按批呈现。新文本使用 150 ms 模糊淡入，相邻批次的动画可以重叠，已显示文本保持稳定。减少动态效果模式关闭模糊和循环动效。
- 普通网页链接保留 Markdown 导航语义。回复完成后，与本轮搜索结果匹配的 URL 可显示为来源胶囊，相邻来源可合并并在摘要卡内逐条查看。胶囊优先展示文章标题，长标题单行省略。
- 来源摘要使用搜索结果已有的标题、站点、摘要和日期。悬停或键盘聚焦可查看，指针从胶囊移入卡片时保持打开，按 Esc 可关闭。触屏提供点按入口。摘要卡避开窗口边缘和滚动容器裁切。
- 站点图标由固定图标服务按域名提供，请求只传站点域名。加载失败时使用通用链接图标。正文和来源元数据均按不可信内容处理。

## 工具信息与运行状态

| 阶段 | 显示规则 |
| --- | --- |
| 等待首段回复 | 左侧递进三点和「正在准备回复」，与工具摘要共用状态行样式 |
| 工具运行 | 显示正在执行的工具名和呼吸状态点，并行时补充其他运行中的数量 |
| 工具间等待 | 超过 300 ms 再切换为「正在整理结果」及左侧递进三点。文案根据实际运行状态选择 |
| 等待用户答复 | 使用明确的确认或回复状态，停止循环动画。用户操作在专属交互卡完成 |
| 正文开始或运行结束 | 定格为「调用了 N 个工具」，补充失败或未完成数量及已记录的工具耗时合计 |

- 两段助手正文之间的工具调用归为一组。摘要默认折叠，展开后逐项显示工具名、状态、耗时；点开某项才展示输入和结果。摘要、工具标题和工具详情都支持键盘访问。
- 摘要主文案使用小号文字令牌（12px），失败和未完成数量用较小的状态文字。累计耗时沿用工具明细的数字样式，紧跟状态文案，展开箭头置于末尾。摘要与后续独立链接卡或正文使用相同间距，无可复制正文的中间卡片省去复制页脚。
- 活动组的执行中和排队工具名称以每字 32 ms 显示，完整文案停留 240 ms 后再切换。新出现的每个字单独播放 150 ms 模糊淡入，其他状态沿用原有淡入，减少动态效果模式直接更新文案。展开保持摘要位置稳定，箭头用公共开合组件。
- 点击立即读取按需加载的详情，150 ms 内返回时直接展开，慢请求才显示加载提示。取消展开后，晚到结果可以缓存。失败允许重试。
- 输入和结果保留原始可读格式，结构化数据可缩进展示。复用现有脱敏结果。详情展开和折叠只改变呈现状态。

## 咕咕卡片

**咕咕卡片**是通过 `gugu://` 引用应用内已有对象的导航卡。项目、笔记、画布和文件沿用各自已支持的引用地址；文件使用路径引用。点击进入应用内目标，打开文件时遵循当前宿主的打开方式。

现有聊天已支持部分 `gugu://` 对象链接。以下行内、独立和横排规则是后续统一呈现的设计约定。

- 嵌在正文句子里的 Markdown 链接显示为紧凑引用。独占一行的 Markdown 链接或有效的 `gugu://` 裸地址显示为独立卡。连续的独立链接可合成横向卡片组，在紧凑窗口中滑动浏览，网页与桌面支持键盘滚动。
- 含独立咕咕卡片的助手气泡使用当前窗口模式的气泡宽度上限。所有对象类型共用铺满气泡内容区的宽度规则，横滑卡片组中每张卡同样占满一屏。
- 卡片展示名称、对象类型和少量有辨识度的字段。项目卡按当前权限读取项目详情，展示实时名称、状态、当前阶段、截止日和与看板一致的完成度。查询失败时保留原始引用。笔记可展示标题和摘录，文件卡与项目卡共享外壳，由文件库共用图标与真实文件名标识类型。路径引用经授权读取后，补充文件大小和所在文件夹。有可用缩略图时才展示图像。
- 项目卡用醒目的「项目」标签标识类型，标题单独占行，阶段和截止日可并排，进度占一整行。窄窗时字段可换行。
- 当前阶段只显示阶段名。项目状态在右上角使用语义状态色，进度条使用项目选定的配色。
- 截止日复用看板的相对日期文案，临近截止和逾期分别用提醒色与危险色。
- 单张卡提供明确的打开入口。对象被删除、移动或当前用户无权访问时，用应用统一的失效提示。打开实时详情时重新校验引用和权限。
- 第一版验收单项目卡、多项目横排和详情跳转。对比一组对象的同类字段时，正文可同时用表格表达。

建议使用标准 Markdown 对象链接，连续独立链接可组成卡片组。

```markdown
[项目甲](gugu://open-object/project/2)
[项目乙](gugu://open-object/project/4)
```

## 智能界面

**智能界面**用于展示数据或完成对话中的具体交互。视图可包含格式化文字、表格、图表、选项、按钮和滑条。拟议的 Markdown 围栏名称是 `gugu-ui`，目前是设计约定。

- 模板定义版式、可用字段、控件和动作。咕咕提供模板名和已核验的数据引用。运行时负责装配数据、校验权限和执行动作。
- 选项可以在界面内筛选，也可以作为一次明确的用户答复。按钮可打开对象详情或提交当前表单。滑条变化先更新草稿，提交后才写入数据。
- 写入动作使用现有应用更新流程和确认门。保存前检查对象当前状态和权限，失效或冲突时在界面内说明。模型输出只负责声明界面，动作等待用户触发。
- 历史消息保留回答时的展示快照。再次编辑时加载实时数据。桌面和 Web 共享模板；IM 或其他无法渲染的客户端显示文字摘要，按渠道能力附上导航或答复入口。
- 优先实现只读数据展示。需要交互的模板再按具体任务增加控件和验收条件。

## 验收

- 桌面紧凑和展开模式、Web、亮色与暗色主题均检查正文、宽表、来源摘要和对象卡边界。
- 使用快慢请求验证等待态与工具详情门槛，验证流式正文、连续工具、并行工具、等待确认、失败和中断的状态衔接。
- 验证鼠标、键盘和触屏入口，检查减少动态效果模式。回看历史消息时验证数据快照、导航权限和失效提示。
- 检查不完整的 Markdown、空数据和未知模板。正文应保持可读，交互控件只在模板与参数有效时出现。
