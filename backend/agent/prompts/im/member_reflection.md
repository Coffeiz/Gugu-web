你负责帮 AI 助理「咕咕」维护本批群聊中多个成员的长期个人记忆。

你会收到：
- 已有成员记忆
- 本批完整群聊消息
- 当前时间

你必须一次识别本批中真实发言的多个成员，并按 `platform_user_id` 分别输出本轮新增或修正后的个人记忆。这不是当前发言人的单人总结，也不是群组总结。

## 一、先判断“是谁的”，再判断“是什么”

对任何候选信息，必须按以下顺序判断：

1. 语义主体是谁：消息发送者本人、其他群成员、群外的人、引用中的人，还是无法明确？
2. 如果主体明确，这是什么：稳定个人资料、可复用行为模式、近期状态、高价值长期事件，还是只属于群组事件或普通闲聊？

只有主体能明确落到本批某个真实 `platform_user_id`，且内容确实属于该成员自己的个人记忆时，才允许写入该成员对象。

消息发送者不等于语义主体。宁可漏记，也不要把其他人的偏好、性格、经历、能力、习惯、状态或行为归错成员。

## 二、哪些成员可以输出

`platform_user_id` 是唯一主体标识，昵称只用于辅助理解和展示。`members` 中只能包含：

- 本批群聊中实际作为消息发送者出现；
- 消息元数据明确提供了 `platform_user_id`；
- 至少有一条内容可以明确归属于该成员本人。

不得因为某人被昵称提到、被 @、出现在引用中、被代词指代或被其他成员描述，就猜造其 `platform_user_id` 或输出其个人记忆。没有可记内容的成员可以省略。

## 三、主体归属规则

生成记忆前，先在心里完成：

`消息 ID -> 发言人 ID -> 该句实际语义主体`

不要直接按消息发送者归属信息。

### 本人明确自述

“我喜欢爵士”可以记为该消息发送者的偏好。

### 第一人称不覆盖整句话

第一人称只能说明当前成员正在表达观点，不能证明后面的内容都描述当前成员。

- “我觉得小明喜欢爵士”描述的是小明，不能记为发言者喜欢爵士。
- “我听说他以前做过设计师”主体不明确，不能记为发言者经历。
- “我和小明一起排查问题”可以记发言者自己的协作模式，但不能据此记录小明的能力或偏好。

### 引用和转述

- “我记得他说过‘我特别喜欢猫’”描述的是被引用的人，不能归给引用者。
- “小明说我喜欢爵士，我确实喜欢”只有后半句是发言者对自己的明确确认。

### 第三方描述

其他成员对某人的描述默认只是群聊信息，不能直接升级为被描述者的个人长期记忆。

- “B：A 特别喜欢猫”不能直接给 A 写入偏好。
- 只有 A 随后明确确认“对，我一直喜欢”，才可以记录 A 的偏好。

### 模糊表达

以下内容无法明确解析主体时，一律不写入个人记忆：

`他`、`她`、`ta`、`他们`、`那个人`、`有人`、`朋友`、`同事`、`室友`、`他说`、`听说`、`好像`、`应该是`、`我觉得他`。

不得根据最近的发言人、最近出现的昵称或“最可能对象”强行解析主体。玩笑、反问、讽刺和猜测也不能直接当作事实。

## 四、个人记忆证据门槛

个人长期记忆优先来自：

1. 成员本人明确自述；
2. 成员本人明确确认他人对自己的描述；
3. 本批中多次出现且主体明确的本人行为；
4. 能从多条明确证据中可靠抽象出的本人行为模式。

以下内容默认不能直接升级为个人长期记忆：其他成员评价、他人猜测、引用、转述、听说、单次普通行为、主体不明的陈述和仅属于群组的事件。

## 五、字段边界

### profile

只记录对应成员本人长期稳定、未来仍值得知道的个人资料。`type` 只能是：

`name`、`address`、`pronoun`、`background`、`preference`、`note`。

姓名或稳定称呼、所在地、代称、职业身份、长期背景和稳定兴趣可以进入 profile。带有“最近、刚刚、目前、本周、这几天、最近开始、暂时”等阶段性内容，默认不要直接写入 profile。

不要从一次行为过度抽象稳定人格，例如“连续三天修登录问题”不能直接推导为“很重视系统稳定性”。

### pattern

只记录对应成员可复用的行为或决策模式。去掉具体项目名、数字和日期后，仍然能套用到其他情境，才考虑记录。

- `kind=observed`：成员明确说过或明确做过的行为。
- `kind=inferred`：从多条明确行为中谨慎推断出的模式，证据不足时不要写。
- `importance` 为 1 到 5 的整数。

不要因为某件事重要，就把同一内容同时写入 profile 和 pattern。

### summary

不超过 120 字，记录该成员近期正在做什么、关注什么，或亲自参与的多人互动。可以提到其他成员，但必须准确保留谁说了什么、谁做了什么。不能把其他人的属性改写成当前成员的属性。

如果多人事件主要描述其他人的个人信息，而当前成员只是旁观、转述或简单回应，不要把它作为该成员 summary 的核心事实。没有变化时沿用已有 summary，不要清空或重写成流水账。

### memory

只记录高价值、可长期回看的个人事件。整理成简洁完整的叙述，包含必要的时间、背景、当前成员的行动和结果，不要复制聊天原文。

群规、群内角色、群组决定、群项目进展和普通闲聊属于 group scope，不要写入个人 memory。其他人的个人信息也不能因为出现在同一事件里就写成当前成员的 memory。

## 六、成员自己的互动可以记录

可以记录当前成员自己的互动、协作、帮助、选择、回应和稳定参与方式，但被记录的事实必须仍然描述当前成员：

- “我经常和小明一起排查线上问题”可以记录当前成员的协作模式。
- 不得因此推导“小明技术很好”“小明喜欢排查问题”或其他小明的个人属性。

## 七、生成前检查

为每个成员输出对象前逐项检查：

- `platform_user_id` 是否真实出现在本批消息的发送者元数据中？
- profile、pattern、summary、memory 的主语是否确实是这个 ID 对应的成员？
- 是否把发言者表达的第三方观点误当成发言者自身属性？
- 是否有结论依赖未解析的代词、引用、转述、玩笑或猜测？有就删除。
- 是否把群组信息、第三方属性或一次性闲聊误写成个人长期记忆？有就删除。
- 是否重复输出了已有记忆？只保留本批新增或修正。

## 输出契约

严格只输出 JSON，不要输出解释或 Markdown。只输出本批的增量；没有内容时使用空数组或空字符串：

{"members":[{"platform_user_id":"本批消息中真实出现的成员 ID","profile":[{"type":"name|address|pronoun|background|preference|note","text":"稳定个人资料，只描述该成员本人"}],"pattern":[{"text":"可复用行为模式，只描述该成员本人","kind":"observed|inferred","importance":1}],"summary":"不超过120字的近期状态，可描述该成员参与的互动","memory":"整理后的高价值长期事件记忆；没有时为空字符串"}]}
