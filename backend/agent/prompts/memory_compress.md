你在帮 AI 助理「咕咕」把一批近期 daily 记录沉淀为用户长期记忆的新增章节。

这是追加式流程：你只处理本批次记录，不读取也不重写已有的 memory.md。输出会直接追加到现有 memory.md，因此不要输出已有内容，不要尝试合并或改写旧章节。

## 规则
- 长期记忆不是项目日报，也不是固定格式的数据库。除了项目和工作，也可以记录用户主动表达、对用户有持续意义或明显情绪价值的生活经历、人际关系、开心事、难过事、期待、遗憾、重要体验和态度变化。
- 只记录本批次中值得长期保留的内容，不要把每句普通闲聊都存下来。
- 【历史事件参考】只用于识别重复、核对背景和发现冲突，不是本批次的新事实。
- 与历史明确重复且没有新进展的记录跳过；有新进展时另起一个新增章节，保留新进展及其与旧事件的关系。
- 不要把 profile/pattern 的稳定结论原句复制进 memory。
- 每个新增事件必须使用标题 `## 记录长期记忆：<事件标题>`。标题可以是生活事件，不必是项目名称。
- 时间按能确认的精度记录：优先使用明确日期，也可以使用“2026 年夏天”“2026-09 上旬”“近期”或“时间不确定”。不要猜测日期，也不要把“昨天/最近/下周”写成脱离上下文的相对时间。
- 只有确实存在多个时间节点时才整理时间线，不要为了格式虚构时间线。
- 背景、过程、结果、情绪、已完成、未解决、后续等内容按事件需要选择性记录，不要强行补齐空字段。
- 项目事件重点保留来龙去脉、决策、结果和未解决事项；生活或情绪事件重点保留发生了什么、用户表达的感受以及它为什么值得记住。
- 可以记录用户明确表达的情绪和态度，但不能替用户推断没有说过的心理、原因或结论。
- 不评判、不推测，不输出内部 id、hash、scope、向量或来源元数据。
- 没有值得新增的事件时，返回空字符串，不要为了填充而重复历史。

## 新增章节格式
每个新增事件必须是一个独立的 Markdown 章节，并严格遵守以下边界：

```md
## 记录长期记忆：<简短事件标题>

- 时间：<明确日期、时间范围、近期或时间不确定>
- 类型：<项目工作 / 生活 / 开心时刻 / 情绪 / 人际关系 / 兴趣体验 / 重要决定 / 其他>
- 状态：<已完成 / 进行中 / 未解决 / 已取消 / 已阻塞 / 已发生 / 未知>

### 事件经过
<事件的背景、经过、关键事实和决定。>

### 用户感受
<仅记录用户明确表达的感受或态度；没有明确表达时省略本节。>

### 结果与当前状态
<已经发生的结果、已完成事项和当前状态；没有内容时省略本节。>

### 未解决与后续
<仍未解决的问题、约定或下一步；没有内容时省略本节。>
```

- `## 记录长期记忆：...`、`- 时间`、`- 类型`、`- 状态` 是章节的固定骨架；其余小节按内容选择性保留，禁止输出空小节。
- 多个独立事件必须输出多个完整章节，不能把不同事件混在同一章。
- 同一事件的新进展也输出新章节，并在“事件经过”中说明与此前事件的关系；不要改写或复制旧章节。
- 保留事实原貌和用户原意，必要时可以压缩措辞，但不能合并掉关键日期、人物、决定、结果或未解决事项。

## 输出
严格只输出 JSON：
{"entries": "要追加的新事件章节；没有新增内容时为空字符串"}

【历史事件参考】
{{history_references}}

【本批次近期记录】
{{daily_entries}}
