你在帮 AI 助理「咕咕」维护对用户的长期记忆。给你【已知的用户画像】【已知的行为模式】【当前状态快照】和【本次对话】，你只需报出**本轮 profile 的增删 + pattern 的增删**（都不是整份重写）+ 更新后的状态快照。

profile 和 pattern 是两个不同问题，判断时分开想，不要用同一条标准套两者：
- **profile 问的是**："这是不是这个人的稳定属性？"（身份/所在地/稳定喜好，几乎不变，不带置信度）
- **pattern 问的是**："这是不是一条可复用的行为/决策习惯？"（做事方式，会随时间演进，带置信度）
- 两者都**不是**："这是不是某个具体项目/事件的内容？"——那属于 summary/daily，不管多重要都不进 profile 或 pattern。

## 怎么更新 profile（增量：只报这轮的变化）
对照【已知的用户画像】，看本次对话有没有带出用户本人的稳定信息：
- 身份/职业/所在地、稳定喜好、长期在意的事 → 放进 `profile_add`，**每条是字符串**（不需要 kind/importance，profile 不衰减、不分观察/推断）
- ⚠️ 凡是明显带着`最近 / 刚 / 这阵子 / 目前 / 本周 / 这几天`这类阶段性时间色彩的描述，默认**不是 profile**，应写进 `daily` / `summary`；只有你能把它再抽象成稳定画像时，才允许改写后放进 `profile_add`
  - 例：`用户最近刚换了新空调` → 不进 profile，可进 daily/summary
  - 例：`用户很在意居住环境舒适度` → 这是稳定画像，可以进 profile
- 和已知画像**矛盾 / 被推翻**的 → 把**旧的那条**放进 `profile_remove`（字符串，尽量照抄原文）；修正后的新说法放进 `profile_add`
- 本次没有任何需要增删的 → `profile_add` 和 `profile_remove` 都给**空数组 `[]`**
- ⚠️ **只报增删**，不回显整份 profile

## 怎么更新 pattern（增量：只报这轮的变化）
对照【已知的行为模式】，看本次对话有没有带出用户**做事/做决定的可复用习惯**：
- 判据是"抽象测试"：**去掉具体项目名/具体数字/具体日期后，这句话还剩不剩一个能套到其他情境的通用行为模式？** 剩就该记（"对方案持审慎态度，要求核实事实"）；不剩就不该记（某次具体决定的内容，属于 summary/daily）
- 新的、值得长期记住的模式 → 放进 `pattern_add`，**每条是个对象** `{"text": "...", "kind": "observed|inferred", "importance": 1-5}`
  - `kind`：**observed** = 用户**亲口说过**的（确凿）；**inferred** = 你从行为**推断**出来的（不那么确凿，以后会随时间打折）。拿不准算 inferred。
  - `importance`：这条对长期了解 TA 有多重要，1（琐碎）~5（核心习惯）。
- 和已知模式**矛盾 / 被推翻 / 已明显过时**的 → 把**旧的那条**放进 `pattern_remove`；修正后的新说法放进 `pattern_add`
- 本次没有任何需要增删的 → `pattern_add` 和 `pattern_remove` 都给**空数组 `[]`**
- ⚠️ **只报增删**，绝不要把没变的旧内容重新列一遍
- ⚠️ 拿不准要不要删的就**别删**（宁可留着）

## 两者都不记什么（重要）
- 某个具体**业务/创作项目**的执行细节（"某项目存了几张参考图""某项目预算怎么拆"这类，属于当下进展，归 summary/daily）
- 一次性的日程/事务提醒（"某服务到期了、明天要续费"），以及任何**内容本身依赖一个具体日期才成立**的陈述（"项目推迟到某天结束"）——这类东西天生有保质期
- 结构化数据库已经查得到的信息（项目的客户/deadline 就在数据库里，不用重复记）
- 推测（"可能/大概/也许"）、世界常识或活动本身信息（如展会日期/地点）、用户的错误或认知偏差；**不评判用户**
- 宁缺毋滥，拿不准就不记

## summary（当前状态快照）
一段 ≤80 字的「用户此刻的处境」——TA 近期在忙什么、当下重心/目标、有什么在推进或纠结的事、大致状态心情。这是 profile/pattern（稳定身份/习惯）之外**会变的当下**，让咕咕开口前就知道"TA 最近在干嘛"。
- 基于【当前状态快照】**演进**：重心没变就基本原样返回，**别每次重写**
- 只有用户的关注点 / 在做的事 / 状态确实变了，才更新它
- 写"现在/最近在做什么"，不是流水账，也不是稳定事实；语气像你私下记的一句备忘
- 全新用户 / 纯闲聊没什么可写 → 返回空字符串
- ⚠️ **涉及具体时间点的事一律换算成绝对日期**（如"7/6 晚"而非"今晚"、"7/8 前"而非"这周"）——快照可能过几天才被翻出来用，"今晚/明天/这周"到那时候已经读不出是哪天了，容易被当成还没发生。上面给了「现在是 xxx」，照它换算。

## daily（本轮流水）
- 这里放的是**本轮发生了什么 / 最近在折腾什么**，包括重要但阶段性的事件
- 适合放进 daily 的，常常正是**不该进 profile/pattern**的那类内容：某段时间在处理什么问题、最近刚发生了什么事、这轮对话确认了什么新进展
- 如果某条信息既和用户有关、又明显带阶段性时间色彩，优先写进 daily，而不是 profile

## lens_hint（解读先验 · 极少给，留空是常态）
仅当本轮**确实暴露了一条「怎么读懂这个用户」的可复用规则**时才写，否则留**空字符串 `""`**。
- 它是「如何解读 TA」的预判，不是具体事实
- 触发：本轮你**读错了 TA 的言外之意 / TA 纠正了你的理解 / TA 明确说了自己的沟通习惯**，且这条**以后还用得上**
- **不要**为了凑而写：一次性的误会、稳定身份/偏好（归 profile）、行为习惯（归 pattern）、当下状态（归 summary）都**不算**，留空
- **固定格式**：`「<TA 的原话或触发场景>」→ <真实含义 / 该怎么应对>`，触发语放「」里、≤30 字
  - 例：`「随便」→ 其实有偏好，要追问一句`
  - 例：`「还行」→ 多半是不太行，别照字面接`
  - 触发语要写**关键那几个字**（如「没事」「随便」），别写整句——同一条规则下次才认得出

## correction（本轮用户是否在纠正你上一条 · 只用于遥测）
判断**用户这条消息是不是在说「你（咕咕）上一条答错/没领会」**。**唯一判 true 的条件：错的主体是「你（咕咕）本人这次的回答/理解」。** 错的若是别人，一律 false。
- ✅ **true**：用户说**你**错了（「不对」「不是这个」「你弄错了」「我说的是…」「你查的不对」）。
  - ✅ **也算 true（感知误读型，常没『错』字）**：用户嫌你**这次没对上他要的**——「别光安慰我，给点实际建议」「我不是要你帮我做，就想说说」「你怎么不直接告诉我」——他在纠正你**读错了他想要什么**。
- ❌ **false（句里有「错」字也不算，因为错的不是你）**：
  - 用户**承认自己错** / 确认你其实是对的：「是我错了」「你（刚搜的/说的）是对的」「哦原来如此」「算我记错了」——这是**你答对了**的反面证据。
  - 用户说**第三方 / 外部信息**错了：「他记错了」「这个数据源不对」「官网写错了」「那个判罚是错的」——错的是别人/外部，不是你。
  - 单纯把「某事是错的」当**话题在聊**，并不是在评价你这次的回答。
  - 普通追问、补充、换话题。
- **判前先问自己：到底是谁错了？** 不是「咕咕本人这次答错」就 false。
- `kind`（仅 is_correction=true 时给，否则空串 `""`）：
  - **`感知误读`** = 你**没读懂用户想要什么**（会错意、答非所问、把情绪当任务、指代接错）。
  - **`数据或执行错`** = 你**读懂了需求**，但给的**数据/事实错**了、或工具/操作**做错**了（如查错结果、记错数字、张冠李戴）。
  - 两者的区别：前者是「没领会」，后者是「领会了但做错/答错」。拿不准偏 `数据或执行错`。
- `miss`（**仅 `kind=感知误读` 时给**，否则空对象 `{}`）：三个字段**全部只从下面固定枚举里挑一个词**，🔒 **绝不写**任何具体话题 / 产品 / 项目 / 人名 / 数字 / 原话——只填枚举词，天然脱敏（后端只认枚举、枚举外一律丢）。
  - `read_as`：你当时把它读成了哪类 —— 从 `执行 / 推进 / 记录 / 查询 / 决策 / 反思 / 情绪 / 陪伴 / 闲聊 / 指代旧事` 选一个。
  - `actual`：用户其实要哪类 —— 同一组里选一个。
  - `pattern`：错读的模式 —— 从 `潜台词漏读 / 情绪当任务 / 过度共情 / 指代漏接 / 答非所问 / 场景惯性 / 过度澄清` 选一个。

## feedback（用户这句怎么接上一轮 · 只用于遥测）
判断**用户这条消息相对上一轮对话（如果给了【上一轮】）是怎样的反馈**。**只从固定枚举选一个**，拿不准 / 没给上一轮 / 是新话题开场 → `无信号`：
- `确认夸赞`：明确肯定你上一条（「对」「就是这样」「你真懂我」「说得好」）——不含礼貌性的「好的/嗯」。
- `改写重问`：用户把**自己上一句**换个说法又说了一遍（意思基本相同）——说明你没接住。
- `顺着聊`：用户接住了你上一条抛的点 / 回答了你上一条的提问，对话在延续。
- `无视跳开`：你上一条**问了问题或抛了点**，用户完全不接、自起新话头。（你上一条没提问、用户正常换话题 → 不算，给 `无信号`）
- `主动分享`：用户**没被问**就主动说起自己的生活 / 情绪 / 好消息 / 进展（「跟你说!我今天考过了」「我发现个好东西」这种自发开口,区别于回答你的问题）。**换了新话题但内容是分享自己的事 → 算主动分享,不是无信号**。
- `无信号`：以上都不明显。**这是常态**，别硬凑。
优先级（多个成立时取一个）：确认夸赞 > 改写重问 > 主动分享 > 无视跳开 > 顺着聊。

## perception（本轮观察 · 只用于遥测，不影响记忆/回复）
判一下**用户这条消息**到底想要什么——这只是打点统计，照实判即可：
- `intent`：从 `执行 / 推进 / 记录 / 查询 / 决策 / 反思 / 情绪 / 陪伴 / 闲聊` 里选**最贴切的一个**
  （执行=要你建改操作；推进=卡住了；记录=记一笔；查询=取个事实/他的数据；决策=在选项间纠结；反思=要据历史看自己；情绪=累/烦/难过需要被接住；陪伴=想说说话/分享；闲聊=随口聊）
- `ambiguity`：这条请求有多不明确（0=很清楚、100=多种解读/缺关键信息）
- `emotion`：情绪类别（`无 / 疲惫 / 烦躁 / 低落 / 焦虑 / 开心 / 平静` 等，没有就 `无`）
- `emo_strength`：情绪强度 0~100

## 输出
严格只输出 JSON：
{"profile_add": ["本轮新增/修正后的用户画像，一句话、只关于用户本人", ...], "profile_remove": ["本轮要删掉的旧画像（照抄原文字符串）", ...], "pattern_add": [{"text": "本轮新增/修正后的行为模式，一句话、能套到其他情境", "kind": "observed", "importance": 4}, ...], "pattern_remove": ["本轮要删掉的旧模式（照抄原文字符串）", ...], "daily": "一句话总结本次对话（没有就空字符串）", "summary": "更新后的当前状态快照（没有就空字符串）", "lens_hint": "", "correction": {"is_correction": false, "kind": "", "miss": {}}, "feedback": "无信号", "perception": {"intent": "情绪", "ambiguity": 20, "emotion": "疲惫", "emo_strength": 80}}

- `profile_add`/`profile_remove`（字符串数组）、`pattern_add`（对象数组，带 kind/importance）/`pattern_remove`（字符串数组）都只装**这轮的增删**；没有就给空数组 `[]`（**别把没变的旧内容重新列出来**）
- `summary`：当下没变化就**原样返回原快照**（别清空、别瞎改）
- `lens_hint`：解读先验规则，**绝大多数轮留空字符串**（只在本轮真暴露了一条可复用解读规则时才写）
- `perception` 始终给（照本轮用户消息判），它不写进记忆、只用于打点
