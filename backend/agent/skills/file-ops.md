# 文件操作技能

## 核心原则

真实性和数据安全优先：文件名、位置、ID、数量和操作结果必须以本轮最近一次工具回执为准；不可逆删除、覆盖和发送附件必须遵守工具确认门。

## 必须遵守

- 修改内容前先读取最新版本，不要用旧正文覆盖用户的新改动。
- 指定行编辑必须基于最新 `numbered_content` 和对应 `expected` 原文，不能猜行号。
- 删除、永久清理、覆盖和发送附件必须遵守工具确认要求。
- 文件库 personal/project 默认只读；写入、移动、改名、删除、恢复和永久清理会按当前 Session/定时任务的统一 filesystem policy 校验。workspace 绑定或完整授权由系统事实决定，不要自行猜测权限。
- 工具逐项返回成功/失败时，逐项如实汇报，不能笼统声称“全部完成”。

## 查询与批量入口
- **查询多个候选文件名时优先一次传 `list_files.queries`**：默认 OR，避免为了不同关键词重复查询；只有用户明确要求同时满足多个词时才使用 `mode: "AND"`。
- **移动 / 改名 / 编辑多个文件或文件夹 → 用批量入口一次调用，别一个个调**：
  - `move_items`：files + folders 一次搬到同一目标；**移文件夹会连里面的文件和子文件夹递归一起搬**，你不用管里面有几个。
  - `rename_file` 的 `renames`：多文件改名（按顺序编号等），自己排好序号一次传。
-  - `edit_file` 的 `edits`：多文件统一查找替换、或各自编辑。
- 需要修改或删除指定行时，先 `read_file` 获取最新 `numbered_content`，它按原始 Markdown 物理行编号，不是页面渲染行号；再使用 `mode: "line_edit"` 和 `line_edits`，数字目标必须带对应的 `expected` 原文。每项用 `target_lines` 表示 `8`、`8-11` 或 `8,11`，整篇用 `all`，`content: ""` 表示删除。校验失败就重新读取，不能猜行号；多个范围不能重叠，行号变化的多个操作由工具按倒序处理。
- 后端逐项执行、回报每项成功/失败——**严格按回报如实汇报**（成功几个、哪些失败及原因），不能笼统说"全部完成"。仍是单文件工具（如 `delete_file`）的多次操作，则每个都真调用并确认。
- 删除多个文件或文件夹时优先使用 `delete_file.file_ids` / `delete_folder.folder_ids` 一次调用；永久清理回收站时使用 `permanent_delete.file_ids/folder_ids` 或 `all=true`，不要逐项调用制造重复确认。批量结果仍须逐项如实汇报成功与失败。

## 创建与编辑

### 编辑后反馈「改了啥」
- 改完文件**一定要告诉用户这次具体改了什么**，别只说"改好了"。**不用详细**，一句话即可——照 `edit_file` 回执里的 `change` 字段说（如"把『喝水』换成『收集科技新闻』了"、"末尾追加了一段"、"按第 8～11 行更新了内容"），让用户知道动了哪儿。
- 多文件批量编辑：按每项的 `change` 简要汇总（"3 个文件都把 X 换成了 Y"）。
- 回执带 `warning`（改后明显变短）时，**先 `read_file` 读回核对**再回话，别直接报"改好了"。

### 改文件内容前先读最新（防覆盖）
- 用户可能在网页 / IM 自己改过、上传、删过文件，你上次 `read_file` 的内容可能已过期。
- **修改文件内容前（尤其 `target_lines=all` 整篇编辑）先 `read_file` 拿当前真实内容再改**，别用几轮前的旧内容把用户的改动盖掉。（`find_replace` 在当前内容上操作、相对安全；整篇编辑最危险。）
- 文件是否存在 / 在哪 / 几个，以本轮注入的「文件概览」为准（每轮最新，用户的增删即时反映）。

## 列出文件与核对存在性
- 列文件 / 项目 / 事件 / 客户时，**严格按工具结果逐条列**，绝不凭印象脑补文件名、数量、id（别无中生有列 favicon、logo 之类"常见文件"）；不确定就调工具查，查不到就如实说"没有"。
- **`list_files` 结果默认用目录树呈现，别写成一段话堆文件名**：按 `folder_path` 分组，文件夹一行，文件用缩进列出；每个文件带名称、大小或位置。结果横跨多个文件夹/项目时保持完整层级，让用户一眼看出“哪个文件夹下有哪些文件”。同名文件必须保留完整路径区分；不要把未出现在查询结果中的文件夹判断为空。文件很少（1~2个）时一句话带过也可以，不用为几个文件硬套目录树。
- **核对存在性 / 数量时搜全空间**：同名文件可能同时在个人空间和某项目里（个人有 A5、项目「神椿插画」也有 A5）。你在个人空间删/改了几个，**不代表别处同名的也没了**。查"X 还在不在"时 **`list_files` 不要传 `space`/`project_id`（全空间搜）**，按返回的 `space`/`project_id` 看清它在哪，再下结论。用户说"还在"多半是真的——多半在你没查的那个空间。
- 拿不准某文件现在在哪 / 叫什么 → 这正是该**重新调一次查询工具**的少数情形（不属"省调用"）。

## 结果与落点
- 具体的文件名 / 所在项目 / 文件夹 / id，**必须来自本轮最近一次工具返回**，绝不凭几轮前记忆或推测。
- 移动 / 保存类工具会回报 `project_name`、`folder_id` 等落点，**照回执原样说**（如"已放进 maimai 角色插画 #89"），别自己改写或猜项目。

## 保存、跳转与发送是三件事
- `create_document` 等新建文档后，**一句话告诉存到了哪**（照回执的 `project_name` / 文件夹说，如「存到『神椿插画』的素材文件夹了」），方便去找。
- 同一文件在本轮被**连续编辑**时，只在「刚创建」那次报一次位置就够，后面别每次重复念目录。
- **绝不主动调 `send_file`**：保存好 ≠ 发给用户。`send_file` 在飞书 / QQ 是**真把文件推到对方聊天里**（网页是下载卡片）——**只有用户明确说「发给我 / 给我那个 / 发过来」时才调**。创建 / 改完默认只告知位置。

## 公网下载
- 用户明确说「下载 / 保存 / 导入这个链接」时使用 `web_download`；它会把文件写入文件库，不是把正文读进上下文。
- 不要因为用户提到一个 URL 就自动下载；只想阅读网页用 `http_get`，只想把已有文件发到聊天用 `send_file`。
- 不传落点时保存到个人空间根目录；明确给出 `folder_id` 时直接使用它，`space` / `project_id` 只在用户明确指定项目或空间时传。
- 下载结果的文件名、大小和真实落点以工具回执为准；不要自行猜测保存目录。单文件上限为 50MB，公网安全校验和重定向限制由工具统一执行。

## 音视频读取
- 文件库里的 `read_file` 不只支持文本、PDF/Office 和图片，也支持音频与视频：音频会转写，视频会提取代表画面并尽量转写音频。
- 用户要求读取 `.mp4`、`.mov`、`.mkv` 等视频时，直接调用 `read_file`，不要先回复“不支持视频”。如果工具实际返回未配置视觉/语音模型、ffmpeg 缺失或文件过大，再按工具回执说明具体原因。
- 视频读取是代表画面分析，不等于逐帧完整理解；需要完整时间线时应如实说明限制。

## 创建与保存位置
- 用户已明确给出 `folder_id` 或明确说了文件夹名：直接按指定位置存，不再替他分类。
- 其它情况下，目标项目或个人空间存在文件夹时，**先调 `list_folders`**。先看一级目录；只有某个一级目录和文件主题明显相关时，才继续看它的二级目录。
- 二级目录有唯一明显匹配就放进去；没有就放在匹配的一级目录。一级目录也没有相关项，才可以放根目录。
- 多个目录都合理、或语义拿不准：问用户选哪个。宁可放根目录，也不要硬塞进错误目录。

## 文件库跳转链接
- 任何文件库工具本轮返回真实 `file_id` 后，用户询问文件位置、路径、打开或查看时，回复里用 `[文件名.ext](gugu://open-file/{file_id})`；适用于 `read_file`、`create_document`、`web_download`、`save_uploaded_file` 等产出文件的工具。
- `file_id` 必须来自本轮最近一次工具回执，禁止猜测或复用不确定的 id。示例：`[w3-svg-test.svg](gugu://open-file/2449)`。
- `gugu://open-file/{file_id}` 是文件库跳转按钮，不是发送附件；不要把它写成普通 HTTP 下载地址。
- 同一文件在同一条回复里多次提到，**只第一次**加链接，后面直接写文件名。
- 搜索结果、推测的文件名或没有真实 `file_id` 的文件一律不加链接（防 file_id 对不上）。

## 跳转链接与附件发送分离
- `gugu://open-file/{file_id}`：用户要位置、路径、打开或查看文件时使用，前端点击后跳转文件库。
- `send_file(file_id=...)`：只有用户明确说“发给我 / 发过来 / 发送文件”时使用，表示把附件真正发送到当前聊天。
- 创建/下载/保存文件后默认只告知文件已保存的位置；如果用户同时要跳转和附件，先按需求调用 `send_file`，回复中再附上文件库跳转链接。
- `send_file(url=...)` 中的 `url` 只是网络图片的发送来源，不是文件库跳转链接；不要把 `gugu://open-file/...` 传给 `send_file.url`。
