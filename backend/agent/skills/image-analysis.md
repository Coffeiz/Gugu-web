# 图片分析技能

## 什么时候使用

- 用户要求辨认角色、物体、场景或图片内容。
- 用户要求比较多张图片的共同点、差异、版本或风格。
- 用户要求核对搜索结果是否符合目标，而不是只要图片链接。
- 用户要求找同款、相似图、类似图片或相近风格。

## 标准流程

1. **先区分任务类型。** 已有用户图片且用户要求辨认角色、物体、出处或同款时，先调用 `image_search(mode="image")` 获取当前图片的相似候选，再确认结论。当前消息图片使用上下文中的 `attach_id`，网络图片使用 `image_url`。
2. **每次反向搜图必须独立。** 搜索请求只能使用当前待分析图片的 `attach_id` 或 `image_url`，不得把上一轮对话猜出的角色名、作品名、标题或候选结论带入图片搜索；历史对话只能作为待验证线索，不能作为搜图输入。每次搜图都要重新从当前图片产生候选。
3. 如果用户只是要求描述当前附带图片，且当前模型已经能看到图片，直接分析，不要为了“读取”而重复下载；如果需要更可靠的视觉输入，再调用 `inspect_images`。
4. 相似候选返回后，优先用候选的标题、来源页 URL、页面正文和实体关键词调用 `web_search`，检查候选是否包含有效角色/作品/商品信息；再按需要从候选中挑选 2～5 张调用 `inspect_images`，对比当前原图与候选的外观细节。不要先凭上一轮结论搜网页，再反过来把网页结论当成图片证据。
5. `similarity` / `score` 只用于排序，不是事实置信度，也不是“相似度 X/5”。分数达到 2 或以上的候选应作为重要参考，必须结合标题、来源页、网页内容、候选图和用户线索核对；低于 2 也不能直接判定无关。
6. 如果用户要查出处的文字资料、角色背景或购买信息，使用 `web_search`；如果用户是按关键词找一张并不存在于当前上下文的图片，使用 `image_search(mode="text")`。`image_search(mode="text")` 负责关键词找图，不能替代 `image_search(mode="image")` 的反向图片搜索。
7. 简单判断默认读取 2～5 张；只有用户要求全面比较时才扩大数量，单次最多 20 张。
8. 先逐图描述可观察事实，再给出跨图比较和结论。

## 输出要求

- 明确区分“图片中直接可见的事实”和“基于事实的推测”。
- 比较时按统一维度组织：主体、构图、颜色、文字、动作/姿态、相同点、差异点。
- 不能仅凭搜索标题、文件名、来源页或缩略图推断图片内容。
- 图片模糊、遮挡、加载失败或角度不足时，直接说明不确定，不要补猜。
- 需要引用某张图时使用 `result_id` 或标题标识，避免把不同候选混淆。
- `image_search(mode="image")` 的 `similarity` / `score` 只是服务端排序等级，不是百分比、置信度或“相似度 X/5”；其中 `score >= 2` 的候选属于重要参考，但仍需核实。即使分值低，只要标题、来源或图像内容与用户线索吻合，也不能直接判定结果无关；证据不足时使用“可能相关”，不要武断否定。
- 搜到相似候选后，辨认角色或核对候选时，先用候选来源页和标题做 `web_search` 文字核对，再按需要调用 `inspect_images` 对比图像细节；不能把上一轮对话中的角色名当成当前搜图结论。
- `web_search` 和 `inspect_images` 的职责不同：前者核对网页文字、角色/作品关联、出处和页面内容，后者核对候选图片的实际视觉内容。两者可以组合使用，但不要用网页标题替代看图，也不要用图片相似度替代出处核实。
- 用户说“只给我结果/不用看图”时，只展示返回的标题、来源和图片 URL，不调用 `inspect_images`，也不要对候选做额外视觉结论。

## 成本与安全

- `image_search(mode="image")` 负责找相似候选，不代表确认是同一张图；需要视觉分析时必须单独调用 `inspect_images`。
- 只读取能影响结论的图片，不要默认读取全部搜索结果。
- `image_search` 只负责列出当前图片的独立候选；需要视觉分析时必须单独调用 `inspect_images`。一轮对话最多发起 3 次网络图片读取，每次最多 20 张；历史附件不占用网络图片额度。
- 图片下载仍由工具执行 URL 安全校验、格式校验和大小限制；技能层不要绕过这些限制。
