# 图片分析技能

## 什么时候使用

- 用户要求辨认角色、物体、场景或图片内容。
- 用户要求比较多张图片的共同点、差异、版本或风格。
- 用户要求核对搜索结果是否符合目标，而不是只要图片链接。
- 用户要求找同款、相似图、类似图片或相近风格。

## 标准流程

1. **先区分任务类型。** 用户说“找同款”“找相似图”“这张图还有哪些类似图片”时，优先调用 `search_similar_images`，不要先调用 `image_search`。当前消息图片使用上下文中的 `attach_id`，网络图片使用 `image_url`。
2. 如果用户只是要求描述当前附带图片，且当前模型已经能看到图片，直接分析，不要为了“读取”而重复下载；如果需要更可靠的视觉输入，再调用 `inspect_images`。
3. 如果用户要求核对、比较相似候选，先用 `search_similar_images` 得到候选，再从候选中挑选真正需要分析的图片调用 `inspect_images`。候选图填写 `result_id + img_src + title`。
4. 如果用户要查出处或按关键词找一张并不存在于当前上下文的图片，使用 `image_search`；它负责关键词找图，不替代相似图搜索。
5. 简单判断默认读取 2～5 张；只有用户要求全面比较时才扩大数量，单次最多 20 张。
6. 先逐图描述可观察事实，再给出跨图比较和结论。

## 输出要求

- 明确区分“图片中直接可见的事实”和“基于事实的推测”。
- 比较时按统一维度组织：主体、构图、颜色、文字、动作/姿态、相同点、差异点。
- 不能仅凭搜索标题、文件名、来源页或缩略图推断图片内容。
- 图片模糊、遮挡、加载失败或角度不足时，直接说明不确定，不要补猜。
- 需要引用某张图时使用 `result_id` 或标题标识，避免把不同候选混淆。
- 相似图结果的 `score` 仅用于结果排序，不是事实置信度，也不能据此判断结果无关或错误。按返回顺序展示结果，不要把 `score` 转换成“相似度 2/5”或“结果不理想”。
- 结合标题、来源、图片内容和用户补充信息综合判断；如果结果与用户描述、角色名、作品名或物品特征吻合，即使 `score` 较低，也不要主动否定。无法确认时说“可能相关”，不要断言“不是同款”。
- 除非用户要求分析候选图，否则不要调用 `inspect_images`；用户说“只给我结果/不用看图”时，只展示返回的标题、来源和 URL。

## 成本与安全

- `search_similar_images` 负责找相似候选，不代表确认是同一张图；需要视觉分析时必须单独调用 `inspect_images`。
- 只读取能影响结论的图片，不要默认读取全部搜索结果。
- `image_search` 只负责列出候选；需要视觉分析时必须单独调用 `inspect_images`。一轮对话最多发起一次网络图片读取，单次最多 20 张；历史附件不占用网络图片额度。
- 图片下载仍由工具执行 URL 安全校验、格式校验和大小限制；技能层不要绕过这些限制。
