# 图片分析技能

## 什么时候使用

- 用户要求辨认角色、物体、场景或图片内容。
- 用户要求比较多张图片的共同点、差异、版本或风格。
- 用户要求核对搜索结果是否符合目标，而不是只要图片链接。
- 用户要求找同款、相似图、类似图片或相近风格。

## 标准流程

1. **先区分任务类型。** 已有用户图片时，用户说“搜图”“搜搜这个”“用这张图找同款/相似图/来源”都属于反向图片搜索，优先调用 `search_similar_images`，不要先调用 `image_search`。当前消息图片使用上下文中的 `attach_id`，网络图片使用 `image_url`。
2. 如果用户只是要求描述当前附带图片，且当前模型已经能看到图片，直接分析，不要为了“读取”而重复下载；如果需要更可靠的视觉输入，再调用 `inspect_images`。
3. 如果用户要求辨认角色、核对同款或比较相似候选，先用 `search_similar_images` 得到候选，再按返回顺序和标题/来源线索挑选 2～5 张候选调用 `inspect_images` 做视觉比对。相似图候选填写 `result_id + image_url + title`；`image_search` 候选填写 `result_id + img_src + title`。不要只看 score、标题或来源就判定候选无关。
4. 如果用户要查出处的文字资料、角色背景或购买信息，使用 `web_search`；如果用户是按关键词找一张并不存在于当前上下文的图片，使用 `image_search`。`image_search` 负责关键词找图，不能替代 `search_similar_images` 的反向图片搜索。
5. 简单判断默认读取 2～5 张；只有用户要求全面比较时才扩大数量，单次最多 20 张。
6. 先逐图描述可观察事实，再给出跨图比较和结论。

## 输出要求

- 明确区分“图片中直接可见的事实”和“基于事实的推测”。
- 比较时按统一维度组织：主体、构图、颜色、文字、动作/姿态、相同点、差异点。
- 不能仅凭搜索标题、文件名、来源页或缩略图推断图片内容。
- 图片模糊、遮挡、加载失败或角度不足时，直接说明不确定，不要补猜。
- 需要引用某张图时使用 `result_id` 或标题标识，避免把不同候选混淆。
- `search_similar_images` 的 `similarity` 只是服务端排序等级，不是百分比、置信度或“相似度 X/5”。即使分值低，只要标题、来源或图像内容与用户线索吻合，也不能直接判定结果无关；证据不足时使用“可能相关”，不要武断否定。
- 搜到相似候选后，如果任务是辨认角色或核对候选，必须优先调用 `inspect_images` 读取少量候选，再把候选图像与用户原图的可见特征逐项比较；不要把“没有高分命中”当成不需要看图的理由。
- 用户说“只给我结果/不用看图”时，只展示返回的标题、来源和图片 URL，不调用 `inspect_images`，也不要对候选做额外视觉结论。

## 成本与安全

- `search_similar_images` 负责找相似候选，不代表确认是同一张图；需要视觉分析时必须单独调用 `inspect_images`。
- 只读取能影响结论的图片，不要默认读取全部搜索结果。
- `image_search` 只负责列出候选；需要视觉分析时必须单独调用 `inspect_images`。一轮对话最多发起 3 次网络图片读取，每次最多 20 张；历史附件不占用网络图片额度。
- 图片下载仍由工具执行 URL 安全校验、格式校验和大小限制；技能层不要绕过这些限制。
