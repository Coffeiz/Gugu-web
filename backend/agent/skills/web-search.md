# 联网搜索技能

按可用工具和任务性质选择搜索路径：

| 工具 | 用途 | 成本 |
|---|---|---|
| `web_search` | 当前模型 Provider 提供的原生网页搜索，适合大部分信息检索与事实核验；支持 MiniMax、GLM、Qwen 百炼、DeepSeek、MiMo 与 Ollama Cloud | 工具由 Provider 提供，使用当前模型凭据；调用可能产生搜索服务和模型费用，按 Provider 规则计费 |
| `xng_search` | 免费搜索引擎，适合简单查找、定位官网/文档和关键词搜图：`mode=web` / `images` / `both` | 免费、无配额；简单任务优先 |
| `deep_research` | 管理员选择的 Tavily / 百度搜索 / You.com：Tavily/You.com 返回研究答案，百度返回普通搜索引用，适合"读+总结/比较/研究/给引用" | 有每日次数配额（`SearchUsage`） |
| `similar_image_search` | 根据已有图片以图搜图，找同款/相似图 | 按独立日额度限制 |
| `read_file` | 读取文件、历史附件或图片搜索选中的网络图片；支持混合批量并交给多模态模型分析 | `items` 最多 20 项、源文件总量最多 64 MiB；网络 URL 仅限图片 |

需要判断或比较图片内容时，详细的分析维度和输出规范见 [`image-analysis.md`](image-analysis.md)；本技能只负责搜索、选图和调用工具。

## 怎么选

1. **按任务复杂度选择普通搜索**：`xng_search` 是免费搜索引擎，简单任务优先使用，例如定位官网、文档、下载地址、查单个明确事实或关键词搜图；它主要提供候选网页与摘要，适合简单查找。`web_search` 适合大部分信息检索与事实核验，例如问题有多个条件、需要理解上下文、查证近期动态或追查来源。简单任务用 XNG 即可完成时，不必再调用可能收费的 Provider 搜索；任务超出简单查找时，直接使用 `web_search`，不要求先走一遍 XNG。需要交叉核验时，可用两种搜索补充不同来源。
2. **复杂任务混合使用多种搜索与阅读方式**（跨来源汇总、行业研究、趋势梳理、多维方案比较、研究报告）→ 按子问题组合 `xng_search`、`web_search`、`http_get` 与 `deep_research`：用免费的 XNG 定位官网、文档和原始数据，用 Provider 搜索检索大部分信息与补充不同线索，用网页原文阅读核验关键证据，再用深度研究聚合资料、分析关联。可以先通过深度研究建立框架，再针对缺口或分歧用普通搜索和原文阅读补证；不固定顺序，也不要求每次调用全部工具。复杂任务不要只依赖单个引擎或一份生成式汇总，关键结论仍须比较独立来源。仅查一个事实、读一篇文章、附来源链接或做简单对照，不因此自动升级为深度研究。
3. **已有图片要以图搜图**（找同款、相似图、出处）→ 先加载 `image-analysis` 技能，再调用 `similar_image_search`。使用当前图片的 `attach_id` 或网络图片的 `image_url`；不要先把图片外观改写成文字去搜索。它返回相似候选，不代表确认是同一张图。
4. **按文字关键词找图片** → `xng_search(mode="images")`；需要同时找文字和图片线索时用 `mode="both"`。它不能替代已有图片的以图搜图。
5. **单篇网页阅读** → 用 `http_get` 读取已找到的页面；需要聚合多个页面的信息并展开分析时，再用 `deep_research`。
6. **覆盖不足或搜索失败** → XNG 覆盖不足时转用 `web_search`；Provider 搜索缺少可验证链接时用 XNG 定位原始页面。仍缺少关键资料且任务需要聚合分析时，再使用 `deep_research`。没有足够证据时说明缺口，不把工具失败当成内容不存在。

### 具体事实的真实性核验

- 推荐、列举、比较、介绍或引用具体内容时，核对实体是否真实存在，以及名称与作者、创作者、型号、版本、出处等属性是否对应；注意同名、译名、翻唱、改编与不同版本，不能只因名称看起来合理就采用。
- 不确定的候选先查证，再纳入回答；模糊记忆与生成式搜索答案只作为线索。优先核对官方作品页、发行方目录、产品文档、论文原文或可信内容平台的原始记录。
- 主观评价与推断应和客观事实区分。无法核实时，删去候选、收窄结论或说明不确定；不要为满足推荐数量、补齐列表或迎合用户期待编造内容，也不要把“本次没查到”说成“不存在”。

### 多来源查找与比对

- 信息搜索默认考虑多个来源。对影响结论的关键事实，建议用 **2～3 个相互独立、直接相关的来源**核对，优先包含官方公告、产品文档、论文、原始数据或当事方声明等一手资料；简单网址定位或单一官方规格无需凑数量。
- 搜索工具不同不等于来源独立。XNG 与 Provider 搜索若都指向同一篇文章，仍只算一个来源；同一新闻稿的转载、互相引用的文章和相同摘要不能充当多份独立证据。
- 对照实体、版本、时间、地域、统计口径及适用条件，再判断是否一致；不要只比较标题或搜索摘要。关键结论应打开来源页面核验，区分事实、作者观点、预测和传闻。
- 结果冲突时，优先追溯原始资料与更新记录，检查是否因时间或口径不同造成差异；仍无法消除分歧时，列明各方说法、对应来源及不确定点，不取平均、不凭搜索排名裁决，也不隐藏反例。
- Provider 返回的生成式答案与深度研究汇总都是待核验材料。缺少来源链接时，用 XNG 查找可验证的原始页面；不要把另一模型重复同一结论当成事实已经被证实。
- 最终回答让关键结论与支撑它的来源相对应；只有一个来源或暂时无法核验时，如实说明，不虚构“多方证实”。

### Provider 原生参数

工具名统一为 `web_search`，参数按本轮返回的 Schema 填写，不能跨 Provider 套用：

- MiniMax：`query`。
- GLM：`search_query`、`search_engine`、`search_intent` 及官方筛选字段。
- 百炼：Responses 使用 `input`；Chat Completions 使用 `messages`、`search_options`。后者返回联网答案，但不提供结构化来源链接。
- DeepSeek：`query`、`count`、`ori_question`、`localization`、`need_content`。
- MiMo：`messages`、`tools=[{type:"web_search", ...}]`；需在官方控制台开通联网服务插件并选择支持的模型。
- Ollama：`query`、`max_results`（最多 10）；搜索由官方云端提供，需 Ollama Cloud API Key，不能使用本地服务的鉴权密钥。

### 图片路由优先级

消息带图片时，按以下顺序判断：

1. 识别、找角色、找出处、找同款或相似图：先 `similar_image_search`。
2. 候选需要核对文字事实：再用 `xng_search` 查来源页和作品资料。
3. 用户只要描述当前图片：直接视觉分析，不强制搜索。
4. 用户明确要求关键词找图，且没有要分析的图片：`xng_search(mode="images")`。

“以图搜图没有结果”时，可以补一次 `xng_search`，但应使用用户明确提供的作品名、角色名等文字线索，不要把模型猜测的外观描述当成事实反复搜索。

## query 怎么写

`xng_search` 面向传统搜索引擎，第一次调用优先把用户问题提炼成**实体 + 关键术语**的短关键词组合：

- 保留人名、组织名、项目名、产品名、版本号、年份/日期、关键技术术语。
- 不要把用户完整自然语言问题原样复制成一大句。
- 可以按需要混用中英文关键词；冷门技术项目英文名/仓库名应保留原文。
- **精确文件名、完整报错文本、论文标题、产品完整型号**本身就是高价值检索词，不要为了“短”而破坏它们。

### 宽泛新闻查询（先判断范围，再收敛搜索）

下面这些在没有其它限定时都不是可执行的搜索范围：`新闻`、`国际新闻`、`最新消息`、`看看有什么`、`随便搜搜`。遇到完全没有主题、对象/地区或时间范围的请求时：

- **禁止调用 `xng_search`、`deep_research` 或其它搜索工具**；
- **禁止先输出“我去搜搜看”“我先查一下”再调用工具**；
- 先向用户追问一个最小限定，至少明确具体主题、对象/地区或时间范围中的一项；
- 用户补充了明确地区或对象（例如“欧美的”）后，视为已经足够收敛：默认搜索最近 24 小时，按科技、经济、体育、文化等安全类别分组，每类只取少量结果；不要继续追问“具体想看哪一类”；
- 用户明确说“随便搜搜国际新闻”也不能跳过澄清，因为它仍会一次召回不可控的政治、战争、灾难等敏感内容；
- 用户补充范围后，再把请求改写成少量具体关键词，不要原样把宽泛句子作为 query；必要时主动排除高风险类别。

示例：

- `随便搜搜国际新闻` → 先问“想看哪个国家/地区，或者哪段时间的？”
- `欧美的` → 直接按最近 24 小时的科技、经济、体育、文化等安全类别少量搜索，不再重复追问栏目。
- `最近有什么新闻` → 先问主题或地区，再确认时间范围。
- `最近 Anthropic 发布了什么新模型` → 可以搜索 `Anthropic 新模型 2026`。

涉及政治、战争、暴力、灾难、极端主义等敏感新闻时：

- 只提取来源、日期、事件主体和中性事实；
- 不复制标题、摘要或正文原文，不展开图形化细节；
- 不把多个结果的敏感摘要整段拼接进模型上下文；
- 如果结果包含明显敏感片段，跳过该片段，只保留安全元数据和必要的中性概括；
- 提供商拒绝时不要原样重试同一批结果，也不要为了绕过限制而隐晦改写。

例：用户问“最近 Anthropic 发布了什么新模型”时，`xng_search.query` 优先类似 `Anthropic 新模型 2026`，而不是把整句问题原样传入。

## 事实准确性与时效核验

新闻、赛事、行情、版本发布、人物任职等时效事实，搜索结果只是候选线索，不是已核实事实。整理前必须以当前时间为基准逐条核验：

1. **先锁定时间范围**：从 system prompt / 当前消息时间取得 `as_of`，查询词带上当前年份、具体日期或明确时间窗口；“今日/本周”不能只靠标题理解。
2. **区分三个时间**：记录来源发布时间、事件实际发生时间和当前状态（已发生 / 进行中 / 未开始）。来源发布时间不能代替事件发生时间。
3. **赛事和未来事件**：只有确认事件已开始或结束，且来源对应当前年份/当前场次，才能写比分、排名、冠军、杆位等结果；未开始只能写赛程和“待开始”，禁止预写结果。
4. **历史页面排除**：页面没有明确年份、年份不符、或内容明显是往届/旧闻时，不得放入今日速览；不要根据标题、摘要或搜索排序猜年份。
5. **来源交叉核验**：重大或容易混淆的事实，优先用官方赛程/公告或至少两个独立可靠来源核对；来源日期、事件年份或当前状态无法确认时，舍弃该条并说明未纳入。
6. **输出边界**：每条新闻只陈述已核验事实，必要时标注“截至 YYYY-MM-DD HH:MM”；不要把搜索结果中的推测、预测或传闻改写成确定事实。

## 汇总时附信息源

- 用户要总结、梳理、比较或研究联网资料时，最终答复必须附上实际支撑结论的来源链接。优先把 Markdown 链接放在对应结论附近；长总结可在末尾增加简短“来源”列表。
- 选择与结论直接相关、内容确实读过或核验过的页面；能找到时优先使用官方公告、产品文档、论文原文等一手来源。多个来源支持不同结论时，分别标明，不能把来源拼成一个笼统背书。
- 链接必须原样来自 `xng_search` / `web_search` / `deep_research` 等工具的真实结果。只有标题没有 URL 时，不要猜 URL；来源不足以支撑结论时，收窄或标注该结论，不要靠加链接制造可信感。
- 简单查找可以直接列出“标题 + 链接 + 简短说明”；无需重复列出大量相似结果，通常保留最相关的少量来源即可。

## 看 `search_status` 决定下一步

SearXNG 搜索结果会带 `search_status.state`，不要把所有 `results=[]` 都理解成“网上没有”：

1. `state=ok`：基础设施正常且已有结果，直接使用；够答就停。
2. `state=empty`：搜索设施没有报告故障，但本次 0 结果。换同义词/中英文/更宽的一组短关键词再搜 **最多一次**。
3. `state=degraded`：部分搜索引擎不可用，覆盖下降。若已有足够结果就直接用；若 `results=[]`，最多做一次更宽查询，仍空则用 `web_search` 补充；需要聚合研究时再考虑 `deep_research`。
4. `state=unavailable`：当前配置的 SearXNG 引擎均不可用。**不要继续换关键词轰炸同一个 SearXNG**，改用 `web_search` 补充；任务需要聚合研究时用 `deep_research`。这不代表互联网上没有相关内容。

`failed_engines` 里的 reason 是归一化诊断（如 `timeout` / `captcha` / `rate_limited` / `suspended` / `unavailable` / `unknown`），用于判断搜索设施状态，不要把它当成内容结论。

## 成本与预算

- `web_search` 由当前模型 Provider 提供，使用其凭据，调用可能产生搜索服务及模型费用；`deep_research` 与 `similar_image_search` 有独立每日次数。XNG 走自建搜索，不消耗 Provider 搜索服务额度。
- 简单任务优先使用免费的 XNG；大部分信息检索使用 `web_search`；复杂任务混合使用普通搜索、原文阅读和深度研究，按子问题分工。按任务复杂度直接选择，不要求每次先试 XNG，也不要求调用全部工具。交叉核验的目标是增加独立证据，不是增加工具调用次数。
- 第一轮围绕问题做宽搜，随后只针对关键事实、来源冲突、时效性或缺失维度补查。已有足够可靠来源且能够回答问题时停止，不为凑来源数量、润色措辞或重复同一材料继续调用。
- `empty` 可以换一次关键词；`unavailable` 表示搜索设施失效，应换搜索路径，不代表内容不存在。

## 搜索到图后怎么发

`xng_search(mode="images")` 和 `similar_image_search` 都只返回候选列表（标题+来源页+图片直链 `img_src`+缩略图），**不会自动发送**。

用户明确要看图/要一张图时——找图本身就是要看/要发，没有额外的"保存"步骤——搜到后**同一轮直接接着调 `send_file(url=选中候选的 img_src, title=简短描述)`** 把图发进对话/IM，不用再问一句"要不要发"。

多个候选且用户没指定要哪张时，挑最匹配关键词的第一条发；用户明确想多看几张再多发几张（IM 端一次发太多张会很吵，建议 1~3 张为宜）。

如果用户要求快速辨认、比较或核对搜索到的图片，先按来源调用 `xng_search(mode="images")` 或
`similar_image_search`，再单独调用 `read_file(items=[...])`。关键词搜图候选在 item 中填写
`url: img_src`、`result_id`、`title`；以图搜图候选填写 `url: image_url`、`result_id`、
`title`；文件库图片填写 `file_id`，聊天附件填写 `attach_id`。一轮对话最多发起 3 次含网络图片的读取，每批最多 20 项且源文件总量不超过 64 MiB；文件库图片和历史附件不占网络图片额度。不需要看图时不要读取，避免额外下载和视觉输入成本。

## similar_image_search 找同款后怎么处理

用户说“找同款”“找相似图”“这张图还有哪些类似图片”时，调用
`similar_image_search`。当前消息图片填写上下文中的 `attach_id`；如果目标是网络图片，填写可靠的
`image_url`。工具返回的是相似候选列表；用户还要求辨认角色、核对同款或比较候选内容时，必须从候选中挑选 2～5 张调用 `read_file(items=[{url: image_url, title, result_id}, ...])`，结合图像内容判断，不能只按 similarity、标题或来源下结论。

相似图结果返回后，优先用候选标题、来源页 URL、页面正文线索和实体关键词调用 `xng_search`，检查候选是否包含有效角色名、作品名、出处或商品信息；再按需要调用 `read_file(items=[...])` 比较候选图像细节。不要把上一轮对话中的猜测直接当作当前图片搜索结论，也不要把图片直链本身当作搜索词。

`similar_image_search` 的 `similarity` / `score` 仅用于服务端排序，不能当成百分比、置信度或“相似度 X/5”。`score >= 2` 的候选应作为重要参考，但仍需通过网页内容或图像细节核对；不要因分值较低就主动否定候选。用户只要结果时，直接列出标题、来源和 URL，不读取候选图。

如果管理员未配置或额度用尽，直接说明 `similar_image_search` 当前不可用；需要按关键词找其他图片时，改用 `xng_search(mode="images")`。

注意：这条和 `文件操作` 技能里"`send_file` 只在用户明说「发给我」时才调（保存≠发送）"针对的是**文件库文件**——库文件有"生成/保存"和"发送"两个独立动作，不能默认发送；网络图片没有保存这一步，两者不冲突。
