# Qwen description 与 full Schema 连续会话对比报告

## 实验定义

本实验比较的是**完整工具集注入成本**，不是缩减工具集后的成本：

- 5 工具脚本：向模型注入完整 100 个工具的 Schema/description，连续测试 5 个目标工具。
- 20 工具脚本：向模型注入完整 100 个工具的 Schema/description，连续测试 20 个目标工具。
- 每种模式均为 1 次预热加连续 session 测试。
- 工具执行被拦截为脱敏占位结果，不写入真实业务数据。

之前出现两张固定成本表完全相同，实际上是符合这个实验定义的：固定成本由“完整工具集”决定，而不是由本轮实际调用了多少种工具决定。差异应体现在连续会话的运行时请求、续轮和累计 input，而不是固定 Schema 本身。

## 固定注入成本

两套脚本都注入完整 100 工具，因此固定成本相同。

| 项目 | description | full | description 节省 |

| Schema 工具数量 | 4 adapter | 100 | 96 个注册 Schema |
| Schema token/逻辑请求 | 351 | 13,111 | 12,760 |
| 目录 token/逻辑请求 | 5,705 | 0 | -5,705 |

| 固定成本节省比例 | - | - | 53.81% |

这里的 `21 次`是 1 次预热加 20 次测量的归一化口径。description 模式不是只描述当前被调用的工具，而是通过目录描述完整工具集；full 模式则直接注入完整 Schema。

## 固定成本与实际请求次数

固定 token 只描述每次 provider 请求中由工具 Schema/目录带来的固定部分；实际固定总量还要乘以请求次数。含预热的实际请求数和折算结果如下：

| 测试脚本 | 模式 | 每次固定 token | 实际请求数（含预热） | 实际固定注入 token |
|---|---|---:|---:|---:|
| 5 工具 | description | 6,056 | 50 | 302,800 |
| 5 工具 | full | 13,111 | 51 | 668,661 |
| 20 工具 | description | 6,056 | 71 | 429,976 |
| 20 工具 | full | 13,111 | 51 | 668,661 |

因此，按固定部分的实际请求总量折算：5 工具 description 节省 `365,861`，约 **54.72%**；20 工具 description 节省 `238,685`，约 **35.70%**。但这不是最终 provider input 节省，因为额外续轮也会带来上下文、工具结果和模型输出成本。

## Token 统计公式

- Anthropic 口径下：`provider input = fresh input + cache read`。
- 加权缓存率：`cache read total / provider input total`。
- 连续会话每轮的 `run input` 是该轮所有 provider 子请求 input 的累计，不等同于最后一次上下文长度。
- 实际 provider input 节省率：`(full provider input - description provider input) / full provider input`。
- Schema 固定成本节省率：`(full fixed token - description fixed token) / full fixed token`。

## 对实验结果的解释

5 工具场景中，description 的固定 Schema 成本明显较低，且只发生 49 次测量阶段 provider 请求，所以累计 input 比 full 少 43.33%。20 工具场景中，description 虽然每次固定注入仍少 7,055 token，但发生了 70 次 provider 请求，full 只有 50 次；额外的 Schema 查询、工具续轮和输出历史把固定成本优势大幅抵消，最终只少 4.30%。

因此，“实际调用工具类型越少，description 一定节省越多”只能作为趋势假设，不能从这四组结果直接证明。要做严格对照，需要固定相同的用户消息、模型输出路径和 provider 请求次数，只改变工具调用种类。

## 结论

这两个脚本的固定成本数据相同是正确的，因为两者都应该注入完整工具集。5 工具和 20 工具的比较重点是：在相同完整工具集下，实际连续调用规模如何影响运行时 provider 请求数、工具续轮和累计 input。

本次旧的“只注入 5/20 个工具”的重测结果不属于本实验口径，已废弃，不写入结论。
