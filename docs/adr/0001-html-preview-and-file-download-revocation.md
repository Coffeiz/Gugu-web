# ADR-0001：HTML 预览信任边界与文件下载撤销语义

> 状态：已接受
> 创建：2026-10-16
> 最近更新：2026-10-16
> 关联范围：HTML 文件预览、文件下载授权与会话撤销
> 关联文档：PR #102

## 0. 决策摘要

| 决策主题 | 当前结论 | 主要边界 |
|---|---|---|
| 用户上传的 HTML 预览 | 保留页面脚本、表单和外部网络能力，不增加默认确认弹窗 | HTML 在 sandbox iframe 内运行；不得获得宿主同源权限、顶层导航权限或其他用户数据 |
| 文件流中的令牌撤销 | 每个请求开始时授权一次，开始后的响应流允许完成 | 新请求及 Range 续传重新鉴权；不按传输分块查询数据库 |

## 1. 背景与问题

### 1.1 HTML 文件预览

文件库允许用户上传并预览 HTML。交互页面、可视化报告和依赖 CDN 的页面需要脚本、表单及外部网络请求。完全禁用这些能力会使一部分用户上传的页面无法按原设计运行。

当前预览使用 sandbox iframe，允许 `allow-scripts` 和 `allow-forms`，不授予 `allow-same-origin` 或顶层页面导航权限，并设置 `referrerpolicy="no-referrer"`。内容安全策略允许预览页面发起外部网络请求。此隔离阻止 HTML 直接读取咕咕宿主页面的 DOM 和认证 Cookie；脚本仍可发送该 HTML 自身能够读取的内容。

### 1.2 文件下载撤销

文件下载通过短时签名 URL 授权。令牌关联文件、用户和安全版本。请求开始时校验令牌、账户状态和安全版本；HTTP Range 续传会发起新请求，因此会重新校验。已开始的响应流当前不会因用户随后登出、改密或安全版本变化而中途终止。

此前按数据块检查会话状态的实现会在传输期间反复创建数据库会话和查询账户状态，需要判断这类即时撤销是否值得其持续开销。

## 2. 目标与约束

### 2.1 目标

- 让用户预览自己上传的 HTML 时，页面常见交互能力能够正常工作。
- 保证预览内容不能越过 iframe 边界访问咕咕宿主认证信息、宿主 DOM 或其他用户的数据。
- 撤销会话后阻止使用该会话发起新的文件请求，同时避免按传输分块反复查询数据库。

### 2.2 范围外

- 不判断用户 HTML 是否善意，也不承诺阻止它发送自身可读取的数据。
- 不提供下载开始后的即时中断语义。
- 本决策不覆盖公开分享、第三方 HTML 分发或 Agent 自动打开不可信 HTML 的新信任模型。

## 3. 候选方案

### 3.1 HTML 预览

| 方案 | 取舍 |
|---|---|
| 禁用脚本或外网，或每次预览前要求用户确认 | 降低预览内容主动联网的能力，但会破坏交互页面和依赖外部资源的正常用途；没有发现具体的宿主边界突破路径来证明该限制有必要 |
| 保留 HTML 功能并维持 iframe 隔离 | 页面可按设计运行；产品继续负责隔离宿主数据和权限，用户承担其 HTML 自身内容的行为风险 |

### 3.2 文件流撤销

| 方案 | 取舍 |
|---|---|
| 每个数据块或固定间隔重新查询账户状态 | 可以更快中断在途流，但增加数据库访问和连接开销 |
| 每个 HTTP 请求开始时授权，之后允许响应完成 | 撤销后不能开始新请求；在途下载可能继续完成，数据库授权检查次数与请求数而非文件大小相关 |

## 4. 决策

### 4.1 HTML 预览信任边界

- 保留脚本、表单和外部网络访问；不增加默认确认弹窗或交互预览模式切换。
- 保留 sandbox 隔离，不授予 `allow-same-origin`、顶层页面导航等宿主权限。
- 宿主页面不得因预览运行而向 iframe 注入其他用户数据或认证凭据，也不得无条件信任 iframe 发来的 `postMessage`。
- 用户打开自己上传的 HTML，即接受该 HTML 可以运行脚本、访问外网并发送其自身可读取内容的风险。咕咕负责维护宿主权限边界，不负责判断用户 HTML 是否善意。

### 4.2 文件下载撤销语义

- 每个文件流 HTTP 请求开始时执行一次权威授权、账户状态和安全版本校验。
- 授权通过并开始传输后，允许当前响应完成；不按数据分块重复查询数据库。
- 新下载请求和断线后的 Range 续传都视为新请求，必须重新校验。已撤销会话不能使用旧令牌开始新的流请求。

## 5. 后果与取舍

| 结果 | 影响 |
|---|---|
| HTML 页面能力保持完整 | 用户上传的 HTML 可以连接外部网络并发送自身能够读取的内容；这是预览功能明确接受的行为 |
| iframe 隔离仍是安全边界 | 若移除同源隔离或授予宿主导航权限，必须重新进行安全评审 |
| 在途文件流不会即时撤销 | 登出、改密或停用账户不会中断已经开始的文件传输；后续请求和 Range 续传仍会被拒绝 |
| 不按块查询数据库 | 长文件下载的授权查询量降低；产品不承诺传输中的即时会话撤销 |

## 6. 依据与验证

### 6.1 HTML 预览

本决策基于当前 iframe sandbox 权限和预览策略：预览没有 `allow-same-origin`，因此其脚本不能直接读取咕咕宿主页面 DOM 或 Cookie。没有发现 HTML 能越过该隔离访问咕咕其他私有数据的具体路径。HTML 向外部发送其自身内容属于用户文件运行行为，不等同于宿主权限突破。

这项结论依赖宿主不向 iframe 注入认证信息或其他用户数据，并持续保持 sandbox 隔离。若实现边界改变，应按第 7 节重新评估。

### 6.2 文件流

隔离 SQLite A/B 压测使用 64 MiB 文件比较“每块检查”与“每请求检查”：每路数据库状态检查从 65 次降为 1 次；吞吐分别为 1 路并发 `517.6 → 3763.8 MiB/s`、4 路 `453.5 → 2990.1 MiB/s`、8 路 `416.9 → 2797.6 MiB/s`。

这些数据说明两种检查频率在该测试环境下的相对开销，不代表生产 PostgreSQL、实际磁盘或网络的吞吐承诺。撤销语义由每个请求重新授权保证；Range 续传会重新鉴权。

## 7. 重新评估条件

出现以下变化时重新评估 HTML 预览决策：

- 支持公开分享或预览第三方来源的 HTML。
- Agent 开始自动打开用户未主动选择的 HTML。
- 宿主需要向预览注入私有数据或凭据。
- 发现预览内容能够突破 iframe 隔离访问宿主数据或执行宿主权限操作。

出现明确的下载即时撤销需求、敏感文件专属访问策略或新的存储授权模型时，重新评估文件流撤销决策及其数据库开销。
