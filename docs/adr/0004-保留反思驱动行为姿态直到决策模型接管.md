# ADR-0004：保留反思驱动行为姿态直到决策模型接管

> 状态：已接受
> 创建：2026-10-20
> 最近更新：2026-10-20
> 关联范围：对话后反思、行为提示词选择、感知遥测与主对话上下文
> 关联文档：`backend/agent/memory/reflection.py`、`backend/agent/behaviors.py`

## 0. 决策摘要

| 主题 | 决策 | 边界 |
| --- | --- | --- |
| 当前行为选择 | 保留反思输出 `perception.intent` 并写入 stance，供后续对话选择行为模块 | 不为 stance 增加独立模型调用，不在本 ADR 中停用现有 behavior |
| 感知遥测 | 保留反思产出的结构化观测、误判和反馈遥测 | 作为诊断与评估数据，不自动构成决策模型训练或行为更新闭环 |
| 未来决策模型 | 等决策模型具备接管条件后，再评估并迁移行为选择职责 | 新架构应单独记录决策，并明确行为状态的作用域、保留、切换和清除语义 |

## 1. 背景与问题

当前系统在对话结束后异步运行反思。反思调用除维护记忆外，还产出本轮 `perception.intent`；系统将其写为用户级 stance，下一次构建上下文时由 `agent/behaviors.py` 映射到行为提示词模块。

曾考虑停用 behavior 系统，等待未来的决策模型统一决定行为。但当前 stance 是既有反思结果中的一个字段，没有独立的 stance 模型调用。停用它会先移除现有行为选择能力，却不会带来避免额外 stance 调用的收益。

反思同时产出结构化感知数据，供 `agent.perc` 事件和管理端感知面板使用。遥测不参与当前回复的热路径，也不自动改变行为策略。

## 2. 目标与约束

- 在未来决策模型尚未接管前，保留现有行为提示词与 stance 选择链路。
- 不为 stance 另增独立模型调用。
- 保留可用于观察意图分布、误判、歧义和反馈的结构化遥测。
- 明确区分反思记忆更新、遥测记录与行为决策，避免把遥测误认为自动学习闭环。
- 本决策不预先规定未来决策模型的调用时机、模型选择或行为状态存储方案。

## 3. 候选方案

1. 立即停用 stance 与 behavior，等待决策模型：暂时失去当前行为提示词选择能力，但没有现成决策模型可以替代。
2. 保留当前链路，未来模型成熟后再迁移：复用已有反思输出，保留当前能力；接受 stance 仍是反思后的滞后判断。

采用第二种。

## 4. 决策

### 4.1 当前架构

- 继续由反思输出 `perception.intent` 并按现有规则写入 stance。
- 继续由行为模块选择逻辑读取 stance、应用新鲜度规则并选择提示词模块。
- 继续将生效的行为规则按上下文组装逻辑注入主对话。stance 变化时追加新的上下文记录；相同摘要不重复追加。
- 不增加专门用于 stance 决策的模型调用，也不因本 ADR 删除行为提示词、选择逻辑或 stance 持久化。

### 4.2 遥测

- 保留反思产出的结构化感知、纠正和反馈遥测，以及现有聚合和诊断入口。
- 遥测只用于观察与评估；除非未来另有明确决策，不得据此自动改写 stance、行为模块或用户记忆。
- 遥测继续遵守现有脱敏边界，不记录用户原文、附件名、令牌或密钥。

### 4.3 未来迁移边界

当决策模型准备接管行为选择时，应重新评估旧 stance 链路，并在新的 ADR 中明确替代关系。新决策与旧反思遥测应分开记录：至少能区分决策模型选定/保留/清除的行为与反思观察到的用户 intent。

若新模型提供“保留当前行为”动作，必须定义当前行为的作用域、有效期和清除规则。对每次生成，组装阶段仍须提供最终有效的行为提示词；“不更新状态”不能被解释成“本轮无需让生成模型知道现有行为”。新增回复前模型调用的延迟、成本与缓存影响应在迁移决策中明确评估。

## 5. 后果与取舍

- 继续保有当前的行为提示词选择能力，不产生新的同步模型调用。
- 行为选择仍可能滞后于当前用户输入，因为 stance 来自先前完成的反思；主生成模型仍可依据当前消息修正回应。
- 结构化遥测保留一定的提示词与存储开销，但能继续支持误判分析和未来决策模型评估；本决策不承诺遥测会自动提升模型质量。
- 未来引入独立决策模型时，可能增加回复延迟和调用成本，需单独评估。

## 6. 依据与验证

- `backend/agent/memory/reflection.py` 在现有反思结果处理中记录感知遥测并写入 stance；该字段与记忆反思共用一次反思结果。
- `backend/agent/memory/store.py` 提供 stance 的读取与写入；`backend/agent/behaviors.py` 实施 stance 到模块的映射及新鲜度规则。
- `backend/agent/context/assembly/turn.py` 仅在 stance 摘要变化时把 stance 上下文追加到当前消息区域。由此可知 stance 不改固定 system prompt，但变化会影响动态上下文及其后的缓存匹配。
- 本 ADR 仅记录架构决策，没有修改运行时代码，也未执行测试或缓存基准；上述代码引用描述当前实现，不代表未来实现约束。

## 7. 重新评估条件

当决策模型能够稳定地选择、保留和清除行为，并有明确的质量评估方法时，重新评估 stance 的来源、存储作用域、行为注入方式及相关遥测。若遥测不再用于诊断或评估，也可另行审查其保留范围和成本。
