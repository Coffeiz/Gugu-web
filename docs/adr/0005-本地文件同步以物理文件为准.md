# ADR-0005：本地文件同步以物理文件为准

> 状态：已接受
> 创建：2026-10-20
> 最近更新：2026-10-20
> 关联范围：本地文件同步、目录对账、File 元数据与配额
> 关联文档：`docs/adr/README.md`

## 0. 决策摘要

| 决策主题 | 当前结论 | 主要边界 |
| --- | --- | --- |
| 文件冲突与缺失 | 在绑定范围及文件状态通过验证后，以物理文件为准；完整扫描确认缺失时软删除对应 File 记录 | 不完整扫描、根身份变化、路径越界、权限/读取/投影失败时保留记录并报告失败 |
| 目录对账 | 只补齐数据库期望存在的缺失目录 | 不删除孤儿目录，不搬迁文件，不静默删除或移动目录记录 |
| 漏事件恢复 | 保留 watcher 与周期性完整扫描 | 完整扫描是漏事件恢复机制，删除判定必须通过根身份与路径二次校验 |

## 1. 背景与问题

本地同步同时维护物理文件与数据库 `File` 元数据。Shell 等外部操作可以绕过 watcher；文件删除事件丢失后，物理文件已不存在，但活动 `File` 记录仍留在数据库，导致界面展示失效条目，打开时无法读取内容。反过来，物理文件与数据库元数据同时变化时，人工冲突记录会阻止物理文件重新投影。

单次事件、部分扫描或无法访问的目录不足以证明文件已删除。只有一次完整、可访问且绑定根目录身份未变化的扫描，结合逐路径二次检查，才可把缺失作为物理事实处理。

## 2. 目标与约束

- 让漏掉 watcher 事件的 Shell 文件删除能由完整修复扫描收敛，避免无效 File 记录长期残留。
- 保留物理文件内容作为本地同步的权威事实；稳定读取并通过范围校验后，投影更新数据库元数据。
- 对未能安全验证的对象保留数据并报告失败，不把错误解释为删除。
- 限定普通目录对账为补齐缺失目录，不在其中删除目录或搬迁文件。
- 不把本地文件同步语义扩展到对象存储；OSS 无本地目录绑定，不执行这些规则。

## 3. 候选方案

1. 继续要求管理员逐条选择保留数据库版本或本地版本。该方式安全但不能自动修复 watcher 漏掉的 Shell 删除，且让可验证的本地事实长期停留在待处理状态。
2. 无条件按文件缺失删除 File 记录。实现简单，但无法区分真实删除、权限错误、根目录错误、扫描不完整或竞态，不接受。
3. 以通过完整性和路径验证的物理事实为准；验证失败时保留记录并失败退出。该方案可自动恢复正常漏事件，同时保留错误边界，予以采用。

## 4. 决策

1. 对本地绑定执行 `repair` 时，完整扫描并确认绑定根目录身份未变化后，物理文件为文件内容及文件存在性的权威来源。
2. 对物理文件仍存在的候选项，必须确认它位于绑定根目录内、不是符号链接，并在读取期间保持稳定。验证通过后，以该文件更新 `File` 元数据、同步 journal、缩略图和配额投影；两侧同时变化不再要求人工冲突选择。
3. 对物理缺失候选项，只有在完整扫描未被权限跳过、扫描范围非失效、绑定根目录身份未变，且投影前再次确认路径仍缺失时，才软删除对应活动 `File` 记录，并在同一同步流程中记录删除 journal、通知及配额校准。该规则也适用于完整扫描发现绑定范围内所有文件均缺失的情况。
4. 扫描不完整、根目录不可用或身份变化、路径越界/符号链接、读取不稳定、权限不足、数据库投影失败等情况，不得据此删除 File 记录；相应任务必须保留错误状态和可观察的失败计数。
5. 文件夹记录的物理目录缺失不等于可删除目录记录。普通修复不投影物理目录删除；文件夹记录与物理目录不一致时保留记录并计数跳过。
6. 目录对账可以补建数据库结构所需的缺失目录。它不得删除孤儿目录，不得搬迁文件，也不得通过移动或删除目录来改变文件归属。孤儿目录与位置不一致文件仍可报告。
7. 文件内容缺失对应的 File 软删除与“目录对账”是不同职责：前者由有完整扫描证明的本地文件同步修复完成，后者仅管理目录结构。

## 5. 后果与取舍

- Shell 删除漏过实时 watcher 后，完整修复扫描可清理对应 File 记录；用户不再看到无法打开的失效条目。
- 已验证的本地文件可以自动覆盖数据库中的陈旧元数据，减少人工冲突处理。
- 软删除保留可恢复性；配额和同步记录需要与删除投影一致更新。
- 扫描验证失败时任务可能保持异常，需要修复权限或绑定路径后重新运行；这是为避免误删接受的成本。
- 孤儿目录和位置错位报告可能继续存在，需由专门且明确授权的维护流程处理，普通补修不再顺手改变其物理布局。

## 6. 依据与验证

- `backend/app/services/filesync/scan.py` 对清单内文件进行稳定读取及指纹验证，并对缺失路径进行投影前二次检查；扫描会检测权限排除与符号链接遮蔽。
- `backend/app/services/filesync/runner.py` 负责校验根目录身份、按候选批次投影以及把任务结果持久化。
- `backend/app/services/filesync/targeted.py` 在同一数据库事务内投影 File 删除、journal 和配额变化；修复完成后另有全量配额校准。
- `backend/app/services/storage/folder_doctor.py` 报告缺失目录、孤儿目录和错位文件；普通修复范围限定为缺失目录补建。
- 本地执行文件同步与目录对账回归：`tests/storage/test_folder_doctor.py` 与 `tests/storage/filesync/test_filesync_periodic.py`、`test_filesync_phase1.py`、`test_filesync_runner.py`、`test_filesync_phase5_admin.py`、`test_linux_watcher.py`，结果为 109 passed、9 skipped。此结果只覆盖上述后端测试，不代表 CI 或生产验证。

## 7. 重新评估条件

- 若同步改为对象存储或出现多份同等权威的物理副本，需要重新定义文件存在性与冲突权威。
- 若绑定根身份、完整扫描或逐路径验证机制发生改变，应重新评估缺失记录软删除的安全条件。
- 若产品要自动清理孤儿目录或搬迁错位文件，应另行定义明确授权、预览、审计及失败回滚边界，不扩展普通目录补修。
