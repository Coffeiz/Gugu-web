# ADR-0007：主对话模型读取超时统一为五分钟

> 状态：已接受
> 创建：2026-10-22
> 最近更新：2026-10-22
> 关联范围：主对话 Anthropic、Chat Completions、Responses、Ollama 模型请求
> 关联文档：`docs/reports/2026-10-22-INVEST-MiniMax完整视频首响应超时隔离复现.md`、`docs/devlog/2026-10-22-长视频理解超时与LLM重试风暴调查.md`

## 0. 决策摘要

各主对话协议的模型请求读取超时统一由 120 秒调整为 300 秒，通过共享常量维护。沿用现有重试策略，先观察真实运行；遇到进一步的长等待故障再评估任务保活、异步执行及重试机制。

## 1. 背景与问题

真实视频上传成功后，MiniMax 首次返回模型事件需要约 129～131 秒。旧读取超时在 120 秒终止请求，后续重试仍使用相同门槛，造成长时间等待后失败。

同一完整视频的隔离请求在延长等待后正常返回非空正文，输出仅 183～388 token，没有耗尽 25600 的输出预算。这些数据证明当前门槛会阻止该输入完成，不代表所有长视频都能在五分钟以内返回。

## 2. 目标与约束

统一主对话模型请求的读取等待，不因 Provider、协议或是否包含视频而采用不同门槛。连接、写入、连接池、附件上传、工具执行和独立反思/压缩分支各自的超时策略不属于本次调整。

读取超时是等待网络响应数据的空闲时间，包含首次响应等待；它不是 Run 总时长限制。上游持续返回数据的请求可以执行超过五分钟；上游连续五分钟没有返回数据仍会触发超时。

## 3. 候选方案

- 仅放宽视频请求：可以减少普通请求的失败等待，但需要按媒体识别和协议分别维护策略。
- 统一主对话读取等待至五分钟：改动小，覆盖视频和其他首响应较慢的请求，接受真实故障的发现变慢。
- 立即引入持久化心跳及异步任务管理：本地心跳无法证明同步上游仍在计算，完整机制也超出这次故障修复范围。

采用第二种，未来遇到新故障时再评估第三种。

## 4. 决策

`backend/app/core/retry.py` 维护共享的 `LLM_READ_TIMEOUT_SECONDS = 300.0`。主对话四种协议的驱动均引用此常量，保留现有连接、写入及连接池参数，以及 SDK 的适配方式。

沿用现有的五秒重试间隔、最多五次重试及主对话 900 秒重试准入预算；已输出正文后不重试。900 秒是决定是否开始下一次重试的预算，不会强制中断已开始的请求，因此总等待可能超过 900 秒。不得将五分钟对用户描述成整个任务必定完成或失败的时限。

## 5. 后果与取舍

首响应超过两分钟但不足五分钟的请求不再被旧门槛提前中止。代价是上游卡死或网络失联时，单次失败可能更晚被发现，重试期间的总等待也可能增加。

按当前重试准入规则估算一个没有任何响应数据、且每次都等到读取超时的场景：旧的 120 秒设置可进行 6 次请求尝试，连同 5 次 5 秒间隔约为 745 秒；改为 300 秒后可进行 3 次尝试，连同 2 次间隔约为 910 秒。此估算描述的是重试准入预算与单次读取超时共同作用下的静默等待，不是所有 Run 的总时长上限；持续收到数据的请求仍可能运行更久。

本决策不保证长任务永久存活，不增加本地假进度，不修改视频规格、输出 token 预算或转码策略。运行配置和数据库结构无需迁移。

## 6. 依据与验证

关联报告记录完整视频在 125 秒读取等待时失败、延长等待后两种输入结构均成功，首事件分别出现在 128.793 秒和 131.423 秒。随后一次真实应用链路验证中，首个正文 token 在 197.6 秒到达，最终正文在 207.7 秒完成，未发生重试；另一次成功 Run 的第二轮模型请求耗时 138.8 秒。该组数据与复现细节见 `docs/devlog/2026-10-22-长视频理解超时与LLM重试风暴调查.md` 第 7 节。隔离请求与真实链路的构造、观察指标不同，数据只说明五分钟阈值覆盖了这些已观测请求，不构成响应时间承诺。

回归测试直接构造四个主对话驱动，并用客户端替身捕获传入的 HTTP 超时，断言共享常量仍为 300 秒、四个驱动的读取超时都等于该常量，且连接、写入、连接池参数保持原值。测试使用合成配置，不联网、不读写用户运行配置。本次 Provider、流式重试、视觉消息与用量语义相关的既有回归及新增参数化用例共 116 项通过；新增用例在 devserver 也通过 4 个协议场景。本测试不模拟真实等待五分钟，也不对所有 Provider 逐个发起真实模型请求。

## 7. 重新评估条件

再次遇到有效请求连续五分钟没有数据、长视频仍无法完成、重试造成明显重复计费或过长等待，或 Provider 提供可查询和恢复的异步任务接口时，重新评估按请求分类等待、总时限、重试及持久化任务状态。本轮不提前引入这些机制。
