# ADR-0010：QQ 连接池按主机限流并取消全局上限

> 状态：已接受
> 创建：2026-10-24
> 最近更新：2026-10-24
> 关联范围：QQ 网关进程内的 REST HTTP 连接池
> 关联文档：无

## 0. 决策摘要

| 决策主题 | 当前结论 | 主要边界 |
| --- | --- | --- |
| QQ REST 连接池并发上限 | 不设全局连接总数上限；每个 endpoint 最多 64 条并发连接 | 限制作用于单个进程和 endpoint，不是每个用户独享额度 |

## 1. 背景与问题

QQ 网关进程使用共享的 `aiohttp.ClientSession` 请求 QQ REST API 和 access-token 服务。原连接器配置全局上限 100、每个 endpoint 上限 32。全局上限会让不同 endpoint 争用同一额度；每个 endpoint 上限则直接约束同一服务地址的并发请求。

连接池对照探针显示，在 devserver 的 loopback 模拟服务中，提高 per-host 上限可减少高并发排队，但模拟服务无法代表 QQ 的网络延迟和限流。随后使用已配置 QQ 机器人凭据，对只读 `GET /users/@me` 做了小规模真实请求：32 上限下 33 并发全部成功并创建 32 条连接；64 上限下 33 个请求也全部成功。每档仅有一批请求，不能据此证明提高上限会稳定提升生产吞吐，也没有测试超过 33 的真实并发。

## 2. 目标与约束

- 避免全局连接上限让独立 endpoint 之间争用额度。
- 将单 endpoint 并发上限从 32 提高到 64，以允许更高的同 host 并发。
- 不把本决策解释为 QQ 服务端承诺的容量或速率，不以无上限压力测试验证服务端边界。

## 3. 候选方案

- 保留全局 100、per-host 32：资源边界更紧，但会保留 endpoint 间的全局争用及 32 条单 host 上限。
- 取消全局限制、per-host 64：减少跨 endpoint 的总量争用，并提高单 host 并发；接受多 endpoint 同时繁忙时连接总量增长的风险。

## 4. 决策

- `backend/agent/gateway/qq/client.py` 的 `aiohttp.TCPConnector` 使用 `limit=0`（不设全局连接总数上限）和 `limit_per_host=64`。
- `keepalive_timeout` 保持现有 300 秒，不因本 ADR 改变。
- `limit_per_host` 按 aiohttp 的 endpoint 定义生效：同一连接器内相同 `(host, port, is_ssl)` 的请求共享上限；不是按用户分别计数。
- 连接池按进程创建；独立 QQ 网关进程分别持有连接池。因此系统总体连接数可能达到多个进程及多个 endpoint 上限的总和，本决策不提供跨进程总上限。
- 不更改请求重试、超时、凭据、API 调用行为或其他平台连接池。

## 5. 后果与取舍

该配置允许单 endpoint 最多 64 个并发连接，并避免不同 endpoint 竞争连接器的全局 100 条额度。代价是没有全局 socket 数保护；多 endpoint、高并发或多个 QQ 网关进程同时活跃时，进程及系统文件描述符使用量可能增加。每 host 的 64 条上限仍是连接池保护，但不是对所有外部目标或所有进程的统一上限。QQ 服务端仍可能依据自身策略限流或拒绝请求。

## 6. 依据与验证

- devserver loopback 模拟服务在固定 128 并发、80ms 服务延迟下，对 8/16/32/64 per-host 上限进行了各 512 次请求的对照；峰值服务端并发分别达到配置上限，吞吐随上限升高而增加。此结果只说明连接池排队行为，不代表 QQ API 性能。
- devserver 真实只读探针对 `GET /users/@me` 做了单请求基线和 33 并发测试；32 与 64 两档均为 200，无传输错误或 API 错误。32 档创建 32 条 TCP 连接并有一次连接复用，64 档创建 33 条连接。每档只有一批，样本不足以断言稳定收益，也未测试更高真实并发或 QQ 限流阈值。
- 本 ADR 的配置修改尚未在运行中的 QQ 网关进程加载；需按正常部署/进程重启流程生效。未运行本地测试。

## 7. 重新评估条件

当出现文件描述符压力、连接错误、内存增长，或 QQ API 的 429/服务端错误增加时，应重新评估并考虑恢复全局上限或增加全局并发协调。若后续观测显示单 endpoint 排队仍明显、且服务端错误率稳定，可再依据多轮真实请求数据评估是否调整 64；不得仅凭 loopback 模拟结果提高生产并发。
