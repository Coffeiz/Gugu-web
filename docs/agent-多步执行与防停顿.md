# Agent 多步执行与防停顿（回复循环终止策略）

> **状态**：方案对比 + 选型记录。**当前决策：A-lite + B 保底，观察后再定是否升 A。**
> **进度（2026-06-29）：phase 1（B 意图守卫）已落地** —— `agent/core.py` 新增 `_announces_intent`（将来式宣告 + 问句硬排除 + 本轮零工具 → 逼一轮），anthropic/openai 两路已接、各只追一次。**phase 2（finish 工具 + 翻转终止规则 = A-lite 结构件）待观察后再上**（翻转风险见 §3、§5）。

## 1. 要解决的问题

咕咕有时**只说话不执行**：用户说「帮我查下 X」，咕咕回「好的~我去查一下」**然后就停了**，没有接下来的动作；要用户再追问「查了吗?」才继续。

### 根因
咕咕的回复循环（`agent/core.py` 的 `_run_anthropic` / `_run_openai` 里的 `while` 轮循环）规则是：

> 这轮模型**输出了 tool_use / tool_calls** → 执行、喂回结果、继续循环；
> 这轮**只有文字、没有工具** → **turn 结束**（那段文字就是最终回复）。

即 **「自由文字 + 无工具 = 终止态」**。于是模型一旦把「我去查一下」当成普通文字吐出来、又没在同一轮发出工具调用，turn 就结束了。

两类停顿：
- **意外型**（绝大多数、也是实际遇到的）：模型只是「随口叙述了一下意图」，并非真想停，但那句话触发了终止。
- **故意型**（罕见）：模型主动把「我去查一下」当作给用户的最终回复来收尾。任何循环结构都拦不住一个"主动选择收尾"的模型——这是模型质量/prompt 问题。

### 为什么 Claude 不犯这病
Claude 跑的是**同款朴素循环**（无显式 finish 工具、文字无工具即结束），但它**把"说了要做就立刻做"的纪律内化进了权重**——相当于"自己就是那个守卫"。mimo / minimax 没内化这条纪律，所以咕咕需要在**循环外面**补结构或守卫来兜。

## 2. 现状架构与代码锚点

- 回复循环：`agent/core.py`
  - `_run_anthropic`（MiniMax / Anthropic 块格式）
  - `_run_openai`（mimo 等 OpenAI 格式；reasoning 走 `reasoning_content`）
  - 两路都是「流式吐文字 + 穿插工具 → 有工具继续 / 无工具结束」，已支持 **tool→tool→tool 连续链式调用**与**交错流式**（文字、工具、文字…）。
- 现有确定性守卫（已在用，是 B 的雏形）：
  - `_looks_like_narration()` + `_NARRATION_RE`：检测「假装已做完」（已建好/改好了…）→ `_NARRATION_NUDGE` 逼一轮真调工具。**只追一次**（`narration_retry < 1`）。
  - `_is_decision_dodge()` + `_DECISION_NUDGE`：用户明确要改、模型零工具却「不用改/已合理」驳回 → 逼执行或问清。注释明确**排除问句**（高精度优先）。
- 模型路由插槽：`agent/llm_select.py` 的 `set_router()` / `strategy="router"`（**已留口、未实装**）——可用于"工具重的轮路由到强模型"。

> ⚠️ 现状的局限正是 §1：`_NARRATION_RE` 偏向"假装已做完"，对"**宣告将要做**"（我去查/这就查）覆盖弱，且 `我(来|先)?(读|看|查|改)` **不含「去」** → 「我去查一下」漏网 → 停住。

## 3. 三个方案

同一请求「帮我查下北京天气，顺便记到日历」在各方案下的用户可见对话，见会话里的可视化对比。下面是机制与取舍。

### 方案 B —— 补丁级（最小改动）
保持「无工具即结束」的默认，只**扩宽确定性守卫**：

```
要 nudge  =  命中"宣告意图"措辞（我去/这就/我来/稍等/马上 + 查/搜/找/看/建/改/删/发…）
           且  ✗ 不是问句（排除：吗 / 呢 / ? / ？ / 要不要 / 需不需要 / 好吗 / 可以吗 / 行不行 / 帮你…吗）
           且  ✗ 这轮没调过任何工具
→ 命中则追一轮，注入 nudge 逼它当场调工具。
```

- **改动面**：仅 `core.py` 两路各加一个检测 + nudge（沿用 `narration_retry` 脚手架）。不碰流式 / 前端 / prompt 协议。
- **优点**：今天就能上，零风险。
- **缺点**：靠正则区分"陈述 vs 疑问 vs 求信息"，**边界永远擦不干净**，得不断补否决词。
- **致命失败模式**：正则**漏掉**某个意图说法 → 默认"无工具即结束" → **静默卡住（bug 复活）**。

### 方案 A-lite —— 翻转终止规则（保留流式）
最终回复**仍是普通流式文字**（和现在逐字一致），但**新增一个空的 `finish()` 工具**当收尾信号：

```
模型调了真工具    → 执行、继续
模型调了 finish() → 收尾结束
只有文字、没 finish → 不结束 → 守卫判定（见下）
```

- **改动面**：`core.py` 两路循环 + prompt 协议（"说完必须调 finish"）。**不碰流式**（回复仍走自由文字通道、原生逐 token 流）。
- **优点**：把默认从「结束」翻成「继续」——**正则漏判时失败模式从"静默卡住"降级成"多跑一轮"**（病 → 小代价）。
- **缺点/代价**：依赖模型**记得调 finish()**；忘了就被多追一轮（对 mimo/minimax 这种不算听话的模型，可能时不时空追）。

### 方案 A —— 全结构化（AgentScope / QwenPaw 那套）
**取消"自由文字回复"通道**：最终回复放进 `generate_response(reply="…")` 的**参数**里；要对用户说话只能调它（=终止），要做事调别的工具（=继续）。

```
[思考文字(可隐藏)] → 工具 → 工具 → … → generate_response(reply="正文")  ← 解析流式参数边拼边吐
```

- **改动面**：`core.py` 两路 + prompt 协议 + **增量解析流式工具参数**（Anthropic `input_json_delta` / OpenAI `arguments` 分片）把 reply 流式吐出 + 决定中间思考文字怎么展示。改动最大。
- **优点**：**意外型停顿结构性消失**——纯叙述不再是终止态；"先做完再统一答"的多步最顺。
- **缺点**：正文进参数 → 流式要自己解析 JSON（偏脆）；中间叙述与最终回复分离，**观感更利落但少了"边做边唠"的陪伴感**（对咕咕"伙伴"人设要权衡）。
- **注意**：A **也不是银弹**——模型仍能第一步就 `generate_response("我去查")` **故意停**（罕见，需守卫）。A 只是把门槛从"随口一说就停（易）"抬到"必须刻意误用 finish 才停（难）"。

### 对比速查

| 维度 | B | A-lite | A |
|---|---|---|---|
| 回复正文在哪 | 自由文字 | 自由文字 | `generate_response` 参数 |
| 流式 | 原生 | 原生 | 需解析参数 JSON |
| 终止规则 | 无工具即结束 | 无 finish 不结束 | 只有 generate_response 终止 |
| 改动面 | 最小（仅守卫） | 中（循环+协议） | 大（循环+协议+流式解析） |
| 漏判时失败 | **静默卡住** ❌ | 多一轮 ⚠️ | 多一轮 / 不发生 |
| 主要靠 | 正则措辞 | 模型调 finish + 守卫 | 结构 + 守卫 |

## 4. 关键洞察（选型时反复确认过的）

1. **真正解决问题的是"未兑现意图守卫"，不是循环结构。** 这条守卫——"**这段回复是不是承诺了一个本轮没执行的动作？是 → 拒绝收尾、逼继续**"——**在 A/A-lite/B 上都能装**。A/A-lite/B 的差别只是"给守卫多少结构性帮助"：A 让守卫几乎没活干，A-lite/B 让守卫干主力。
2. **失败模式的方向比能不能解更重要。** A-lite 把默认偏向"继续"，所以漏判只是"多一轮"；B 默认"结束"，漏判就是"静默卡住"（原 bug）。
3. **问句是硬排除，不是"拿不准偏 nudge"。** 误 nudge 一个陈述句=多一轮（便宜）；误 nudge 一个问句（"要我去查吗?"）=替用户做了没同意的事（贵）。所以**先判是否在征询/提问 → 是就一律不碰**。这与现有 `_is_decision_dodge` 哲学一致。
4. **A-lite ≈ 把 A 的 generate_response 拆成「先发正文文字 + 再发空 finish」。** 这"一拆一调序"恰好用 **A 的零歧义** 换 **A-lite 的原生流式**。
5. **装了守卫之后，三档防停顿效果趋同**；剩下的差别回到"流式实现复杂度 + 观感"，而非"防不防得住"。
6. **根子上取决于模型。** 换 Claude 级 / 更强的 agentic 模型，这些脚手架可以越做越薄。

## 5. 当前决策与理由

**先实现 A-lite + B 保底，观察一段时间效果，再决定是否升级到 A。**

= **A-lite（保留原生流式 + finish 收尾信号）+ B 的守卫（未兑现意图检测 + 问句硬排除 + 不确定偏继续）**。

理由：
- 是"短于换 Claude 级模型时最稳的组合"：意外型由 A-lite 的"无 finish 不结束"结构性兜掉；故意型 / 措辞漏判由守卫补；**失败只降级成"多一轮"，不再静默卡住**。
- **不用** A 那套"正文塞进参数 + 解析流式 JSON"的改造，保住咕咕的实时打字机体验与"边做边唠"陪伴感。
- 留好升级路径：观察期若发现"模型频繁忘调 finish 导致空追轮"很烦，或想要更利落的"先做后答"，再升 A。

## 6. A-lite + B 实现要点（落地时照这个）

循环规则（`core.py` 两路统一）：
1. 模型**调了真工具** → 执行、喂回、继续。
2. 模型**调了 finish()** → 但**先过守卫**：reply/本 turn 是否承诺了未执行的动作？是 → 拒绝收尾、逼继续；否 → 收尾。
3. **没 finish、只有文字** → 守卫判定：
   - 像"已收尾/问句" → **合成 finish、收尾**（避免空追轮）；
   - 像"宣告意图" / **拿不准** → **nudge 逼继续**（偏继续，漏判=多一轮）。

守卫条件（高精度）：
- 意图措辞：`我去/这就/我来/稍等/马上/接下来 + 查/搜/找/看/读/建/改/删/发/整理…`；
- **问句硬排除**：`吗 / 呢 / ? / ？ / 要不要 / 需不需要 / 好吗 / 可以吗 / 行不行 / 帮你…吗`；
- 本轮**零工具**才考虑；
- 设追轮上限（参考现有 `narration_retry`/`MAX_VERIFY`），防死循环；
- prompt 侧加协议（`persona.md`/`skills.md`）+ few-shot 示例「宣告→立刻调工具→…→finish」。

注意事项：
- mimo 路若开了思考，finish/工具消息要带 `reasoning_content`（见 `_asst` 收口，已实现）。
- 守卫注入的 nudge 文字不要流式发给用户、不入历史污染（参考现有 verify 缓冲做法）。
- 两路（anthropic / openai）都要改，保持一致。

## 7. 其它杠杆（让咕咕更"像 Claude"）

让 continue/stop 纪律更接近"长在模型里"，按成本/可控性：
1. **租更强的脑子（最快）**：实装 `llm_select.py` 的 router 插槽——"**这轮要多步调工具 → 切强模型（甚至 Claude API）；纯闲聊 → 留便宜模型**"。
2. **把系统做成 Claude（最可控、=本方案）**：B / A-lite / A 守卫 + 强 prompt + few-shot。
3. **把纪律灌进权重（最重、真正"像 Claude"）**：微调/蒸馏——Qwen 开权重可 SFT；从 Claude 蒸馏 agentic 轨迹；**咕咕已有的决策轨迹（`agent.traj`，已脱敏）可当种子数据**。
   - 天花板：小模型不可能全面等于 Claude，但"continue/stop 这一个窄行为"窄、可学，能走到接近。
