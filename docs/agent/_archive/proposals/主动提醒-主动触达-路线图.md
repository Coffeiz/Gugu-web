## 1. 核心分界:提醒（被告知）vs 触达（自己判断）

这条线的本质:**不是两个功能，是同一条管道换一道「决策闸」**。

| | 触发由谁决定 | 决策闸 | 阶段 |
|---|---|---|---|
| **主动提醒** | **被告知的**——用户设了时间 / 事件有 deadline。到点就发。 | 确定性死规则 | v1 |
| **主动触达** | **咕咕自己判断的**——没人叫它发，它判断「现在该不该说、说什么」 | 会判断（bandit → 规划） | future |

**升级 = 把决策闸从死规则换成会判断的（死规则 → contextual bandit → 规划/MCTS），管线/候选源/投递一行不改。** 所以 v1 必须把「候选生成 → 决策闸 → 投递」三段解耦，闸做成可替换接口。

## 2. 「什么时候提醒」的判据框架（贯穿全程）

"什么时候"没有单一答案——**按类型定结构时机 × 三层通用约束 × 相关性没变 × 还没被处理；拿不准就不发**。

- **按类型定结构时机**（每类驱动变量不同，别用一个全局闹钟）:
  - deadline → **相对截止**的提前量（按任务大小）+ 可选升级式（提前轻推 + 当天硬提）
  - 明说要做的 → 用户给的**模糊时间**的软 check-in（"你说要联系老王，进展如何"，不是硬闹钟）
  - 停滞 → **不活动时长**（最险、最保守）
  - 情绪/陪伴 → 关系状态/离开时长（**触达阶段才上**）
- **三层通用约束**（压在所有类型上）:① **锚用户作息**（发在用户活跃、能行动的时段；免打扰时段是底线；用现成的回访节奏/last_active）② **合并去抖**（同时段多条合成一条，绝不连发 ping）③ **硬限频**（≤1/天、≤3/周）
- **相关性 + 何时停**:发前查「还相关吗」（deadline 还开着 / 意图没被行动 / 项目真停）；用户**一旦行动/确认/表示不做了 → 立刻停、不升级**。对已办之事的提醒比不提醒更伤。
- **默认不发**:宁可漏，不可扰（同「漏判偏无信号=保守安全」哲学）。

## 3. 分期路线 + TODO

### Phase 0 · 地基盘点（不写代码，确认复用，避免重建）

### Phase 1 · 主动提醒 v1（确定性 · deadline 优先 · 埋点）

> 管道:**候选生成 → 死规则闸 → 投递**。目标=能用的提醒 + 触达的地基，一次跑通整圈。

- [ ] **管道骨架**:`Candidate` 数据结构（reason/上下文/相关性/新鲜窗口）+ **决策闸接口**（v1 是死规则，未来可换 bandit）+ 复用现成投递
- [ ] **候选源 v1 只做 deadline 类**:日历事件 + 项目截止（相关性最硬）
- [ ] **deadline 时机规则**:相对截止的提前量（按任务大小/紧急度）+ 可选升级式（提前 + 当天）
- [ ] **三层通用约束**:免打扰时段（锚用户活跃窗口）/ 合并去抖 / 硬限频（≤1天、≤3周）
- [ ] **相关性 + 停**:发前查 deadline 还开着 / 没被处理；用户行动或确认 → 停、不升级
- [ ] **结果埋点（重中之重）**:每条记 `{reason, ts, 渠道, opened, acted, dismissed, muted, delay}`，结构化脱敏存起来——**这是 Phase 3-4 世界模型的训练数据，不埋=触达冷启动**
- [ ] **红线落地**:默认保守不发 / 不假亲密 / 用户可关（全局 + 单类型开关 + 调频）
- **验收**:只发过闸的、仍相关的 deadline；埋点在积累；无「提醒已办事」「半夜打扰」「连发」

### Phase 2 · 扩候选类型（仍确定性，把「由头」做全）

- [ ] **承诺兑现**（咕咕说过「回头帮你看 X」→ 需先**捕获承诺**→ 软 check-in）★像伙伴
- [ ] **明说要做的**（facts 里的意图 → 软 check-in）
- [ ] **summary 追问**（当下重心）
- [ ] **记忆驱动早报**（summary + deadline 合成一条）
- [ ] **停滞类**（项目 N 天没动 → 轻推）★最保守、阈值高、**殿后**
- [ ] 每类各自的时机规则 + 相关性检查；埋点继续积累
- **验收**:多由头共存、合并成一条、各自相关性把关；埋点数据量够启动学习

### Phase 3 · 主动触达 v1（决策闸:死规则 → contextual bandit + 冷却）

> 从「被告知」到「咕咕自己判断」的转折。把架构草案 §6.3 的 `Interrupt Value` / `Silence Value` 落成学习版。

- [ ] 决策闸换成 **带触达历史状态的 contextual bandit + 硬冷却启发式**（状态:距上次触达几天 / 最近发过啥类型 / 用户近期反应）
- [ ] **双时间尺度奖励**（见改进方案跨模块章 B）:快信号（点击/回复/阅读/没关）驱动学习 + 慢目标（留存/项目推进/是否开始屏蔽）审计防「刷点击率」
- [ ] **LLM 把关**（草案 §6.2 ③）:过闸的极少数，给最后一道「算了这会没必要」的否决权 + 润色
- [ ] 探索保守（触达试错成本全系统最高:发错=静音/卸载）+ population 先验兜底新用户
- **前置**:Phase 1-2 攒的埋点数据（否则冷启动）

### Phase 4 · 主动触达 v2（规划，gated on 用户响应世界模型）

- [ ] **用户响应世界模型** `P(下个状态 | 状态, 动作)` 从埋点数据学出并验证（没它，MCTS 就是搜脑补的未来树）
- [ ] 上**规划（MCTS/tree search）**搜「未来 N 天触达序列」:搜 **「做什么」**（今天主动吗 / 发什么 / 何时 / 带不带项目 / 要不要等），**LLM 负责「说什么」**（责任分层，绝不搜 token 级话术）
- [ ] **per-user 最佳时机/频率**学出来（接相处镜片 / 关系温度）
- [ ] **情绪/陪伴 check-in** 类才在此阶段上（最像伙伴、最容易翻车，需关系系统 + 世界模型都到位）

## 4. 贯穿全程:两条不能省的

1. **红线**（每期都守）:默认不发 / 硬限频 + 免打扰 + 一键关 / **不假亲密**（主动消息绝不"好久没聊想你了"）/ **有据不脑补**（恐怖谷:提到的事不准比沉默更糟，情绪类尤其）/ **慢目标盯「骚扰/留存」不盯「点击率」**（防「天天发→回复率涨→自觉成功→一周被静音」）。
2. **埋点从第一天**:每条主动消息的「动作→结果」是 Phase 3-4 学习的**唯一燃料**。v1 就要埋齐，等做触达时已有几个月数据，不用冷启动。**这比提醒功能本身更值钱。**

## 6. 一句话

**v1 做「主动提醒」，但心里装着「触达」**:管道搭成「候选→闸→投递」、闸先用 deadline 死规则、**结果从第一天埋点**（喂未来世界模型）、红线从头就严（保守 + 限频 + 不假亲密）。这样 v1 是能用的提醒，又是触达的地基，从确定性死规则 → bandit → 规划一路换闸，不推倒重来。
