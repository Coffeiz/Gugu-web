# 咕咕产品结构与精力系统设计总结

> **状态**：💡 设计中
> **分类**：产品设计
> **创建时间**：2026-06-19

---

## 一、产品本质问题

咕咕不适合做成传统项目管理工具，因为用户实际使用的内容分为三类：

### 1. 项目（短期、有目标）

有明确开始与结束，有进度，有交付，例如：
- 开发咕咕
- 学习 Vue
- 旅行计划

**特点**：可完成、可归档、强目标导向

---

### 2. 日常记录（长期、无目标）

没有完成概念，是生活轨迹，例如：
- 今日收入
- 心情记录
- 体重变化
- 灵感

**特点**：持续积累，用于回顾

---

### 3. 持续型空间（长期系统）

例如：
- 财务
- 健康
- 日记
- 内容创作

**特点**：长期存在，不会结束，是数据容器

---

## 二、信息结构设计（MVP建议）

一级导航建议保持极简：

- 首页
- 文件
- 项目
- 咕咕

不要一开始拆分成"日记/财务/健康"等独立模块，否则系统会过度复杂。

---

## 三、统一数据模型：Record（记录）

所有内容最终都归为记录：

| 内容 | 记录类型 |
|------|---------|
| 日记 | 日常记录 |
| 收入 | 财务记录 |
| 体重 | 健康记录 |
| 完成任务 | 项目进展 |
| 上传文件 | 文件记录 |

### 自动分类

由咕咕自动识别，例如：

```
今天收入 328 元 → 财务记录
体重 96.75 → 健康记录
完成缩略图系统 → 项目进展
```

---

## 四、项目系统设计

### 1. 普通项目（可完成）

例如：
- 开发咕咕
- 学习 Vue
- 旅行计划

**状态流转**：

```
未开始 → 进行中 → 已完成
```

支持拖拽完成，这是核心交互。

---

### 2. 持续项目（长期存在）

例如：
- 财务
- 日记
- 健身
- 内容创作

**特点**：
- 没有"完成"
- 持续累积记录
- 用于长期数据沉淀

---

## 五、进度条系统（核心体验）

进度条的价值是"可视化成长"。

**推荐方式**：

```
任务完成率 = 已完成 / 总任务
或
里程碑完成比例
```

### UI 示例

```
咕咕项目进度：

████████░░ 80%

已完成：
✓ 文件系统
✓ 缩略图
✓ HDR预览

未完成：
□ AI记忆
□ 移动端
```

### 关键点

**进度必须自动计算，不让用户手动维护。**

---

## 六、AI使用限制设计（核心结论）

**不推荐**：
- Token 展示（用户不理解）
- 对话轮数限制（成本不准确）

---

## 七、推荐方案：精力系统

用户看到的是：

```
🕊️ 咕咕精力
████████░░ 80%
```

### 内部逻辑

```
Token → 成本 → 精力值
```

用户不接触 Token。

---

## 八、精力消耗模型

| 行为 | 消耗精力 |
|------|---------|
| 普通聊天 | 1 |
| 长对话 | 2 |
| 搜索 | 5 |
| 文件分析 | 10 |
| Agent任务 | 15 |

---

## 九、精力恢复机制

- 每日恢复或每月恢复
- 可付费扩展容量

---

## 十、关键体验原则

### ❌ 不推荐表达

- 额度用完
- AI不可用
- 请明天再来

---

### ✅ 推荐表达

```
🕊️ 咕咕有点累了

今天已经陪你处理了很多事情，我想先整理一下状态
```

---

## 十一、能力降级设计

精力不足时：

| 功能 | 状态 |
|------|------|
| 普通聊天 | 仍可用 |
| 文件查看 | 正常 |
| 项目浏览 | 正常 |
| 深度分析 | 暂缓 |

---

## 十二、恢复表达

```
🕊️ 咕咕休息好了，现在可以继续陪你了
```

---

## 十三、产品核心原则

### 1. 不做工具感限制

避免 Token / 次数 / 冷冰冰额度

---

### 2. 做有状态的伙伴

咕咕不是工具，而是有状态的存在：

```
有精力、有节奏、有恢复
```

---

### 3. 所有系统统一底层

```
文件 + 项目 + 记录 + 咕咕
全部归入 Record 系统
```

---

### 4. 满足感来源

用户满足感来自：

- 进度增长
- 数值变化
- 可视化反馈
- 被持续陪伴

---

## 十四、最终产品形态

咕咕 =

```
文件管理系统
+ 项目推进系统
+ 人生记录系统
+ 有状态的陪伴体
```

**而不是传统 SaaS 工具集合**

---

## 十五、一级导航设计

| 入口 | 功能 |
|------|------|
| 首页 | 总览、最近、统计 |
| 文件 | 文件管理 |
| 项目 | 项目管理 |
| 咕咕 | 聊天交互 |

---

## 十六、Record 统一模型

```python
class Record:
    id: str
    type: str  # daily / finance / health / project / file
    content: dict
    created_at: datetime
    updated_at: datetime
    tags: list
    relations: list  # 关联其他记录
```
