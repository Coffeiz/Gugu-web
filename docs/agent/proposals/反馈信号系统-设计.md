# 反馈信号系统 · 设计稿

> **状态:①②④ 已落地（2026-07-02,含 7 场景真实验证:漏判方向保守=往「无信号」漏,安全）;③ lens 写回等 feedback 数据攒 1–2 周。**本文是 [`../10-感知系统.md`](../10-感知系统.md) **§11.6 step 2 的施工图**——把原「误判 → lens 写回」**加宽**为「反馈信号系统 → 写回」。
> **动机**:整个学习闭环（误判→lens→Person Model→Relationship）目前只有一个燃料源——用户显式纠正。实测误判率 3–11%、检测召回随机偏低、用户 N 极小 → **低频信号驱动高维模型,上层永远饥饿**。出路 = 把信号源加宽一个数量级（显式补正向 + 开采隐式），噪声交给写协议兜。

## 1. 信号清单（两层）

### 1.1 显式信号（高置信、低频）

| 信号 | 现状 | 说明 |
|---|---|---|
| 用户纠正 | ✅ 已采 | misperc + 错读案例收集器（kind=感知误读 → 脱敏枚举 miss） |
| **用户确认/夸赞** | ❌ **未采,显式层最大缺口** | 「对」「就是这样」「你真懂我」——与纠正**同等干净的真值**,现在完全流失。采集方式与 correction 完全对称:反思顺带判,零成本。消费:lens 规则印证↑ + 正向关系信号 |
| 用户主动陈述偏好 | ⚠️ 部分 | lens_hint 覆盖,够用 |

### 1.2 隐式信号（低置信、高频——量的来源）

| 信号 | 判据（反思可见的窗口内） | 极性 | 置信 |
|---|---|---|---|
| **改写重问** | 用户把上一句换个说法再说一遍 | 强负（没接住） | **高**——几乎不误报 |
| 顺着聊 | 用户回应接了咕咕抛的点/回答了咕咕的问题 | 弱正 | 中 |
| 无视跳开 | 咕咕问了问题,用户完全不接、自起话头 | 弱负 | 中 |
| **主动分享** | 没被问就分享生活/情绪/进展 | 强正（关系温度） | 高 |
| 会话深度 | 本次聊了几轮（admin 面板已有分布） | 温度指标 | 高 |
| 回访节奏 | 多久来一次、来了先说什么 | 温度指标 | 高 |

## 2. 采集机制:搭反思顺风车 + 只认枚举

- 反思本来每轮看「上一句咕咕说什么 + 用户这句怎么接」→ 判延续性是**零新增 LLM 调用**的搭车。
- **「上一轮」按 session 判延续，不按时间窗**（2026-07-04 精度改进）:`lastturn:{uid}` 缓存带 `session_id`，读时**只有同一会话才算上一轮**（换会话/新对话 → prev_turn=None → 无信号，不跨会话拿上段的话乱比）。原来纯 `per-uid + 2h TTL` 有两个坑:① 2h 内切到另一段对话会串味;② 隔 >2h 回来接同一话题被漏判。session 闸修掉①、TTL 放宽到 24h 修掉②（延续性靠 session、时间只作陈旧兜底）。
- 输出**只认固定枚举**（错读收集器 5 轮验证逼出的通法——隐私敏感/易漂移的 LLM 产出别用 free-text）:
  `feedback ∈ { 顺着聊 / 无视跳开 / 改写重问 / 主动分享 / 确认夸赞 / 无信号 }`,后端白名单校验,枚举外落「无信号」。
- 会话深度/回访节奏**不经 LLM**——纯数据侧统计（conversation_messages / last_active）。

## 3. 噪声治理:写协议兜底

单条隐式信号**不直接动任何东西**:
- 只累积计数;lens 要 **N 次同向信号**才动 confidence（复用 PROMOTE_AT 思路）;
- 关系温度看**滑动窗口聚合**（周维度）,单周波动被衰减吸收——用户忙三天没回,不会被误学成「变冷了」;
- 全部走 `Hypothesis→Evidence→Confidence→Decay→可推翻` 五步（低置信、快衰减起步）。

## 4. 三个消费者

### 4.1 lens / Person Model（学习燃料）
- 「确认夸赞」→ 现有规则**印证↑**;
- 「改写重问」→ **反驳↓ 的候选信号**（正好补 lens v2 缺的通道——比「识别哪条纠正推翻哪条规则」的 LLM 对齐问题好落地得多）;
- 聚合后的延续性模式 → observation。

### 4.2 关系温度（Relationship 层第一个可落地的数据结构）

- 温度 = 滑动窗口聚合（近 3–4 周）:主动分享次数 + 正/负延续比 + 平均会话深度 + 回访节奏。per-user、带 ts。
- **不违反「关系只能挣不能设计」红线——温度是测出来的,不是填出来的。**
- 关系是双向的:共同经历（我们做过什么）之外,温度测的是**用户怎么对咕咕**（分享深度在不在加深、语气在不在变随意、是否主动来找）——这半边更可观测。
- 现成基建:admin「使用分析」的会话深度分布/周活跃维度已算一半;后续把它接成感知系统的**成长曲线**（「真的越来越懂你」的尺子）。

#### 温度动力学:有上限、窗口冷却,且必须与「深度」拆成双量

- **有上限（归一化饱和）**:各分量天然封顶（延续比 ≤1、分享/深度归一化）。意义 = 防刷 + **语气档位封顶**——天天聊 50 轮语气也只到「熟络」,再往上不由热度单独解锁。不封顶的温度会变成分数游戏,而关系不是分数。
- **冷却 = 滑动窗口本身,不再叠半衰期**:不互动 → 旧信号滑出窗口 → 值自然落。双重衰减会对短期波动过敏。**冷却曲线要缓**:一周没聊掉一点、一个月才明显凉——对齐真实关系的节奏。
- **温度（快变）≠ 深度（慢变）,单一数字必犯错**。想「五年老友三年没联系」:温度凉了（重逢别自来熟）,深度还在（老梗接得上）。只衰减 → 老用户回来被当陌生人（「咕咕把我忘了」）;只累积 → 三个月没聊还老友腔（时长虚构的近亲）。所以拆两个量（正好落在「伞不是桶」半衰期分层红线上）:

| 量 | 性质 | 动力学 | 类比 |
|---|---|---|---|
| **温度** | 当下互动质量 | 滑动窗口、自然冷却、有上限 | 体温 |
| **深度** | 共同经历的沉淀 | 只增不减（或极慢衰）、增速递减 | 年轮 |

- **语气定档 = 三输入合成**:温度给油门（现在该多热络）× 深度给权限（能提什么老梗、开什么玩笑）× 时长给里程表（「认识 N 天」硬数字,§4.3）。老用户三个月后回来的正确语气=「诶,好久没来了!上次那个 XX 后来怎么样了」——**既认得你,又承认间隔**。
- **纪律:温度低 ≠ 关系坏**。用户忙季没来,温度低是事实,但绝不能被反思解读成「用户最近疏远」写进 observation（把忙碌学成情感状态=危险推断）。**温度只喂语气校准,不进语义记忆**——分层消费,与写协议「不要相信自己」一脉相承。

### 4.3 时间纪律（防时长虚构——真实踩坑驱动）
> 病例:GPT 把上个月才开始的话题说成「这几个月的观察」——模型看到一堆记忆,时间跨度靠语感自由发挥,且永远往「显得更熟」的方向漂。**时长虚构 = 最字面的假亲密。**

- 存储侧已达标（facts/lens/stance/observation 全带 ts）;缺的是**注入侧**:
- **时长由系统算好、以硬数字喂给模型**:「认识 N 天」「该话题最早出现于 X 天前」「此观察基于最近 2 周的 5 次对话」——不是给时间戳让它算,是给算好的结论。
- **红线**:谈及时间跨度只准用给定数字;无数据支撑的时间词（「这几个月」「一直以来」）与虚构共同经历**同罪**。
- 这同时是「语气限速」的第一块砖:关系时长是最硬的语气锚——认识 23 天,「五年老友腔」就没了生存空间。将来 Relationship 层据温度+时长给全栈**语气定档**。
