> 配套文案稿：`新手引导设计.md`（设计/文案的唯一真相源）。本文件只讲**怎么实现**。
> 小提示：文中前端文件名写的是 `.js`（`useOnboarding.js`/`api.js` 等），落地时随项目 TS 化改成了 `.ts`（如 `composables/useOnboarding.ts`），逻辑与文档描述一致，未特地逐处改写后缀。

## 易读概述

**要解决的问题**：新用户第一次打开咕咕，面对空空如也的界面容易不知道从哪下手。新手引导要让用户"被接住"——注册后自动给 TA 造一点看得见摸得着的东西（一个示范项目、几个文件、一首小彩蛋音乐），再用几句轻量的气泡文案，在合适的时机点一下"这是什么、可以怎么用"。

**核心思路**：
- **静态优先**：所有引导文案都是写死的、随机挑选，绝不过 LLM——避免不确定性和 emoji 红线风险，保证引导体验稳定可控。
- **claim-once 语义**：每类气泡（欢迎/引导/情境/回头看）后端原子地"首次返回内容，之后返回空"，前端不用自己记状态，问一次就知道该不该弹。
- **独立子系统**：整个 onboarding 逻辑放在 `backend/onboarding/`，与核心 `agent/` 完全解耦（播种直接操作数据库/存储，不走 agent 工具），减少对核心链路的侵入。
- **分阶段推进**：Phase 1（播种 + 欢迎/引导气泡）→ Phase 2（7 个情境气泡）→ Phase 3（"回头看"里程碑气泡），三期都已完成。

以下 §1 起是实现的专业细节（数据模型、接口、前后端接入点、已知坑）。

## 0. 已定决策

1. **欢迎气泡**：用户打开应用后**过几秒**自动弹通知气泡（不是聊天消息）。
2. **后端持久化** onboarding 状态（跨设备 / 重登只触发一次）；**demo 阶段做一个快速控制面板**，一键测试 / 重放各块内容。
3. **播种一账号一次**；用户删了引导项目**不重建**。
4. 所有引导文案**完全静态 + 随机挑选**（绝不过 LLM，避免 emoji 红线 / 不确定性改样）。
5. 顺序：先弹**欢迎气泡(01)** → 再弹**引导进项目气泡(02)** → 同时**高亮自动创建的引导项目卡**。

## 1. 总体时序

```
注册成功
  └─ 后端播种：建引导项目(03 命名 + 04 阶段 + 05 待办 + 06 两个文件)
                + 个人文件夹放 1 个 mp3「小惊喜」(对应 07 音乐彩蛋)
                标记 onboarding.seeded=true, seeded_project_id=<pid>
首次打开应用（welcome_shown=false）
  └─ 前端等待 ~3s
       ├─ 弹「欢迎气泡」(01 随机) ── claim welcome
       └─ 几秒后 / 用户关掉欢迎后：
            ├─ 弹「引导气泡」(02 随机) ── claim guide
            └─ 高亮引导项目卡（滚动到 + 脉冲描边）
之后用户各处「第一次」操作
  └─ 命中即弹情境气泡(07)，每个 key 只一次 ── claim hint:<key>
完成第 5 个项目                              [Phase 3]
  └─ 弹「回头看」(08) ── claim lookback
```

## 1.5 模块边界与目录结构（独立系统）

onboarding 是**独立子系统**：直接放在 `backend/onboarding/`，**与 `agent/`、`app/` 平级**，自成一包。

**依赖方向（单向、不碰 agent）**：
- onboarding **不依赖、不调用 `agent/`**（播种用 `app` 的 model/storage 直接建数据，不走 agent 工具）。
- onboarding 只依赖 `app` 的共享基础设施：`app.db`（Base/session）、`app.models`（Project/File/User）、`app.services.storage`、`app.core.events`（通知推送）。
- `app` 侧仅两处「引用」onboarding（薄接入，不反向耦合逻辑）：① 注册流程 call `onboarding.seed`；② `main.py` 挂载 onboarding 的路由。

```
backend/
├── agent/                 # AI agent（onboarding 不碰它）
├── app/                   # FastAPI app（共享基础设施）
│   ├── api/v1/auth.py     #   注册成功 → call onboarding.seed（唯一接入点）
│   └── main.py            #   include onboarding.router
├── onboarding/            # ← 【新建】独立子系统
│   ├── __init__.py
│   ├── content.py         #   静态文案池(01–08) + 随机选取（不过 LLM）
│   ├── models.py          #   OnboardingState 表（自有，不改 User）
│   ├── state.py           #   状态读写 + claim-once 原子语义
│   ├── seed.py            #   播种：建项目/阶段/待办/2 文件 + 个人空间 mp3
│   ├── routes.py          #   路由：用户端 /onboarding/* + demo /admin/onboarding/*
│   └── assets/            #   静态资源（你放 welcome.mp3）
└── alembic/versions/      #   OnboardingState 建表迁移
```

> 导入根是 `backend/`（现有 `from agent...` / `from app...` 即此约定），故新增 `from onboarding...` 同理可用。

## 2. 数据模型

onboarding **自有一张表 `OnboardingState`**（`onboarding/models.py`，用 `app.db.base.Base`），一用户一行，**不改 `User` 模型**（保持子系统独立）：

- `user_id`（PK/FK → users.id）
- `state`（JSON）— 内容如下（JSON 而非多列：字段随文案迭代增减，免逐字段迁移）：

```jsonc
{
  "seeded": true,              // 已播种？防重复；删了项目/文件也保持 true → 不重建
  "seeded_project_id": 91,     // 引导项目 id（高亮 / 回头看对照用）
  "welcome_shown": false,      // 欢迎气泡(01)
  "guide_shown":   false,      // 引导气泡(02)
  "lookback_shown": false,     // 回头看(08)
  "hints": {                   // 情境气泡(07) 各自 claim-once
    "file_lib": false, "music": false, "calendar": false,
    "stage_switch": false, "todo_roam": false, "todo_newproj": false, "im_bind": false
  }
}
```

> 用「独立表 + JSON 列」而非「User 上加列」：既不污染 User、子系统自带数据，又保留 JSON 的免迁移灵活性。`onboarding/models.py` 需被 import 一次让 Base 注册（alembic 自动生成迁移）。

## 3. 后端实现

### 3.1 播种（注册 hook）— Phase 1

- 接入点：`app/api/v1/auth.py` 注册成功后 call `onboarding.seed.seed_for_user(user, db)`（唯一耦合点）。`onboarding/seed.py` 里，若状态 `seeded != true`：
  - 用 **`app` 的 model / storage 直接建数据**（**不依赖、不调用 agent**；文案/命名从 `onboarding/content.py` 随机取）：
    - `Project`：`name` 从 03 池随机；`stages_json` = 04 三阶段（带 emoji），每阶段 todos = 05；`current_stage` = 阶段1；**`start_date` = 初次登陆日、`deadline` = +3 天**。
    - **日历活动**：初次登陆当天一条「和咕咕的第一天」（`CalendarEvent`，挂到引导项目）。
    - 2 个 `File`（06）：「给未来的自己 / 第一份记录」二选一作欢迎文件 + 「可以删掉我」作附属文件；正文从各自池随机；走 storage 写入（归属引导项目）。
    - **1 个 mp3「小惊喜」**：放在**个人空间根目录**（`space=personal`、`folder_id=None`），即 07「我先偷偷放了个小礼物」+「第一次打开音乐文件 🎵😌」的彩蛋。播种时从约定的 onboarding 静态资源目录 **`backend/onboarding/assets/`**（如 `welcome.mp3`）复制进该用户 storage、建 `File`（personal 根）。**素材由用户放入该目录**；目录缺文件时跳过 mp3 播种（其余照常）、记一条 warn。
  - 置 `seeded=true`、`seeded_project_id=<新项目 id>`。
- **幂等**：以 `seeded` 为唯一闸门。删项目 / 删 mp3 都不重建（`seeded` 仍 true）。

### 3.2 claim-once API（07 / 01 / 02 / 08 通用）

路由在 `onboarding/routes.py`（用户端，`main.py` 挂载）；状态读写 `onboarding/state.py`；文案 `onboarding/content.py`。后端原子地「首次返回内容 + 标记已读，之后返回空」：

```
GET  /onboarding/state                 → 当前 onboarding（前端判断该不该弹）
POST /onboarding/claim/{key}           → key ∈ {welcome,guide,lookback,hint:file_lib,...}
       首次：标记已读 + 返回 { text: "<随机选中的静态文案>" }
       已读：返回 { text: null }
```

- **随机 + 静态都在后端**：文案池作为后端常量（见 §5），claim 时随机选一条返回。前端只负责「有 text 就弹气泡」。好处：随机/once 语义集中、可测、前端零文案。
- claim-once 用行级更新或 `UPDATE ... WHERE not_claimed` 保证并发只触发一次。

### 3.3 回头看（08）— Phase 3 ✅ 已落地

- **触发：完成第 5 个项目**。前端 `projectStore.moveProject` 里，项目转入「已完成」(`status='done'`) 那刻，数已完成项目数 `>=5` → `fireLookback()`（claim-once 只一次）。
- `fireLookback()`（`useOnboarding.js`）：claim `lookback` → 弹「还记得『〈引导项目名〉』吗？[[p:1500]]…」（`{project_name}` 后端用 `seeded_project_name` 回填；1s 延迟 + 咕咕语气样式）。
- 实现走前端 claim（与情境气泡同套，可靠），未用后端 SSE 推。

### 3.4 Demo 控制面板 API（决策 2）

后台一个 onboarding 调试面板（路由也在 `onboarding/routes.py` 的 admin 段，`require_admin`），给每块一个「立刻触发 / 重置 / 重新播种」：

```
POST /admin/onboarding/fire/{key}      → 不改 claim 状态，直接给当前用户推一次该内容（纯测试）
POST /admin/onboarding/reset           → 把当前用户 onboarding 标记全部清零（hints/welcome/...），可重新自然触发
POST /admin/onboarding/reseed          → 删旧引导项目（如存在）并重新播种，供反复测试
GET  /admin/onboarding/pools           → 列出各文案池（demo 面板展示/挑选）
```

> 仅 dev/admin 可用。`fire` 绕过 once 标记，方便不重注册就反复看效果。

## 4. 前端实现

### 4.1 欢迎 + 引导气泡时序（决策 1、5）— 实现版

`DefaultLayout` onMounted 调 `runOnboarding(router)`（`composables/useOnboarding.js`）：
- 拉 `GET /onboarding/state`；`welcome_shown=false` → **等 1s** → `claim/welcome` → 有 text 弹**欢迎气泡**。
- `guide_shown=false` → 欢迎后**再隔 ~4.5s** → `claim/guide` → 弹**引导气泡** + **高亮引导项目卡**（`router.push('/projects')` + `uiStore.pendingProjectHighlight`）。
- **高亮**：5s + **一次「呼吸」效果**（光晕渐强渐弱，`ProjectCard.vue` `.onboard-flash` / `proj-onboard-breath`）；时长/动画类经 `pendingProjectHighlightMs=5000` + `pendingProjectHighlightBreath=true` 传入，**与搜索高亮(1.8s flash)解耦**。
- **气泡**：复用通知 toast（`uiStore.pushNotification({content, bubble:true, persist:false, gugu:true})` → `NotificationBubble.vue`），无标题、打字机入场；**文字用 GuguChat 聊天正文样式**（13px / 主色 / 行高 1.5，靠 `gugu` 标记加 `.nb-gugu`，不影响 IM/广播气泡）；**打完停留 5s 自动消失**（`AUTO_MS`，被新气泡顶替则 0.5s）。

## 5. 静态文案池（实现版，全在 `onboarding/content.py`，随机取一条）

> 改文案只动 `content.py`。气泡文案支持标记（见 §5.1）。**onboarding/ 不在 uvicorn 监视目录，改后需强制 reload，见 §8**。

- **01 欢迎**（`WELCOME`，7 条全用）：来得刚刚好… / 来啦～希望这里… / 今天开始这里就是你的空间… / 终于见面啦（4 个变体）。
- **02 引导进项目**（`GUIDE`，5 条）：我先留了一点东西给你。点开看看？／以后很多东西都会放在这里… 等。
- **03 项目命名**（`PROJECT_NAMES`，3 条**无 emoji**）：`从这里开始` / `第一份记录` / `初次见面`。
- **04 阶段**（`STAGE_LABEL_POOLS`，固定 3 段、每段标签随机、**带 emoji**）：① 🌱 这里还有一点空 / 目前还空空的；② 🌿 慢慢有样子了 / 开始丰富起来了 / 有点像样了；③ 💬 找我聊聊吧 / 来聊聊吧 / 有什么想聊的吗？/ 有事就来找我。
- **05 待办**（`STAGE_TODOS`，固定）：① 随便逛逛、建个项目试试；② 去日历看看、去文件库看看；③ 我就在右下角 😊 / 加个 QQ 好友吧（飞书也行📪）。
- **06 文件**（`WELCOME_FILES` / `SCRATCH_FILE_BODIES`，正文是**排版好的 markdown**：标题 `#` + 引用块 `>` + 分割线 + 落款）：欢迎文件＝「给未来的自己 / 第一份记录」二选一；附属＝「可以删掉我」（正文 **2 选 1**）。
- **个人空间根目录 mp3「小惊喜」**＝ `backend/onboarding/assets/` 下任意 `*.mp3`（用户自放，缺则跳过、不报错），对应 07 `music` 彩蛋。
- **07 情境**（`HINTS`）：file_lib / music(🎵😌) / calendar / stage_switch / todo_roam / todo_newproj / im_bind，逐条静态。
- **08 回头看**（`LOOKBACK`，模板 `{project_name}` 回填实际项目名）。

### 5.1 气泡文案标记（前端打字机识别、不显示）

- `[[p]]` / `[[p:1500]]`：停顿（默认 1s，可指定毫秒）。例：回头看「…吗？`[[p:1500]]`\n那时候…」。
- `[[slow]]…[[/slow]]`：段内逐字慢速冒出（`SLOW_MS≈400`/字）。例：文件库「…不过`[[slow]]...[[/slow]]`我先偷偷…」（三个点一个个慢慢出）。
- 解析在 `NotificationBubble.vue` 的打字机：带标记的文案逐 op 推进（普通字 `BODY_MS` / 慢字 `SLOW_MS` / 纯停顿），无标记的走原快路径。

## 7. 待确认 / 风险

- **注册 hook 的确切位置** + **通知系统主动推送的接口签名**：开工前确认（播种挂哪、气泡走哪条 publish）。

- **重置语义**：demo `reset` 只清 onboarding 标记，是否连带删/重建引导项目由 `reseed` 单独负责，别混。
- **「沉默」时机**是体感活，需联调打磨（哪几处不弹、延迟多久）。
