# 咕咕 Runtime Router（轻量路由层）设计方案

> **状态**：💡 设计中
> **分类**：技术架构 / AI交互
> **创建时间**：2026-06-19

---

## 设计目标

在传统 Agent 架构中，用户发送的所有消息都会进入主模型。

这会带来几个问题：

- 成本高
- 响应慢
- 无法处理中断
- 无法感知当前执行状态
- 用户容易认为系统卡死

因此在咕咕架构中，引入独立的 Runtime Router（轻量路由层）。

**Router 位于所有 Agent 之前**，负责理解用户当前意图和系统状态，并决定是否需要进入主 Agent。

---

## 整体架构

```
用户
  ↓
Runtime Router
  ↓
State Manager
  ↓
Memory
  ↓
Main Agent
  ↓
Tool Executor
```

### 职责划分

| 组件 | 负责 |
|------|------|
| **Router** | 意图分类、状态查询、中断处理、简单闲聊、情绪识别 |
| **State Manager** | 当前任务状态、Agent运行状态、Workflow状态、Tool执行状态 |
| **Main Agent** | 深度思考、规划、工具调用、文件分析、项目管理 |

---

## 为什么需要 Router

### 场景示例

```
用户：帮我分析这个项目架构

Agent开始工作：
  状态 = THINKING

30秒后用户发送：
  ？
  或者：
  还在吗
```

**如果继续进入主Agent**：
- 浪费 Token
- 增加延迟
- 影响体验

### 正确流程

```
Router检测：
{
  "current_state": "THINKING",
  "message": "还在吗"
}

输出：
{
  "intent": "CHECK_PROGRESS"
}

直接返回：
还在分析中哦～
无需进入主Agent。
```

## 状态管理（State Manager）

### THINKING - Agent正在思考

**场景**：
- 长上下文分析
- 项目规划
- 复杂推理

**用户**：还在吗

**回复**：还在分析中哦～

---

### SEARCHING - Agent正在搜索

**场景**：
- 网络搜索
- 知识检索
- 文件搜索

**用户**：怎么这么慢

**回复**：正在查资料，可能还需要几秒钟～

---

### GENERATING - Agent正在生成内容

**场景**：
- 生成文档
- 生成PRD
- 生成代码
- 导出文件

**用户**：进度怎么样

**回复**：已经完成大部分内容，正在整理最后部分～

---

### WAITING_CONFIRM - 等待用户确认

**场景**：
- 删除文件
- 覆盖数据
- 创建大量内容

**用户**：算了

**直接结束流程**。

---

### IDLE - 空闲状态

默认状态。

---

## 自然语言中断机制

**设计原则**：用户无需学习命令。

不需要：
- `/stop`
- `/cancel`
- `/abort`

用户可以直接自然表达。

---

### 取消意图识别

**例如**：
- 不用了
- 算了
- 停一下
- 别分析了
- 先别弄这个
- 换个话题

**Router 统一识别**：

```json
{
  "intent": "CANCEL"
}
```

**执行**：
- 停止 Agent
- 停止 Workflow
- 释放资源
- 清除执行状态

**回复**：好的，那我们先不继续这个啦～

---

### 状态查询意图

**用户**：
- ？
- 还在吗
- 好了吗
- 怎么没反应

**Router 识别**：

```json
{
  "intent": "CHECK_PROGRESS"
}
```

**返回当前状态信息**。

---

## 情绪识别

Router 可增加轻量情绪分类。

---

### 用户焦虑

**例如**：
- 急
- 怎么还没好
- 有结果了吗

**Router**：

```json
{
  "intent": "ANXIETY"
}
```

**回复**：马上好啦，我已经分析到最后一步了～

---

### 用户催促

**例如**：
- 快点
- 快快快

**回复**：收到，我正在尽快处理～

---

## Router 适合处理的请求

**无需进入主 Agent**：

- 状态查询
- 中断
- 简单确认
- 表情回应
- 心跳消息
- 情绪安抚
- 简单闲聊

**例如**：
- 嗯
- 哈哈
- 好的
- 收到

这些都不需要消耗主模型资源。

## 技术实现建议

### 第一阶段

```
关键词匹配 + 状态机
```

即可实现。

---

### 第二阶段

```
小模型分类器
```

**例如**：
- Qwen3-0.6B
- Qwen3-1.7B
- Gemma 3 1B

**负责**：
- Intent Classification

**输出**：

```json
{
  "intent": "CHECK_PROGRESS",
  "confidence": 0.95
}
```

再由 Router 决定是否进入主 Agent。
