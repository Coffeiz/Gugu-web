# Agent 权限与审批设计

本文适用于桌面端和 WebUI 的 Agent 工具调用。宿主负责授权，Core 负责执行前的审批编排和回执。两端共用审批机制，各自决定可以开放哪些能力。

## 授权与审批

授权决定当前用户和会话可以使用哪些工具、访问哪些数据，以及能否在宿主机上执行命令。宿主从可信身份和设置读取授权，并在实际执行前复核。工具参数、模型输出、消息内容和工具结果都不能更改授权。授权不足时拒绝执行。

审批决定已获授权的操作是否需要用户确认。目标设计由宿主为 Run 提供统一策略，工具声明操作是否需要审批，Core 统一处理确认、取消、过期和续跑。

| 模式 | 审批策略 | 已获授权的操作 |
| --- | --- | --- |
| 普通模式 | `ask` | 需审批的操作弹出确认卡，其他操作直接执行 |
| 自动模式 | `never` | 直接执行，无需逐条确认 |

自动模式适用于已获授权的删除、发送和 Shell 等操作。开启工具、变更执行范围或授予宿主机访问仍由相应的授权入口处理。工具继续校验业务参数与资源归属。收据必须绑定当前用户、会话、Run 和工具调用，并在恢复执行时单次消费。模型提供的确认字段不能代替可信收据。

## 宿主机 Shell

| 端 | 执行范围 | 宿主授权 |
| --- | --- | --- |
| 桌面 | 工具 Schema 省略 `scope`。`cwd=.` 进入隔离目录，绝对工作目录进入宿主环境 | 普通模式首次确认授予当前会话 30 分钟宿主执行权限。自动模式直接以当前系统用户执行 |
| WebUI | 保留 `scope: "sandbox"` 和 `scope: "system"` | 系统 Shell 由管理员和用户共同开启。普通模式首次确认授予当前会话 30 分钟权限，自动模式下已开放的系统 Shell 以 Web Host 服务账号直接执行 |

临时授权从用户批准时起算，只对原用户与会话有效。后续调用不续期，进程重启后需重新确认。执行环境应在启动进程前确定。沙箱中已经尝试过的命令即使失败，也不得自动在宿主机重跑。

## 现状与落地边界

两端已接入宿主 Shell 分流与限时会话授权。跨工具统一的 `ask`／`never` 编排是后续收口目标，当前部分工具仍在各自入口处理审批。收口时由桌面和 WebUI 各自解析可信设置，Core 传递策略并执行业务工具声明的确认流程。

平台细节见[桌面 Shell 执行权限](desktop/shell.md)和 [Web Host Shell 沙盒](../../apps/web-host/README.md#shell-沙盒)。
