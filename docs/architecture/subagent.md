# 子 Agent 运行架构

子 Agent 是挂在主会话下的普通 Agent 会话。它拥有自己的上下文，使用主 Agent 同一套 Runner、调度、持久化、恢复、模型和权限。预设只提供提示词和工具选择。Searcher 是这套机制下的第一个预设。

## 会话归属

- 父会话保存 `childId` 到普通子会话的绑定。`childId` 由子会话 UUID 的前 8 位生成，在该父会话内唯一。Web 与 Desktop 从可信 owner 和父会话解析绑定。
- 子会话保存自己的消息、快照和压缩基线，默认只收到显式委派输入和自己的历史。父对话无需复制。每次任务使用普通 Agent 的既有执行记录、租约和恢复机制。
- 父 Agent 只用 `childId` 操作子 Agent。内部执行 ID 继续供现有运行基础设施、已授权的 UI 详情及交付去重使用。

## 预设与权限

内置定义放在 `packages/core/src/agent/subagent/<agentName>/`。以 Searcher 为例，`prompt.md` 定义任务行为，`definition.ts` 定义名称和业务工具选择。任务内容和显式引用走现有输入与上下文组装流程。新预设只需提供提示词和工具选择。

子 Agent 从父会话获取模型、工作区、读写授权及自动模式。业务工具选择经同一工具注册表和权限门校验；Shell 等常驻工具沿用普通 Agent 的注入规则。任何确认都在父会话展示，回执绑定实际操作和执行者。运行预算、取消和超时复用普通 Agent 的策略。

## 通信

| 操作 | 行为 |
| --- | --- |
| `agent_message(start)` | 创建普通子会话、绑定短 ID 并投递首条任务，随后立即返回 |
| `agent_message(send)` | 通过 `childId` 投递消息。正在运行则由收件箱接收；空闲则按普通 Agent 的新回合规则开始，沿用自身历史 |
| `agent_wait` | 指定短 ID 时等待登记时对应的任务。空参数等待收件箱更新 |
| `agent_cancel` | 取消当前任务，保留子会话和历史 |
| `agent_inspect` | 查看可访问的子会话、当前或最近一次任务及其模型轮次 |

父 Agent 可以先回复用户，子 Agent 继续独立处理任务。子 Agent 的消息和 final 沿用现有持久收件箱与交付去重。父 Agent 主动等待时可续跑原执行；允许后台汇报且父会话空闲时，沿用普通调度创建回复。压缩、历史保留、取消和重启恢复均沿用普通 Agent 的规则。

## 切换与验收

Web 与 Desktop 已通过公共委派入口调用 Canonical Runner。Searcher 预设没有单独的 Runner 或固定执行计时器。两端已增加父会话作用域的短 ID 索引，查看子 Agent 和给活动子 Agent 发消息可跨父 Run。已完成的子会话可由新父 Run 发消息开启下一轮，复用相同的子会话并从自己的已提交 checkpoint 恢复历史。直接取消和父 Run 级联取消都使用持久执行关联与普通 Run 的取消端口。新一轮的等待和 final 暂沿用既有执行交付协调，Web 的新派单和恢复使用普通调度的 Redis 唤醒与扫描。Desktop 的新派单和重启共用一个持久队列扫描入口。两端仍保留委派执行装配和交付协调器。切换时复用已有子会话及历史，按父会话迁移短 ID 归属；数据库迁移一次性将旧派单和续聊记录搬入统一执行表，保留原解密坐标和执行绑定。运行时只读写统一表。两端验证跨父回合发送、空闲续跑、权限和确认、原等待恢复与交付去重后，删除专用执行路径。
