# 文件库写入围栏移除：workspace 绑定只约束 Shell

日期：2026-09-11
关联：`backend/agent/tools/files/{locations,folders,documents}.py`、`backend/agent/tools/{trash,web}.py`、`backend/agent/tools/filesystem_policy.py`、`backend/app/services/filesystem_authorization.py`、`docs/prds/【已完成】PRD-SHELL-4-用户沙箱授权与定时任务工作区绑定.md`

## 现象

用户把会话绑定到某个工作区后，咕咕连普通文件操作都做不了：在项目里 `create_folder` 被拒，报「当前文件系统权限只允许读取该个人/项目位置；请绑定对应 workspace，或先显式授权完整用户沙箱读写权限。」用户给该会话开了完整沙箱授权也没能立刻恢复可用手感，且咕咕据此还错误推断 `update_project`/`update_stage` 也被拦。

## 根因

PRD-SHELL-4 的 Phase 3（`SHELL4-010`）把「统一 filesystem policy」铺到了文件工具、回收站和 `web_download`：`filesystem_location_can_write` 在「绑定了 workspace 但没有完整沙箱授权」时，只允许写入绑定 workspace 子树内的位置，其余个人/项目位置一律只读。

这条规则对 Shell 是合理的（Shell 的挂载根就应该是绑定工作区），但对文件库工具是错位的：文件库有自己的空间与 ownership 模型，绑定 workspace 本意只是「省略目标时的默认落点」，却被升级成了写权限围栏。于是绑定工作区 = 文件工具被锁在该工作区内。

## 产品定案（2026-09-11）

> 这个权限也不应该拦 create_file / create_folder / edit_file / rename / move / copy，沙箱和工作区限制只针对 shell，其他工具一律不针对。

即：**workspace 绑定与完整沙箱授权只约束 Shell**（挂载哪些根、哪个根可写）；文件库工具一律不做位置写权限拦截；绑定只保留「默认落点」语义。

## 实现

- `agent/tools/files/locations.py`：`_resolve_create_location` 去掉围栏分支，显式 `space`/`project_id`/`folder_id` 一律按参数使用，省略时才落绑定工作区；删除 `_location_matches`、`_workspace_conflict`。
- `agent/tools/files/folders.py`：删除 `_move_one`/`_move_folder`/`_create_folder`/`_rename_folder`/`_delete_folder` 的 `write_access_error` 调用；`_create_folder` 显式目标按参数（空间跟随父文件夹），省略目标才用绑定工作区。
- `agent/tools/files/documents.py`：删除编辑、创建、附件落库、改名、删除、复制各处的写权限检查；`copy_file` 目标冲突检查一并移除。
- `agent/tools/trash.py`、`agent/tools/web.py`：删除还原/永久删除/下载落库的写权限检查（`folder_write_space` 保留，仅用于 `list_trash` 展示 `space` 字段）。
- `agent/tools/filesystem_policy.py`：删除 `write_access_error`、`file_write_access_error`；保留 `current_filesystem_policy`（Shell 与默认落点解析）与 `current_workspace_target`、`folder_write_space`。
- `app/services/filesystem_authorization.py`：删除位置级写权限门 `filesystem_location_can_write`、`filesystem_write_error` 及 `_location_is_in_workspace`（连同只被它们使用的 `Folder` 导入）。`FilesystemPolicy` 与 grant/revoke、`resolve_filesystem_policy` 保留，供 Shell 判定 `full_user_sandbox`。
- 技能文案 `agent/skills/file-ops.md`：把「personal/project 默认只读、按 policy 校验」改写为「文件工具不受绑定与沙箱授权限制，围栏只约束 Shell」。
- `agent/tools/files/transfer.py`（`send_file` 读 `/personal`、`/project` 逻辑路径）**保持原样**：它读的是 Shell 沙箱挂载根，属于 Shell 边界，不是文件库围栏。

## 副作用与取舍

- `filesystem.authorization.denied` 指标不再发出：文件工具已无拒绝路径，Shell 的拒绝走 `evaluate`/确认门，本来也不发该指标。这是移除围栏的直接结果，不是观测缺口。
- `SHELL4-010` 的验收语义被推翻，已在 PRD-SHELL-4 §0 与唯一 TODO 原条目上直接更新（保留 `[x]` 并标注 `🟡 推翻`）。

## 验证

- 后端全量：`2503 passed, 69 warnings`。
- 专项：`test_phase3_filesystem_policy`（含新增 `test_bound_session_writes_outside_workspace`、把 web 下载拒绝断言翻转为放行）、`test_phase4_filesystem_authorization`、`test_folder_workspace_write_access`、`test_shell_workspaces`、`test_files_api`、`test_trash_folders`、`test_agent_file_folder_parity`、`test_send_file_paths` 等 `126 passed`。
