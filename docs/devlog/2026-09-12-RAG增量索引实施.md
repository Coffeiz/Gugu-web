# PRD-RAG-9 增量索引重建与来源级同步实施

PRD：`docs/prds/PRD-RAG-9-增量索引重建与来源级同步.md`

## Phase 0（2026-09-12）：契约冻结 + 基线

### 已落地

- `backend/agent/rag/delta.py`：冻结增量契约——`parent_document_key`、`chunk_slot_key`、
  `document_digest`（覆盖 slot/source_type/title/summary/content/context/chunk_count/scope，
  **不含 version**）、`compute_chunk_delta`（upserts/deletes/unchanged，输出按 slot 键排序确定）、
  `projection_revision_stamp`。
- 契约单源化：`ts_sidecar._worker_document_key` / `_index_document_digest` 与
  `index_cache` 本地同族函数全部改为委托 delta，消除双份实现漂移。
- `index_cache` 的 patch 分支改用 `compute_chunk_delta`（查询侧增量本已存在，替换 digest 逻辑）。
- 诊断扩展（PRD §9）：`record_index_update` 增加 mode / upsert_count / delete_count /
  projection_ms / status / base_revision_match；`rebuild_source_index` 通过显式 `stats_out`
  回传统计，事件处理层记 `mode="source_replace"`（当前唯一路径）。
- `replace_source_documents` 增加 stats 出参（inserted/updated/deleted/elapsed_ms），返回值不变。
- 测试：`backend/tests/test_rag_delta.py` 9 例全绿；RAG 回归 242 例全绿。
  其中测试驱动出两个 digest 缺口并已补：chunk_count（chunk 收缩不可见）、scope（范围变更不可见）。

### 基线脚本踩坑

- 初版 owner 每次调用重新生成 → seed 与 measure 数据对不上（空 record）；改为单 owner 贯穿。
- knowledge 是文件库存储（KnowledgeStore 读 .md），不存在 DB 表；种子必须走
  `save_capture`（normalize_capture + KnowledgeStore.save），并把
  `settings.storage.local_path` 指向临时目录（`get_storage()` 每次重读 settings，生效）。
- devserver 上脚本正常退出但 asyncio worker transport 在 loop 关闭后析构，
  打印 `Event loop is closed` 噪音——不影响结果文件，未处理。
