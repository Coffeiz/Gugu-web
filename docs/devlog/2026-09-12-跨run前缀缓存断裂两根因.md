# 跨 run 前缀缓存断裂两根因：tool_calls 字节失真 + 摘要水位竞态

- 日期：2026-09-12
- 相关提交：`fca04f561`（断点1：raw_arguments 字节保真）、`04b0bb84e`（断点2：covers_until_id 水位）

## 现象

LoopScope 三个 DeepSeek run（QQ 链路、同一会话）全部在 round1 前缀断裂：
断点1 应命中的历史段整段冷读（约 60k fresh token），个别 run 中段还有
一次预期内的压缩降幅。跨 run 缓存本身是通的——更早一个 run 的 round1
实测 99.3% 命中，说明字节对齐时 DeepSeek 前缀缓存工作正常。

## 排查

导出被删后改从 devserver 取数：LoopScope 活库经 `/proc/<pid>/environ`
的 `LOOPSCOPE_DB_PATH` 定位（`~/loopscope-data/loopscope.db`，注意
`loopscope/data/` 下还有一个停在 8/26 的旧库，别误用）；生产侧历史在
postgres `conversation_messages` 表（没有 agent_messages 表）。

逐消息 MD5 对比 live 序列化与回放序列化，找到两处分叉：

### 断点1：tool_calls.arguments 序列化失真

live 轮 provider 返回的 `arguments` 是带空格的原始 JSON 字符串，而历史
回放路径 `json.loads → json.dumps` 成紧凑形式再发给 provider。字节不同
→ 前缀从此断开。这是所有 run 断点1 的直接原因。

修复（`fca04f561`）：

- `NormalizedToolCall` 增加 `raw_arguments`，OpenAI 流解析处保留原始串；
- canonical tool round 的 assistant tool_call block 直接存原始字符串，
  不再 parse→dumps 往返；
- Anthropic adapter 遇到字符串 arguments 时 `json.loads` 成对象（Anthropic
  的 `tool_use.input` 必须是 object），畸形串降级 `{}`。

### 断点2：finalize 与压缩两个事务之间的「新摘要 + 旧 baseline」竞态

`run_finalize.finalize_run` 先提交 turns，随后 `compress_if_needed` 在
**另一个事务**里写 summary 行并推进 `session.baseline_message_id`。生产
会话 388 的取证：summary 行（id 48339）14:58:52 落库，而有效水位停留在
约 48282——下一次装配（14:58:58 的 run3）夹在两次提交之间，读到
「新摘要 + 旧 baseline」，把摘要已覆盖的原文（含 run1 的
list_scheduled_tasks 轮）整段重复拼进上下文。

run1 r7 / run2 r5 的 cache 突降（cr=23296）是 run 内压缩折叠
64→25 条所致，属预期行为，不在本修复范围。

修复（`04b0bb84e`）：

- `conversation_messages` 新增 `covers_until_id`（迁移
  `20260912000002`，链在 pending-queues 迁移 `20260912000001` 之后），
  压缩事务把 `to_compress[-1].id` 与 baseline CAS **同事务**写进 summary 行；
- `load_session_history` 取 `max(传入 baseline, summary.covers)` 作有效
  水位过滤 rows，两者分叉时记一条 `history-baseline-divergence` 日志
  （只含 id，无正文）；旧摘要行无水位时退回传入 baseline，行为不变；
- stats 增补 `history_effective_baseline_id` / `history_summary_covers_until_id`。

语句级快照保证了不加锁也自洽：若压缩提交发生在 summary 读取与 rows 读取
之间，summary 读到旧值（无水位）→ 退回旧 baseline + rows 含新追加 turns
= 恰好是压缩前的视图，最多损失一次缓存命中，不会重复。

## 验证

- 新增 `tests/test_summary_covers_watermark.py` 竞态矩阵：旧 baseline +
  新 covers 去重、legacy 摘要回退、baseline 封顶、压缩事务落水位断言；
- 连同 `test_session_history` / `test_baseline_run_summary_reuse` /
  `test_run_finalize` 定向 20 个全绿；
- 全量 2652 passed，3 个失败均为另一条并行工作线的在途改动
  （capability 注册表 ×2、systemd 模板），与本修复无关。

## 备注

- `20260912000002` 的 down_revision 指向并行工作线的 untracked 迁移
  `20260912000001`；在该迁移入库前，fresh clone 的 alembic 链不完整
  （devserver 工作区两个文件都在，不受影响）。
- 会话级复现时优先对比 LoopScope `spans.input_json` 里的
  `cache.stable_prefix_digest` 与逐消息 MD5，分叉点定位比看 token 数快。
