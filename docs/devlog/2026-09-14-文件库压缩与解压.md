# 文件库压缩与解压

## 目标

完成 PRD-FS-5 的个人文件、项目文件与 Workspace 文件压缩/解压能力，复用同一归档服务，保证 Web、API 和咕咕工具遵守相同的空间归属、安全、冲突与配额规则。

## 实施

- Phase 1：新增归档服务，使用 Python 标准库处理 ZIP / TAR / TAR.GZ；实现同空间校验、512MB 压缩源上限、条目数/展开字节预算、路径安全校验、链接条目跳过、重名自动改名、配额检查与失败回滚。
- Phase 2：增加 `POST /files/archive`、`POST /files/unarchive` 与 `compress_files`、`extract_files` 工具。API 和工具仅负责身份/输入边界及事件发布，归档规则集中在服务中。
- Phase 3：文件多选工具条增加压缩入口；网格卡片及列表行对受支持归档显示解压入口。压缩只填写 ZIP 名称并落在所选内容当前目录；解压只填写新目录名，默认取压缩包主体名，并在压缩包所在目录创建子目录。
- 后续补齐文件库右键菜单：右键多选项或已选中的单个文件/文件夹可直接压缩；右键 ZIP/TAR 归档直接打开解压命名对话框，不再选择目标目录；已选中的压缩包处于多选菜单时，解压操作仍然保留。
- 解压命名目录与全部条目处于同一数据库 savepoint，失败时回滚行记录并清理物理目录/文件；旧 API 调用未传 `folder_name` 时仍兼容原有目标语义，工具调用不受影响。
- 将 `.tar.gz` 识别为规范格式提示，避免错误地把单独的 `gz` 作为格式传入；单纯 `.gz` 不显示解压入口。
- 前端操作完成后复用文件缓存变更监听刷新当前视图与存储用量，避免重复触发手动重载。
- 更新能力注册表总数断言，覆盖新增的两个内置文件库工具。

## 当前交互调整

- 压缩：产物放到所选文件/文件夹所在的当前目录，弹窗仅输入压缩包名称。
- 解压：压缩包保留原位，默认以压缩包主体名在旁边新建文件夹，用户可编辑名称；不再显示目录选择器。
- 若压缩包的全部有效条目都被同名顶层目录包裹，解压时去掉该重复层，避免出现内容为空的外层文件夹。
- 自动化覆盖：验证压缩包同目录创建、解压目录命名、已有同名目录的自动重命名、重复顶层目录去重，以及非法目录名拒绝。
