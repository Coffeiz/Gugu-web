# Owner 反思共享闲置 TTL 与持久历史重建

## 背景

owner 记忆原先只按固定轮数阈值冲刷。群/群友反思已有 15 分钟 idle 收束，但 TTL 常量和 owner 群主缓冲的 ZSET drain 独立维护；owner 私聊也只依赖进程内的 15 分钟主会话快照，快照过期后无法继续反思。

## 调整

- 新增共享闲置策略模块，统一 owner 私聊、群主 owner 缓冲和群/群友游标的 15 分钟 TTL。
- owner 缓冲仍保留原固定轮数阈值；新增按 user+session 记录活动时间，由 worker 每 30 秒扫描到期队列。
- owner 私聊与群主 drain 共用一套原子取队列、快照读取、失败回滚和重试调度实现；旧群主队列按 session 拆分迁移。
- 快照不可用时，校验数据库 session 归属及 idle 状态，从 baseline 之后读取持久化历史，并用当前模型配置构建最小追加输入；完整 provider 快照不会写入 Redis 或数据库。
- owner 与 IM 群/群友反思调用共享的 `run_reflection_branch`，统一 `ContextBranch` 追加执行策略。

## 缓存与安全边界

持久历史重建不包含原 run 的完整 tools 声明、动态业务上下文，也不能保证 system prompt 字节一致。因此它保证复用 `append_reuse` 分支机制，不标记为原前缀完全复用，也不承诺缓存命中。历史查询以 session id 和 owner id 同时限界，运行中或仍有 pending 消息的会话会延迟处理。
