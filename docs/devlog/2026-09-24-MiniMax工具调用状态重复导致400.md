# MiniMax 工具调用状态重复导致 400

## 现象

QQ 私聊 session 388 收到短消息后，worker 记录 `BadRequestError`，模型没有开始生成，用户收到失败提示。LoopScope 显示本次请求 usage 为 0。

## 排查与根因

通过 LoopScope 的受限诊断结构检查请求消息，只查看角色、块类型和工具配对，不输出会话正文、工具参数或完整工具 ID。

- MiniMax Anthropic 接口返回 HTTP 400，错误为 `invalid params, tool call result does not follow tool call (2013)`。
- 请求包含 105 条消息，`tool_use` 有 17 个，`tool_result` 有 16 个。
- 同一个工具调用指纹在两个 assistant 消息位置出现；第二次出现后紧接普通 user 消息，没有对应的 `tool_result`。
- 失败发生在 provider 请求入口，模型尚未执行，因此不是 QQ 传输、用户输入或缓存问题。

代码链路如下：

1. `AnthropicDriver.extract_provider_state()` 原先把 thinking、文本和 `tool_use` 一起保存为跨请求 provider state。
2. 上一轮工具调用已经通过 `build_tool_round()` 写入 canonical history，并保存了对应的 `tool_result`。
3. 下一轮 `ReasoningStateCoordinator.prepared()` 恢复旧 provider state。
4. `AnthropicDriver.run_round()` 在 provider 边界再次插入旧的 `tool_use`，造成重复 ID 和未配对调用。

历史清洗发生在 provider state 插入之前，因此无法拦截这条重复块。

## 修复

- Anthropic 跨请求状态只保存 `thinking` 和 `redacted_thinking` 块。
- 恢复旧状态时再次过滤非 thinking 块，兼容已经落库的旧状态。
- 旧状态如果只包含工具调用，则判为不可恢复并失效，不再发送给 MiniMax。
- 增加回归测试，覆盖正常 thinking 恢复和仅含重复 `tool_use` 的旧状态。
