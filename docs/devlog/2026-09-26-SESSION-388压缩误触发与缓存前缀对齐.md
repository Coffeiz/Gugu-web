# SESSION 388 压缩误触发与缓存前缀对齐

## 现象

128k MiniMax BYOK 会话在 provider 实际输入约 81.5k tokens 时发生反思前压缩，压缩请求缓存命中仅约 0.1%。按 90% 策略应在实际输入达到 115,200 tokens 后触发。

## 根因

主 run 已使用 provider 返回的实际用量判定阈值，但反思预检重新估算完整快照并计入保留量，约 118k 的估算越过触发线。随后压缩前缀校验因纯文本字符串与单个 text block 的结构差异失败，回退到数据库重放；持久化行的 id 顺序与主会话的创建时间顺序还可能交错。

## 修复

- 同进程反思快照保存最近一轮实际 provider context input 和本 run 是否已压缩，避免反思预检重复用估算触发。
- 压缩前缀允许纯文本字符串与单个 text block 等价，其余消息结构保持严格校验，成功时发送原始主请求前缀、system 与工具声明。
- 仅验证待压缩前缀，按主会话时间顺序回放；无法对齐的截点向前退少量消息并保留在尾部。
- 诊断脚本新增明确的真实模型开关与合成压缩 A/B 模式。

## 验证与限制

相关回归测试 90 项通过。真实 MiniMax 合成 A/B 的完整前缀追加命中 57,984 / 58,094（99.81%），截断重放命中 128 / 38,786（0.33%）。只读复现确认 81,515 不触发、115,200 触发，旧版找不到的持久化前缀在新版能对齐。完整数据见 [缓存策略报告](../reports/OPT-Cache-Strategy-2026-09-26.md)。

本次 devserver Mutagen 同步暂停，运行服务尚未应用源代码修复。缺少 provider 实际用量的重启接管与静默群路径仍用本地估算，需在后续真实运行中单独观测。

## Token 口径回归补充

后端 skill 明确规定：压缩触发以同一请求的 provider 完整输入量为准，缓存读取和写入均计入；本地估算仅在没有有效实际用量时兜底，不能与实际值混算或覆盖实际阈值。反思预检将非正数 provider 用量视为缺失，并在快照已压缩时先停止，避免兜底重复触发。

新增回归测试直接禁止有实际用量的路径调用本地预算器，并验证缺失或零用量的兜底、快照字段透传，以及 128k 模型在 115,199 / 115,200 tokens 两侧的触发结果。相关组合回归 124 项通过。
