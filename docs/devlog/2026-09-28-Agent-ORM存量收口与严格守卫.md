# Agent ORM 存量收口并恢复严格守卫

## 问题

快速门禁曾将 Agent ORM 检查改成相对 `origin/main` 的增量扫描。它能阻止新问题增加，却不会发现或修复存量违规，因此“门禁通过”被误当成 ORM 边界已收口。严格扫描最初报告 45 条，涉及历史对话、文件列表、工作区目录、MCP 管理、Skill 管理及定时任务授权。

## 修复

- 将历史 RAG 结果的消息归属回查下沉到 `app.services.conversations`。
- 将文件夹直属文件计数下沉到 `app.services.files.browser`，复用已有文件域查询边界。
- 将工作区目录归属校验封装到 `app.services.workspaces`，文件位置与工作区工具不再导入 Model/ownership helper。
- 新增 `app.services.mcp_servers`，集中承接用户范围 MCP server 的列表、定位、重名/数量检查、创建、保存、启停 flush 和删除；工具保留确认、参数验证、结果整形和运行时管理。
- 将用户 Skill 列表和删除前查询下沉到 `app.services.mind`。
- 删除定时任务授权工具中在授权 Service 已 flush 后的重复 flush；授权 Service 仍负责本身写入所需的 flush，任务调用边界仍负责提交。
- 快速门禁恢复 `check_orm_boundaries.py --agent-strict`，不再用增量基线替代存量修复。

## 验证

- `check_orm_boundaries.py --agent-strict`：通过。
- 对话搜索、文件工具/目录、用户 Skill、工作区目录和 MCP 设置相关专项测试：114 passed。

本次只收敛 Agent 工具 ORM 边界，不改变 API 契约、确认流程、归属过滤或现有事务语义。
