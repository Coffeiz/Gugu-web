# 一体化镜像默认启用 Shell 沙盒与候选构建缺口

## 现象与根因

FNOS Admin 显示沙盒部署模式为 `disabled`、Docker daemon 不可用、执行器不可用。检查发现上一轮用于测试的镜像是直接运行根目录 `Dockerfile` 构建的基础 app 镜像，而不是 release 流程组装后的 bundled candidate：

- 根目录 `Dockerfile` 曾把 embedded manager 和 `SANDBOX__ENABLED` 设为关闭。
- FNOS 宿主 Docker Socket 没有挂载到应用容器；Docker CLI 存在并不代表容器内有 daemon。
- 基础镜像不含 `/opt/gugu/sandbox-bundle/runtime-images.tar` 与 manifest；这些由 `Dockerfile.sandbox-bundle` 在 app 镜像后追加。

Shell 只经 sandboxd 创建隔离容器；运行时未就绪时拒绝执行，不回退到 app 容器本机。

## 修复

- 一体化 app 镜像默认启用 `GUGU_SANDBOX_MANAGER_MODE=embedded` 和 `SANDBOX__ENABLED=true`，并设置 `/var/run/docker.sock` 为默认 `DOCKER_HOST`。
- 一体化镜像默认启用受控 egress 网络配置；首次运行仍需宿主 Docker daemon 可用。
- 默认 Compose 显式启用沙盒；通用 `SandboxSettings` fail-closed 默认及分体部署 `external` 模式保持不变。
- PRD 明确区分镜像自带 runtime bundle 与必须由用户挂载的宿主 Docker Socket。
