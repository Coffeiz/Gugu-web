# PRD-LLM-29 Phase 4：入口复审与隔离 20-run 验证

## 背景

Phase 1–3 已建立 Canonical MessageArea、ProviderConversation 投影与按序持久化增量。本阶段继续检查各类入口和只读分支是否遵循同一账本，并验证连续工具轮次经过落库、重新加载后不会丢失、重复或改变 Provider wire 顺序。

## 本次完成

- 主 run 收尾对缺少 `message_area` 属性的轻量测试对象使用显式空值读取，保留生产对象的 Area 路径，同时避免测试/辅助对象因属性缺失而异常。
- 历史内容格式化允许没有 request 对象的非分组调用，避免仅在该调用形态下访问 `request` 时失败。
- 持久化恢复入口统一到 `message_area_repository.restore_entries()`；session history restore 复用该入口，并新增测试验证恢复后持久化消息身份与时间戳仍在。
- 新增 20 轮合成连续工具调用回归：每轮将上一轮增量提交到隔离测试数据库，重新加载 canonical history，对照历史 renderer 与 Area projection 的 wire 顺序；最终恢复结果包含预期的 80 条消息。该测试不调用真实模型、不使用真实用户会话或运行配置。
- ContextBranch 向 Provider 传递 sibling history 时改为深拷贝；新增行为测试模拟 Provider 原位修改嵌套工具块，确认源 history 保持不变。
- 20-run shadow compare 显式断言每轮 old/new wire 的 `first_diff_index` 均为空；该结构对照不等价于真实 Provider cache usage 测量。
- 收敛 finalize 契约：`finalize_run()` 现在必须接收 `MessageArea`，只提交 `persistence_delta()`；删除从 Provider wire 反推消息、独立 `canonical_batches` 输入以及 RAG/stance 无 Area 写入分支。缺少 Area 会明确报错。
- 删除 `persistable_canonical_batch_records()` 与 `PromptMessages` 暴露的 canonical batch/record/digest 属性；runtime-context、工具轮和中断收尾测试改为直接验证 Area entries/delta。
- 更新 Context Engineering 文档，明确 Area 是 canonical 与 persistence 的唯一事实源；同步补充 finalize 无 Area 会拒绝的行为回归。
- LoopScope 迁移为 Area/projection 双身份观测：trace 展示的仍是实际 Provider projection 正文，结构诊断只记录 Area revision/digest、entry source/persistence 计数、wire digest 与 fixed/dynamic 边界；删除 canonical batch 探针及其调用。cache 诊断拒绝原始可变消息列表，必须消费 `ProviderConversation`；Anthropic 成功/失败请求诊断统一改用 projection 身份字段。
- 清理 LoopScope 的旧 list-only 测试：快照/历史展示测试改用不可变 Provider projection；cache 断点测试验证已 sanitize、已投影的真实消息结构；新增 Area 身份与正文不泄漏的诊断合同测试。
