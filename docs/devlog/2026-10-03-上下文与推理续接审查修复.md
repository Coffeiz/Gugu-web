# 上下文与推理续接审查修复

## 背景与边界

LLM-29/LLM-23 完整审查发现，Canonical 分层已建立，但状态提交、回放位置和最终收尾仍有契约缺口。压缩与反思的固定前缀和 wire 类型修复由另一项工作负责；本次保留其改动，并补充最终请求投影的私有推理回放覆盖。未修改用户运行配置或业务数据，未提交、部署或调用真实 Provider。

## 修复

- 循环成功只暂存状态；`finalize_run` 在同一事务写入历史、最终回复、用量和加密推理状态。仅事务提交成功后更新协调器版本。状态 CAS 冲突在 savepoint 内处理，不覆盖另一 Run 的状态。
- 复用现有 ConversationBatch 唯一账本，以 Run 身份生成 `finalize-v1` 收尾凭据，无新数据库表或迁移。重复收尾直接返回本次零新增用量。
- 失败和压缩失效携带 expected_version；成功失效后读取新版本，陈旧 Run 无权清除新的续接状态。
- 状态配置身份纳入去用户名、认证查询参数和片段的 endpoint 摘要，不记录地址或凭据原文；旧配置指纹自然失效，不保留旧 envelope `blocks` 恢复入口。
- Responses reasoning 放在最新输出组之前，包含无文本、多工具调用场景；保留 native input item 类型，反思分支不二次转换 reasoning/function items。
- Anthropic 保存签名块的原始索引，恢复时按索引插回，内部位置标记不发送给 Provider。
- Driver 保存不含 cache marker 的最终请求投影；反思捕获同 revision 投影，保留恢复的 thinking，排除动态尾部。baseline 变化后旧投影不复用。
- Chat reasoning 仅按工具调用身份保存在 Run 内私有映射，出站时恢复；Canonical batch 拒绝私有 reasoning block，恢复旧行时不把它带入新的 Area。
- 临时 Shell 环境提醒通过 batch 元数据进入动态尾部，不创建 runtime 持久化行；保留已有动态尾部。
- Web 累计展示和最后轮 Canonical 回复分开，避免此前工具正文重复写入最终历史。

## 清理与覆盖

删除临时环境转持久化 runtime-context 的旧 helper、旧 entry 构建路径、工具轮私有 reasoning 持久化代码及旧 blocks 续接入口。替换要求保存临时环境或私有推理的旧测试；保留跨 Run 前缀、工具配对、历史恢复、数据隔离和状态加密覆盖。

新增行为测试验证：交错 thinking/text 顺序、Responses 工具-only 输出定位、接口身份隔离、同 Run reasoning 回放而不持久化、Driver 投影反思、状态失效后的版本刷新、陈旧 Run 失败不清新状态、事务失败整体回滚，以及重复 finalize 不重复回复和用量。

## 验证

本机专项回归 375 项通过，补充 session snapshot 回归 33 项通过；ownership、确认门守卫、语法与差异检查通过。最终后端广泛回归 3859 项通过，命令显式排除以下两项与本次上下文修改无关的既有失败，未删除测试或放宽断言，因此不宣称完整套件全绿：

- `test_image_search_accepts_numeric_string_result_count_after_normalization`：引用已不存在的 `agent.tools.base.validate_input`。
- `test_list_dir_path_ambiguous_segment_reports_candidates`：夹具创建同范围、同名目录，被现有唯一约束拒绝。

全量回归还产生 139 条警告，包含依赖弃用和 aiosqlite 线程在事件循环关闭后的清理警告。一次较早的全量运行在大量错误且测试未结束时主动中断；当时磁盘仅剩约 176 MB，未确认这些错误的具体原因，未据此修改业务逻辑或清理业务数据。后续重跑未再出现该批 setup 错误。

测试使用合成数据和隔离数据库，不代表真实 Provider 缓存比例或 devserver 灰度验收。修复过程中替换的旧 snapshot 用例明确验证：临时提醒仍发给 Provider，但不进入 conversation 或持久化 delta；全量 worker 曾载入修改前的测试版本，最终重新启动测试进程确认通过。

静态质量检查指出 Anthropic 状态代码的短期重复修改风险；此次修改属于审查确认的顺序恢复缺陷修复，保留针对原始块顺序的行为覆盖，不通过批量接受其他工作区告警来掩盖风险。
