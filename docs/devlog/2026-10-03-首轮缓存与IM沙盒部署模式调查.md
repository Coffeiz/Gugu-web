## IM 拒绝执行的独立根因与修复

devserver 已安装的 backend 和 sandboxd 通过 systemd drop-in 声明 `GUGU_SANDBOX_MANAGER_MODE=external`，worker 和 gateway 没有声明。部署模式不由 Admin 的 enabled 开关替代，也不从普通 override 读取；无环境声明时默认 disabled。

只读探针显式要求 `--allow-real-data`，仅在自身进程内改变环境，对现有 sandboxd 做就绪查询：

- disabled：拒绝，原因“沙盒部署模式已禁用”。
- external：通过，原因“Docker 沙盒运行时已就绪”。

仓库四个 systemd 模板统一声明 external，新增部署环境一致性回归测试。devserver `tests/test_start_systemd.py`：4 passed。该测试保护不同交互入口和执行器必须采用一致部署拓扑的边界，不锁定普通用户文案。

当前模板已同步，但已安装的 systemd unit 尚未替换：写入系统配置需要提权。本次没有修改 `.env`、`config.override.json`，也没有重启业务服务。之前两次成功的具体进程来源尚未逐调用确认，不把它解释为次数限制。
