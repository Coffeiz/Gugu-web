# 升级停服与 Shell 确认边界修复

## 确认的问题

- 一体化旧数据需要工作区迁移，但正常入口只检查布局，内置数据库又不能通过绕过入口直接启动，原升级说明不可执行。
- 危险 Shell 命令共用会话级授权，第一次确认可能覆盖后续不同脚本。
- 分体更新仅停止 Compose 服务和普通 Docker 的容器，无法保证 external Rootless 管理器停止写入。

## 修复

- 增加 `gugu-offline-migrate --services-stopped` 正式入口，只启动内置 PostgreSQL/Redis，备份数据库与 users，再执行 Alembic、工作区迁移和数据库检查；退出时关闭依赖。失败保留恢复标记与成套备份，不自动换回旧镜像。
- 移除通用 Shell lease，危险调用的授权绑定准确命令、会话、工作区、cwd 与主体，仅消费一次。自动模式保持原有明确授权语义。
- external 更新要求管理员提供固定生命周期控制器与真实 Rootless Unix socket；验证停服，停止本部署数据挂载对应的执行容器后才允许备份迁移。成功只恢复原先运行的管理器，失败保持停服；拒绝退回 rootful daemon。
- 更正密码找回与危险 Shell 文案；部署说明补齐升级命令和成套恢复规则。

## 验证与限制

- 后端联合定向测试 110 项、更新脚本测试 14 项通过，覆盖确认单次消费、命令/上下文变化、迁移失败禁止启动与 external 停服失败禁止备份。
- devserver 隔离 PostgreSQL 测试通过：真实 Alembic 与布局迁移可重跑；custom 数据库备份可恢复，users 备份保留旧布局。测试使用临时数据库与目录，未迁移真实用户数据。
- 旧式 Compose Docker 夹具明确保留内管理器拓扑；external 控制器和失败边界使用脚本行为测试，不宣称完整 Rootless 部署已验收。
- 完整候选一体化发布镜像升级尚需验收；未触发 GitHub CI。前端类型检查仍有既存的技能测试类型错误，未修改无关文件。
- 单独收集终端确认测试还会触发现有 terminal/sandbox 导入循环；与 Shell 测试联合收集通过。该依赖问题不在本次修改范围，不把联合通过当作独立导入检查通过。

部署 external 模式时须配置控制器权限和实际 socket，缺失配置会拒绝更新，而不是在未停服时继续迁移。
