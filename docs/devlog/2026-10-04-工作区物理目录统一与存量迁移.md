# 工作区物理目录统一与存量迁移

## 问题与根因

Shell 展示的 `/workspace/default`、`/workspace/qq` 原先只是挂载别名：默认目录实际位于用户根下的 `workspace`，命名目录则与它并列。文件库 key 构造、默认根解析和目录对账仍采用旧布局，导致磁盘目录与 Shell 展示不一致。

## 实现

- 统一为 `<用户ID>/workspace/<稳定目录段>`，默认 `default`。目录改显示名不改物理段，Shell 挂载复用同一段名。
- 统一文件 key、逻辑路径、对账、默认 Shell 根、回收站还原和导入后的默认目录身份。配额仍统计整个 `workspace` 命名空间，包含未登记的 Shell 文件。
- 移除重复的 Shell 别名推导和旧顶层路径构造，更新旧路径测试与注释；保留历史数据库迁移及独立的旧 Shell 目录扫描功能。
- 添加全用户停服迁移脚本，更新文件/附件 key，并通过同盘目录改名保留未登记文件和 inode。带时间戳计划、原子检查点、目录身份验证与全局锁支持中断续跑，冲突及源目录符号链接直接拒绝。
- 文件迁移不挂到普通 `make migrate`，因为它不能保证服务已停止。提供显式预检/停服执行入口；镜像启动在数据库升级后、接收流量前执行。

## 验证与交付边界

在 devserver 使用隔离测试数据库和临时目录验证多用户迁移、重复执行、提交前中断、改名后检查点中断、符号链接拒绝，以及文件库/Shell/回收站/配额/数据导入相关行为：129 项通过。Shell 入口语法与差异空白检查通过；未构建镜像。没有执行真实用户目录迁移，没有重启运行服务，没有修改运行配置。

升级操作与备份、停服要求见 [工作区目录布局迁移](../ops/workspace-layout-migration.md)。迁移计划不能替代数据库与完整文件备份。
