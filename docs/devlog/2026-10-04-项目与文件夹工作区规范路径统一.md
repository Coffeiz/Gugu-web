# 项目与文件夹工作区规范路径统一

## 目标与改动

绑定项目或文件夹原先被单独挂载为 `/workspace/<工作区显示名>`，同一文件又能通过 `/project`、`/personal` 访问，容易使 Agent 混淆归属。现在只保留其规范路径：项目为 `/project/<年>/<月>/<项目名 #ID>`，项目内文件夹追加实际相对路径，个人文件夹位于 `/personal`，独立工作区仍为 `/workspace/<稳定目录段>`。

挂载协议改为显式 `target/root`；业务服务与 sandboxd 共用物理空间到规范路径的映射。sandboxd 验证同一用户归属及目标和来源的一致性，拒绝路径穿越、空间根、旧别名及 Docker 参数注入。Shell、脚本和 PTY 使用同一挂载清单；相对路径从绑定目录开始，项目或文件夹内脚本不必为此申请整个文件库写权限，确认门和定时任务的精确脚本授权继续保留。

文件库父根先只读挂载，绑定目录在其规范子路径覆盖为可写。修改工作区显示名不改变 cwd。删除旧别名规范化、冲突后缀推导和旧 cwd 特例，更新相关行为测试、工具说明及 PRD。保留 OSS/MCP 独立单根模式，未改其存储模型。

## 验证与上线注意

devserver 隔离测试 263 项通过，覆盖项目、项目内文件夹、个人文件夹、跨用户拒绝、重命名路径稳定、脚本绝对/相对路径与邻接项目拒绝、定时任务精确脚本授权、Shell 与 PTY 参数、协议校验及相关执行生命周期。差异空白检查通过；现有 Redis setex 弃用警告未在本任务处理。

devserver 真实 Docker 使用现有本地 Node 镜像及临时目录验证新执行器生成的挂载参数：项目 cwd 正确、绑定目录可写、相邻项目只读；不拉取镜像，不访问业务文件，测试容器与临时目录均随测试清理。

本次不变更业务绑定 ID，不移动项目/个人文件，也不修改用户配置。挂载协议无旧格式兼容，需要后端和 sandboxd 一起升级；现存 PTY 应重新连接。独立工作区物理布局升级仍需按 [目录迁移说明](../ops/workspace-layout-migration.md) 先停服迁移，不能直接重启绕过迁移。
