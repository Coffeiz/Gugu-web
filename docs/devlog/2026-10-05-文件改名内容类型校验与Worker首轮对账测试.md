# 文件改名内容类型校验与 Worker 首轮对账测试

## 问题

- 文档工具只在 Agent 改名函数内做不完整的文本/二进制后缀判断；文件库 PATCH 直接改扩展名和存储 key，导致 UI/API 可把文本字节改名为图片、压缩包或 `.pyc`。
- 文件同步 Worker 的 inactive-user 覆盖测试把补偿间隔设为 0，旧的 `_last_compensation = 0` 在通常 uptime 下也能触发扫描，无法锁住 Worker 启动时漏掉首轮全量对账的回归。

## 修复

- 将文本类型判定和后缀改名校验放进 FileService 共用模块；FileService 拒绝可识别的跨文本/二进制改名，Agent `_rename_one` 也委托 FileService，API、UI 和 Agent 共用改名语义。
- Worker 覆盖测试保留一天补偿间隔，并固定单调时钟为短 uptime，验证新 manager 仍对所有可补偿绑定执行首轮强制投影。

## 验证

- `test_file_service.py`、`test_documents_tools.py`、`test_filesync_phase1.py`：94 项通过。
- 覆盖 md → png/jpg/zip/pyc/docx 被拒且 key、字节不变；二进制改名到文本后缀被拒；未知自定义后缀继续保留原有处理；Worker 首轮强制对账。
