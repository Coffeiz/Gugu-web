# PRD-FS-7 Phase 1：实时监听可靠性

## 目标

恢复“文件系统精确事件立即 targeted 投影”的职责边界。目录监听受理不再等待 Chokidar 初始遍历完成；事件消费独立运行。监听缺口只持久化健康状态并提示人工恢复，不自动触发整树扫描。

## 实现

- TS watcher 的 `watch` 响应表示监听已受理；`ready` 单独报告初始遍历完成，`error` / `ENOSPC` 不会被后续 `ready` 或重复注册掩盖。
- Worker 将绑定刷新/监听注册与 sidecar 事件消费并行运行。当前按顺序受理绑定，注册并发上限为 1；注册期间到达的路径事件仍由 targeted 投影处理。
- TS 输出队列和 Python 事件队列发生溢出时保留已接受的精确事件，并额外给出 sticky 的 `needs_reconcile` 信号。事件缓冲有界，超过上限后记录健康缺口。
- 路径投影失败只对路径批次局部重试，最多 3 次；最终失败会记录脱敏错误码并保留“需要手动核对”状态，不回退整树扫描。
- 绑定持久化 watcher 状态、缺口版本和错误码；成功重建监听只恢复后续接收，不清除已有缺口。Admin 状态接口与面板展示监听状态和人工核对入口。
- 删除 watcher 的每日/启动/错误触发整树扫描与补偿间隔配置。StatCache 仍供显式完整核对复用；精确 targeted 路径始终重新计算内容指纹。

## 回归验证

- Python 文件同步测试：`test_filesync_phase1.py`、`test_filesync_ts_sidecar.py`、`test_filesync_watcher_health.py`，37 项通过。
- TS watcher 测试 5 项通过，覆盖 ready 前事件、监听额度失败、输出拥塞；backend TS typecheck 通过。
- 前端 `FileSyncAdminPanel` 组件测试通过，验证异常筛选展示待核对绑定、人工恢复提示和错误码；前端 typecheck 通过。
- 测试边界/元数据检查通过；Alembic 当前唯一 head 为 `20261007000002`；`git diff --check` 通过。
- Python 集成测试让 fake sidecar 在注册中保持未 ready，实际运行 Worker 消费循环和 targeted 投影，证明注册等待不会阻塞事件处理。物理大目录 devserver 探针尚未执行；本地 Mutagen session 因已有跨平台文件/符号链接冲突而不能 flush，本阶段没有改 Mutagen 配置或清理用户目录。
- ripwire test-gate 已列出并由上述命令手动执行所有文件同步测试；TS 测试 runner 未被 ripwire 自动识别。quality-delta 因仓库没有基线且工作树含其他未提交修改，未创建会吸收用户改动的基线。
