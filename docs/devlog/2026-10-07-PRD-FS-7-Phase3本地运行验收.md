# PRD-FS-7 Phase 3：本地运行验收

## 范围

本记录覆盖本地隔离环境下可重复的目录规模、实时事件和并发/取消边界验证。规模数据由同一批临时文件分别运行旧式“整树路径列表 + 逐文件 SHA-256”参照流程和当前流式 SQLite manifest 扫描；每种方式在独立进程运行，均包含相同的应用模块导入开销。文件内容均为 92 字节。当前扫描使用 256 MiB manifest 上限及实现默认 8 MiB SQLite page cache。

扫描器对比是本地合成数据的一次性观测，不代表 devserver/生产吞吐基线。计时包含磁盘遍历、读取/哈希和当前扫描的 manifest 写入；该部分不包含数据库 `File/Folder` 分页暂存、对账投影或 PostgreSQL 事务。另有独立的 10,000 文件 PostgreSQL 端到端 dry-run 与实时 watcher 探针，结果见下文。

## 目录扫描观测

| 文件数 | 参照流程耗时 / 峰值 RSS | 流式扫描耗时 / 峰值 RSS | manifest 大小 |
| ---: | ---: | ---: | ---: |
| 1,000 | 0.028 秒 / 89.34 MiB | 0.085 秒 / 89.89 MiB | 208 KiB |
| 10,000 | 0.228 秒 / 94.92 MiB | 0.944 秒 / 91.50 MiB | 1.58 MiB |
| 100,000 | 39.206 秒 / 151.61 MiB | 72.238 秒 / 92.20 MiB | 16.17 MiB |

RSS 包含进程固定导入开销。10 万文件样本中，当前扫描相对 1 千文件的峰值增加约 2.31 MiB，参照流程增加约 62.27 MiB；当前扫描体现了较低的内存增长，但该次样本耗时更长，尚不能宣称吞吐改善。10 万规模的单次用时受本地文件系统噪声影响，应在同一运行环境多轮复测后再做性能结论。

另以 10,000 文件比较 manifest 提交批次：256 项 1.043 秒、1,024 项 0.922 秒、4,096 项 0.831 秒。变化幅度有限且来自单次本地测量，暂不据此调整 PRD 中约定的默认资源预算。

## 实时与故障边界

隔离的真实 Shell 探针使用多连接临时 SQLite 重复观测 3 次：创建 0.399–0.427 秒、等长内容修改 0.329–0.331 秒、删除 0.062–0.066 秒。定义为 Shell 操作到 File/journal 观察条件成立的等待时长，测试以 50 ms 间隔轮询，因此包含轮询量化误差；这不是纯 watcher 内部延迟，也不代表 PostgreSQL 线上时延。

新增/扩展的行为回归覆盖：

- 同步屏障下，旧扫描的更新、新建、移动源/目标和删除候选遇到 targeted 已提交的更新、新建、移动、软删除时均被跳过；不会覆盖新对象，也不会重复建档。
- 文件完成 stat 复核后、短投影事务开始前被实时写入时，旧指纹不会覆盖数据库中的当前记录。
- manifest 超出固定空间预算时临时清单被清理；任务失败不会把数据库孤儿误判为可删除项。
- 目录遍历和真实大文件哈希分块中的取消/超时均等待线程退出；执行期间同用户第二个绑定不能领取执行槽，线程收口后才可领取。
- 真实扫描线程被目录遍历屏障暂停时，SQLite 集成用例确认 Worker 租约心跳仍前进、取消请求和任务领取查询仍可响应；这证明事件循环/短 DB 操作没有被扫描线程占用，但不证明 PostgreSQL idle transaction 行为。
- 使用临时 PostgreSQL 16.14 集群并将该测试连接的 `idle_in_transaction_session_timeout` 设为 700 ms；真实扫描线程在目录遍历屏障暂停 1.5 秒后，租约心跳仍前进，`pg_stat_activity` 未观察到 `idle in transaction`，Watcher 路径事件仍进入消费缓冲，取消请求正常提交。停止信号发出后任务仍等待被阻塞线程退出，释放屏障后以 `cancelled` 收尾。探针未修改 devserver 或用户数据库配置。
- SQLite 多连接屏障用例在扫描线程仍阻塞时直接调用 Agent 会话取消路由并成功返回；PostgreSQL 屏障探针向 Watcher 投递路径事件并确认事件进入消费缓冲。独立 Shell 探针验证实际 File/journal 投影。
- 取消时 `asyncio.wait_for(asyncio.shield(scan_task))` 曾产生未消费的扫描子任务异常告警；改用 `asyncio.wait` 等待完成状态后，PostgreSQL 探针及取消/超时回归均未再出现该告警。
- 冲突仍通过既有管理状态 API 可见；冲突列表与脱敏由现有管理端契约测试覆盖。

## PostgreSQL 大目录与实时链路测量

在本机独立 PostgreSQL 16.14 临时集群中，以 10,000 个同内容（92 字节）合成文件运行完整手动 `dry_run`。测试连接设置 `idle_in_transaction_session_timeout=700ms`；扫描与差异计算共 254 个独立事务，P95 1.19 ms、最大 4.42 ms。任务耗时 2.025 秒，扫描计数 10,001（含一个 `个人文件` 目录），计划新增 10,001 项；进程峰值 RSS 从扫描前 103.14 MiB 到扫描后 109.44 MiB，增量约 6.30 MiB。数字包含 Python/应用导入的固定内存基线，不外推到生产硬件。

同一隔离 PostgreSQL 集群另启动真实 TS watcher，对合成个人目录执行 Shell 创建；从 Shell 操作开始到匹配指纹的 File 与 journal 均可查询为止，端到端 458.41 ms。事件由 TS sidecar 进入 Python targeted 投影并写入 PostgreSQL；这是独立小目录探针，不代表 10,000 文件扫描期间的并发延迟。此前三次文件变更延迟来自隔离 SQLite 探针，口径和数据库不同，不与此数值合并。

这些测量补齐了本地大目录、峰值内存、实时投影端到端延迟和 PostgreSQL 事务时长的验收记录。基线与优化版的扫描器规模对比使用相同合成文件集；全流程 PostgreSQL 数据仅测量当前实现，尚无等价的旧版 PostgreSQL 全链路基准，因此不据此声称数据库全链路吞吐提升。

## 验收边界

- 本记录的 PostgreSQL 与目录数据均为本地合成数据，不代表 devserver 的实际文件分布、磁盘性能、并发 Worker 或生产流量。没有等价旧版 PostgreSQL 全链路基准，不宣称完整数据库路径吞吐提升。
- 本地临时 PostgreSQL 探针验证了空闲事务超时、心跳、Watcher 事件消费与任务取消路径；它不代表 devserver 多 Worker 或生产流量验收。
