# 文件同步重构遗留数据库结构清理

## 范围与原因

用户明确要求清理 devserver 文件同步快照重构后的数据库结构，使数据库与已恢复的开发线运行实现一致。此操作不实施 PRD-FS-7 的实时/手动任务方案，也不修复 watcher 初始化问题。

执行前代码与数据库均为迁移 `20261006000003`；旧重构表仍存在，但当前模型已不再使用。直接降级会跨过项目摘要和回收站迁移，而且旧快照迁移的 downgrade 并不删除结构，不能通过 stamp 或删除版本记录冒充清理完成。

新增前向迁移 `20261007000001`：移除 `file_sync_reconcile_runs`、`file_sync_user_scan_states` 和绑定/journal 的九个快照专用字段。保留原绑定、Journal、冲突、Outbox、File/Folder、项目摘要、回收站与既有迁移链。不使用 CASCADE；有未结束任务则拒绝执行，锁等待与语句执行均有限时。

## 备份与执行

- 使用已有 PostgreSQL 18 临时客户端生成完整 custom-format 数据库备份；宿主机 PostgreSQL 16 客户端因版本不匹配拒绝备份，未因此执行清理或更换宿主软件。
- 备份大小 137,311,789 字节，保存在 `<devserver备份目录>` 的私有目录；运行配置另存带时间戳备份，文件访问权限受限。
- 在独立 PostgreSQL 18 临时容器中实际恢复完整备份并运行同一迁移，核对关键业务表行数；成功后删除临时恢复库及其卷，完整备份保留。
- 核对远端代码摘要与本地一致；按 local skill 的精准命令重启服务，使撤回前的执行器退出并加载当前代码，之后应用前向迁移。
- 用户配置只读，未操作用户文件、快照磁盘文件或运行配置；未修改其他服务器，未推送或触发 CI。

## 验证

- 迁移前后关键表计数一致：23 用户、53,580 文件、5,400 文件夹、29 同步绑定、133,840 Journal、1 回收站任务。
