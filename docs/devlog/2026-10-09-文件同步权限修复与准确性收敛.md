# 文件同步权限修复与准确性收敛

## 范围与原则

记录跨夜的 Rootless 沙盒文件访问、后台监听、Admin 文件对账与路径归属扫描排查。仅整理权限相关修改，不回退工作区其他功能，不提交或推送，不新增数据库迁移。

准确性优先：权限助手成功、监听 ready、任务结束是不同事实。无法读取的范围不能解释为空目录，不能据此删除记录，不能宣称完整核对成功。

## 根因与修复经过

1. 沙盒 UID 在 Rootless namespace 中映射到 subordinate UID。沙盒创建的私有目录/文件采用 700/600 时，应用服务身份可能无法访问。不能用某台机器的宿主 UID/GID 常量修复。
2. 最初把递归 ACL 修复放到 watcher 注册之前，导致原本可直接监听的绑定也依赖 Docker 权限助手。执行镜像缺少 setfacl 时，大量绑定统一报权限修复失败；这是新增前置依赖造成的放大，不等于所有目录实际不可读。
3. 在执行镜像加入 acl。devserver 经明确授权构建候选镜像、备份运行配置、只调整沙盒镜像摘要，再重启既有服务。没有部署另一套应用或改变数据库连接。镜像标签与固定摘要必须一起核实，不能认为修改 Dockerfile 就更新了已运行镜像。
4. 初版助手只接受 workspace 子目录，错误拒绝用户数据根和项目绑定目录。现限定在单个 UUID 用户数据目录以内，复用解析后的路径边界；不接受全局用户根、非用户目录和越界路径。
5. 助手以沙盒属主身份修复自己创建的对象，ACL 目标为 namespace UID 0。非 root 运行时先确认本地 Rootless daemon socket 属主与应用身份一致；身份不同必须报告失败，不扩大权限或使用递归 chmod 777。
6. 全用户根中可能含应用属主的私有运行目录，沙盒助手自身无权遍历。曾按英文 find 错误文本忽略 Permission denied，这是依赖语言和错误格式的脆弱补丁，现已删除。遍历明确剪枝助手无权进入且不属于沙盒 UID 的目录；实际遍历和 setfacl 错误仍非零退出。剪枝只界定助手可修复范围，不证明监听或扫描完整。

## 最终职责

- Watcher：正常注册直接建立监听，不再强制递归修 ACL，不保存额外的“已修复根”缓存。只有真实 watcher_permission_denied 才通过 sandboxd 请求修复，随后重建监听，沿用已有重建次数上限。
- Sandboxd：复用既有受控 Unix socket，仅增加单用户目录权限修复操作，不引入另一套后台守护或状态模型。
- Docker 助手：单目录挂载、无网络、受限资源、沙盒 UID，只修复该 UID 的对象。绕开普通挂载初始化 ACL，避免权限助手启动前又被递归权限检查阻断。
- 存储遍历：普通清单与范围过滤共用一份本地遍历。目录读取错误继续上抛；仅对明确不属于 File 库的内部范围剪枝。Admin 文件对象对账不等于 workspace 全量对账，后者由对应文件同步绑定任务负责。
- Admin：真实扫描失败不生成幽灵/孤儿结论；可见错误不输出原始路径和异常，详细诊断进入受限诊断日志。保留已有路径修复的唯一匹配检查与删除前重新核实。
- Runner：权限跳过的任务以 scan_permission_denied 失败结束，可读范围已完成的投影保留，但不能把缺口清除。扫描证据在投影前失效也计为拒绝，而不是当成覆盖成功；实时监听中过期事件仍可等待后续事件补齐。

## 清理与测试取舍

- 删除注册前置修复、重复权限缓存、英文 stderr 过滤包装与重复本地清单遍历。
- 删除不参与被测行为的 mapped_uid 参数化；保留单用户根边界、daemon 身份不一致拒绝、实际助手错误返回等安全测试。
- 补充权限修复失败/重试耗尽仍保留缺口的行为测试。
- 补充真实扫描遇到权限拒绝的任务回归：允许删除时仍保留受限子树旧记录，任务失败、权限跳过计数与缺口保留。
- 扩大回归揭示手动扫描证据失效被实时事件逻辑静默忽略的问题，修正实现，不放宽断言。
- 另一个测试使用 201 个汉字超长目录，先触发文件系统单段字节上限，未进入业务字符上限验证。改为 201 个 ASCII 字符的合成目录，保留原业务拒绝及事务回滚断言。
- 结构检查报告事件处理与遍历的复杂度仍高，部分嵌套函数被重复计为克隆；不通过拆分算法、删除保护或接受全部指标来换取绿色。仅收敛已经确认的重复与无效前置依赖。

## 验证

- devserver 四个既有后台服务重启后均 active；数据库健康汇总为 13 ready、20 inactive，没有权限错误。历史同步缺口没有因权限修复或 ready 被直接清除。
- 真实 Rootless 临时目录冒烟：沙盒 UID 创建 700 目录与 600 文件，应用身份修复前读取失败，调用同一 ACL 命令后读取成功；只使用合成内容，临时文件与目录已清理。
- 文件同步回归覆盖新增、更新、移动、删除、并发变更、越界、取消、任务持久化和扫描不完整保护；权限与 Admin 对账回归覆盖范围剪枝、权限异常传播和删除前核实。
- 最终权限助手、文件同步目录和 Admin 对账回归：161 passed。补充 Rootless ACL、路径迁移、存储清理和 key 策略回归：32 passed。最后移除未使用的返回值与重复模式判断后，watcher 权限及健康状态定向复跑：5 passed（与前述范围重叠，不重复累计）。
- devserver 只读 Admin 文件扫描：1046 条 File 记录与 1046 个范围内对象匹配，幽灵 0、孤儿 0；路径归属扫描正常返回。仅扫描，没有调用修复或清理操作。
- 语法编译与 git diff --check 通过。不是仓库全量测试，也没有声称所有部署模式均通过实测。

## 后续安装与运维注意

- v1.6.0 没有当前新增的 watcher ACL 前置助手；不能把此次放大的依赖失败解释为旧版本权限模型更完整。
- acl 是实际 Rootless 私有对象修复所需的工具，不再是正常注册监听的强制依赖；旧执行镜像缺少它时，真正的修复请求应失败并保留缺口。
- 不同安装身份、daemon、文件系统 ACL 能力需要独立验收。本轮验证的是 devserver Rootless 环境，不宣称所有安装组合已实测。
- ready 只表示监听建立。已有缺口需要完整成功的核对；权限跳过、并发证据失效、范围改变或超时均不能作为完整对账成功。
