# PRD-FS-8 根目录计数架构 A/B 验证

## 验证范围

补测个人文件与回收站根目录卡片计数。Phase 3 验收后已删除原临时数据库，因此本次在本机另建隔离 PostgreSQL，按 Phase 3 的总规模重建合成数据：1,025,000 个文件、170,001 个文件夹、100 个项目。数据覆盖大量个人文件、平面目录、项目、工作区及回收站。具体数据分布按报告描述重建，并非原 Phase 3 数据库的逐行快照；不连接 devserver，不读取或改动用户数据和运行配置。

旧架构按 Phase 2 前的 `get_file_tree_rows` 行为执行：项目文件分组、项目行、个人文件总数、个人根目录计数，再加回收站根计数；新架构执行独立个人根目录和回收站计数。两边对个人根目录及回收站的结果一致。计时前做过预热，之后交替运行旧、新架构各 25 次，避免固定执行顺序造成的缓存优势。

## 结果

| 指标 | 旧架构 | 新架构 | 新架构变化 |
| --- | ---: | ---: | ---: |
| 暖机后 p50 | 177.27 ms | 47.04 ms | 快 3.77 倍，耗时下降 73.5% |
| 暖机后 p95 | 199.93 ms | 51.93 ms | 快 3.85 倍，耗时下降 74.0% |
| 最小值 | 153.08 ms | 44.31 ms | — |
| 最大值 | 206.28 ms | 54.55 ms | — |

两种架构返回的个人根目录数均为 130,000，回收站根项目数均为 85,000。旧架构执行 6 个查询，其中包含项目聚合、项目行读取和全量个人文件总数；新架构执行 4 个计数查询，只取根目录卡片需要的数据。主要收益来自删除根目录渲染不需要的旧查询和项目实体读取，计数本身仍是精确计数。

## 查询计划与实际 service 确认

- 新个人文件计数命中 `ix_files_page_created_scope`，本次计划约 19.6 ms，读取 100,000 个根目录文件对应的索引项；不是固定常数开销，计数范围随根目录文件数增长。
- 新回收站文件计数命中 `ix_files_trash_folder_page`，但还需连接文件夹以排除已删除父文件夹下的文件。本次计划约 15.6 ms，文件夹侧使用并行扫描，数据规模为 170,001 个文件夹。
- 通过实际 SQLAlchemy service 调用再次确认计数正确，单次首调约 120.1 ms，后续 25 次 p50 47.1 ms、p95 52.6 ms。首调包含连接/缓存等启动成本，不与暖机后 A/B 直接比较。
- A/B 结果是在本机隔离数据库上取得，硬件、缓存和并发负载不同会改变绝对延迟；不能直接当作 devserver 或生产延迟承诺。此次没有对 devserver 进行负载测试。

## 结论

在 Phase 3 相同总数据量级的合成数据上，新根目录计数路径保持精确计数，且相较旧树数据组装路径，暖机后 p50/p95 均约快 3.8 倍。当前结果支持保留新架构。由于新接口仍执行精确计数，具有大量根目录项目的账户仍会承担随数据量增长的查询成本；若将来需要进一步降低延迟，应另行评估异步/缓存计数及其一致性边界。

临时 PostgreSQL 实例与合成数据在验证后删除。
