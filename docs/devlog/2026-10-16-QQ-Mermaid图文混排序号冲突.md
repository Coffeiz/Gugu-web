# QQ Mermaid 图文混排序号冲突

## 现象与证据

相同 IM Mermaid 源码在 devserver 可以发送图片，业务部署却在富媒体上传成功后的消息发送阶段返回 HTTP 400。受限诊断日志给出 QQ 错误码 `40054005`：消息被去重，请检查请求 msgseq。对照新请求后，业务部署重复出现同一错误。

核对 QQ 出站、Mermaid 解析与图文交付相关的五个源码文件，devserver 与业务部署的内容摘要一致。读取计数器发现，业务部署的流式计数较低，而 devserver 已累积较高的流式计数。

## 根因

`backend/agent/gateway/qq/outbound.py` 将被动回复序号分成两套：

- 普通文本、图片使用 `qqseq:<msg_id>`。
- 流式消息使用 `qqstreamseq:<channel_id>`。

QQ 对相同 `msg_id + msg_seq` 去重，流式与普通消息接口共同受此约束。两套计数器均从 1 开始，冷计数时图前流式文字和图片会重复占用序号 1；图片发送失败后，源码回退文本与后续文字流也可能继续撞号。频道流式计数较高时，这个缺陷被已有流量掩盖。

本次证据不支持将 Redis 故障或图片消息缺少 `content` 认定为直接原因，未为这些猜测扩大修复范围。

## 修复

关联入站消息的流式首帧通过现有 `_next_seq(message_id)` 取得序号，与普通文字、图片共享 Redis 原子计数。该流的后续帧继续复用首帧序号，通过帧索引和 `stream_msg_id` 续接；没有入站消息关联的流保留原频道计数路径。

## 验证与边界

新增 `backend/tests/im/qq/test_qq_reply_sequences.py`，使用隔离 Redis 计数器和模拟 QQ 去重协议运行真实网关发送代码，不调用真实 QQ API、模型或用户存储。

- 修复前：冷计数图文混排、并发图文发送两例失败；已有流量下的一例通过，与环境差异吻合。
- 修复后：三例全部通过，覆盖图前文字、图片、图后文字和普通文本序号互不重复，以及流式首帧与结束帧复用序号。
- QQ、Mermaid 与流式回归测试 137 项通过，另有私聊流式开关回归 5 项通过，共 142 项通过。

本记录中的测试验证协议组装及状态组合，不能代替修复部署后的真实 QQ 端到端验收。业务服务器尚未部署本次修复。
