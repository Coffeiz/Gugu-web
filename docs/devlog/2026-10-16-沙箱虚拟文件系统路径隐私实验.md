# 沙箱虚拟文件系统路径隐私实验

## 目标与状态

在 devserver 的独立临时环境验证：非 root 沙箱进程直接读取 `/proc` 挂载信息时，不能获得宿主机真实目录及根文件系统镜像层来源路径。

**状态：文件系统层原型通过；独立 Docker 启动阻塞已解决；ACL 兼容问题已有 devserver 隔离修复并通过权限对照及容器验证；尚未接入应用执行器或生产部署。** 完整目录转接方案的隐私及兼容性联合验收仍待完成。这不是生产修复完成记录，也不是完整的沙箱安全认证。

## 原有泄露来源

- 原生目录 bind mount 的 `mountinfo` 文件系统根字段保留来源目录，容器内改名不能消除此信息。
- 原生 OverlayFS 根挂载的选项包含镜像层目录，可能带出宿主用户目录。
- `/proc/self/mountinfo` 不是唯一入口；数字 PID、线程和 `mounts`、`mountstats` 也需要检查。

## 实验边界与方法

- 只使用独立临时目录和合成文件，不挂载真实用户数据，不修改现有 Docker 配置，不重启服务。
- bindfs `1.14.7` 与 libfuse `2.9.9` 来自发行版软件包，仅下载并解包，没有安装系统包。
- 使用独立 RootlessKit 用户/挂载命名空间；文件系统层测试另建 PID 和网络命名空间。
- 使用已有测试镜像导出的文件系统副本，不修改镜像本体。
- 根文件系统使用 `fuse-overlayfs`，内核报告的来源名为中性标识，不显示原生 OverlayFS 的镜像层参数。
- 用户目录先在管理命名空间映射到中性来源目录，再由 bindfs 转接；最终沙箱只挂载转接文件系统，不直接挂载物理用户目录。
- 最终探针进程 UID/GID 均为 `65532`；根挂载只读，工作区挂载可写。

不能直接把 `bindfs -o fsname=...` 当成可靠的隐私配置：该版本会自动追加来源目录覆盖指定名称。实验通过管理命名空间内的中性来源挂载避免真实来源出现在名称中。正式实现必须对此行为做明确验证，不依赖路径含特殊字符这一偶然条件。

## 已验证行为

| 检查 | 结果 |
| --- | --- |
| `/proc/mounts` | 未发现宿主家目录、实验目录或 OverlayFS 层路径参数 |
| `/proc/self/{mountinfo,mounts,mountstats}` | 同上 |
| `/proc/thread-self/mountinfo` | 同上 |
| `/proc/1/{mountinfo,mounts,mountstats}` | 同上 |
| `/proc/1/task/1/mountinfo` | 同上 |
| 合成工作区文件读取、复制、改名、删除及目录创建/删除 | 通过 |
| 宿主临时来源目录与沙箱写入文件逐字节比较 | 一致 |
| 指向已存在但未挂载的宿主合成文件的绝对符号链接 | 沙箱读取失败 |
| 根挂载只读标志、进程 UID/GID | 已核对 |
| `df` / 文件系统容量 | 仍可见底层容量，本轮没有解决 |

上述路径检查共 9 个入口，只证明这些受测入口及合成目录操作的结果，不代表覆盖所有信息侧信道、符号链接并发攻击或跨用户访问组合。

## Docker 启动崩溃及解决

独立启动本机 Docker `29.1.3` 的实验 daemon 时发生 `Events.Close` 空指针崩溃。初次实验仅记录了清理阶段的栈，没有取得最初错误；后续通过系统调用 trace 复现并定位。

### 原始错误与二次崩溃

1. 手工实验绕过了官方 `dockerd-rootless.sh` 的子进程初始化步骤。
2. RootlessKit 对 `/run` 使用 copy-up 后，既有 `/run/docker` 被表示为指向宿主只读来源的符号链接。仅有独立 Docker socket、data-root 和 exec-root 仍不足以隔离插件路径。
3. 插件管理器访问并尝试创建 `/run/docker/plugins`，系统调用返回 `EACCES`。
4. `NewDaemon` 因插件管理器初始化失败而进入清理；此时事件服务还未初始化，`Shutdown` 无条件调用 `EventsService.Close()`，造成空指针，掩盖原始权限错误。

因此，该复现并不能证明 FUSE 不兼容；最初错误属于实验启动流程遗漏，二次空指针属于 Docker 当前版本的初始化失败清理路径。没有修改或替换系统 Docker 二进制。

### 实验启动修正

官方 Rootless 脚本在子命名空间解除 `/run/docker`、`/run/containerd`、`/run/xtables.lock` 的旧链接，目的是使新 daemon 在自己的命名空间创建运行目录。实验补齐这一步后，原始权限错误和随后空指针均不再出现。

操作前核对 `/run` 为本次 copy-up 的独立 tmpfs，且目标为符号链接；只解除子命名空间里的链接，不递归删除、不调整宿主目录权限。**不能在普通宿主 Shell 中照抄这类清理命令。** 后续实验优先使用官方版本匹配的 Rootless 启动脚本，避免继续手工漏掉初始化步骤。

### 修正后验证

| 独立 daemon | 验证结果 |
| --- | --- |
| 默认 containerd OverlayFS | API 就绪，报告 rootless，导入合成测试文件系统并运行 UID/GID 65532 容器成功 |
| fuse-overlayfs（独立数据目录，关闭 containerd snapshotter） | API 就绪，报告 rootless，导入并运行同样的非 root 容器成功 |
| fuse-overlayfs 容器根挂载 | `ro`，来源为中性 `fuse-overlayfs`，没有原生 OverlayFS 的层路径选项 |

冒烟容器均启用 `--network=none`、只读根、`--cap-drop=ALL` 和 `no-new-privileges`，没有挂载业务数据。此验证只解决 daemon 启动阻塞并确认根挂载；Docker 自动生成文件及用户目录转接的完整验收尚未完成。

没有切换现有 daemon 的存储驱动，没有向既有 daemon 注册实验运行时。Shell、PTY 和 MCP 仍使用原有实现。

## 接入前必须完成

1. 独立 Docker 启动失败已定位并解决；接下来取得完整真实容器的路径隐私测试结果，同时覆盖根文件系统、用户目录和 Docker 自动生成的 hosts/hostname/resolv.conf 挂载。
2. 明确 external 与 embedded 管理器的 FUSE 权限、依赖来源和启动生命周期；不得向用户执行容器开放 Docker Socket 或挂载管理权限。
3. 补充跨用户隔离、只读授权、符号链接及并发重命名、撤销授权、进程退出和异常卸载测试。
4. 验证文件同步监听、双向修改可见性、缓存一致性、锁、mmap 和权限语义；当前顺序读写测试不足以证明兼容。
5. 测量 FUSE 对构建/测试及大量小文件操作的成本，再决定存储驱动和部署方案；不得直接迁移现有 Docker 数据目录。
6. 经真实 Docker 执行器验证后，再分别验收一次性 Shell、交互 PTY 与长驻 MCP stdio。容量、内核和出口地址隐藏属于后续独立目标。

## 生产环境候选验证：ACL 阻断切换

上述清理结论对应 devserver 原型。后续在业务服务器另建了独立候选 daemon：安装了发行版 `bindfs` 和 `libfuse2t64`，没有升级 Docker 或重启现有 daemon。现有环境已经使用官方 Rootless 启动脚本，无需重复修正上节的实验启动遗漏。

候选使用 Docker `29.8.0`、独立 socket 和新数据目录，由官方脚本通过可信 child hook 创建用户目录、运行时目录的中性 FUSE 转接视图，再启动 fuse-overlayfs daemon。仅导入已有的最小测试镜像，并挂载合成临时目录，没有挂载真实用户数据。

| 对照检查 | 结果 |
| --- | --- |
| 同一合成目录，原生绑定挂载，UID/GID 65532 | ACL 允许写入，检查退出码 0 |
| 同一目录，同一执行 UID/GID，bindfs 转接 | 写入检查退出码 1，实际创建文件返回 Permission denied |
| 候选容器 9 个 `/proc` 入口 | 路径检查通过，包括容器自动生成文件的挂载信息 |
| 完整合成文件操作探针 | 在文件创建时退出码 2，未通过 |

这是生产部署阻断项：不能以目录可见、路径隐藏或 daemon 启动成功代替 ACL 契约。不得通过整树 chmod/chown、强制改文件属主或直接挂回原始路径将其报告为成功。候选验证使用实时 `/proc/<rootless-child>/uid_map` 解析目标 UID；现场存在多段映射，不能只取 `/etc/subuid` 第一行计算。

本轮没有切换业务 manager 的 socket、来源映射或现有 Rootless 存储目录；没有修改用户配置、数据库或用户文件。下一步必须先解决并验证 ACL 保真转接，再完成跨用户、只读、文件同步和应用入口验收。候选不能作为后续生产默认配置直接启用。

候选 daemon 已停止，临时文件系统及探针已移除；原 Rootless daemon 和出口代理仍运行，业务容器未重启，网站及站点配置 API 均返回 HTTP 200。新增的两个发行版依赖保留，未启用任何新的持久服务。磁盘余量约 8.8 GiB；与创建候选前的小幅差异包含正常运行期间的写入，不能将其归因为用户数据变化。

## devserver 隔离 ACL 修复

后续已在 devserver 的全新合成目录和独立 RootlessKit 命名空间复现原版 bindfs 的拒绝行为，并在相同 bindfs 1.18.3 / libfuse 3.14.0 的 A/B 构建中验证修复；没有替换系统程序、读取用户文件或操作生产配置。

根因有两层：未协商 `FUSE_CAP_POSIX_ACL` 导致内核按 mode 位拒绝命名用户；只开启该能力又会因创建请求提前应用 umask 而破坏默认 ACL。实验修复协商 ACL 与 DONT_MASK，单线程创建回调临时使用调用者 umask，由底层文件系统处理默认 ACL，随后恢复原 umask。实验模式拒绝 UID/GID/权限变换和多线程；不通过放宽文件权限恢复写入。

文件系统层回归通过：授权与拒绝、命名组、只读 ACL、mask、保留 mask 的外部撤销/重新授权、属主 ACL 更新与非属主提权拒绝、普通 umask、文件属主、文件/目录/FIFO 默认 ACL 继承和只读挂载。独立 Rootless Docker 对照确认原版拒绝写入，修正版允许创建；未授权和只读身份仍拒绝写入，容器实际新建/改名/删除也通过。

探针中两类误判已修正，权限预期没有放宽：目录写权限必须以新建操作验证，不能覆盖已有文件；ACL 提权必须实际改变权限，不能把写回相同值当作一定会发出变更请求。默认 ACL 的读取用例必须同时授予父目录穿越权限。

可复现的[实验补丁与回归脚本](../../scripts/ops/sandbox-acl/README.md)已保存，未提交。生产仍使用原配置；该修复消除了已复现的 ACL 阻断，但完整转接服务、文件同步、并发安全及应用入口尚未联合验收，不应直接宣布生产路径隐私已完成。

本轮实验 daemon、FUSE 挂载、导出容器、构建依赖解包和合成数据均已清理；未安装系统包或替换系统程序。devserver 四个原后台单元仍为 active，后端健康检查返回 HTTP 200。
