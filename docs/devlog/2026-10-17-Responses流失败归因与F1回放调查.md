# Responses 流失败归因与 F1 回放调查

## 改动

- 为 Responses 流内失败增加独立异常类型，共享错误描述器向 Web 和所有 IM 返回一致的上游流错误及诊断编号。
- 识别通用 `error` 事件，避免失败被当作空的成功回复；保留流关闭语义。
- 上游失败详情只写受限诊断日志，用户错误不带上游正文。
- 增加仓库外真实 trace 的单请求诊断脚本；显式允许真实数据与模型后才能运行，不执行模型返回的工具。

## 调查结论

对比同模型的 10 轮工具操作、4 次 MCP 调用与两次 QQ F1 故障。正常 PR 请求的完整 359 条 conversation 消息是失败请求的精确前缀，固定 system 与历史 Skill 相同。103 组工具调用结构完整，未发现重复 ID 或非法参数 JSON。

重建请求最初 3 次流式失败，后续同请求成功 1 次；非流式两次完成单轮响应。未证明 F1 Skill、timeout 或多轮调用是固定触发原因，不能宣称出图全流程已修复。详细方法、结果及限制见[调查报告](../reports/2026-10-17-INVEST-F1工具轮Responses失败.md)。
