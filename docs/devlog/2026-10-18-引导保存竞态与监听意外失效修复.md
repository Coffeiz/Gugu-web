# 引导保存竞态与监听意外失效修复

## 问题与修改

- 引导进度保存虽然串行，但旧响应仍可能覆盖更新的本地步骤与完成列表。为每次排队操作记录递增版本，仅最新版本的响应允许回写本地状态；后续保存仍按原顺序执行。
- Linux `IN_IGNORED` 原先只清理描述符。主动解除监听已经预先移除订阅映射，因此事件到达时仍有订阅即表示意外失效；向每个订阅绑定报告 `watcher_watch_lost` 错误，复用上层健康缺口与重建路径。该错误不属于允许自动删除的队列溢出类别。

## 验证

- 新增引导时序测试：A 请求期间进入 B，A 响应后继续进入 C，保留本地进度及全部已完成步骤。旧代码回退到 A，修复后通过。
- 在临时目录使用真实 inotify，直接从内核解除共享 watch：旧代码没有任何缺口事件，修复后两个绑定均收到错误；重新注册后两个绑定都继续收到变更，主动解除不误报。
- 未执行文件系统卸载；真实描述符失效测试验证 `IN_IGNORED` 处理路径，不声称已覆盖所有挂载设备场景。
