# 搜索成本边界与迁移部署说明修复

## 问题

- PR 部署说明沿用旧范围，错误声称无数据库迁移；搜索更新实际新增 BYOK 联网搜索开关列，并迁移旧工具授权和技能快照。
- 免费 XNG 网络失败时隐式调用付费深度研究，违背工具分工和成本预期。
- Provider 原生搜索结果未在适配层设定大小预算，可能引入过长正文。

## 修复

- PR #103 明确要求执行 `alembic upgrade head`，确认 revision `20261018000001`，说明镜像入口和分离部署更新脚本会自动迁移，手动部署需显式迁移。降级会丢失新增开关，并不能精确恢复原始工具引用，精确恢复依赖备份。
- XNG 失败只返回错误，不自动调用付费研究；模型可依据任务需要另行选择搜索工具。
- 六家 Provider 共用流式响应读取：拒绝超过 2 MiB 的响应（包括解压后的正文），上下文结果预算为 64 KiB UTF-8 JSON、单段文本 8,000 字符、每个数组 20 项。保留原生字段；状态和计费元数据优先保留；链接保留完整值或省略，不截成错误地址。超限结果带明确截断说明。
- 百炼 Responses 默认输出 1,200 Token，MiMo 默认 1,024 Token，两者最多 2,048；百炼 Chat 固定最多 1,200 Token。继续使用各家原生参数。响应截断不退还已发生的搜索和模型费用，也不限制供应商内部执行次数。

## 验证

- devserver 串行运行搜索 HTTP、Schema 隔离、历史切换、预算、XNG 错误和迁移辅助回归，58 项通过；真实 PostgreSQL 迁移测试另 1 项通过。
- 真实 PostgreSQL 验证当前迁移函数升级→降级→再次升级，包括新增列非空约束、默认值、JSONB 默认值、授权及快照转换。使用随机临时 schema 和合成记录，在事务结束后回滚清除；不修改业务表或运行配置。此项不等同于完整历史迁移链的发布演练。
- HTTP 使用模拟上游，不消耗真实 Provider 额度；未触发 GitHub Actions。
