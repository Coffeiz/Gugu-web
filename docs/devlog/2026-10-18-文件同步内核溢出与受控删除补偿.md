# 文件同步内核溢出与受控删除补偿

Linux 大量文件删除期间暂停 watcher，可触发内核事件队列溢出。原 TS `fs.watch` 链路未上报溢出，之后仍能接收新事件，文件库却可能长期保留遗漏记录。

## 实现

1. Linux 使用标准库原生 inotify sidecar，保留现有协议与 Python supervisor；其他系统仍使用 TS watcher。
2. 显式上报内核溢出并持久化缺口；ready 不再覆盖已知溢出原因。
3. 已知溢出修复可在根身份、完整扫描、路径缺失及对象版本均有效时软删除记录；权限排除、空根及身份不匹配保持保护。
4. 入队元数据保存监听根的设备与 inode，进度和重试继续保留；已有任务不被强行升级权限，后续补偿复用旧身份。
5. 原生扫描不跟随越界符号链接；普通文件删除避免整树遍历。

本次契约调整仅允许有明确溢出证据及原根身份的自动补偿删除，不把所有周期核对改成允许删除。不修改用户运行配置，不执行真实工作区的手动批量清理。
