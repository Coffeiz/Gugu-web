# 文件同步缺失记录批量确认

## 问题与契约调整

原管理端只要发现本地缺失冲突就禁用全部通用批量按钮，缺失记录只能逐项确认。大量 Shell 删除事件遗漏后，管理员无法高效处理残留。

新增入口直接放在“待处理冲突”的现有批量操作栏，不创建第二个业务区域。按绑定预览当前真实缺失的文件记录，确认弹窗显示精确数量及前五项样本；明确确认后每批最多 25 项执行，并显示完成、跳过与未处理数量。取消只停止后续批次，不回滚已经完成的批次。

## 后台边界

- 预览只枚举目标绑定、目标归属用户的待处理本地缺失冲突及匹配的活动文件记录，不受页面列表截断影响；超过 5000 项拒绝预览。
- 分批提交必须显式确认；根路径身份、设备与 inode 身份、冲突更新时间、文件 ID、版本及存储路径均需匹配预览。
- 每项重新检查物理路径仍然缺失，恢复文件、变更对象、替换根目录和跨用户伪造项不会被应用。
- 复用已有逐项确认删除逻辑、回收站状态、journal、配额和 outbox；只软删除文件库记录，不删除物理文件。
- 自动监听和自动补偿的删除权限保持原契约。此功能解决管理员批量恢复，不代表内核事件溢出问题已修复。
- 无 schema 或运行配置变更；不自动处理真实已有冲突。

## 验证

- 后端：临时 SQLite 验证真正缺失项软删除、恢复项和版本变化项保留、根替换拒绝、跨用户隔离、冲突变化跳过及确认门。
- 前端：确认取消不提交、按预览快照每 25 项分批、展示跳过结果；更新管理面板行为断言，确保新入口位于同一批量操作栏，原通用批量操作在缺失场景仍被限制。
- 管理页面既有回归、字段标题交互扫描、完整 typecheck 与 strict typecheck。

回归用例分别保护用户可观察行为和后端隔离边界，不使用源码字符串断言。
