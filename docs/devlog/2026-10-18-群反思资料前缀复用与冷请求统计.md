## 变更

- 群与成员反思：已有记忆资料 → 各自任务规则 → 本批范围。保留所有字段与原文，成员名单仍不进入模型输入；不改变 scope、历史、主请求工具声明和结果写入。
- 私聊 `private-owner` 与 owner 快照路径保持原顺序。没有持久化完整运行时快照，没有新建预热请求或改动闲置调度。
- 用量 API 的日／周／月场景聚合新增 `cold_calls`、`warm_tokens_in`、`warm_cache_ratio`，复用已有日期、BYOK、开发者筛选与历史完整输入口径；无需数据库迁移。
- 冷请求定义为有完整输入且 provider 缓存读取为 0 的成功调用。这是可观测统计分类，不据此断言请求低命中的原因。无输入的 MCP 工具计数不算冷请求，微量命中仍算非冷请求。
- 非冷缓存率 = 缓存读取 tokens 合计 / 非冷请求完整输入 tokens 合计。无非冷样本返回 null，前端显示“—”；不平均逐请求百分比，也不把 cache_write 当作 cache_read。
- 将场景表从 `UsagePanel.vue` 拆为 `UsageScenarioTable.vue`，展示两个新指标及口径说明；保留原总缓存率。新增组件使用语义设计 token，表格在窄屏可横向滚动。只有主对话时也展示场景统计。
- 更新中、英、日三种界面文案和 backend skill 的缓存布局约定。

## 限制

真实缓存率由 provider 决定，可能发生缓存不可用或尚未可读的波动。本轮只改变共同资料和任务规则的顺序；不承诺首次冷重建命中率，也未把内容完整性测试当作长期记忆质量评估的替代。

共同资料置前的收益还取决于两次任务之间资料是否变化：生产任务会重新读取最新记忆；若前一个任务写入了新记忆，公共前缀可能缩短。不会为提高缓存率冻结或复用过期记忆。真实 A/B 使用同一份资料验证顺序这一单独因素，不等同于生产任务写回后的固定命中率承诺。
