# Web 聊天历史向上分页

## 原因

会话保留服务最多保存 2000 条数据库记录，但 Web 首屏只请求最近 50 条正文。旧实现只有搜索跳转的定向历史请求，没有接入顶部连续分页；虚拟滚动只能渲染已在内存中的消息。数据库上限包含工具和摘要记录，不等于 2000 个正文气泡。

## 修改

- 独立 composable 管理旧页游标、在途状态、错误和视图代次。接近顶部时读取更早的 50 条，复用时间线映射、身份去重和排序；顶部可手动加载或在失败后重试。
- 失败不触发自动请求循环，空页或明确无下一页后停止。切换会话、同会话重载和卸载后丢弃旧响应，分页游标与搜索跳转窗口分离。
- 虚拟列表复用稳定消息 key 的锚定，补入旧页时保留当前阅读位置；窗口过渡期间仍由窗口域负责尺寸锚点，不启用自动跟随新增消息。
- 旧页接口统一返回旧到新的顺序，修正 oldestId/newestId 及 hasMore 的方向语义。分页间正文之外的工具结果随旧页归属，避免落入两个窗口之间而丢失。
- 未改变数据库保留上限或模型上下文窗口。

## 验证

前端覆盖逐页游标、身份去重、单请求、失败重试、空页、同会话重载、会话切换及卸载；聊天域测试 98 项通过，随后补充的两项边界另行通过。后端消息 API 46 项通过，包含连续读取到最早记录、跨页工具配对和所有权边界。完整及严格 TypeScript 检查通过。

devserver 页面验证连续上翻能取回更早消息，新增旧页后仍保持虚拟渲染；后续异步布局中当前可见记录和位置保持稳定。原始消息与真实环境细节不写入仓库。
