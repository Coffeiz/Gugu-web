# 群被动消息反思触发策略

## 决策与原因

按 [ADR-0003](../adr/0003-群反思按主动闲置与消息压力触发.md) 分开被动消息记录、主动闲置和上下文压力。保留全群累计 50 条触发群组/群友反思；被动消息不再启动或续期 4 分 30 秒闲置。私聊策略不变。

此前的 [TTL 与长间隔缓存调查](../reports/2026-10-19-INVEST-记忆反思闲置TTL与长间隔缓存调查.md) 描述旧策略和当时建议；新策略是后续产品决策，不是该调查已证明移除被动 TTL 会改善缓存。

## 实现边界

- 群游标以主动 run 完成时间计时，持续被动消息不会延迟收束；旧扫描按版本与活动时间校验，避免清掉新 run 的窗口。较晚完成的旧回合不能倒退消息水位。
- owner 群缓冲显式接收 `passive` 标志，保留记录及条数/压力冲刷，不为被动记录登记或重置 idle。已有任务和失败重试保留。
- `group_pressure.py` 在被动入库事件上复用模型配置、历史重建与共享预算；无需等待 50 条，达到 90% 即创建持久反思任务。按作用域加锁、按两类在途任务去重，不新增模型轮询。
- 压力入口的被动正文已经在重建历史中，不再次作为 current turn 累加；增加真实预算的短/长正文对照，防止因重复计数而过早触发。
- 压力任务以及末条为被动消息的群任务不能复用旧 run 的 usage/已压缩标志。执行器重建当前历史，走现有 `compact_for_reflection`；需要时先压缩、重建，再反思；无法安全压缩则延后，不发送超预算反思请求。
- 没有新增数据库字段，未修改运行配置、历史保留上限、provider 缓存标记或反思模型指令。没有当前请求实际用量的静默预检标记为 `estimate`，不冒充 provider usage。

## 验证

使用 devserver 的独立 pytest 进程串行运行，内存 SQLite、fake Redis、合成用户/消息及模型替身。未连接真实 provider、未调用真实反思模型、未修改用户数据库或存储。

测试入口：

- [群触发策略回归](../../backend/tests/im/test_group_reflection_policy.py)：被动不建/续期 TTL，主动时钟，水位不倒退，旧扫描与新 run 交错，89.9%/90%/90.1% 压力边界，真实被动记录入口生成任务，先压缩后反思及受阻延后。
- [既有 IM 作用域测试](../../backend/tests/im/test_im_memory_scopes.py)：保留 50 条双任务和私聊策略；更新旧的“任意群消息重开闲置”预期，以反映本次明确的契约变化。
- [反思阈值测试](../../backend/tests/agent/context/test_reflection_threshold.py)：被动 owner 缓冲仍受共享群阈值冲刷，不采用私聊阈值。
- [压缩测试](../../backend/tests/agent/context/test_compaction.py)：实际 provider 用量优先、缓存输入计入、90% 边界及无用量估算保持有效。

运行命令（在 `backend/`）：

```bash
PYTHONPATH=. .venv/bin/pytest -q tests/im tests/agent/context --tb=short
```

扩大回归输出保存在 devserver 临时目录的 `gugu-group-policy-regression-final.log`，未提交，暂留复查；针对性最终复跑结果见下。未重启运行服务。不运行真实模型缓存对比脚本，不以隔离调度测试宣称命中率提升；本次没有变更缓存请求标记，线上调用数、预检耗时与缓存收益仍待部署后观察。

验证结果：

- 本轮策略、既有 IM scope、反思阈值、压缩、失败生命周期、追加复用和 owner 缓冲七个测试文件，最终 **166 项通过**。
- 全部 `tests/im` 与 `tests/agent/context` 扩大回归为 **933 项通过、2 项失败**。该轮后补充了短正文不重复估算的参数化场景并完成上述针对性复跑。失败为 `test_cache_drop_probe.py::test_reflection_cache_observation_is_attached_to_an_active_trace` 和 `test_context_branch.py::test_reflection_provider_usage_is_added_to_active_trace_without_prompt_text`：并行改动将观测统一写入独立 reflection trace，原用例仍要求写入当前 run。本次未修改该观测实现或放宽这两项断言，扩大回归不宣称全绿。
- ownership、确认门、修改模块语法及新增测试元数据检查通过。
- 最终作用域静态质量检查为零阻断、九项轻微提示，主要是既有长函数的少量复杂度/参数增长，没有添加豁免。作用域外的并行改动仍有其他告警，不宣称全仓质量全绿。实际调用契约检查中群观察入口签名未变，owner 调度新增默认关闭的 `passive` 参数保持旧调用兼容。
