# IM 即时反馈（ack）误删恢复

## 现象

分支整理时把 IM 的「即时反馈」整块删掉了，用户侧表现为：

- QQ 发了文件过去，机器人一声不吭，连「收到了」都没有；
- 飞书发消息后没有秒回表情，用户只能干等完整回复；
- QQ 附件下载失败时彻底静默——附件丢了，用户既看不到秒回，也看不到任何错误提示。

## 根因

提交 `3ac787dcb`（标题是「功能：增加 IM 工具展示偏好与权限迁移」，与 ack 无关）删除了三处：

1. `backend/agent/gateway/qq/events.py` 的附件秒回：`_ACK_COOLDOWN = 10.0` 常量、`_qq_ack` helper、`_handle_raw_qq_message` 的 `last_ack` 参数，以及「文件收到啦，让我看看~」的发送块；原函数 `_qq_ack` 被改名为 `_qq_reply`，`last_ack` 状态从 `qq/runtime.py` 一并移除。
2. `backend/agent/im/shortcuts.py` 的整个 `choose_instant_reaction()`：`_QUICK_REACTION_RULES`（9 类关键词规则）、`_QUICK_DEFAULT`、`_QUICK_MEDIA` 一并删除。
3. `backend/agent/gateway/feishu/events.py` 的秒回表情：`_EventServices` 的 `do_react` 字段和入队前的 `services.do_react(...)` 调用。

用 `git show 3ac787dcb^:<path>` 逐文件比对确认：这几个文件在 `3ac787dcb` 之后没有再被改动过，删除范围与 ack 边界完全重合，没有夹带其他逻辑。

## 恢复范围

按确认的方案恢复，**放回原位置（gateway 层）**，不搬到 worker：

- **通用即时反馈选择器** `choose_instant_reaction(text, has_media)`：连同 9 类关键词规则、默认档、媒体档逐字恢复。返回的 emoji 取自飞书官方 `emoji_type` 词表（`LAUGH`/`THANKS`/`DONE`/`WOW`/`CRY`/`PARTY`/`THINKING`/`OnIt` 均在列），可直接用于 reaction，不需要额外映射。
- **飞书秒回表情**：`_EventServices` 加回 `do_react` 字段，`feishu/runtime.py` 补注入 `messages._do_react`，事件处理在入队前调用一次 `services.do_react(...)`。
- **QQ 附件秒回**：`_ACK_COOLDOWN = 10.0` 冷却、`last_ack` 状态挂回 `qq/runtime.py` 并透传给 `_handle_raw_qq_message`、发送块按「群聊策略 + 冷却窗口」判定。
- **QQ 附件下载失败提示**：原本 `if size == 0: continue` 直接丢弃，现在记账为下载失败，回填 `MediaIngressResult.failure_notice`，由 `agent/im/dispatch.py` 的 `send_text` 发回用户。下载失败与暂存失败分成两条提示，因为两者的用户动作不一样（重发 vs 等一下）。

**明确不加回的部分**：

- QQ 文本秒回——私聊路径支持 Markdown 流式输出，插入一条文本会打乱流式消息序列；
- 微信 / Telegram 的 ack——保持各平台现状，不在本次范围内。

## 实现取舍

- 保留现名 `_qq_reply`，不为了对齐历史把名字改回 `_qq_ack`。秒回块接回这个 helper 即可，省掉一次无谓的全量改名（`_qq_ack` 在该文件里有 9 处调用点）。
- `_qq_reply` 的注释从「只发送取消、绑定等答复」扩成同时覆盖「附件秒回提示」和「取消/绑定确认」两种语义，避免后来人误以为秒回走的是另一条链路。
- 秒回和正式回复共用同一套 QQ 出站，序号由 `qq/outbound.py` 的 `_next_seq`（Redis `INCR qqseq:{msg_id}`）统一发号，恢复 ack 不会和正式回复撞号。
- `agent/im/dispatch.py` 里「下载失败」和「超限」两条提示各自带一个提前返回，会互相遮蔽：先发的提示把 `return None` 触发后，后一条就发不出去了。改成两条提示都先发、判空放到最后，两种情况同时出现时用户能收到完整的两条。

## 经验与约束

- 功能删除前必须把受影响的完整链路列出来：选择器、状态挂载点、平台适配、测试签名、文档。这次连带着 `last_ack` 状态和 `_EventServices` 字段一起被删，说明删除时没有逐项核对「谁在用」。
- 恢复历史实现时，先用 `git show <ref>^:<path>` 逐文件比对，而不是凭记忆重写——本例中 `feishu/events.py`、`feishu/runtime.py`、`qq/runtime.py` 三个文件恢复后与历史版本**逐字一致**，`qq/events.py` 仅差一处有意保留的改名。
- 但「逐字恢复」不等于「原样上线」：本次就发现历史实现把内部情绪 key 直接当飞书 `emoji_type` 发出去。恢复时必须查证外部平台的取值域，否则默认路径（未命中关键词 → `OnIt`）会一直失败。这里查证结果是 `OnIt` 确实在官方词表内，因此**不改**，并补了一条守卫测试把这条约束固化下来。
- 附件类入口必须有失败提示。下载失败和暂存失败要分开表述——用户对这两件事的下一步动作不同。
