# 实时展示与持久历史统一交接

## 原因与范围

旧流程将数据库展示行、流式临时气泡和 Redis token 快照分别组装：时间可能在重放时生成，排序由客户端末尾自增，正文缺少轮次身份时还依赖前缀匹配。结果是运行中刷新后重复气泡、全部显示刷新时间、正文被移到工具后面，或终态只能刷新后看到。

本次统一 Web、QQ、飞书、Telegram 的**展示事件**，不改变模型 canonical 历史、Provider 请求、QQ 最终消息的主动交付策略和工具实际执行。

## 新契约

- 展示事件首次产生时固定 `eventId`、`runId`、`roundId`、`anchorMessageId`、`sequence`、`createdAt`；更新只推进 `updatedAt` 和正文/工具状态。
- `timelineOrder = anchorMessageId × 1,000,000 + sequence`。正文、工具、文件和链接卡共用一个 run 内递增序号；并行工具完成顺序不会改变首次出现的位置。
- 首次出现、工具状态变化和轮次边界保存展示检查点；连续正文更新最多每秒一次检查点。流式展示不等待每个 token 单独写数据库，不复制媒体正文到检查点。
- 实时通道统一传递 `display_event` 的完整事件当前值。Redis 和前端都按 `eventId` 原位更新；重放与实时消息使用同一协议，不额外生成时间、身份或排序。
- 成功收尾在事务内更新同一检查点为最终展示历史，再发布终态。失败/中断也封存展示检查点，但不把部分工具执行写成成功的模型历史。
- 网页收到终态后按目标 run 查询历史，原位接替该 run 的临时展示。重复通知幂等，不影响下一轮输入或其他 run。
- 重连先校准最新历史窗口，再补自增消息增量。这样同一检查点行的原位修改不会被 `after_id` 漏掉。旧检查点晚到时按 `updatedAt` 拒绝覆盖新事件。

## 本版本迁移与清理

Alembic revision `20261023000001`，前置版本 `20261022000003`。按会话迁移，PostgreSQL 事务内锁定消息写入。所有旧展示项一次性补齐稳定事件身份、锚点、序号和时间；普通历史助手正文/附件转换为展示事件。重复执行不改变结果；正文、模型上下文和附件引用不改写。

历史未记录的实际产生时间不可恢复，使用原消息记录时间，不声称是精确执行时间。缺失身份使用确定性的迁移身份，不在运行时猜测。

已删除：旧 Redis 累计正文/工具快照恢复、正文前缀匹配、按 run/round 猜气泡身份、工具/正文各自追加的临时列表组装、Web 单独的跨轮正文前缀去重。原始工具完成事件只保留文件预览和资源失效等副作用，不再构建第二份气泡。

旧 Alembic revision 及其迁移测试仍保留，以支持从早期数据库顺序升级；它们不是运行时兼容路径。迁移前必须排空旧任务并备份数据库，前后端同步升级后刷新已打开页面，不支持新旧流协议混跑。

本次 revision 明确拒绝空操作降级；需要回退时恢复升级前备份并同步部署旧版前后端，不允许只回滚代码继续混用排序协议。
