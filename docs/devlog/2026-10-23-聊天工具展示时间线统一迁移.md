# 聊天工具展示时间线统一迁移

## 问题与证据

旧接口同时读取展示时间线和 canonical 工具记录，前端也分别映射这两种事件。展示时间线保存执行时的真实耗时；canonical 记录用于模型上下文，可能在收尾阶段批量提交，行时间不能代表工具执行时间。两条路径跨分页后可能形成不同身份的重复卡片。

本次移除运行时双通道，而非继续追加跨页查重查询。缺少原始执行计时的历史工具不再依据数据库行时间推算耗时。

## 实现

- `backend/agent/context/display_timeline.py`：保留写入期工具状态合并，新增统一收尾，固定工具身份；收尾时尚处于排队/运行状态的工具记为中止，不伪装成成功。
- `backend/agent/context/run_finalize.py`：复用上述收尾，继续复用现有媒体剥离与 run 发起消息排序锚点。
- `backend/agent/context/history.py`：移除聊天展示事件重建职责，只保留模型上下文处理。
- `backend/app/api/v1/agent_routes/sessions.py`：分页只读取正文与持久展示列；canonical-only 行不消耗展示分页窗口。工具详情仅按展示消息和事件索引读取，继续校验会话归属。即使展示列挂在历史 canonical 行上，也不把该行的大模型正文载入请求内存。
- 前端移除 `toolEvents` 映射、canonical 详情来源和旧 Adapter 参数解包。首屏、分页和流恢复都消费同一展示协议；工具身份继续使用 run、round、toolCallId。中止状态沿用现有状态样式令牌并补充三种语言文案。

没有删除 canonical 模型历史，也没有修改用户运行配置。执行器收集的 `tool_events` 仍服务于执行结果判定，与已删除的聊天 API `toolEvents` 不是同一个职责。

## 本版本升级

Alembic revision：`20261022000003`，接在 `20261022000002` 后；无版本旧库也通过既有兼容升级入口执行一次转换。空库没有需要补建的历史数据。

迁移逻辑位于 `backend/app/db/migrations/chat_timeline.py`，只供版本升级使用，不由聊天请求导入：

1. 按会话处理，按 run 分组；无 run 身份的旧记录按实际用户输入边界隔离。
2. 解包旧 `call_tool` 名称和参数；补齐可确认的 round、输入、结果和终态。
3. 按调用身份合并跨行重复展示，保留执行时记录的耗时。
4. 只有 canonical 记录的工具生成一次展示事件；优先放到同 run 最终回复前。缺少 run 关联时保留原记录位置。
5. 补齐旧时间线遗漏的助手附件，剥离媒体载荷；canonical 原文不变。
6. PostgreSQL 事务内锁定消息写入，迁移失败整体回滚；重复执行不继续改写数据。

降级不恢复重复卡片。发布需要前后端同步升级；旧的 canonical 详情协议已删除，没有保留运行时兼容分支。

## 验证

- 后端定向回归：124 项通过，覆盖迁移、真实数据库升级操作、幂等、历史分页、工具详情归属、模型上下文、run 收尾与取消排序。
- 前端完整单测：184 个文件、935 项通过；其中聊天域 22 个文件、100 项通过。
- 前端 typecheck、typecheck:strict 和生产构建通过；构建仍提示既有大 chunk 和动态导入告警。
- devserver 数据迁移：41,698 条消息保留，34,278 条 canonical 记录的内容校验前后一致；重复工具身份数为 0，第二次升级展示列校验值不变。
- 对问题所在历史会话逐页读取：20 页、1,236 个唯一工具事件。目标回复关联的 14 个工具均保留计时、详情全部可读取；无未命名工具和运行中残留。这是 API 分页与详情读取验证，不是浏览器滚动验收。
- 后端健康接口与前端页面均返回 HTTP 200。

## 备份与执行过程说明

devserver 热重载在预定备份步骤前自动执行了初版迁移。后续修正执行前，已对全部消息的 ID 与展示列进行数据库原生 COPY 备份，并保存记录数和 SHA-256；已向临时表恢复验证 41,698 条记录。备份位于 devserver 的受限持久备份目录，不进入 Git，也不清理。

因此，这份备份对应初版转换后的展示数据，不是最初升级前的完整数据库快照。canonical 原文始终保留；后续修正版迁移前后均检查消息总数和 canonical 内容一致性。部署到其他环境仍应在升级前按既有发布流程备份。

## 边界

- 历史计时没有记录就不能恢复；界面留空，不制造 `0ms`。
- 旧数据若没有 run/round，且同一用户输入边界内重复使用相同调用 ID，不能凭空重建已经丢失的调用身份。
- 已丢失的工具名称、结果不能凭空补回；有 canonical 证据时才恢复。
- 保留既有的大时间线读取尺寸保护；本次不重做超大消息分页或详情存储结构。
- 用户已打开的页面可能仍缓存旧事件，验收前需刷新页面，再向上加载历史并展开工具。

## 后续优化：工具详情一次展开

工具卡片此前在请求详情的同时展开，动画先测到加载提示的高度，正文返回后又发生一次高度变化。现在未缓存详情先保持折叠，超过 150ms 后通过卡片描边呼吸动效反馈，工具状态和耗时不变；数据就绪后才触发展开，缓存内容直接展开。减少动态效果模式使用延迟出现的静态描边。等待时再次点击可取消展开意图，在途请求复用；失败后点击标题重试。虚拟滚动卸载或切换消息后，晚到响应不会操作旧卡片。

复用既有详情接口、消息缓存、展开状态归属和高度动画，没有引入滚动预加载。新增 6 项组件行为回归，聊天域共 106 项通过。
