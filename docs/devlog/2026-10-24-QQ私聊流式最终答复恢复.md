# QQ 私聊流式最终答复恢复

## 问题与原因

QQ 私聊 Markdown 的调度路径曾改为收集模型输出，最终统一走普通回复出口，导致消息不再逐字流式显示。原本为避免长任务最终消息丢失而采用的独立最终投递策略，后来 QQ 出站路径已调整为被动回复优先、失败时主动消息回退；但调度层仍未恢复流式 sender，造成流式功能一直未生效。

## 改动

- 恢复 QQ 私聊 Markdown 最终正文的流式发送，并继续将实时模型事件镜像至 Web。
- 仅当流式正文确认交付后，最终收尾跳过重复文本；附件仍由统一最终发送流程处理。
- 没有入站消息 ID、流式传输失败或未送达时，交给普通回复出口按现有被动优先/主动回退策略发送。
- 流式文本回退失败时向上报告，不能把未送达的尾部标记为成功；移除不再使用的收集型路径。
- 更新 ADR-0009，明确私聊、群聊、错误终态与取消任务的边界。

## 验证与边界

devserver 串行运行 `tests/im`，605 项通过，另有 2 条第三方 SDK 警告。QQ 最终交付定向回归 45 项通过。覆盖流式成功不重复发送、缺少入站 ID 的普通回复回退、回退失败不误报成功、错误终态、取消及群聊路径。未向真实 QQ 发送测试消息；未触发 GitHub CI。

本次不修改用户运行配置、数据库结构或历史消息，也不追溯关闭客户端中缺少原流标识的旧悬挂气泡。
