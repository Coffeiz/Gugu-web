# 聊天消息去重与会话查询边界收口

## 修复范围

- 并行工具说明明确区分独立调用与有数据依赖的调用，避免工具编排误串行或错误并行。
- IM 控制命令在入口统一校验 Owner 身份，非 Owner 无法触发会话控制操作。
- 文件详情元数据使用收窄后的前端契约类型，移除不必要的宽泛类型。
- Agent 会话相关查询收口到服务层，恢复 ORM 边界棘轮约束。
- 流式用户消息获得数据库身份时，同步折叠历史请求已插入的同一消息；首轮问候由对应持久化记录认领，防止新旧气泡并存。

## E2E 失败归因

跨屏虚拟列表用例的工具时间线夹具使用了普通 `id`，而运行时映射要求稳定 `eventId`。映射因不完整夹具抛错后，加载流程回退到此前问候气泡，截图看似历史 API 丢失了 80 条记录。修正夹具契约，并让用例等待真实持久化首条消息出现后再开始滚动选择。

## 验证

- 后端完整串行回归：4,985 passed、5 skipped。
- 前端完整单测：186 个文件、947 项通过。
- 前端严格类型检查、生产构建、玻璃样式/提醒对话框回归及测试元数据扫描通过。
- 聊天消息同步定向测试覆盖已存在的身份重复折叠与持久化问候认领。
- 远端 E2E 需要在当前提交上重新运行；不得把旧 SHA 的失败当作最终验收结果。
