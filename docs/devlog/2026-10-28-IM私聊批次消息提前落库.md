# IM 私聊批次消息提前落库

## 问题与处理

私聊已共用 worker 防抖队列，但 B、C 在 run2 前曾被合并成单条数据库消息。现在 IM 私聊与要进入 run 的群消息共用逐条早落库和 run 批次复用：run1 期间到达的私聊消息可及时显示，run2 一次消费整批，同时保留每条消息的引用、来源和展示时间。

早落库只匹配已有会话；新私聊的 session 仍由 run 路径串行创建。run 准备时若部分早落库缺失，会按批次原顺序补齐。入站顺序锁覆盖同一 IM 会话，避免较早消息的异步准备被后到消息越过。群聊被动记录和私聊流式回复保持原路径。

## 验证

覆盖私聊 B/C 合并为一次 run、数据库逐条保留、批次行复用、首次私聊无既有 session 时的补写，以及群聊原有被动/主动路径。真实平台和运行服务行为需在部署后确认。
