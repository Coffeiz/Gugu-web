# 会话历史统一 baseline

共享历史加载器原来无 baseline 时只读取最近 100 条，有 baseline 时读取最近 500 条。历史窗口滚动会替换请求开头的消息，造成后续历史的缓存前缀失效。

Web、IM 和反思继续复用同一加载器，改为读取摘要覆盖水位之后的全部连续历史。物理保留服务仅清理摘要已覆盖的旧消息，避免条数目标删除未压缩上下文；保留当前摘要和待处理消息。

模型对照与回归结果见 [连续历史 baseline 与缓存对照](../reports/OPT-Cache-Strategy-2026-10-28-历史baseline.md)。真实会话在新代码加载后的 LoopScope 验证仍待完成。
