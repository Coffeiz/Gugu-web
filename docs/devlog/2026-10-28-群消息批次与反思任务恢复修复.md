# 群消息批次与反思任务恢复修复

## 问题与处理

- 群批次中缺少发言人标识的消息参与权限合并，按 unknown 限制；明确 @ 咕咕的标记跨本批保留。
- 同一群的入站准备按 worker 进程内队列顺序执行。批次保留逐条消息，部分早落库失败时补齐，按消息顺序写入历史并选取最后一条为恢复锚点。命令等未启动 run 的路径释放未消费的早落库标记；释放失败时不确认队列消息，重领时继续清理。
- 选择静默且成功结束的 run 不创建助手正文，但会在同一持久化事务内记录完成收据；ACK 前退出后重领可识别静默成功，不会误标为中断。
- 群反思 `load_messages` 的实际故障为反思范围内无可用消息。消息已清理或游标已超出范围时，任务正常收束且游标不回退，不请求模型；已有 dead 任务不自动重放。
- worker 关闭时先取消尚未触发的本机群反思定时器并等待在途收束，随后关闭 Redis 与事件循环；定时协程保存自己的任务引用，避免异常关闭时在无事件循环的 finally 中调用 `asyncio.current_task()`。

## 验证

本地与 devserver 的自动回复、群批次、早落库、重领、群反思和 worker 准入定向回归通过。覆盖缺失身份、部分早落库、逆序锚点、跨批次排队、明确 @、空反思范围及关停期间旧任务与新定时器并存。完整测试以最终运行结果为准。
