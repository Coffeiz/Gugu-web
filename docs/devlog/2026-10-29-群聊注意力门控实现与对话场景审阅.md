# 群聊注意力门控 v1.4 实现与对话场景审阅报告

> 日期：2026-10-29  |  依据：PRD-IM-17 v1.4 与当前工作区实现  |  状态：代码审阅与合成场景验证，不代表生产验收

## 1. 摘要

本报告按 v1.4 对照实现，并运行 61 条彼此独立的合成群聊情境。场景直接调用生产纯函数 `decide_attention`，验证四种模式的决策、阈值、拒绝原因、媒体兜底和历史证据；相关集成回归另运行 165 项，结果通过。

**审阅结论：已检查部分的主要架构与 v1.4 一致；未发现必须推翻的架构偏离。两项产品语义适合审阅确认：DIRECT 内容去重是否启用，以及短请求“求推荐个笔记本”是否应取得开放候选资格。预发布 E2E 和故障注入仍未完成。**

- **可选行为：** PRD §5.1 允许对同一成员 180 秒内重复、内容相同且没有新请求的文字 DIRECT 做去重；当前没有实现该可选抑制，因此每条有效文字呼叫均可直达 Run。原生真实 @ 与不同成员需求不应被冷却。是否启用可由产品审阅决定。
- **候选边界：** `求推荐个笔记本` 不命中 H02，但当前因缺少问句/明确全群受众证据得到 `PASSIVE/not_open_candidate`，不是按文本长度硬拒绝。PRD §11.2 场景 06 将 P01/P02 标成“若问询资格成立”，场景 11 只要求不能因长度拒绝；当前实现有一种合理解释，但是否要把这种省略主语的请求算作公开求助，建议你审阅定稿。
- **待实测：** 没有向真实预发布群/机器人发消息；表中场景是合成消息进入生产判定函数，不是平台到 Agent 的完整 E2E。
- **上线门槛：** autonomous 零评分零新预算、PASSIVE 持久化/收据/ACK、出站 UNKNOWN 不重发等有对应自动化回归且本轮纳入的专项用例通过；真实平台字段、Worker 故障恢复与真实出站结果仍需按 §11.3 在预发布验证。

默认模式为 `autonomous`，符合“关闭打分机制的自主回复模式”决策；没有 `enabled` 运维开关。用户选“仅 @”或“静默记录”仍由既有群回复策略控制。

## 2. 实现梳理

### 配置与入口

- `UserBot.group_attention_mode` 按 Bot 持久化 `autonomous / quiet / natural / active`，未设置时回退 `autonomous`；更改时递增 `group_attention_config_version`。前端“接入咕咕”提供选项。
- 群聊既有凭据、命令、交互、群策略、真实 @ 与 owner 权限路由先执行；门控只接入普通自动回复群消息。群批次沿既有防抖和权限分段处理。
- `autonomous` 在运行时直接返回进入原 Run；不读取评分历史、不申请新增预算、不触发新增 PASSIVE 完成事务。之后仍由既有 Agent 与 `choose_no_reply` 决定回复或静默。

### 判定与上下文

- `attention.py` 是确定性规则层：消息事实包含平台、Bot、群、消息 ID、发送者、到达时间、媒体可处理性、原生 @、原生引用对象和 Bot/成员关系。未知字段保持 UNKNOWN，不当作否定证据。
- `build_logical_candidates` 只把同一作用域、同一发送者 8 秒内连续消息合成评分文本；原始消息/event ID 不合并，跨人不拼接。
- scored 模式从同一会话 DB 历史与入站 Stream 构建窗口，检查 60 秒覆盖完整性；回复和已回答事实来自同作用域出站收据。窗口不完整时相关正向推断不成立，开放候选按 PASSIVE 处理。
- 顺序为 DIRECT → VERIFIED_CONTINUE → H 硬拒绝 → SOFT_CONTINUE → 明示媒体兜底/开放候选评分 → PASSIVE。`quiet` 不评分；`natural` 阈值 70，`active` 阈值 55。
- P/N 分数按 v1.4 权重累加并裁剪到 0–100。P04 不存在；P01/P07、N01/N02 不叠加；P05 在人际交流/覆盖不全时不肯定计分；N05 以完整窗口真人消息数计算。
- 纯图片/文件不会因 H01 被硬拒绝。可处理媒体需有显式审阅文字、可信 Bot 引用或服务端索取锚点才能进入有限路径；单独文件名不等同邀请。

### 额度、出站与历史写入

- PROACTIVE 额度按 `(platform, bot_id, group_id)` 原子预留：自然档 10 分钟最多 2 次、间隔 180 秒；活跃档最多 5 次、间隔 60 秒。SOFT 另按成员/群/锚点约束：锚点 90 秒、成员间隔 60 秒、群 10 分钟最多 3 次。运行中租约会续期。
- 出站账本区分 `ACCEPTED / FAILED_CONFIRMED / UNKNOWN / UNRESOLVED`；已确认失败可释放，未知结果保留额度占位，避免盲目重发。账本保存结构化 ID 与状态，不保存消息正文。
- PASSIVE 按每条原始消息逐条写入，在同一 DB 事务内写完成收据与决策摘要；提交后发布会话事件，Worker 之后才 ACK。重复 event_id 复用既有行。早落库可复用，附件 claim 与消息持久化一起完成。
- 决策审计包含模式、配置版本、快照覆盖、实际 decision/reason、分数与阈值；日志不写正文。

主要实现入口：`backend/agent/im/auto_reply/attention.py`（纯规则）、`backend/agent/im/auto_reply/runtime.py`（快照与模式执行）、`backend/agent/im/auto_reply/budget.py`（额度）、`backend/agent/im/auto_reply/delivery.py`（出站账本）、`backend/agent/im/dispatch.py`（接入与 PASSIVE 分流）、`backend/agent/im/conversation.py`（逐条持久化），以及 `backend/agent/im/dispatch_finalization.py`（结果结算）。

## 3. 对设计的核对结果

| 项目 | 结论 | 证据/说明 |
|---|---|---|
| 无运维 `enabled`/shadow 开关；模式按 Bot 设置 | 符合 | 模型、API、前端四种值；默认 autonomous |
| autonomous 复用旧 Run，零新评分/预算/PASSIVE | 符合代码路径 | 运行时直接放行；模式回归通过；未做真实平台等价 E2E |
| 明确 @ /可信续接优先于评分 | 符合判定顺序 | 场景矩阵及既有特征测试 |
| P/N、H、natural 70 / active 55 | 主体符合 | 规则、边界与原因码测试通过 |
| 短请求 `求推荐个笔记本` | 需确认产品语义 | 当前 PASSIVE 原因是 `not_open_candidate`，不是 H02/长度拦截；PRD 写明“若问询资格成立” |
| 媒体不被误作 H01；有界兜底 | 符合 | 裸媒体、不可处理媒体、显式审阅与可信引用均覆盖 |
| 完整窗口与 UNKNOWN | 符合本轮覆盖 | snapshot incomplete、未知引用目标等采用保守行为 |
| 多人 PASSIVE 逐条持久化 | 自动化覆盖通过 | 专项事务、成员身份、附件、重投与恢复测试通过 |
| 预算并发、续租、发送结果未知 | 自动化覆盖通过 | budget、delivery 与 finalization 相关测试通过 |
| 相同成员 180 秒重复文字 DIRECT 内容去重 | 可选项未启用 | PRD 用“可以”描述；当前实现不做该抑制，重复有效呼叫仍可进入 Run |
| QQ/飞书/Telegram 真实 E2E | 未验证 | 本轮使用合成 fixture / 离线测试；没有连接预发布群发送 |
| 中文以外的 scored 请求覆盖 | 有限制 | 规则基于有限的中文/拉丁对象词表；PRD不允许宣称跨语言完整，非中文请求宜选 autonomous 或补规则 |

**审阅建议：** 确认上述两个产品语义边界；随后按 PRD §11.3 做预发布群 E2E 与目标平台回执验证。其余主体设计未发现需要推翻的架构偏离。
