# 群反思复用原始主 Run 快照

## 背景

群级和成员级反思属于同一个群 session。此前 worker 没有进程内主 Run 快照时，会分别从数据库重建完整历史；重建结果缺少主请求实际使用的完整 Provider 前缀、system 和 tools，也可能使缓存前缀失配。

## 调整

- 群级、成员级及群内 Owner 反思共用同一个群 session 的主 Run 快照。
- 快照记录它覆盖到的持久化消息边界；普通被动群消息只经既有历史 renderer 渲染成尾部，追加到原始 Provider 前缀。
- 普通群闲置或条数触发反思若找不到兼容快照、模型不匹配、边界无法验证，或其间已出现另一条主 Run，任务保留为 `pending` 并标记 `awaiting_run_snapshot`。下一次成功主 Run 会重新调度它，不回退到完整历史重建。
- `context-pressure` 预算检查及压缩改变 baseline 后的输入重建保留为显式例外；网页/私聊 Owner 恢复策略不变。
- 主请求快照仍只保存在进程内，不把完整 Provider 请求体持久化。
