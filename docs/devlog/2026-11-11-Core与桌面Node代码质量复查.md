# Core 与桌面 Node 代码质量复查

本轮限定检查刚迁移的 `gugu-core/`、桌面 Node Host 与制品脚本。前置迁移方案及兼容范围见 [实现记录](../refactor/Gugu-Core与桌面Node迁移实现记录.md)。

## 已修复的问题

- `LocalRuntime.close()` 原先通过业务队列发送关闭指令，队列满时会失败，且异步释放前仍可接收新请求。现在关闭开始即停止入队，取消已排队操作，为关闭控制帧保留容量；并发关闭共享同一轮释放。启动失败也统一清理监听与计时器。
- Rust Host 原先只在管道中断时保留操作 UUID，响应 ID 错误、缺少结果、存储失败或结果过大可能丢失恢复依据。现在未知写入结果均保留操作 ID；非法响应停止 Host，合法业务错误仍允许继续查询；不自动重放写入，也不透出原始异常。
- SQLite 原先会把部分唯一索引当作完整唯一约束。现在要求索引覆盖全部记录，损坏库拒绝打开且不自动改写文件。
- UTC 偏移可能把边界年份换算到 0 或 10000 年，再被字符串截断。现在明确拒绝换算后的越界日期，保留合法边界和微秒。
- 阶段/待办编号原先只检查已有数值，递增仍可超过 JavaScript 安全整数。现在递增前检查，拒绝生成失真或重复身份。

## 冗余与可维护性

SQL 仓储移到 `data/repositories.ts`，`data/runtime.ts` 专注事务、取消和收据；保留原导出入口。数据行编码使用 Kysely `Selectable` 类型，移除跨层 `unknown` 双重断言。stdio 与直接 Worker 入口复用命令参数规则，移除字符串拼接式字段检查；保留各入口的独立校验和 Rust 能力白名单。

启用 `noUnusedLocals`、`noUnusedParameters`，删除未使用导入；整理本轮自写 TS、Rust 和制品脚本的多语句长行。兼容 Python 包仍有 Web 调用方，本轮没有删除它们。

## 回归策略

新增行为测试保护满队列并发关闭、直接 Worker 参数边界、部分唯一约束、UTC 年份、编号溢出。关闭、部分索引和 UTC 用例已在修复前复现失败。Rust 使用随包 Node 启动合成故障进程，覆盖响应错位、缺失或冲突字段、存储失败、超大结果，检查操作 UUID、异常脱敏及后续查询/停止行为。

保留原领域、双库事务、owner 隔离、CAS、备份恢复、进程重启与 Python/TS 对照断言。所有数据测试使用临时文件或隔离测试 schema，制品脚本使用合成数据库；不访问用户运行配置。最终测试数量与精确提交的 CI 链接记录在 PR 正文。
