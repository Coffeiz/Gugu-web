# 主对话冷请求统计与压缩摘要前缀

11 月 12 日 devserver 的主对话用量显示排除冷请求后命中率为 86.1%。该口径只排除缓存读取为零的账本行，且把整个 Run 的工具轮合在一行。逐笔对照 LoopScope 后，32 行中有 14 行匹配主 Run。其余记录成对出现在反思之后，符合 `profile` 与 `pattern` 自动维护继承主 Run 用量场景的行为。用截断响应模拟重放复现了这条记账路径，daily 沉淀已使用独立的压缩场景。

- 将画像和行为自动整理显式记为 `compaction`，保留同用户的触发会话。存量账本缺少原始调用类型，不推断回填。
- 完整输入大于零且缓存读取低于 1% 的调用计为冷请求。新 Run 保存可与账本对齐的逐轮汇总，排除冷请求的分子和分母均取非冷轮。无逐轮统计的账本行按整行判定，总用量及总命中率沿用原口径。
- Run 内压缩结果进入 MessageArea 时使用与数据库恢复一致的摘要角色。两条路径通过同一摘要渲染输出，避免在历史首部产生 `【消息正文】` 信封差异。

在 devserver 使用合成摘要和两组隔离缓存前缀做真实 MiniMax A/B。每组先发送 Run 内压缩投影，再发送持久摘要恢复投影。旧路径读取 186 / 6,110 tokens（3.04%），新路径读取 6,102 / 6,110 tokens（99.87%）。测试覆盖生产投影和 Provider 缓存读取，运行中服务的真实对话命中率仍待部署后验证。
