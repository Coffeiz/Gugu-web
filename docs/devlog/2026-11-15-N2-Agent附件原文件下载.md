# N2 Agent附件原文件下载

## 范围与消费者

迁移 `GET /api/v1/agent/attachment/{attach_id}/download`。基线为 Python `agent_routes/attachments.py:attachment_download` 与 `chat_attach/queries.py:get_meta`，前端FloatPreviewWindow、FilePreviewModal、GuguChat及音频播放器均有实际调用。

Core `agent/attachments/download.ts` 按owner读取chat_attachments，存在DB记录时优先使用它；仅缺行时调用Host注入的旧Redis元数据读取。旧协议键是 `chatfile:<用户UUID>:<attach_id>`，不是新建队列。Core限制存储key属于当前owner或当前owner的已导入目录，并复用Core files/read授权路径检查；Host直接注入 `@gugu/fs/node` 安全只读打开句柄，不依赖旧Node内部兼容转发。

Host `modules/agent/attachments/download.ts` 按Python合同设置中文文件名Content-Disposition、private max-age=300，以及文本类型UTF-8 charset。通过已打开文件句柄创建自动关闭流，错误设置响应头时关闭句柄。

## 明确差异

- Python附件下载Content-Length取meta.size。实际handler对照确认：脏size=1时声明1，但迭代器仍返回12字节，存在截断/断连风险。Node保留正常size的原合同，同时对脏size取安全打开句柄的真实物理长度，独立回归验证12字节不会被声明为1。未修改或放宽正常头部断言。
- Python get_meta在DB或Redis故障时可能掩盖为legacy/缺失。Node对基础设施错误返回脱敏500，不从DB故障进入legacy，也不把Redis故障伪装404。缺行及正常legacy仍兼容。
- owner路径和不安全路径拒绝进一步保护旧元数据，不能凭Redis元数据读取其他owner或根外文件。静态符号链接拒绝已验证；共享文件原语的并发路径替换边界不由本切片扩大声明。
