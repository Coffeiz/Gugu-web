# N2 BYOK 凭据创建与信封前置

新增目标 Host BYOK 信封适配、Core 凭据创建用例和 Host 请求解析原型。创建按 owner 锁串行禁用同能力旧凭据、插入新凭据并在 LLM 模式同事务失效推理状态；空密钥仅允许 local 或非云 Ollama embedding。生产组合根已加入创建入口；真实入口测试因 devserver 高负载超时，尚未验收，不能视为 API 完成。

Python 基线：`app/byok/crypto.py`、`app/api/v1/byok.py:create_credential`、`app/byok/schemas.py`、`app/byok/policy.py`。密钥选择支持显式当前/上一版本密钥及持久文件；文件首次创建使用与 Python 同源的 O_EXCL 方式，避免生成含密钥的临时文件；同进程并发共享读取，跨进程遇到尚未写完的空文件时失败而不派生空密钥。已有空密钥文件或符号链接拒绝读取是安全差异；已存在的常规文件使用句柄设为 0600。自定义路径落在仓库内（或父目录符号链接解析回仓库）时拒绝创建。Linux 文件模式使用目录句柄和 inode 校验，后续读写锚定打开的目录，拒绝目录替换导致写入其他位置；默认路径是仓库的 Git 忽略数据文件，部署同步规则必须同样忽略它。代码不校验祖先目录权限：有权限移动已打开目录的同用户进程仍可将目录整体移入同步区域，因此部署需确保目录及祖先由可信主体控制。非 Linux 文件模式拒绝运行，可使用环境主密钥。密钥文件每次使用重新读取；不读取 dotenv 或运行配置中的 master_key；后者是遵循凭据来源约束的安全差异。环境的直接密钥、嵌套及 JSON 优先级已对照 Python。

## 验证

- 信封测试先因模块缺失失败；隔离临时目录实际 Python AES-GCM 双向解密、旧版本轮换、8 个同进程独立实例并发首次创建、空文件及权限保护和运行中文件变更合计 9/9。文件变更用例先红后修复跨请求缓存；目录替换用例先复现目标目录出现密钥而失败，再验证句柄锚定后通过。
- 创建用例先缺模块红灯，仅关闭开关测试在实现前；其余隔离 PG 事务和正式模型测试在实现后补写，因此不声称完整 TDD。正式 Python ORM 模型和实际 handler 的 keyless embedding DTO 对照、Python密文解密、并发唯一启用、插入失败回滚均通过，Node 3/3，Node持久化密文由实际 Python `decrypt_value` 消费。
- Host 请求实际 Python Pydantic 对照 10 组有效/无效输入通过，布尔和整数字符串先红后绿，Node 2/2。Python 原凭据测试定向 2/2。
- 测试只在 devserver 隔离 PG schema 和临时目录执行，测试配置/密钥均为合成值，本地与 devserver 被测文件摘要一致。生产入口测试接线前超时，未取得入口先红证据；接线后的同版本验证尚待执行。未验证正式 SQLite、完整所有字段/协议、真实部署或线上主密钥迁移。未触碰用户运行配置、提交或推送。
