# N2 BYOK 凭据删除

## 范围与基线

迁移 `DELETE /api/v1/byok/{credential_id}`；Python 基线为 `backend/app/api/v1/byok.py:delete_credential`、`app/byok/policy.py` 和 `app/services/provider_reasoning_state.py:invalidate_user_states`。

Core `byok/credential-delete.ts` 先核对可信 BYOK 策略，再在同一事务删除 owner 限定凭据。只有 llm 凭据删除会失效同 owner 的 active 推理状态，清空三项密文、payload_size，递增 version 并记录 config_changed。事务失败保留凭据，不修改其他 owner 或已失效行；该 API 不解密凭据，也不调用 Provider。

Host `modules/byok/credential-delete.ts` 承担认证、整数路径解析和204空响应；生产组合根注入 Core 与只读策略读取器。

## 配置策略

`modules/byok/gate.ts:createByokGateReader` 每次请求重新读取可信配置。正常配置优先级为默认值 < 环境 JSON < 嵌套环境变量 < override。最终开关保持 Python `byok.enabled or ai.deployment_mode == 'local'`；local 匹配大小写与原行为一致。不能复用既有 env 优先的配额配置读取器，否则后台关闭无法即时生效。

Python override 使用 model_construct，读取器保留 enabled 的 Python truthiness。损坏 JSON 或非法配置结构明确失败，不沿用 Python 对部分 override 异常的静默回退；不会将解析失败当空对象或写回运行配置。整个读取器只读。

## 边界

正式SQLite、完整Alembic升级历史及真实部署未验收；生产metadata验证没有替代整库迁移。凭据创建/更新、解密、模型探测和完整BYOK设置页仍有独立依赖，不从删除成功推断已接通。不访问真实凭据、不调用付费服务、不运行Docker。未提交、推送或触发CI。
