# N2：IM 记忆只读汇总与维护预览

## 范围与调用链

- `GET /api/v1/admin/agent/memory/im-scopes`
- `POST /api/v1/admin/agent/memory/im-scopes/maintenance/preview`

Python 基线为 `backend/app/api/v1/agent_admin.py` 的 `list_im_memory_scopes`、`preview_im_memory_maintenance`，以及 `backend/agent/memory/scope_lifecycle.py:list_scopes`。前端维护面板 `apps/web/src/views/Admin/Agent/memory/useImMemoryMaintenance.ts` 已调用 POST 预览。

共享用例位于 `packages/core/src/memory/im-scope-summary.ts`；Host 的 `modules/admin/im-memory-summary.ts` 只承担管理员认证与 HTTP 接线。组合根和 package 导出由主会话增量接入。真实生产 `startServer` 已验证管理员登录后经 Host → Core → PostgreSQL 的调用链。

只读汇总使用四张实际模型表：游标、墓碑、记忆条目、反思任务。不读取文件正文、记忆内容或任务错误信息；只返回数量及平台分类，不返回 owner、bot、scope 标识。inactive 条目也参与计数，与 Python 一致。先按更新时间选择最多 10000 个游标，再补墓碑、按墓碑优先及 Unicode 码点顺序排序，最后再次截断 10000；不能直接对全表做无上限聚合替代。
