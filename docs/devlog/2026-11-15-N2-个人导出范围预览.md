# N2 个人导出范围预览

## 接口与范围

`GET /api/v1/data-portability/export/preview` 的真实调用方是 `apps/web/src/services/api.ts` 的数据迁移 preview。它展示可导出类别、记录数和字节，不生成归档、不创建任务、不写入 portable identity。

基线为 `backend/app/api/v1/data_portability.py:export_preview`、`services/data_portability/api_jobs.py:export_preview` 和 `projection.py:count_owned_records/_pending_attachment_ids/select_owned_records`，以及 `schema.py` 的类别集合。

实现只迁移此读取所需的规则，没有迁移归档 serializer、全量投影写入、Worker 或导入写门禁。

## 目标实现

- Core `data-portability/export-preview.ts` 使用 Kysely 生成查询，集中承载类别聚合、关联 owner 条件和附件范围，不依赖 Node 旧目录转发。
- Host `modules/data-portability/export-preview.ts` 只建立认证及可信 owner 上下文；请求中的 owner 参数不起作用。
- 26 个 record_type 中，22 类按自身 owner 列统计；消息/批次通过所属会话；memory_source 同时限制 entry owner 与来源会话 owner；附件同时限制上传者、消息会话 owner，草稿还必须被该用户 pending queue 引用。
- 文件统计包括墓碑，与 Python 当前行为一致；账户记录恒为 1，未由数据库投影提供的 owner_memory/archive_docs 保留零值。
- 附件以主键每批 500 条读取三类统计字段，孤立草稿不计入，但不能使分页提前停止。重复草稿引用仅计一次。
- 草稿 JSON 从数据库取原始文本后解析，兼容合法 JSON 字符串等历史形态；避免把驱动已经解出的字符串误当 JSON 文本再次解析。查询失败不会返回伪造的零统计。
