# N2 个人数据导入只读 API 复核

复核 Python 路由、服务、Vue 实际消费者和 Node 组合根后，未发现尚未迁移的导入只读 GET API；不能为了增加接口数量将写操作描述成只读。

| API | Python 实际行为 | 当前真实调用链 |
| --- | --- | --- |
| `GET /api/v1/data-portability/imports` | 当前 owner、created_at 倒序、最多20条，公开 import DTO 不返回 token hash/私有路径 | Vue `listImports` → 已认证 Host read-jobs → Core createPortabilityJobReader → PostgreSQL |
| `GET /api/v1/data-portability/imports/{job_id}` | 当前 owner+job，跨 owner 或不存在404，原样公开 preview 和到期状态 | Vue `getImport` → 已认证 Host read-jobs → 同一 Core PostgreSQL 用例 |

两个接口均已在本会话之前的切片完成真实生产认证/隔离 PG 和 Python handler 对照，证据见《个人数据迁移任务只读状态》。本次再次确认生产 main 注入真实 pool.query，app 使用保护域挂载，Core 只做查询和公开投影，没有仅注册401或队列无人消费的问题。正式 SQLite 与完整 Alembic 升级路径仍未验收。本次是盘点，没有新增实现，不声称进行了新的红绿 TDD。

## 其余导入路径的具体范围

- `POST imports/{job_id}/resume` 是写操作：轮换一次性能力 token hash、更新更新时间并返回新 token；不是只读状态读取，不能纳入当前只读任务完成声明。
- `POST imports/preflight` 上传并持久化加密暂存、排队预检；尚缺 Node GUGUPV1 写入端及失败上传的安全物理清理链，不能复用仅下载解密端作为完整预检迁移。
- `POST imports/{job_id}/cancel` 和 `DELETE imports/{job_id}` 会删除私有暂存/回滚文件；当前共享破坏性 FS 原语存在已记录的目录替换安全缺口，不能安全接通。
- `POST imports/{job_id}/apply`、`rollback`、`recover` 写入任务与确认/恢复状态，消费者可能改写、替换或恢复真实业务数据和文件。当前 Core 尚无完整导入/替换/恢复用例及安全存储事务，不能只写 queued 状态作为业务完成。
- `GET export/preview` 是导出范围估算，不是导入读取；依赖完整可移植记录规范、owner投影、附件父会话归属和待发草稿引用，当前 Core 无等价完整投影模块，不以简单按上传者计数替代。

未新增或修改共享入口，没有执行进一步破坏性文件系统测试、真实导入、模型调用、构建、提交或推送。
