# N2 个人数据导出创建与消费者

新增 `POST /api/v1/data-portability/exports`，实际 Vue 调用方已存在。Python 基线为 `data_portability.create_export()`、`api_jobs.create_export_job()`；现有 `worker.py` 实际注册归档消费者。

Core `data-portability/create-export.ts` 在用户行锁内完成类别校验、幂等范围检查和跨导入/导出任务互斥，再创建与 Python 消费者兼容的 queued/stage=queued 记录、排序去重的类别集合和 24 小时到期时间。相同 owner 和幂等键/类别返回同一任务，改类别 409；活跃导出或上传、执行、回滚、待恢复导入阻止新任务。archive_docs 及未知类别 422。提交后复用只读公开 DTO 刷新语义，不返回内部路径或凭据。Host 只处理身份、DTO、HTTP 202；组合根注入稳定事务、时钟和 UUID 生成。

## 验收边界

真实消费者证据来自隔离 PG 与临时 FS，不是只写无人消费队列。仍由 Python Worker 生成归档，不宣称 Node Worker 已迁移。正式 SQLAlchemy 模型表测试不等价于 Alembic 升级路径和真实部署验收；正式 SQLite、线上消费者服务配置及真实大数据归档性能未验收。Node 生产认证用例仍使用必要列精简表。测试入口先屏蔽 dotenv/override，使用合成密钥，不读取真实用户配置或存储；未运行付费 Provider 或 Docker，未提交或推送。
