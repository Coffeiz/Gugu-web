# N2 个人数据导出取消请求

新增 `POST /api/v1/data-portability/exports/{job_id}/cancel`，真实 Vue data-portability API 已有调用方。Python 参考为 `data_portability.cancel_export()` 和 `api_jobs.cancel_export_job()`。

Core `data-portability/cancel-export.ts` 通过 owner+job 行锁执行完整事务：queued 转 canceled 并设置 finished_at/updated_at，running 转 canceling 并只更新 updated_at；其他状态 409，未找到或他人任务 404，过期时间不阻止取消。提交后按既有读取用例刷新公开 DTO，不返回内部归档路径。Host 模块仅负责认证和 UUID 参数，事务通过现有稳定 `withPostgresTransaction` 注入。此 API 的 Python handler 没有 SSE 发布，本切片不额外引入事件副作用。

## TDD 与并发证据

## Worker 与数据库边界

已有 Python `worker.py` 实际创建 `run_portability_worker`；`process_export_job` 的续租/取消流程检查 canceling 并收敛 canceled。这里复核了真实生产调用链，不是新增无人消费队列。新增 `compat/tests/test_data_export_cancel_worker_postgres.py` 在随机隔离 PG schema 创建 SQLAlchemy 正式 DataExportJob 表并使用临时 LocalStorage，实际执行 process_export_job 与 renew_lease；合成 producer 仅阻塞投影，不读取真实业务数据。测试调用真实 Node Core 取消同一 job 后，实际 Python Worker 心跳识别 canceling，完成取消、清理尝试并释放租约，1/1 通过。入口缺少显式测试数据库时跳过，在导入业务模块前将 dotenv/override 指向空源；子进程继承该隔离配置。此证据不覆盖完整归档构造/上传、跨进程常驻 Worker 或物理归档已写入后的删除。queued 取消已经是终态；running 的成功响应只表示取消请求持久化，不能声称任务立即停止。

PG 测试使用模型必要列精简表，没有验收完整 Alembic schema 或正式 SQLite；真实部署、实际归档消费者停止和存储清理仍未验收。未修改 Python 参考代码，未调用付费 Provider、Docker 或真实用户存储，未提交或推送。
