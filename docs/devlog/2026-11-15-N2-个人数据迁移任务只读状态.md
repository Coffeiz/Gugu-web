# N2 个人数据迁移任务只读状态

## 范围与基线

新增四个已存在前端消费者的读取 API：

- `GET /api/v1/data-portability/exports`
- `GET /api/v1/data-portability/exports/{job_id}`
- `GET /api/v1/data-portability/imports`
- `GET /api/v1/data-portability/imports/{job_id}`

Python 依据是 `backend/app/api/v1/data_portability.py` 的列表/详情 handler 与 `app/services/data_portability/api_jobs.py` 的四个读取函数。列表始终限定当前 owner、按创建时间倒序；导出最多 10 条，导入最多 20 条。详情未找到和跨 owner 均为领域 404，分别使用“找不到此导出任务”“找不到此导入任务”。读取不更新状态、续租或创建队列。

公开 DTO 与 Python 显式字段投影一致：保留空值和 UTC 微秒；导出只有 status=ready 且 artifact_key 非 null 时标记 download_available，不按到期时间二次推断。内部 artifact/staging key、能力令牌 hash、租约及幂等信息不返回。导入 preview 保留权威预检结果，不返回 import_token。现有 Vue `services/api.ts` 的列表和详情调用路径无需修改。

Core `data-portability/read-jobs.ts` 承载 owner 查询、列表范围、404 和投影，Web Host `modules/data-portability/read-jobs.ts` 只建立认证身份、解析 UUID 并映射 HTTP。生产组合根直接注入 PostgreSQL 查询，不依赖旧 Node domains 转发。Host 接受标准及紧凑 UUID 形式，无效值 422。
