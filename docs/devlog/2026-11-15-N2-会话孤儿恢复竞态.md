# N2 会话孤儿恢复竞态

会话状态查询依赖现有孤儿恢复；不能只注册查询而跳过恢复。原 Node 恢复在获取会话行锁前探测 Redis，锁等待期间新 run 接管会被错误清为 idle。devserver 隔离 PostgreSQL 新增交错测试先失败（返回 true 而预期 false），改为持锁后复探并检查活跃 PG run lease 后通过。

僵尸快照清理增加 Redis Lua compare-and-reap：快照原文必须未变，owner、lease 和 beat 必须仍不存在，只删除旧 state/cancel；PG session 的 active_run_id 与旧快照 owner 不一致时拒绝恢复。隔离真实 Redis 验证快照替换、新 owner 和正常清理；PG 验证新租约、owner 隔离和压缩锁。相关 Node 定向合批 11/11，源文件哈希本地与 devserver 一致。测试使用合成数据与本任务隔离服务。

仍未完全消除旧 Python 与 Node 混跑窗口：Python session gate 先提交数据库 active_run_id，随后写 Redis lease；恢复在两次操作间可能看到数据库 running 而 Redis 空，当前协议没有可证明的跨系统启动标记。不得用等待/超时猜测代替同步，也不修改 Python 参考。因而 state API 尚未接入生产，不能声称完整恢复语义或跨进程闭环已完成。

interaction resume 的 Node enqueuer 和恢复 worker 仍未装配生产生命周期；仅写入队列不能视为消费。未修改这些旧 worker，也未改 Python、提交或推送。
