# N2：用户凭据提示取消

## 接口与基线

`POST /api/v1/agent/interactions/{prompt_id}/secrets/cancel` 由 GuguChat/GuguChatInteraction 凭据表单取消按钮实际调用。Python 基线为 `agent_routes/interactions.cancel_secret_interaction` 与 `mcp_secret_inputs.cancel_mcp_secret_prompt_web`；旧回归 `test_im_secret_callback_is_bound_to_private_actor_and_web_can_cancel_group_prompt`。

Core 用例位于 `packages/core/src/agent/interactions/secret-cancel.ts`，Host 位于 `modules/agent-sessions/secret-cancel.ts`。按认证 owner 锁定提示，验证 secret_fields 与 mcp_credentials 目标；非对应提示 400、已解决或过期 409、跨 owner 或不存在 404。Web 可以取消历史群聊来源提示，不凭 IM 来源新增权限门。

锁住 active staging 后清空三项短时密文字段、置 cancelled；提示同事务写 resolved 与原协议 resolved_result。没有 staging 时也可以取消，非 active 或其他 owner 的 staging 保持原状。不读取临时密文本身，不解密，不修改 MCP server 凭据或文件。取锁后使用实时数据库时钟复核到期，不能让等待数据库锁期间过期的提示通过旧事务时间判定。

先新增 `tests/interactions/secret-cancel.test.ts`：devserver 缺 Core 模块红灯，随后缺 Host 模块红灯；实现后 2/2 通过。

使用真实 InteractionRequest、McpSecretInput metadata 生成 PostgreSQL DDL，依赖 users/session/server 表为隔离外键最小前置。保护 owner、过期、已解决、非 secret、重复取消、无 staging、完成 staging 保留和 foreign staging 不误清。两个并发取消仅一个成功；数据库 trigger 在提示写入失败时验证 staging 清空与提示修改全部回滚；外部事务持锁跨过 expires_at 验证取消拒绝且密文保留。

同库调用真实 Python handler 作持久结果对照，并调用实际 `app.services.interactions.wait_for_resolution` 消费 Node 写入结果，确认原等待者收到 cancelled/option_id/text，而不是只更新无人消费的状态。Python 旧群聊 Web 取消回归串行 1/1。

## 生产接线与消费边界

由主会话增量加入 package export、真实用户认证与 main。生产 startServer 测试补充匿名 401、foreign owner 404、成功及重复 409、真实 staging 清空和 Python waiter 消费。

Python 原取消接口不发布 Redis 事件；前端根据成功响应本地标记 resolved，Python 原运行协程通过数据库 wait_for_resolution 消费。Node 持久 Harness 的恢复接口属于另外的调用链：旧 Host domains 中 createPersistentInteractionWorker/createInteractionResumeEnqueuer 尚不能据其原型声明生产接通。本接口没有向无消费者队列写入，也不依赖待删的旧 Node 转发。没有验收 Node checkpoint 恢复、继续调用 Provider 或真实 IM 网关；这些不因 Python waiter 通过而视为完成。

正式 SQLite、部署未验收；没有调用真实付费 Provider 或 Docker。未修改 Python 参考后端、用户配置、其他会话修改，没有提交或推送。
