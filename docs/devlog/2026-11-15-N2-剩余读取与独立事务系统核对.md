## 没有逐项证明的范围

### 追加精确核对

- `GET /admin/agent/llm-presets`：没有 ai_presets 时并非纯读取，会持锁从 ai 段迁移并写入；每项还必须调用 capability_snapshot，直接受既有 Ollama/custom 失败对照阻断。不能只把保存 JSON 的 items 返回就声明完整列表。
- `POST /admin/agent/llm-presets/strategy`：除校验 active/pool/router、random/round_robin/least_loaded，还要先原子写配置，再独立清空全局 active ProviderReasoningState 的三段 envelope、payload_size、状态/原因/版本/时间；失败时配置已保留但 API 失败。Core 当前没有相同池/路由策略消费者，不能把配置保存等同于 Node 主对话已分流。
- 邮件 test/publish：preview HTML 的 data URI 不能直接代替正式发送；Python 还有完整 HTML sanitizer、multipart alternative/related CID、SSL/强制 STARTTLS、错误分类和 opsmetrics。既有旧 Node SMTP smoke 仅简化 HTML，不作为新 API 依赖。
- files XLSX 三个预览接口：实际服务包括 ZIP 条目体积/压缩率限制、图片 ID 映射、单元格数据、版本 single-flight 和字节预算缓存；前端 SheetJS 依赖不足以证明同源服务等价。
- sandbox restart/rebuild/clear 均调用实际 Docker cleanup；clear 还需确认文字与真实目录清理，不在本轮 Docker/文件破坏操作范围。
- workspace-migration scan：已经逐段阅读正式扫描服务，查询启用 owner，盘点 legacy shell 并按 owner/source_directory 唯一键持久化报告，保留 ready/not_found/failed、错误类型及时间。源树由 owner 影响，需可证明的安全目录扫描和完整路径真源；当前 `@gugu/fs` 的普通文件只读句柄不等于具备目录遍历的安全原语，不用 lstat 后 path walk 的竞态窗口充数。
- voice：追加有效差分红灯及 SDK 依赖未证明边界见 [语音试呼共享前置差异](./2026-11-15-N2-语音试呼共享前置差异.md)。没有改共享 ASR 的认证或内网安全规则。
- QQ 创建：最小 owner IM snapshot 失效能力已独立补齐并完成正式 PG、加密、Python create/gateway、Node SSE 验证，见 [QQ 创建记录](./2026-11-15-N2-QQ机器人创建与快照失效.md)。Bot PUT/DELETE 随后由另一 agent 推进，本会话未重叠修改；不继续沿用旧“全部缺共享失效能力”的判断。
- 追加复核目标结构：MCP 仍只有 `core/src/mcp/status.ts`，未出现正式动态用户 manager/加密服务运行时；Core tools registry 也没有 Python CapabilityIndex 的完整生产标签/能力目录。greeting handler 即使 enabled=false 仍调用真实 generate 再隐藏文本，不能把开关投影当完整接口。未以重复读取相同候选推导全清单穷尽。

邮件发送/翻译的全部语言和并发分支、LLM/BYOK 的全部真实模型测试、workspace-migration 扫描全部路径规则、filesync initialize/repair/reconcile 全执行链、全部 IM 外部授权/网关生命周期仍需各自详细核对。perception 总览本轮已按完整 DTO 和真实生产者完成独立验收，不再列为未逐项核对的整个领域。文件破坏性操作、账户删除、沙箱清理、导入替换/回滚等没有纳入本轮实现候选。

此前盘点已记录 MCP 动态 manager/凭据、工具目录与技能注册、定时任务执行/投递、交互 checkpoint 恢复、终端 PTY、安全附件清理等缺口；这里不把旧判断扩大为当前未读接口的证明。所有接口状态由主会话按对应生产证据更新清单。
