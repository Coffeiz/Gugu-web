# N2 可移植导出删除安全阻塞

评估接口 `DELETE /api/v1/data-portability/exports/{job_id}`，真实 Vue 调用方存在，但本次没有注册或实现生产删除路由。

## Python 实际顺序

`data_portability.delete_export()` 先调用 `api_jobs.delete_export_job()`：owner+job 查询并持有行锁，queued/running/canceling 拒绝 409，其他状态允许删除。存在 artifact_key 时，先执行物理删除；物理异常记录受限诊断并返回 503，数据库行保留。随后 `finish_delete_export_job()` 删除数据库行并提交。数据库删除或提交失败时，已删除的物理归档没有补偿恢复；此顺序不能被描述为原子跨数据库/文件系统事务。

## 共享原语运行时复核

现有 `packages/fs/src/node.ts` 的 `stageLocalFile()`、`finishStagedLocalFile()` 先按路径逐层 lstat 校验，再按字符串路径执行 link/unlink。目录检查和物理操作之间没有目录句柄锚定。

在 devserver 的唯一临时目录中完成一次合成 canary 探针：授权 root 和另一个临时 outside 目录各有同名合成文件；在 stageLocalFile 检查完目录、调用 link 前，由隔离进程测试钩子将父目录移动并替换为指向 outside 的符号链接。实际原语随后对该路径执行 link/unlink，运行结果为 `outsideCanaryRemoved=true`。这证明检查后的合法并发目录替换可使破坏操作越出授权 root。探针只触及此次创建的合成目录，已全部清理；没有修改生产源码、真实文件或运行配置，未保留会锁定漏洞的断言测试。

后续任务已明确不再执行文件删除或破坏性文件系统测试，本记录仅保留上述已经完成的证据，不继续探测。

## 具体阻塞

生产接线缺少共享的目录句柄锚定/不跟随符号链接的破坏性文件原语，以及数据库提交失败后可恢复的物理暂存/清理事务语义。不能直接复用当前路径检查原语并宣称安全删除完成，也不能只接无 artifact_key 的分支冒充整条 API。按本任务“发现缺失共享能力先记录、转做其他独立 API”的边界，本次不扩展为公共 FS 重构，不覆盖正在整理的共享层。
