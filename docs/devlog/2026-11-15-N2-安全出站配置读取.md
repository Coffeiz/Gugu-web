# N2 安全出站配置读取

## 行为与实现边界

Python 参考是 `backend/app/api/v1/safe_egress_admin.py` 的 GET handler，实际路径 `GET /api/v1/admin/safe-egress` 无尾斜杠。响应仅含 `enabled`、`proxy_url`、`has_auth`；认证密文不返回，不解密凭据，也不执行连通性请求。

目标实现位于 Core `preferences/safe-egress.ts` 和 Web Host `modules/admin/safe-egress-read.ts`、`safe-egress-settings.ts`。Host 使用稳定配置文件读取器直接读取并校验配置，不依赖旧 Node domains 转发，不写用户运行配置。配置每次读取，优先级为默认值、`SAFE_EGRESS` JSON、`SAFE_EGRESS__字段` 环境变量、override 对应字段；显式空认证覆盖环境密文。环境变量由 Host 注入，未增加隐式 dotenv 文件读取。配置损坏明确失败，不回写或当空对象处理。

Core 投影只禁止历史代理 URL 内嵌账号密码的回显，不在 GET 校验连通性、协议或规范化历史地址；路径、query、fragment 保持 Python 原值。Python GET 本身没有 userinfo 二次检查，该安全差异明确保留。

## 证据

- devserver Node 配置读取测试先因缺少目标模块失败，实现后相同断言通过；历史 URL 测试先因过严 URL 校验失败，收窄为仅拒绝凭据后合计 2/2。覆盖默认、嵌套环境、override 优先级、显式空认证、配置热读、损坏拒绝及只读不改文件。
- Python 原有 `test_admin_read_does_not_return_proxy_auth_secret` 与 `test_safe_egress_override_loads_as_a_validated_settings_model` 串行 2/2。
- 新增可复跑 `compat/tests/test_safe_egress_read.py`：隔离临时文件、禁用 dotenv，配置优先级及历史 URL 路径/query/fragment 直接对照 2/2。
- 保留并移植既有 Node 原型的四条协议和安全行为断言到目标模块测试；生产 Host 集成夹具增加真实管理员登录、临时配置读取及密文不回显检查。devserver 最新 Core build 成功后，目标协议 4 条、配置/历史 URL 2 条及真实生产 Host 集成 1 条，合计 7/7 通过，无跳过，正常退出。
