# N2 定时任务文件授权撤销

## 路径与基线

`DELETE /api/v1/scheduled-tasks/{task_id}/filesystem-authorization` 以 Python `scheduled_tasks.py:revoke_task_filesystem_authorization`、`filesystem_authorization.py:revoke_scheduled_task_filesystem_access` 为基线。前端 `scheduledTaskApi.revokeFilesystemAuthorization` 已有实际调用。

Core `scheduled-tasks/task-filesystem-revoke.ts` 按 owner 锁定普通任务，拒绝日历提醒；先撤销同任务的Redis确认，再在事务内清任务grant引用、更新未撤销grant并写安全审计。重复请求返回revoked=false，不重复安全审计和指标。不存在或跨用户返回404，不触发确认撤销。

Host模块只处理认证与整数参数；组合根复用已有确认Store，注入HMAC指纹及Redis运维指标。Python opsmetrics使用UTC YYYYMMDD键、scheduled_task:revoked字段、14天TTL；指标可被Admin ops观察，Node已接相同协议。它为best-effort，不能阻止持久授权撤销。

## 权限与事务

- grant更新额外限定同owner：对于脏任务指针指向他人grant，Node清当前任务指针但不撤销他人权限。Python按grant主键读取，缺此防线；这是明确的owner安全差异。
- 安全审计与任务/grant修改同事务，审计失败会回滚数据库变更。
- Redis确认撤销位于事务提交前，不受数据库回滚恢复；与Python顺序一致，数据库失败后已撤确认保持撤销，避免重新扩大授权。
- 无功能开关gate；用户在功能关闭时仍可撤权。未新加SSE，因为Python该路径没有发布资源变更。
