# 微信扫码连接与实际网关消费者

## 接口与目标结构

新增 `POST /api/v1/me/wechat/connect` 和 `GET /api/v1/me/wechat/connect/{task_id}`，业务位于 `packages/core/src/im/wechat-connect.ts`，协议接线位于 `apps/web-host/src/modules/im/wechat-connect.ts`。主入口复用动态 IM 平台开关、UserBot 加密、Redis 失效事件与 app.onClose 的安全传输关闭，不依赖旧 Node 兼容转发。

Python 基线为 `app/api/v1/wechat_connect.py`、真实 `ILinkClient` 两个二维码 GET 和 UserBot ORM。二维码挑战只存服务端 Redis，绑定 owner，TTL 600 秒；客户端只拿任务 ID 与扫码地址。成功轮询提交加密 UserBot，按 owner/platform upsert，保留既有名称并重新启用；随后清挑战、失效 owner 的 IM 会话快照并发布 `im_channels/refresh`。等待、过期和缺 bot_token 语义保留；跨 owner 在发请求前返回 403。数据库失败回滚且不清挑战、不失效快照、不发布。

`insertUserBot` 的飞书维护方确认稳定后，仅扩展平台联合类型允许微信；微信调用显式传“我的微信”，没有改 QQ/飞书默认值与事务。Node owner 行锁保护自身并发确认不重复建；不声称与旧 Python 混合并发有数据库唯一约束保护。

## TDD 和真实消费者

所有测试只在 devserver、临时配置/目录、随机 PostgreSQL schema、私有 Redis 运行。

Core 和 Host 分别先因目标模块缺失失败，再实现后定向 2/2 通过。最终合批默认 3/3（含生产入口边界）及 Host typecheck 通过。Core 显式注入临时 TLS iLink 服务和真实安全 Node transport，运行正式 Python 元数据，直接执行真实 Python start/poll 与 `ILinkClient` HTTPX 协议构建，对照请求头、参数和 15/60 秒超时；验证 owner 隔离、TTL、等待/过期、事务失败、并发 upsert、加密列和快照边界。未检索到对应微信连接路由专属旧 pytest，因此不虚报旧 pytest 数量。Python 对照桥为 `tests/im/fixtures/wechat_connect_python.py`。

真实 Python gateway `_fetch_userbots` 解密读取 Node 创建的微信配置，`_spawn_environment` 得到正确 WECHAT_BOT_TOKEN、WECHAT_BASE_URL 和 owner，测试只对密钥做摘要比较，不输出原文，也不启动外部网关连接。

生产默认测试 `tests/host/main/im/wechat.integration.test.ts` 已通过真实认证、owner 403、未知任务 expired、平台热开关及无 Redis 503，验证外发请求为零。生产固定 `https://ilinkai.weixin.qq.com`，没有新增修改门户或启用内网权限的生产开关。

完整生产 TLS/Redis/PostgreSQL/SSE 原断言现已全部通过，恢复为正常测试 `tests/host/main/im/wechat-tls.integration.test.ts` 并登记元数据。固定官方域名的请求经隔离 CONNECT 代理、临时 CA 和 TLS/SNI 验证进入合成服务，完整验证 Redis 挑战、加密 PG、实际 Python gateway、SSE refresh、平台热开关、重定向拒绝、上游错误脱敏和无 Redis 边界；代理只连接临时 TLS 服务，没有向官方业务服务发送请求。

此前“DNS 返回非公网”的判断需要更正：系统 DNS 与显式解析器都返回公网 A 记录，但共享 Node BlockList 将 IPv4/IPv6 规则混放，`::ffff:0:0/96` 在原生 IPv4 check 中也命中，导致所有公网 IPv4 误拒。最小行为测试先有四项失败，分开地址族并保留全部 mapped IPv6 拒绝后，完整传输回归 37/37 通过，再统一 Core build 后重跑原完整生产场景成功。没有修改系统 DNS、生产地址、私网规则或真实配置，详见 [公网分类误拒记录](./2026-11-15-Node公网IPv4被映射IPv6规则误拒.md)。

显式注入的 Core 定向 TLS → Redis → PostgreSQL → 实际 Python gateway 合成链也已通过；真实官方扫码和外部消息收发仍未验收。
前端现有 auth、ProfileImPane、聊天 IM 连接逻辑监听 live 的 `im_channels` revision 后重拉；本切片不修改前端，也不把 SSE 验证算作浏览器渲染验收。

## 边界与差异

Node 显式拒绝非 HTTPS/内嵌凭据扫码地址，限制上游响应大小，Redis 不可用在请求上游前返回 503；上游异常输出固定安全 502，不回显旧 Python 可能携带的原始异常。挑战冲突保留旧挑战并拒绝覆盖。保留平台开关，未擅自开放。

已实现 Web + PostgreSQL 调用链；普通用户能力的正式 SQLite、桌面 IPC、外部微信扫码及消息收发、网关持续生命周期和真实部署均未验收，不能按合成服务通过声称完成全部跨端能力。未运行 Docker 或付费 Provider。未修改 Python 参考后端；保留所有未提交修改，无提交/推送/fetch/CI。
