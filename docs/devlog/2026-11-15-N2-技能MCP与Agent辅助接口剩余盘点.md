# N2 技能、MCP 与 Agent 辅助接口剩余盘点

本轮覆盖此前未逐路径核实的 22 个未完成 API；避开并行会话的邮件预览。仅检查 Python handler、依赖、相关 pytest、前端实际消费者与当前 Node/Core 实现；没有新增实现、空路由、测试或宣称 TDD 完成，没有修改共享入口。

## 用户技能 4 个

真实消费者为 `apps/web/src/services/api.ts:userSkillsApi`、`composables/skills/useUserSkills`、`views/Skills/SkillsHome.vue`。

- `GET /api/v1/skills/`：`user_skills.list_skills` 按 owner 读取、updated_at/id 倒序；默认 `include_tools=true` 时还调用 `_available_skill_tools` 获取内置及该用户 MCP 动态工具。前端首屏确实显式 `include_tools=false`，但只实现该分支不足以宣称完整 GET。不得对默认 true 伪返回空目录。
- `GET /api/v1/skills/tools`：实际调用 `_available_skill_tools`，受当前能力配置和 MCP enabled 影响，动态工具发现只在用户展开选择器时触发。
- `POST /api/v1/skills/`：`_write_skill → _tools_for_skill_update → capability_registry.create_user_skill`；需名称/slug/正文/related_tools 校验、区分静态与动态目录、事务和提交后 skills 事件，不是单表任意字符串插入。
- `PATCH /api/v1/skills/{skill_id}`：同一注册服务更新，owner 404、显式 enabled 与未传字段语义、关联工具动态校验及事件；不能只做 toggle 分支然后宣称全 PATCH。

现 Core `agent/skills/registry.ts:createSkillRegistry` 是由可信 Host 注入 definitions、authorize 和 loader 的通用运行时，`agent/skills/user-delete.ts` 只证明独立 owner 删除用例。`main` 没有从用户 DB 构建同源技能/工具目录的 loader；没有把 Python 全量工具目录迁入此切片。相关基线为 `backend/tests/agent/test_user_skills.py`；此前只读目录/写入前不能用删除测试当覆盖。

## MCP 8 个

真实消费者为 `apps/web/src/services/api.ts` 的 MCP 设置 API，用户配置页会调用列表、编辑、连接测试、loadStatus、reconnect 和 tools。

- `GET /api/v1/mcp/servers`：owner/scope 过滤并排序；`_server_view` 为 owner 编辑用途，按版本/主密钥解密 endpoint 和槽位值；叠加 `mcp_manager.server_states` 已有运行状态。**不能因没有 Node manager 而把所有配置一律显示为未连接**，也不能把已连接 Python worker 的状态冒充当前 Node worker 状态。
- `POST /api/v1/mcp/servers`：名称与用户配额、HTTP/stdio 目的地校验、credential slot 规范化、信封加密、事务；提交后触发用户工具 schema snapshot 刷新。
- `PATCH /api/v1/mcp/servers/{server_id}`：owner 404、目的地/槽位凭据编辑和持久化；即时失效该 server 工具缓存，并调度 schema snapshot 刷新。
- `DELETE /api/v1/mcp/servers/{server_id}`：删除提交后 `_invalidate → mcp_manager.invalidate_server`，然后 `_schedule_schema_snapshot → refresh_user_tool_schema_snapshot`。单条 DELETE 不等于完整行为。
- `POST /api/v1/mcp/servers/{server_id}/test_connection`：实际 initialize+tools/list，调用 manager `refresh_config` 并返回工具数/人话错误，不是 ping 或仅解析 URL。
- `POST /api/v1/mcp/servers/{server_id}/load_status`：实际 manager 配置与工具加载状态，需要对应 worker 运行态。
- `POST /api/v1/mcp/servers/{server_id}/reconnect`：真实断开/刷新、握手、发现工具和状态转换。
- `GET /api/v1/mcp/servers/{server_id}/tools`：owner 许可及真实 manager 的 state/loaded_tool_count/last_error 查询，不能用配置 allowlist 假造载入结果。

当前目标 Core/Host 仅找到平台开关 `mcp/status`，未有同等 MCP manager、HTTP/stdio 客户端及其跨进程失效/schema snapshot 消费组装。已有可注入动态工具运行时不等于 MCP initialize/tools/list/生命周期适配。需要先完成该共享能力及 owner 密钥版本解密链，而非迁移一般单表 CRUD。相关基线为 `tests/agent/mcp/test_mcp_settings_api.py`、`test_mcp_credentials.py`、`test_mcp_manager_dispatch.py`、`test_mcp_schema_snapshot.py`、`test_mcp_user_tools_e2e.py`。

## Agent 辅助及会话 7 个

实际消费者为前端 `services/api.ts` 的 greeting/voice availability、聊天界面会话删除和沙盒设置操作。

- `GET /api/v1/agent/greeting`：`misc.get_greeting → agent.greeting.generate`。设置用户时区，构建最近项目/提醒/记忆及上次活动上下文，模型生成 locale 对应问候，并通过 Redis 缓存/单飞锁协调。Python 即使 greeting disabled 仍调用 generate 后再隐藏正文，不能把固定问候或只读配置算完整用例。Core 暂无同等 greeting 用例与记忆聚合消费者；已有 ProviderRuntime 只解决模型协议。相关 `test_greeting_protocol.py`、`test_greeting_cache.py`。
- `GET /api/v1/agent/voice-availability`：`misc.get_voice_availability → resolve_capability_settings(speech_to_text) → supports_configured_voice_model`，需要每用户 BYOK 解密、能力配置优先级与 Provider 地址解析；不能只检查平台 voice preset 是否 active。现有共享 Provider registry 差异尚未对齐，动态 VoiceSettings reader 也未提供给此读用例。
- `DELETE /api/v1/agent/memory`：直接删除该用户整个 `.agent/` 前缀（含当前及未来衍生记忆文件），再 bump context revision。现无共享跨存储 prefix cleanup/与正在写入记忆及向量缓存一致性链；当前禁止破坏性文件操作，不做临时实现绕过。
- `POST /api/v1/agent/sandbox/restart`：owner 工作区解析，清理该 sandbox root 对应 Docker 容器；不能只返回 ok。
- `POST /api/v1/agent/sandbox/rebuild`：同样清理真实容器并检查 root_ready。Core sandbox 边界/协议并非 Python `cleanup_sandboxes_for_root` 同一部署生命周期实现。
- `POST /api/v1/agent/sandbox/clear`：确认文字、owner root、容器回收、目录安全清理并返回实际计数；当前禁止 Docker 和破坏性文件操作，不能在本轮真实验收。
- `DELETE /api/v1/agent/sessions/{session_id}`：`conversation_cleanup.remove_session_with_attachments` 必须显式删除该会话消息关联附件、消息及会话；先提交，再在共享 advisory lock 下复核 storage_key 活引用后尽力清理物理字节，PG/SQLite 不能依赖相同 cascade 假设。该附件复用/清理共享链尚未接通，不能仅执行会话表 DELETE。

沙盒基线位于 `tests/terminal/test_shell_sandbox.py`、`test_shell_workspaces.py` 等；会话删除需与 storage/attachment reuse 的同锁合同一起验证。本轮未执行上述有副作用操作。

## 文件夹及迁移盘点 3 个

- `POST /api/v1/folders/{fid}/copy`：真实文件管理消费者；`folders.copy_folder → FileService.copy_folder` 递归复制文件树、实际字节、权限/配额和提交后事件。不能只复制 folder 行或无消费者的元数据。
- `DELETE /api/v1/folders/{fid}`：真实文件管理消费者；`FileService.delete_folder` 软删当时存活子树，物理 trash 移动，随后同事务 Undo 记录、提交和根 folder remove 通知。该跨文件/DB/Undo完整链不是现有文件夹简单 metadata 写入能力，不能用业务数据上的删除尝试验证。
- `POST /api/v1/admin/workspace-migration/scan`：`workspaces.scan_legacy_shell_directories` 除只读扫描旧 shell 源目录，还查询 active 用户、计算目标 workspace 目录，upsert `WorkspaceMigrationReport` 后提交；非 local 存储返回空。当前未找到真实前端调用方（只有生成 OpenAPI 类型引用），缺少目标旧目录迁移状态仓储/扫描契约；不为了增加路由数量迁移无消费者的兼容盘点入口。

## 结果与边界

22 个接口已逐路径核对。未发现本轮能在不补整块共享能力、不缩减行为、不做当前禁止验收的副作用条件下，直接独立接通的完整接口。依赖具备后仍可按上述具体基线选择切片；这不是永久退役结论。

本轮只新增这份报告，未改共享入口、清单、Python、运行配置或其他会话代码。未在本机运行测试/构建，未启动 devserver 构建或真实服务操作，未提交、推送、fetch 或触发 CI。
