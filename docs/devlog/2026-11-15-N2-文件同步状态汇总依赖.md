# N2：文件同步状态汇总依赖

`GET /api/v1/admin/filesync/status` 不能等同于只读几张表。实际 Python `get_admin_sync_status` 会对每个可见绑定解析普通目录或工作区根，调用 `cleanup_stale_conflicts`，并在存在清理时提交数据库事务。

清理规则检查 pending 冲突的 root 内规范路径和同 owner 存活 File：仅物理文件与当前数据库记录均已消失才改为 resolved/stale。需要共享 `resolve_local_binding_root`、`resolve_workspace_root`、安全路径解析及正式 File 语义。跳过清理或以固定 unsupported 隐藏绑定会改变用户看到的冲突与后续人工修复选择，不能声称等价。

返回还依赖动态 storage/filesync 配置、真实 workspace_shell_supported 平台能力，以及受限 inotify limit helper 的 Unix socket 状态协议；helper 连接/读取超时及不可用时必须返回真实 available=false 与配置 hardLimit，不能以固定 watcher 数替代。当前目标共享层缺少这些完整根解析、冲突清理及平台接线。遵循不迁移整块 watcher 的范围约束，保持此 API 未迁移。

单独的管理员 events 流仍可独立评估：已有 Python Worker 发布 `events:filesync-admin`；状态刷新消费者为 `useFileSyncAdminEvents.ts`，可与已迁移任务快照读取配合。事件接通不会被当作 status 或 watcher 完成。
