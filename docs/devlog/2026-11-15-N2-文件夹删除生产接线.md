# N2 文件夹删除生产接线

## 行为基线

Python 路由为 `backend/app/api/v1/folders.py:delete_folder`，业务实现位于 `backend/app/services/storage/file_service/folders.py`，涉及 `folder_tree.py:soft_delete`、trash 移动、Undo 持久化和提交后文件资源删除通知。删除只处理操作时仍存活的 owner 子树和文件；已在回收站的子行保持原样。文件实体与数据库墓碑在事务中更新，workspace 对已删除目录的绑定被清除，Undo 仅记录请求根目录并保留 Python 消费协议。

## Node 接线

- Core `files/folder-delete` 规划 owner 范围内存活子树与文件。
- Web Host `modules/files` 注册 `DELETE /api/v1/folders/:fid`；owner 只从已认证请求上下文取得。
- PostgreSQL Local 适配器锁住目录树及 trash 目标，使用本地路径镜像事务，更新目录/文件墓碑、工作区引用和 Undo；提交后发布 folder remove 事件。当前显式限制为 Local 存储，不把对象存储误报为已支持。

## TDD 与验证

先新增 Core、Host、PG adapter 的行为测试。初始运行分别因缺少 Core 导出和生产 Host 路由而失败；PG adapter 测试先因适配器模块不存在失败，随后按假池暴露的 fixture/返回值缺口修正。最终 devserver Node 定向回归 5/5 通过，覆盖存活子树、先前回收站行、认证 owner/Undo 元数据，以及数据库失败不留下文件变更或事件。同步后对本地与 devserver 被测源文件 SHA-1 一致性核对通过。

devserver Core build 与 Web Host TypeScript build 通过。隔离 PostgreSQL 集成测试因未配置 `GUGU_WEBUI_TEST_DATABASE_URL` 跳过；Python pytest 环境没有 pytest/项目 venv，未运行 Python 对照。未接触 Python 参考后端、用户配置或真实数据。
