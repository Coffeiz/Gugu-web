# N2：文件夹对账依赖盘点

## 实际行为

`GET /api/v1/admin/folder-doctor/scan` 与 `POST /api/v1/admin/folder-doctor/repair` 由管理员存储面板 `DirectoryReconciliation.vue` 调用。Python 基线为 `backend/app/api/v1/folder_doctor_admin.py`、`backend/app/services/storage/folder_doctor.py`，已有完整回归 `backend/tests/storage/test_folder_doctor.py`。

扫描必须共同计算存活 Folder、Project、WorkspaceDirectory 的合法目录、合法父容器，以及存活 File 的期望 storage key。无对应记录的空目录只报告；mind 历史文件、物理对象缺失及关联坏链不误报；错位文件最多 300 条，额外条目设置 truncated。省略 user_id 为管理员跨用户全量扫描。对象存储因无空目录概念返回空报告。

repair 当前只在服务端重新扫描并补建缺失目录，再重新扫描返回修复后状态。HTTP 请求含 `remove_orphans` 或 `relocate_files` 真值会返回 400；底层兼容参数也不会删除或搬迁。因此阻塞不是缺少安全删除原语，不能照旧注释实现删除、搬迁。

## 当前共享能力缺口

1. Python 的路径真源 `folders.folder_dir_key`、`resolve_folder_chain`、`keys.compose_logical_path`、`key_strategy.PathMirrorStrategy` 尚无目标 Core 等价入口。它们包含 owner/空间/项目/工作区一致性、环链/坏链处理、项目日期及扩展名规则。Core 当前文件模块只有 `files/read.ts` 的安全相对文件读取，不能据此声称完整目录对账。
2. 旧 Host `domains/files/folder-path-planner.ts` 存在相似内部规则，但新功能不得依赖待删除的旧 Node 内部兼容入口。该原型也不能直接宣称 Python 等价，例如其项目查询过滤 deleted_at，而 Python 当前 folder_dir_key 中项目查询不带此过滤。
3. `packages/fs/src/node.ts` 提供安全文件打开、暂存/恢复普通文件，尚未提供对账需要的受控目录遍历、目录存在检查、子树含文件检查及根内建目录端口。直接以普通 recursive mkdir 和全盘遍历替代将绕开目标存储边界，必须先明确符号链接与非本地后端语义。

本切片保持未迁移；没有注册空接口、没有构造局部存储替身宣称生产完成、没有启动测试或访问真实用户存储。依赖补齐后应移植既有 pytest 中缺目录、孤儿/非空/结构目录、错位/冲突/mind、300 条截断和禁止删除搬迁场景。此次仅记录，不扩大成文件共享领域迁移。
