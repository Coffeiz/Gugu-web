# N2：最近错读案例读取

新增 `GET /api/v1/admin/perception/misread/recent`。基线为 `backend/app/api/v1/agent_perception.py::misread_recent` 与 `agent/memory/reflection.py` 的真实 `_misperc_llm`、`_emit_perc`；前端 `Admin/Perception/index.vue::loadMisread` 已请求该地址并消费 `cases`，无需修改前端。

## 实现与行为

Core `perception/recent-misread.ts` 读取 Python 使用的 `perc:misread_cases` Redis list，并查询真实 `users.is_developer`。默认 n=30，n=0 回到 30，最少 1、最多 200。无筛选时先 LRANGE 前 n 条再解析，坏 JSON 不补足；排除开发者时固定读取前 200 条，解析后按 UUID 前 8 位筛选，再截取 n，不继续向后寻找。开发者标记没有缓存。原样保留合法 JSON 案例；筛选分支遇到非对象按 Python 错误语义失败，不以空列表掩盖。

Host `modules/admin/perception-recent-misread.ts` 负责管理员 guard、Pydantic 查询参数和协议。重复参数取最后一项，bool 复用既有 `pythonQueryBoolean`；n 支持整数小数串、数字间下划线、超大整数及 Pydantic 的 Unicode 空白集合。超大整数只用于夹取条数，不转成不精确 JS 数字。无 Redis 明确 503，实际 Redis/PG 异常通过统一 500 脱敏。

主会话接入包导出、app/main 及最小 Redis list adapter；adapter 通过现有认证/超时连接读取实际 LRANGE，不将空数组变成对象。没有使用旧 Host `domains/admin/admin-perception.ts` 原型，也未修改其聚合或文件读取实现。
