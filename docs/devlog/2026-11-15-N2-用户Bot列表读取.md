# N2 用户 Bot 列表读取

新增 `GET /api/v1/me/bots`，现有生产 Host 兼容末尾斜杠，Vue 的无末尾斜杠调用可直接使用。只迁移读取，不声称 Bot 创建、更新、绑定、网关或外部平台已接通。

## 边界与实现

- Python 基线为 `backend/app/api/v1/user_bots.py:list_my_bots/_out`、`app/services/im_identity.py:normalize_group_allowed_tools`、`app/services/im_platforms.py` 和配置 `IMPlatformSettings/apply_override`。
- Core `im/user-bots.ts` 实现 owner 限定 SQL、字段投影、掩码、群工具白名单及旧模式规范化。Host `modules/im/user-bots.ts` 负责认证、可信 owner、解密与生产接线。
- 既有 SMTP 凭据的真实实现最小提取至 `adapters/encrypted-string.ts`，算法与 Python `EncryptedString` 相同；旧 SMTP 文件仅导出旧调用方别名，新 Bot 直接依赖目标 adapter。
- `modules/im/platform-settings.ts` 每次读取生效平台配置，顺序为 feishu/qq/wechat/telegram。环境 IM JSON 与 IM__字段构建初值，override.im 优先；单字段 null 或无效布尔放弃 IM override，与 Python 行为一致。顶层 im:null 保留环境。Host 不额外读取 `.env`，环境来源由启动方提供。损坏 JSON 文件由已有安全 reader 显式失败；这比 Python apply_override 对坏 JSON 回退环境更严格，未把该异常行为声称完全等价。

## 后续：QQ 身份解绑

新增 `DELETE /api/v1/me/bots/{bot_id}/qq-binding`，Python 基线为 `unbind_qq_identity`，只要求 owner 与 QQ 平台，重复解绑仍成功并返回 204。Core 在单条 owner/platform 限定更新中原子清除两个绑定字段，保留凭据与 Bot；提交后 best-effort 发布 `im_channels/refresh`。不清调度可达地址、不删除 Bot、不重启网关，与该 Python 入口一致。

- devserver Host 模块缺失红灯后实现；隔离 PG 用例 1/1，覆盖未认证、越权/非QQ/不存在404、重复204、字段清除和提交后回查、凭据保留。
- 生产 main + 隔离 PG/Redis 验收 1/1，真实订阅收到 `im_channels` 的 `refresh` 事件；响应与事件均不含明文凭据。随后补强初始绑定字段的最终重跑遇到并行 BYOK 新导出尚缺 dist，待总构建后复验，不把缺制品算业务回归失败。
- Python 追加直接 handler 对照 1/1，Bot夹具共4/4。真实外部IM身份验证和已运行服务未验收；仅确认数据库绑定状态及生产事件链。

最终复验：统一 Core build 后核对本地与 devserver 的 Core、解绑路由和生产测试 SHA-256 一致，Bot 五项 Node 回归 5/5，Python 新旧回归 8/8。生产测试初始绑定字段已补强并通过真实 PG/Redis 事件验收。Host 类型检查本切片无报错，但并行 data-portability-main 测试的 TS7022 和 Core assemble 的 findLastIndex/lib 配置错误仍使整体检查失败，不能报告整体类型检查通过。

后续完整调用链审计发现待补副作用：Python `events.publish(im_channels)` 除 Redis 版本/通知外，还调用 `invalidate_user_im_snapshots`，失效该 owner 四种 IM source 的会话快照（递增 context_epoch、更新 snapshot_expires_at）。现有 Node 发布器尚未执行该数据库失效，因此解绑仅能标记“数据库绑定变更及 Redis 通知接通”，不能标记完整 Python 副作用等价。Bot 新增/更新同样依赖此能力，未扩展实现。实际网关配置重载由生产 Alembic `trg_user_bots_gateway_config` 触发 PG NOTIFY；精简 schema 不包含该触发器，不把本次事件测试称为网关重载验收。

## 解绑副作用复核

Python 的 `events.publish(im_channels)` 还会触发 owner 的 IM 会话快照数据库失效；现有 Node 发布器只发 Redis 资源事件和上下文修订，尚未接入该数据库失效，因此解绑并非完整副作用等价。生产 PG schema 的网关配置通知触发器也未验收；此前 PG/Redis 通过仅证明绑定字段和资源事件。缺口需要共享会话快照失效能力，不在本切片扩展整块共享领域。
