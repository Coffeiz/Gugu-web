## Python 基线和完整行为

对照 `backend/app/api/v1/user_bots.py:BotUpdate/update_my_bot/delete_my_bot`、`app/scheduled_tasks.py:clear_imreach`、`app/core/events.py:bump_context_revision` 及真实 `agent.context.session_snapshot.invalidate_user_im_snapshots`。

PUT：

- owner 不符和不存在均 404。Bot 行在事务内加锁；格式、平台、权限白名单校验失败时不修改字段、不递增 epoch、不通知。
- name 不额外 trim，app_id 和新 secret 按 Python strip；空 secret 或包含遮蔽圆点的值保留原密文，空白但非空输入归一化为空凭据。实际 GCM/HKDF 复用已有 adapter，不写明文入库或响应。
- QQ/Telegram 与飞书群聊开关分开；回复模式与 requires_at/read_enabled 的联动保持 Python 顺序。attention 仅实际变化才增加配置版本，锁保护同值并发只增加一次。
- 群工具校验并复用同一归一化函数（web_search→http_get、similar_image_search→read_file）；QQ 流式仅 Markdown，改 compat 自动停用；非 QQ 不能设置 private_streaming_enabled，包括显式 false。
- 提交后按 owner 失效四个 IM source 的快照（仅 expire+epoch，不清旧正文/hash），再尽力发布 im_channels refresh；后置故障不撤销已提交业务。

DELETE：

- owner 条件 DELETE 在事务提交后才清理/通知，重复删除 404。
- 清 `imreach:<uid>:<platform>`，最近 `imreach:<uid>` 只有 platform 匹配才清；其他用户、其他平台和坏 JSON 最近值保留。
- 复用同一快照失效，再发布 refresh；Redis 或 live 故障按 Python best-effort，不复活已经删除的 Bot。
- Lua 原子读取/条件删除最近键，避免 Python 分开的 GET/DELETE 之间有新平台写入而被误删；这是有意加强并发保护，静态键语义与 Python 相同。
