MCP/技能、交互恢复、定时任务投递这些都是有真实前端消费者的候选，但需要共享能力或生产生命周期接线；本轮不扩大成整块领域迁移。文件清理、账户删除、沙箱重建及目录迁移没有作为新实现候选推进。其余管理员/平台 API 不纳入本轮用户主流程盘点结论，也不声称此表穷尽全部 N2。

## 追加核对：只读外观下的依赖

- QQ/飞书/微信 GET connect poll 不是只读 Redis：还会调用外部授权接口，成功后解密或保存 Bot 凭据、更新绑定/可达身份、清临时状态并发布 IM 刷新。Node 缺完整授权 SDK/加密/网关生命周期，不能只返回 waiting 或 expired。
- MCP load_status 会按需建立运行时，不能用数据库 enabled 字段替代 manager.ensure_server_status。
- dev/attention/defaults 对外声明生产算法版本，score 实际使用生产 IM 因果窗口 scorer；目标 Core 未有等价算法，不能独立复制常量后宣称沙盒可用。
- admin/update/status 调用实际 Docker updater，还会幂等记录终态审计；不是单纯读取文件，不在本轮 Docker 验证范围。
- admin/prompts 需确认目标 Agent 真正消费相同提示词文件和 profile 真源；当前 Core 无等价文件消费者，旧 Node 原型不能算目标接线。
- filesync missing-preview 需安全根解析、root fingerprint、真实 lstat 错误语义与 owner 文件关联；不能把权限错误当缺失。status/repair 等根路径缺口见已有记录。

本轮另外发现管理员兼容 ban 可独立接入，已新增目标 Core/Host 并验证真实认证和 SSE，见独立封禁记录；没有将其假定为缺共享服务而直接跳过。

## 最后一轮：已逐段核对的额外候选

| 候选与本次核对范围 | 具体结论 |
|---|---|
| DELETE `/me/bots/{bot_id}`：Python handler、clear_imreach、events.bump_context_revision 及 snapshot invalidator | 删除 Bot 后还要清平台/最近可达地址，并失效 owner 所有 IM 会话快照。`invalidate_snapshot` 实际设置 snapshot_expires_at=now、context_epoch+1 并记录快照事件；不能仅删行/发前端刷新。目标 Core 当前 UserBots reader/unbinder 没有完整等价接线，本轮不扩展已有 IM 共享领域。 |
| GET `/mcp/servers`、GET `/mcp/servers/{id}/tools`、POST load_status：Python handler 及相关视图/manager 调用 | 列表需解密 endpoint/凭据状态投影和当前进程 server_states；tools 返回当前进程 manager 的已载入状态。load_status 还会真正建立连接。目标 Core 只有入口 status，不能固定 unloaded/0 代替运行时。 |
| POST data-portability imports apply/recover/rollback：api_jobs 实际条件和消费者类型 | resume 的纯令牌轮换已独立完成；apply/recover/rollback 会把任务交给 incremental/replace/rollback 执行链。后两者涉及替换及恢复文件，不属于本轮避免文件破坏性操作的候选。不能把仅更新 queued 状态称作完整迁移。 |
| GET files thumb/xlsx-preview/xlsx-preview-image：Python handler 与 Node 目标实现搜索 | owner 与安全文件读取已有基础，但目标 Core/Host 当前没有对应真实图片预览、XLSX 提取/缓存能力；不能返回原图或固定空预览冒充等价。 |
| GET agent greeting：Python handler | 包含用户时区、近期记忆/项目/提醒生成、语言和缓存语义；不能只复制 enabled 或固定文案。目标共享生成/缓存能力仍缺。 |

本轮在这些已核对候选中，没有找到另一个与已完成 dry-run 同样依赖具备、可直接验收实际消费者且不涉及破坏性文件操作的独立切片。
