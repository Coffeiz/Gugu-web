# N2：管理员同步只读预检任务

## 范围与基线

接通 `POST /api/v1/admin/filesync/bindings/{binding_id}/dry-run`。现有 FileSyncAdminPanel/filesync API 已有实际调用。Python 基线为 `filesync_admin.binding_dry_run`、`jobs.enqueue_reconcile_run`，实际消费者为 `claim_next_run` 与 runner `_run_claimed`。

Core `packages/core/src/filesync/dry-run.ts` 锁定真实 binding，确认本地目录来源、active 和同步方向；同 binding 的 queued/dry_run/禁止删除任务幂等返回，其他活动任务 409。创建正式 FileSyncReconcileRun，快照 owner、binding/gap revision 与 root fingerprint，固定 allow_delete=false，提交后发布现有管理员 SSE 失效频道。Host `modules/filesync/admin-dry-run.ts` 只做 Admin guard、绑定 ID 与 HTTP。调用方伪造删除许可不改变无删除任务类型。

Node 不解析或扫描路径，也不创建新私有队列。没有把缺少共享路径能力误写成固定成功：这里复用既有 Python Worker 的真实正式任务协议，下面验证该消费者确实能完成 Node 创建的任务。

## TDD 和真实 runner

先新增 `tests/filesync/admin-dry-run.test.ts`，在 devserver 因目标 Core 模块缺失失败；实现后通过 2/2。

`compat/support/filesync_dry_run.py` 是受测试参数约束的 fixture 桥：显式临时 override、随机 schema、隔离 Redis 和临时用户存储；从完整 Python Base.metadata 建立 PG 模型表及索引，而非简化手工业务表。它准备一个合成个人文件，然后实际 claim Node 创建的任务并运行 `_run_claimed` 与扫描线程。没有替换扫描函数或构造 succeeded 结果。诊断 handler 在导入生产模块前隔离，不打开工作区运行日志。

验证结果：任务 succeeded、plannedCreated=2、created=0；File、Folder、Journal、Outbox、Conflict 均为 0；临时源文件 SHA-256 不变。源测试还覆盖并发请求同 job、已有其他 action/running/cancelling/允许删除任务不错误复用、无效绑定/方向、事务失败不入队不发布、管理员鉴权及非法 ID。

最初 fixture 同一次 flush 放入 User 与无 ORM relationship 的 binding，被正式 PG 外键拒绝；仅修正测试先 flush User，未降低约束或修改 Python 参考后端。

原 Python 回归各 1/1：`test_dry_run_reports_plan_without_business_side_effects` 和 `test_admin_entrypoints_enqueue_tasks_without_waiting_for_scan`，串行执行。

## 生产验证

独立 `tests/host/filesync-dry-run-main.integration.test.ts` 使用真实 startServer、真实 Admin 登录与相同完整 PG 模型：匿名 401、普通用户 403；两个实际 HTTP 用例并发请求得到同一 job，任意 allow_delete 输入都不获删除许可；真实 HTTP SSE 收到正确 run_id/binding_id/revision。

同一生产 Host 创建的任务随后交给实际 Python runner，完成相同只读扫描；再经生产 GET 快照看到 succeeded 和 plannedCreated=2。不是仅验证入队、401 或测试替身返回。主会话负责 Core 导出、Admin guard、main 与既有 Redis publisher 接线。

## 验收边界

已验证 PostgreSQL 的完整模型表/索引与真实 Python runner、临时本地 FS；未声称 Alembic 全迁移链、正式 SQLite 的 Node 路径或真实部署验收。SQLite 仅已有 Python 原回归通过。Node watcher/执行器未迁移，长驻 Worker 的部署/生命周期未验收；当前生产接线需配合原 Python Worker。

GET filesync/status 仍有共享根解析和冲突清理等缺口，本 API 通过不代表整个 Admin 同步面板已可用。initialize/repair、删除/搬迁和冲突修复没有作为本切片实现或执行。所有数据与文件均为临时合成数据，没有读取真实用户配置、凭据或存储，没有调用 Docker 或付费 Provider，没有提交或推送。

## 最终结果

无活动构建时串行 Core build 通过，Node 最新合批 3/3（业务/HTTP 2、真实生产 1），Python 原回归 2/2。测试 fixture 的日志隔离修正后，核对八份关键文件本地/devserver SHA-256 一致，再以相同最新 Core 产物复跑 Node 3/3 通过；没有用修改前 fixture 或旧产物冒充验证。
