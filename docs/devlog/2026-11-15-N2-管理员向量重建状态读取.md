# N2：管理员向量重建状态读取

## 范围与基线

接通 `GET /api/v1/admin/config/embedding-rebuild/status`。实际前端轮询为 `apps/web/src/views/Admin/Agent/runtime-config/useEmbeddingRebuild.ts`；Python 基线是 `backend/app/api/v1/config.py:embedding_rebuild_status` 与 `_rebuild_worker`。平台使用全局 Redis 键 `emb:rebuild`，与已迁移用户 BYOK 的 `emb:rebuild:user:<owner>` 明确不同。

Core 用例为 `packages/core/src/admin/embedding-rebuild-status.ts`；Host 模块为 `apps/web-host/src/modules/admin/embedding-rebuild-status.ts`。主会话负责 package 导出和组合根接线。读取没有写队列，也不触发新 Worker。

缺失、空值和损坏 JSON 返回 idle；包括 null、数组、数字在内的合法 JSON 保持 Python 返回语义；正常状态的进度、计数、tag、ts 与文案完整保留。Python Worker 的异常分支会把原始异常字符串写入 message，而该状态 handler 原样返回：Node 对 error.message 使用已有 `redactToolError`，保留状态与其余字段，这是明确的安全差异。未配置 Redis 返回 503，不伪造 idle；Redis 实际故障由统一 HTTP 层映射脱敏 500。
