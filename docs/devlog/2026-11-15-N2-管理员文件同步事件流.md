# N2：管理员文件同步事件流

## 范围与结构

接通 `GET /api/v1/admin/filesync/events`。Python 基线为 `filesync_admin.filesync_admin_events`、`live.event_stream_response/_event_stream/_serialize_message` 与 `app.core.events` 两个 filesync publisher。

Core 纯 codec 为 `packages/core/src/realtime/live-message.ts`；Host `modules/filesync/admin-events.ts` 负责管理员认证、SSE、Redis 订阅与连接清理。仅订阅 `events:filesync-admin`，不订阅用户或广播频道、不持有数据库会话、不调用 watcher。主会话接入 package export、Admin guard 和真实 Redis subscription adapter。未修改或迁移其他会话旧 `domains/live` 实现，新调用链不依赖旧 Node 内部兼容转发。

Python 复用通用 live codec，因此本实现不只放行两种 filesync 消息，还保护资源事件、通知、present、trash progress 和 agent 状态；filesync/agent 裁剪为 Python 相同白名单，控制消息与坏 envelope 丢弃。流先发 connected，正常空闲无轮询和心跳；Redis 不可用或断连发 reset 注释并结束，由前端退避重连。未配置 Redis 也是此实际 Python 传输语义，而非伪造同步状态。
