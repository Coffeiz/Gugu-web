# N2 管理员服务状态读取

新增 `GET /api/v1/admin/services`，实际 Python 路径无尾斜杠，真实调用方为 Vue Admin/Services 的读取请求。

Python 基线是 `services_admin.list_services()`、`health.read_all()`、`_status_from()` 与 `_queue_info()`。Node 当前 web 条目使用当前进程 pid、hostname 和 uptime，不伪装成 Python 进程；worker/gateway 条目仅读取对应 Python 生产者已经使用的 Redis 心跳。超过 15 秒为 stale，恰好 15 秒仍 online，没有心跳为 offline。数据库依赖通过真实 `SELECT 1` 探测，Redis 依赖通过真实 ping；队列只读 `im:inbound` 和 `agent-workers` 组的 length/pending/lag/consumers。

服务端生命周期属于 Host，此切片位于 `modules/admin/service-status.ts`，不在 Core 制造空业务层。稳定 Redis 适配由主会话最小增量加入 `adapters/redis-events.ts`。Host 只向该端口传入固定 key 和固定只读 Lua；不接受 HTTP 用户提供的脚本或 Redis key，不写生产心跳、不执行服务重启。

## TDD 与验证

- devserver Node 测试先因缺少目标 Host 模块失败，实现后状态边界、Host 自身事实及依赖故障语义转绿。
- `compat/tests/test_service_status.py` 使用合成心跳和固定时钟直接运行 Python handler，1/1；没有专门既有 services handler pytest，未以无关基线冒充直接对照。
- Node 状态测试与真实 `startServer` 管理员认证、隔离 PG/Redis 集成合计 2/2，正常退出。Redis 测试使用临时实例中的专用逻辑库，先确认固定业务键不存在，再创建合成心跳及测试 Stream，结束只删除自己创建的键，不清空默认库。
- 实际验证在线/stale 心跳、真实 PG 与 Redis 依赖、Stream lag、当前 Node pid 和只读后心跳未变化。两个独立 Redis 命令客户端读取同一心跳，另一个真实断连端口验证 Redis 不可用时依赖 false、队列未知和服务 offline。该结果不宣称跨进程生产多实例生命周期已验收。
- 本地与 devserver 三个被测实现/Node 测试文件 SHA-256 一致。此切片无 Core 变更，无需重建 Core。

## 未覆盖项

生产 PG 仅创建本测试必要的管理员审计表，未验证完整 Alembic schema。无正式 SQLite 业务迁移；Worker 和网关仍由 Python 运行，本 API 只读取现有事实。`POST /admin/services/{name}/restart` 的 Python respawn/systemd/进程校验未迁移，不能把本读取切片称为完整服务管理面板。真实部署、跨进程重启、权限和 systemd 未验收。未调用 Docker、付费 Provider 或真实用户服务，未提交或推送。
