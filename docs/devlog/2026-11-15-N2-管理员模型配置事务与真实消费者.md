# 管理员模型配置事务与真实消费者

## 范围与基线

迁移 `agent_admin.py` 的六个配置事务：`POST /api/v1/admin/agent/llm-presets/strategy`、`POST /api/v1/admin/agent/llm-presets/{preset_id}/activate`、`DELETE /api/v1/admin/agent/llm-presets/{preset_id}`、`PUT /api/v1/admin/agent/llm-presets/{preset_id}/capability-overrides`、`POST /api/v1/admin/agent/llm-presets`、`PUT /api/v1/admin/agent/llm-presets/{preset_id}`。前端模型管理是调用方；真实 Python `pick_model(get_settings())`、`provider_reasoning_state.load_state`、`capability_snapshot(get_settings().ai)` 是配置/失效消费者，不发送模型请求。

共享业务位于 `packages/core/src/agent/config/`，Host 位于 `apps/web-host/src/modules/admin/llm-*.ts`。复用 Host 原子配置文件修改与 POSIX 文件锁，保留配置其他段及机密，不读取或写入用户运行配置。全局配置变化使所有 owner 的 active 推理状态失效，清除三项加密载荷、载荷大小归零、版本递增并保留摘要及其他元数据；expired 状态不改。状态失效独立于配置文件事务：与 Python 一致，DB 失败时已保存文件保留，HTTP 返回脱敏 500。

## 行为与 TDD

所有测试只在 devserver 的临时目录、随机 PostgreSQL schema 和合成数据运行。

- 策略 Core 和 Host 分别先因目标模块不存在失败，再实现后定向 3/3。验证枚举、nullable/no-op、旧 AI 配置迁入、显式 null 保留、并发局部修改不丢字段、腐坏文件不覆盖、状态事务失败不半更新。实际 Python round-robin 依次选择两个池模型，真实 `load_state` 读到 `config_changed` 及递增版本。
- 激活/删除 Core 与 Host 同样先缺模块红灯后定向 3/3。与实际 Python handler 对照完整 AI 字段和默认值、404、禁止删除活动/最后一个预设、删除不存在 ID 仍成功及失效语义；机密仅在文件存储。激活的完整配置由真实 Python 模型选择器消费。
- 能力覆盖 Core 和 Host 同样先缺模块红灯，定向 3/3。对照实际 Python handler 的完整配置；13 种真实 Pydantic 字典布尔转换与白名单错误优先级、401/403、404/400/422、配置错误 503、失效异常 500。完整替换而非合并覆盖，清检测指纹，活动预设同步完整 AI 段，非活动不改 AI。失效失败后真实 Python `capability_snapshot` 仍读到已保存的 tools/parallel_tools/image 覆盖。

六接口均在真实 `startServer` 生产入口通过，使用管理员真实登录、普通用户真实 DB 身份、Python 正式 ORM 元数据与实际模型选择/状态/能力读取器。最终串行 Core build 与 Host typecheck 均通过；合批 10/10 包括六项模型事务生产测试、草稿测试邮件/SMTP 合成 TLS 服务，以及语音 CRUD/读取、真实 Python flock 并发与管理员配置锁回归。

创建/更新先缺 Core/Host 模块失败，再定向 3/3；与真实 Python 对照 12 组完整配置/响应及 17 种 DTO，覆盖空密钥保留、目标变化后的 Python 凭据语义、联网默认与禁用、token 窗口、图片细节归一化、首次创建激活、活动 AI 同步、并发追加及失败后文件保留。未发起网络请求，URL 仅存储，后续外部请求仍须使用安全传输。全部四组定向共 12/12。原 Python pytest 串行 3/3：配置锁并发创建、持久化数组追加、响应密钥遮蔽。

生产合批发现了真实持久化缺陷：`mutateConfigOverride` 回调完整替换 AI/能力覆盖，原 writer 又与旧文档递归合并，导致旧嵌套字段复活。先保留生产精确替换断言的红灯，再补真实文件与 Python `capability_snapshot` 读取红灯；最小修改 writer 的可选整文档模式，仅 mutate 使用，patch 更新保持原语义。修复后文件/消费者定向与全部生产断言通过，语音和管理员 patch 持锁回归通过，未放宽断言。

测试为 `tests/admin/llm-{strategy,preset-selection,capability-overrides,preset-mutations}{,-route}.test.ts` 与 `tests/host/llm-preset-configuration-main.integration.test.ts`；Python 隔离桥为 `compat/support/llm_strategy.py`。未修改 Python 参考后端；直接执行其 handler 与真实消费者。
