# N2 管理员维护状态查询

新增 `GET /api/v1/admin/config/index-rebuild/status` 与 `GET /api/v1/admin/config/memory-cleanup/status`。真实消费者分别为 Vue `useIndexRebuild.ts`、`useMemoryMaintenance.ts`；沿用已有读取请求，不新增轮询流程。

Python 参考为 config API 中两个 handler，固定 Redis key 分别是 `rag:index-rebuild`、`mem_cleanup:plan`。未找到状态返回 idle，损坏 JSON 按既有契约返回 idle；index 状态不擅自裁剪有效 JSON。memory 状态为 running 且距 ts 达到 600 秒时转换 stale，保留 done/total，写回 TTL 3600。读取不启动重建或模型维护。

Core `maintenance/admin-status.ts` 承载状态规则与超时转换，Host `modules/admin/maintenance-status.ts` 负责管理员认证和协议。Redis 固定键的 get/CAS 适配由主会话在稳定适配器最小增量集成。

## 证据

- devserver 先运行 Node 行为测试，因缺少目标 Core 模块失败；实现后空值/损坏 JSON、600 秒边界、TTL 和 CAS 失败重读终态转绿。
- Python `compat/tests/test_admin_maintenance_status.py` 直接运行原 handler，合成 Redis 和固定时钟，1/1。
- 最新 Core build 通过。Node 规则、Redis 读写故障协议及两组真实生产 Host 集成合计 5/5，通过、无跳过且正常退出；覆盖管理员认证、真实隔离 Redis 的状态读取/超时写回/TTL，以及旧 expected 的真实 CAS 失败后新终态保留。无 Redis 的另一生产 Host 返回明确 503。
- 五个被测生产/Node 测试文件的本地和 devserver SHA-256 一致；故障协议测试后续增量也重新核对了哈希。构建前核对无并发 Core build。

## 有意修正与限制

Python memory-cleanup handler 读后无锁直接写 stale，可能覆盖并行 Worker 的新进度或终态。Node 使用比较原始值的原子 CAS；失败时只重读权威状态，不以旧快照覆盖新状态。Python 将 stale 写回时的 Redis 异常吞成 idle；Node 对 Redis 读写故障均返回明确 503，避免把不可用显示为没有任务。这两项为有意行为差异，不宣称原 Python 已有这些保护。损坏 JSON 的 idle 行为仍是兼容基线，区别于传输故障。

状态继续来自现有 Python 生产者，不代表重建、预览、应用、LLM 或 Worker 已迁移。真实 Redis 验收使用临时实例的专用逻辑库，先验证固定键不存在，结束仅删除本测试创建的键；未清空默认库。PG 仅用于生产 Host 管理员认证审计的精简表，不是正式全量 schema 或 SQLite 验收。真实部署与跨进程 Worker 生命周期仍待验收。未调用付费 Provider、Docker 或真实用户数据，未提交或推送。
