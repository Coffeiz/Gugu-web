# N2 管理员通知历史与系统日志

## 范围与行为基线

本切片新增以下 Node API，生产组合根由主会话接入真实 Admin guard 和 Core：

- `GET /api/v1/admin/notifications/history`：默认 50 条，钳制为 1..100，仅返回 `created_by=admin` 的通知，时间倒序。
- `DELETE /api/v1/admin/notifications/history/{nid}`：只删除管理员通知；不存在或任务通知均返回 `{ok:true}`，不误删任务通知。
- `GET /api/v1/admin/system-logs`：实际 Python 路径无尾斜杠；默认 200 条，非空级别转换大写精确筛选，时间倒序，保留空 traceback 和 UTC 微秒。

Python 基线为 `backend/app/api/v1/notifications_admin.py`、`system_logs.py` 及对应 SQLAlchemy 模型。未修改 Python 参考代码。

## TDD 与验证

通知历史先新增 Core 行为测试，测试发现阶段曾被未登记分类清单阻止；随后用 devserver 临时独立 Vitest 配置重跑，明确因缺少 `notifications/admin-history` 实现而失败。实现后相同断言通过，随后扩充为正式 schema 定义生成的 SQLite / 隔离 PostgreSQL 合同，两种后端合计 2/2。覆盖管理员/任务通知隔离、时间顺序、limit 钳制、删除幂等及未命中无副作用。

Python 既有 `tests/scheduling/events/test_notifications.py` 串行 4/4；其中直接历史回归验证管理员历史排除任务通知，其余是用户通知读取/清除邻近回归，不宣称直接覆盖管理员删除 handler。

Host 协议单测 1/1；真实 `startServer`、管理员密码登录、隔离 PG 和 Core 的通知查询删除集成 1/1。集成测试使用正式 `tablesSql('postgres').siteNotifications` 定义，认证审计表为仅供本测试的精简表；不代表全量 Python Alembic schema 已验收。首次集成清理仅调用 `app.close()` 导致测试进程未退出，已修正为生产 Host `close()`，重跑正常退出通过；旧测试子进程已精确终止。

系统日志先新增 PG 行为测试，devserver 运行因缺少 Core 模块失败，随后实现转绿 1/1；Host 参数/鉴权协议 1/1。Python 无直接既有 handler pytest，本次在 devserver 临时目录复制原 conftest 复用隔离 SQLite fixture，新增临时对照断言并串行运行 1/1，覆盖级别、倒序、limit=0、空 traceback 和微秒时间。随后将等价行为整理为可复跑的 `compat/tests/test_admin_system_logs.py`，使用独立内存 engine，仅创建 SystemLog 表，不复制测试 conftest；保存版最终运行结果以主会话批次为准。PG 表依据模型建立精简表，未声称生产 schema 或 SQLite Core 已接通。系统日志已加入相同生产 Host 集成夹具，最终 Host 四文件批次正常退出，4/4 通过，无跳过；覆盖通知协议、系统日志 PG、系统日志协议以及生产 Host 的通知和日志读取。执行期间发生明显连接/主机停顿，批次总耗时约 270 秒，不作为性能基准。

## 限制

- 通知广播未迁移：仍缺用户通知与全局广播的完整 Host 实时事件发布契约；本切片没有创建无人消费队列。
- 系统日志仅服务端 PostgreSQL 查询，Core 正式 SQLite schema 不包含 system_logs；不扩展 schema 或宣称双库完成。
- 集成测试通过生产入口装配，不代表已部署服务、真实 SSE/Redis、Worker、桌面或外部服务已验收；未调用付费 Provider 或 Docker。
- 未触及其他会话已有文件内容；共享包导出、组合根及元数据由主会话最小增量集成。未提交、推送或触发 CI。
