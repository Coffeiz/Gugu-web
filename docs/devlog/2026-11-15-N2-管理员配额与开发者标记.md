# N2 管理员配额与开发者标记

## 切片与基线

- `PATCH /api/v1/admin/users/{user_id}/quota`
- `PATCH /api/v1/admin/users/{user_id}/developer`

基线为 `backend/app/api/v1/users_admin.py` 的 `update_quota`、`toggle_developer`：用户不存在先返回 404；配额只处理四个白名单字段，支持 null、Python int 转换和字段各自的下界；开发者标记切换；提交业务数据后写审计。未发现直接覆盖这两个 handler 的既有 pytest，新增可复现的只读参考对照脚本在 `apps/web-host/tests/admin/fixtures/user_settings_python.py`，不修改 Python 实现。

Core 新增 `admin/user-settings.ts`，包含规则和完整事务用例。Host `modules/admin/user-settings.ts` 负责认证、HTTP 和 PostgreSQL 事务接线。此管理员切片的用户模型/锁为 Web 多用户 PostgreSQL 专用，未声称正式 SQLite 接通。

## 验证证据

- devserver 首次执行 Node 规则测试因缺少 `admin/user-settings` 实现失败（ERR_MODULE_NOT_FOUND）；实现后规则 1/1 通过。
- 随后新增实际 PostgreSQL/HTTP 集成回归，2/2 通过：未授权拒绝、非法配额不部分持久化、null/数字转换、用户不存在、其他账号不受影响、开发者标记可逆及提交后审计。该集成测试是在实现后新增，不声称这一部分完整先红后绿。
- Core build 通过。测试使用独立临时 PostgreSQL 的随机 schema 和合成数据，结束删除 schema；未访问真实用户数据库、运行配置或 Provider。
- Python handler 直接对照 1/1，通过内存 SQLite fixture 验证转换、下界及标记切换。直接传字符串 UUID 会触发 SQLite SQLAlchemy UUID 类型适配错误，改用 fixture UUID 对象；因此不将这个对照声称为 Python HTTP 或 PostgreSQL 路径验收。
- 首次 Core 目录级 ripwire quality-delta 无 HEAD/基线，edit-check 报 no-baseline；不能当作有基线的质量门禁。

生产 Host 装配和总回归由主会话集成；真实服务未验收。未修改运行配置、未提交或推送。
