# N2：语音试呼共享前置差异

评估 `POST /api/v1/admin/config/test-voice` 与 `POST /api/v1/admin/agent/voice-presets/test`，本轮没有实现或接入这两条 API，没有调用付费 Provider。

## 已核对的实际链路

Python config handler 会解析临时/已保存 VoiceSettings、遮蔽 key 回退、格式和产品线，生成一秒静音 WAV，再调用真实 `agent.voice.transcribe`。preset handler 还按 preset/provider/URL 验证保存 key 的目的地，Qwen 产品线由模型映射。既有 Core 包含对应 OpenAI、DashScope、MiniMax ASR 适配，HTTP Transport 的 URL/DNS/取消/关闭契约也已存在。

MiniMax 的完整错误 DTO 需要 HTTP 状态、业务码、错误类别、request ID、诊断 ID、message_key/message_params。共享 ASR 在非零 base_resp 时只保留通用 ProviderError；单请求透明捕获响应原本有机会补齐展示，但进一步验证发现请求发出前也有差异，不能只捕获响应解决。

## 有效失败证据

新增独立阻塞对照 `apps/web-host/tests/admin/voice-provider-parity.blocked.ts`，仅在 devserver 显式指定文件单独执行，不被默认 `tests/**/*.test.ts` 收集，不接生产，也不放宽断言或共享安全规则使其通过。首次取证时的文件名带 .test.ts，随后仅改非默认文件名保留原断言和内容。

第一项是**有效语义红灯**：真实 Python MiniMax ASR，使用合成 HTTPX 客户端与合成音频，空 key 经过 `normalize_ascii_api_key` 后仍发出 `Authorization: Bearer `，收到合成 200/text 空串并成功返回；现有共享 Core `transcribeMiniMax` 在任何 Transport request 前返回 authentication，实际请求数为 0。对照断言保留，exit 1。

改为非默认文件名后，补齐 TypeScript 要求的真实 SHA-256 digest 端口，单独选择 MiniMax 项再次执行，仍取得同一份有效请求语义红灯；没有以缺依赖或类型错误作为该结论证据。

第二项拟验证合成本地 HTTP 服务：Python配置试呼 DTO 与 VoiceSettings 都没有 provider 字段，旧 Python OpenAI 客户端支持本地地址；Core 的实际 Node Transport 只有 Host 允许且请求显式标为 local/ollama 时才准许内网。代码已核对，但本轮运行先被隔离 Python 缺 openai SDK 阻断，**不计第二份有效语义红灯**。按本轮优先级没有安装额外依赖或重跑该阻塞。当前执行结果是 2 项失败，其中 1 项为请求语义差异、1 项为测试依赖缺失，不能笼统计成“两项行为已证明不同”。

## 结论和边界

- 请求前拒绝发生时不存在可捕获响应，包装错误展示不足以使 API 等价。
- 不能为了复刻 Python 空 key 行为给共享 ASR 填 dummy key 后篡改 Authorization，也不能凭 URL 猜 local 或给普通云配置开放内网。
- 普通 HTTP/SDK 的异常呈现与 MiniMax 200 包装业务错误仍需完整正式契约。没有改动共享 ProviderError、ASR 或 Transport，也没有依赖旧 Node 域转发。
- 两条 API 保持未迁移。上述 source 差异和未证明范围已交给主会话；等待共享能力或明确目标安全策略统一后再接入。
