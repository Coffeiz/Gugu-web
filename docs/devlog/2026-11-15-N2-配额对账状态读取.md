# N2 配额对账状态读取

新增 `GET /api/v1/admin/storage-quota/reconcile`。只读取现存 Python 扫描任务的权威状态，不启动扫描，不迁移 POST。生产 Host 通过管理员鉴权调用 Core `admin/storage-quota-status.ts`，由 Host Redis 适配读取正式状态键 `storage:quota_reconcile:manual_state` 与锁 `storage:quota_reconcile:lock`。

Python 基线为 `storage_quota_admin.py:_read_state/get_full_reconcile_status`：状态不存在、坏 JSON 或非对象返回 idle；queued/running 且锁消失时写回 interrupted、finished_at 和七天 TTL；Redis 故障返回 503。Node 保留该语义，但有意修复 Python 读后无条件写回的竞态：Lua CAS 同时检查原状态和锁，避免覆盖并发 completed 或新执行锁，冲突时返回最新权威状态。

验证均在 devserver：

- 首次 Core 模块缺失有效红灯后实现规则；生产缺 Redis 500 != 503 有效红灯后，目标 route 捕获明确服务不可用错误，直接回复固定脱敏 503，未改共享错误 handler。
- Node 3/3：规则、真实隔离 Redis 锁丢失/TTL/陈旧写拒绝、生产 main 管理员登录及真实状态、无 Redis 503/未认证401。
- Python 直接真实隔离 Redis 对照 1 项、旧 quota_periodic 回归5项，共6/6。
- 测试保留正式状态键，但使用任务私有 Redis 的独立逻辑数据库，避免文件间并发污染；结束清理精确键。配置和存储位置均为临时目录，未读取或覆盖真实运行配置或用户数据。
- Core build通过。Host 类型检查另受并行 Core 的 ES2023 lib/隐式类型错误影响；本切片重复导入已清理后复验。

本 API 不涉及 SQL，未将其统计为 PG/SQLite 双库迁移；未验收真实扫描、Worker 生命周期或真实部署。未提交、推送或触发 CI。
