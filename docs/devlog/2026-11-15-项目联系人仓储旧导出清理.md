# 项目和联系人仓储旧导出清理

项目和联系人 SQL 仓储已分别位于 `projects/` 与 `clients/`，实际事务装配直接引用对应实现。确认仓库内没有调用方使用通用数据运行时的旧重导出后，移除该两处导出；仓储实现、事务和对外业务协议未改。

本地与 devserver 的 Core 源码摘要一致；devserver Core 构建通过。本轮没有运行数据库回归，此项仅为内部导出清理，不代表项目文件或恢复路径的双库迁移完成。

项目文件计数读取现由 `@gugu/core/project-read-data` 导出，测试调用方已更新并删除 `data` 旧转发；当前生产 Host 仍使用自己的 PostgreSQL 计数读取，不视作共享读取接线完成。devserver Core 构建及临时配置的 SQLite 项目读取回归 7 项通过；3 项隔离 PostgreSQL 用例因未设置测试连接跳过。正式 Core 测试清单入口仍存在未登记文件问题，临时配置已清理。
