# N2 注意力评分沙盒 API 迁移

## 范围

迁移旧 `backend/app/api/v1/dev_attention.py` 的 `POST /api/v1/dev/attention/score`。该接口用合成消息窗口调用生产注意力决策器，供开发诊断使用；输入正文不应出现在响应中。

## 行为基线

- FastAPI 请求模型拒绝额外字段，限制文本、窗口消息、时间和模式取值；未认证请求由 `get_current_user` 拒绝。
- Python handler 用合成事件和已接受的 outbound receipt 构造 `AttentionSnapshot`，调用 `decide_attention`；响应只暴露算法版本、评分证据和事件 ID，不暴露匹配正文。
- 业务行为以 `backend/agent/im/auto_reply/attention_algorithm.py` 与 `backend/tests/api/test_dev_attention.py`、`backend/tests/im/auto_reply/test_attention_algorithm.py` 为基线。本轮已阅读这些源文件，但 devserver 缺项目 pytest 环境，未运行 Python 对照。

## 实现与 TDD

- Core 新增按 `packages/core/src/im/attention/` 业务组织的 scorer、能力证据、话题匹配和沙盒 DTO 适配；规则落在 Core，Host 只负责认证、严格请求校验和 HTTP 响应。
- 先新增 Core 行为测试并在 devserver 运行，Vitest 因缺少 `src/im/attention/algorithm.js` 失败；随后实现 Core 决策链并重跑通过。
- Core attention 及其现有 normalization/question/visible-units 回归共 **5 个文件、18/18 通过**；Host `createApp` 认证、DTO 和真实 Core scorer 回归 **2/2 通过**。Core build 与 Web Host production build 通过。
- 对照 Python 已有代表场景覆盖问句正负例、位置权重、CALL 档位、能力请求准入/拒绝、话题锚点及失效、成员主动 180 秒边界、模式阈值与安全响应。额外在 devserver 直接加载旧 Python 纯算法模块（绕开不相关的 package 初始化依赖），与 Node Core 对六组相同合成输入逐字段比较，六组输出一致；这不是 pytest，也不覆盖 FastAPI handler 全部用例，因此不宣称完整 Python 等价。
- 续轮从 `backend/tests/im/auto_reply/test_attention_algorithm.py` 补齐边界回归：测试先发现未闭合且无换行的围栏文本 ` ```咕咕看吧` 被 Node 判为 CALL（0.92），与 Python 保守截断不符。修复围栏先于行内代码屏蔽后，Core attention 五文件 **23/23**、Host 认证与 DTO **2/2** 通过。旧 Python 全部算法断言通过临时 harness（32 个测试函数），因未安装 pytest 不能记为 pytest 结果。

## 接线与限制

生产代码调用链为 Web Host 认证路由 → `scoreAttentionSandbox` → Core `decideAttention`。此接口只负责开发诊断，不读取真实 IM 数据、Redis 或数据库；本轮未验证真实部署。正式 IM 自动回复生产路径是否采用该 Core scorer，仍需对照生产消费调用方单独验收。
