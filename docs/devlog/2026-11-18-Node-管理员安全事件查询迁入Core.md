# Node 管理员安全事件查询迁入 Core

## 范围

接通旧 Python 的两个只读入口：

- `GET /api/v1/admin/audit-log/security-events`
- `GET /api/v1/admin/users/{user_id}/security-events`

Fastify 保留管理员认证、UUID/limit/since DTO 校验和通用 HTTP 错误映射。筛选、时间窗口、目标用户存在性、owner 查询、排序/限量、字段投影与 UTC 时间格式已移入 `packages/core/src/admin/audit-log.ts`，由 `main.ts` 将 Core Postgres DB 和服务端 HMAC 注入生产 reader。

## 行为基线

对照 `backend/app/api/v1/audit_log.py`、`backend/app/api/v1/users_admin.py`：全局读取默认 1440 分钟/200 条，边界分别为 1–129600 分钟和 1–500 条；筛选字段按 Python 长度限制截断。用户级读取先查用户，缺失返回 404，事件按 `occurred_at` 倒序并限量。两者均不返回 `metadata_json` 或其他数据库扩展字段；全局用户标识由 Host 使用与 Python 相同的 HMAC 指纹替代。

Python `backend/tests/platform/security/test_ownership_security_events.py` 不覆盖这两个 GET handler，只覆盖安全事件写入和 HMAC。本地隔离运行得到 1 通过、2 失败：写入 helper 通过独立 app `SessionLocal` 保存，未连接到该 pytest `db` fixture，故断言查不到刚写入的事件；不把这项结果作为 Node 查询的 Python 对照通过。

## TDD 与验证

Core SQLite 行为测试在实现前因缺少 reader 导出而 2 项失败，随后覆盖窗口/筛选/字段投影/用户指纹与用户存在性/owner/limit，最终 2/2 通过。

Node Fastify 管理员路由、Host 注入和 `startServer` 随机 PostgreSQL schema 集成合批 31/31。真实生产组合测试先应用 `migrate:security-events:apply`，再验证未认证 401、全局筛选和 HMAC、超窗记录排除、用户级 owner 隔离/404、limit/UUID 422、metadata 与原始用户 ID 不泄露。Web Host production TypeScript 检查和 `git diff --check` 通过。

本轮 devserver SSH 探测超时，测试在本地临时 PostgreSQL schema 与临时配置文件执行。Core reader 在真实 SQLite 合同中通过；Web Host 正式 SQLite 组合、真实部署未验收。没有修改 Python 参考后端，也没有暂存或提交。
