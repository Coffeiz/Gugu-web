# 代理模式下模型联网与目标校验边界

桌面端开启「使用系统代理」后，模型请求在本机代理的 Fake IP 模式下被传输层判成非法目标，报 `input_rejected` 且 `transportHop: "dns"`，表现为模型完全无法联网。

根因有两层。本机代理接管 DNS 之后，公网域名会解析到合成地址段（代理默认使用的假 IP 段），传输层按「非公网地址」拒绝；即使改用物理网卡 DHCP DNS 重查，本地网络出口的 DNS 对部分境外域名仍会返回被污染的地址，把它们固定成 CONNECT 目标会连到错误的服务端。代理模式下真正可信的解析方是代理本身：只有把目标域名交给代理端解析，合成或被污染的本地地址才不会影响连通性。

原修复把「走代理」直接等同于「跳过目标校验」。实测这样会让字面私网与回环地址（含云厂商元数据地址）原样转发给代理，形成可由 Agent 触发的 SSRF 通道。现在目标校验分层：字面 IP 目标在任何模式下都必须判定为公网地址；域名目标在本地解析结果全是假 IP 时没有信息量，只拒绝明显的本机名与真实解析出的私网地址，最终解析交给代理端。直连模式的边界保持不变。

另外，未显式配置 CA 时改用 Node 内置根证书集合：部分环境下 Node 的默认信任存储不可用，校验任何站点都报 `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`。内置集合与 Node 默认信任集合内容一致，不引入系统证书库里已被现代浏览器放弃的旧根证书。

回归用例覆盖假 IP + 代理仍可到达代理、代理模式下字面私网与本机主机名仍被拒绝、直连模式边界不放宽。同批次出现的另一处失败用例经隔离对照确认与本次传输层改动无关：其执行路径使用假传输，不经过传输层。
