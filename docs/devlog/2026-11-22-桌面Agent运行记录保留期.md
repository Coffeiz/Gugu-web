# 桌面 Agent 运行记录保留期

桌面本地库的 Agent 运行事件与检查点从建表起就没有任何删除路径：事件消费完只打确认标记，检查点每次提交原地重写，两张表只增不减，运行记录因此持续膨胀。

模型增量改为按块提交。逐条落库会把累积全文和整份检查点反复重写，单轮存储从平方级降到线性级；界面契约不变，展示项仍按同一气泡给出累积全文。

分块提交补齐了游标一致性。用量、诊断和重试事件会推进已提交游标，必须先提交待写增量再推进，否则游标会越过尚未落库的正文；Provider 报错或上下文溢出前同样先提交，已收到的正文尾部不会随运行失败一起丢失。

事件表新增写入时间列，检查点表新增最后提交时间列，历史运行按会话正文时间回填，保证时间基准不为空。保留期清理只回收终态运行的记录，活跃运行、仍绑定在会话上的运行和租约未过期的运行一律跳过；SQLite 删除行后不会自动收缩磁盘，必须额外压缩才能回收空闲页。桌面端在启动后与固定间隔各执行一次，压缩只在空闲页达到阈值时才做。

PostgreSQL 侧的事件与检查点表本来就带写入时间列，因此只补齐同样的保留期清理任务，不新增结构变更。
