# 桌面应用图标生成可复现

桌面打包后的应用图标渲染异常，而仓库里的 `assets/icon.icns` 是一份没有生成脚本的二进制产物：尺寸齐全但无法追溯来源，图标文件与主图标的关系只能靠人工比对。

排查逐层确认图标资产本身没有问题：icns 的每个尺寸块都与主图标同源且为正方形，图形占比与 macOS 圆角图标的惯例一致；打包产物中的 icns 与仓库文件逐字节相同，`Info.plist` 的图标引用与资源位置都正确，打包过程也没有损坏图标。该现象因此无法从仓库内的图标资产复现。

本次补上可复现的生成链路：新增 `apps/desktop/scripts/build-icons.mjs`，按 Apple 的 iconset 规格（16/32/64/128/256/512/1024 及各自的 @2x）用系统自带工具从主图标生成标准 icns，并在打包前自动执行。重新生成的 icns 与原文件结构完全一致（同样 10 个尺寸块、相同顺序与像素），体积更小，从此可以随时重建，而不再依赖提交进来的二进制。
