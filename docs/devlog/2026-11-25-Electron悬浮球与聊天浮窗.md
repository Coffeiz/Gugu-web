# Electron 悬浮球与聊天浮窗

记录 2026-11-24 至 2026-11-25 桌面悬浮球和聊天浮窗的实现、回归与验证。相关代码位于 `apps/desktop/src/main/chat-fab-window.ts`、`apps/desktop/src/main/index.ts` 和 `apps/ui/src/desktop/chat-fab/`。

## 窗口归属与焦点

- 悬浮球和聊天面板各有一个原生窗口。停靠时作为主窗口的子窗口，随主窗移动、最小化和恢复。脱离后独立置顶，聊天面板继续复用共享聊天组件和本地会话服务。
- 早期点击脱离态球会恢复主窗口里的聊天。改成打开独立面板后，显式聚焦面板和应用级 `activate` 回调仍是可能唤起主窗的路径。macOS 上脱离态打开使用 `showInactive()`，跳过自动聚焦，两个浮窗使用 Electron 的 `panel` 类型。独立窗口可见时，应用激活回调跳过工作台恢复。托盘等显式打开路径仍可打开主窗。
- 回停靠前先取消浮窗的置顶，再挂回主窗口，避免在仍处于浮动层时建立父子关系。此前收到过「整个主窗似乎置顶」的反馈，尚未单独验证这一顺序是否是其根因。
- 用户进一步定位到，关闭聊天动画时把鼠标移入主 App 会把主窗拉到前台。关闭期间现在暂停透明区域的鼠标穿透，直到浮窗隐藏，并取消额外的鼠标移动转发。用户确认此场景修复。系统内部实际怎样完成焦点交接尚未独立确认。

## 手势、停靠与动画

- 快速拖动后松手曾出现球弹回原位。拖动 IPC 改为携带按下、移动和松手时各自的屏幕坐标，松手后才切换原生父窗口，以免在手势中途影响指针捕获。
- 拖动和吸附时，球和可见聊天框一起平移。macOS 可能限制原生视口的实际位置，按请求位移累计会让面板与球越拖越偏。现在以球的初始相对锚点和实际窗口边界计算内容偏移。拖入 App 松手后，回到主窗右下角的停靠布局。紧凑面板按球的可见右边对齐，位于球上方时留 10 px 间距。
- 打开和关闭曾缺少动画或重复播放，焦点也会落在缩放按钮。现在由共享聊天组件负责开合，原生窗口先非激活显示，入场后再按窗口模式处理焦点，退场完成后才隐藏。重复点击与旧的退场消息有独立状态判断。交接时避免应用内面板和独立面板同时显示，去掉叠加的原生外阴影。
- 展开与收起原先逐帧同时改原生窗口的位置和尺寸，Electron 与 Chromium 更新不同步时会出现向左上角飞、只显示中间一条、缩小后消失一帧等现象。切换期间使用共享的原生视口，渲染层用同一段 420 ms 动画插值可见面板的边缘和尺寸。
- 原生采样复现了首次拖出后展开的时序差异，窗口大小和屏幕坐标在不同帧变化。把扩容推到松手时又在交接处产生了同类裁切。当前在停靠的紧凑窗提前预留脱离展开空间，交接尽量复用现有视口。预留视口按脱离态边缘计算，避免展开动画结束时再为启用拖边而收边一次。

## 独立窗口尺寸与材质

- App 内展开沿用原本的布局比例。App 外默认宽度按当前屏幕可用高度的 68% 计算，高度按 78% 计算，并结合可用空间裁定。仅脱离态展开窗支持原生拖边缩放，常规最小尺寸为 480 × 360。紧凑态保持固定尺寸，展开结束后系统缩放边缘贴合可见面板。
- App 外可抓标题栏空白处移动，球随面板移动。原生手动缩放时以面板右下角的相对偏移更新球，目标位置相同时跳过移动。曾尝试拦截缩放提案并重写原生窗口边界，以及添加 CSS 宽高限制来消除快速缩放裁切。用户反馈效果不明显，这两类补丁已撤掉。主窗口缩放稳定，独立透明窗口的合成及悬浮球跟随是待区分的变量。
- CSS 的 `backdrop-filter` 只能采样渲染器能看到的背景。脱离态的 macOS 球使用 `apps/desktop/native/chat-fab-glass.mm` 的圆形 AppKit 毛玻璃，停靠后切回共享球样式。

## 首开性能与验证

- 球就绪后后台预热独立聊天渲染器。隔离 macOS Electron 环境中，冷启动和已预热各测三次，从触发打开到面板首次出现的中位数为 742 ms 和 39 ms。指标不包含预热本身的耗时，也不代表消息发送或后端响应耗时。
- `apps/desktop/tests/chat-fab-window.test.ts` 的四项回归覆盖窗口归属、拖动和吸附、首次展开、原生缩放边缘、开合焦点与鼠标穿透。macOS 原生冒烟使用模拟手势，验证过拖出松手前后的边界、返回停靠坐标和展开时的 DOM 帧几何。最近一次首次展开采样为 94 帧，面板均在原生视口内。
- 坐标和 DOM 采样无法覆盖系统合成器的全部画面，也无法替代真实鼠标快速拖边和跨屏复核。快速手动缩放的偶发裁切未确认消失。麦克风权限曾被提及，用户随后撤回该排查，本记录未形成录音故障结论。
