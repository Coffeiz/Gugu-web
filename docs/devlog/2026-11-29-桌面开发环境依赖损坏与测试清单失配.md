# 桌面开发环境依赖损坏与 Core 测试清单失配

> 排查日期：2026-11-29
> 排查环境：本地开发机（桌面预览实例）
> 排查对象：`apps/desktop` 的 `npm run dev` 启动失败，以及 Core 回归套件无法启动
> 排查目的：记录构建报 `TS2688` 的真实根因，以及同一时间暴露的两处清单/用例失配

---

## 现象

桌面开发启动在构建阶段中止：

```
> gugu-desktop@0.2.0 dev
> node scripts/dev/dev.mjs

error TS2688: Cannot find type definition file for 'node'.
  The file is in the program because:
    Entry point of type library 'node' specified in compilerOptions
桌面构建失败
```

Core 回归同时完全无法启动，与 TS 报错无关：

```
Error: Core 测试发现与分类清单不一致，请登记或清理 tests/suites.json
```

## 根因

### 依赖目录内容缺失（TS2688）

pnpm 虚拟目录 `node_modules/.pnpm` 中有 383 个包的内容为空目录，其中包含本仓库锁定的 `@types/node@26.6.6`。`packages/core/tsconfig.json` 与 `packages/database/tsconfig.json` 都声明了 `types: ["node"]`，类型包解析不到，编译在第一步就以 TS2688 中止。

包索引仍然完整、内容却为空，说明上一次安装过程被中断或被外部清理过；后续安装因为索引看起来齐全而没有补齐内容。同一虚拟目录里的其它包（如 `@types/node` 的旧版本）内容完好，佐证这是部分损坏而不是整体重装。

### 测试清单失配

`packages/core/tests/suites.json` 要求与实际发现结果完全一致，而两个新增测试没有登记：

- `packages/core/tests/runtime/desktop-host-shell.test.ts`
- `packages/core/tests/runtime/windows-output.test.ts`

两者由「完善 Windows 桌面体验与共享交互」提交引入，但该提交没有同步清单。清单校验在加载 Vitest 配置时执行，因此 unit / integration / ipc 等所有 Core 套件都会直接失败，而不是只跳过这两个文件。

### 桌面群媒体用例落后于实现

`apps/desktop/tests/im-attachment-delivery.test.ts` 断言 QQ 媒体发送的入参形状，而同一批改动已让实现带上回复序号与失败回调，用例未同步，导致该用例自 21:45 那次提交起持续失败。

## 处理

- 依赖修复：用仓库锁定的 pnpm 版本在 Node 26 下重新安装，1248 个包中 1245 个从本地 store 复用、零下载完成重建；`@types/node@26.6.6` 内容恢复，`better-sqlite3`、`esbuild`、`node-pty` 的本地二进制在安装后逐一验证可加载。
- 清单补登记：两个运行时测试按各自行为归类（前者起真实进程标记 `process`、L2；后者是纯解码逻辑、L1）写入 `packages/core/tests/suites.json`，Core 套件恢复可启动。
- 用例同步：`apps/desktop/tests/im-attachment-delivery.test.ts` 改为断言当前 QQ 媒体契约（目标带回复消息 ID、文件信息含文件名与图片标记、失败回调透传），不再断言已移除的旧入参形状。
- 测试元数据：`docs/testing/metadata/` 下补登记同一批新增测试，`pnpm test:metadata` 校验通过。

## 验证

- `packages/core` 9 个共享包 + 桌面宿主打包全部编译通过，桌面开发启动成功，Vite 预览页可访问、Electron 主进程正常拉起。
- `packages/core/tests/im/desktop-inbox.test.ts` 通过（14 项），其中「QQ群文字请求可以发送同群历史附件，拒绝其他群的附件」在移除历史附件放行条件后会失败，确认该用例有效。
- `apps/desktop/tests/im-attachment-delivery.test.ts` 通过（3 项）。

## 遗留

Core unit 与桌面套件仍有若干既有失败用例，与本次改动无关（例如可移植目录边界用例要求 `packages/core/src/shared`、`packages/core/src/projects` 不引入 Node 内置模块，而现有源码已引入）。这些属于仓库既有状态，未在本次排查中处理。
