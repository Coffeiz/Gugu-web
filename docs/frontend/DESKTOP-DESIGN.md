# 咕咕桌面端视觉与层级规范

本文规定 Electron 桌面端的窗口表面层级、层间距离、玻璃材质和浮层边界。看板、日历、笔记、画布等领域内容继续复用 Web 的页面、组件和交互；本规范只约束桌面 Shell 和跨页面的桌面呈现，不为桌面复制一套领域视觉。

## 1. 设计原则

- 桌面界面按由后向前的 L0–L5 组织。L 编号表达视觉与交互层级，不等同于全局 `z-index` 数值。
- L0–L3 是常驻窗口结构；L4、L5 是临时或浮动层，目前只定义目标边界，具体窗口化和拖拽能力待后续需求确认。
- 同一层内使用明确的组件 owner 和局部 stacking context。禁止依赖不断增加的全局 `z-index` 修补遮挡问题。
- 主题、色板、间距、圆角、描边、阴影优先消费 Web 已有 design token。桌面 Shell 可以有独立几何，但不应另造一套领域卡片颜色和状态规则。
- 常驻层用色调、边框、阴影和少量模糊建立区分；模糊不能代替足够的文字对比度。

## 2. L0–L5 层级

| 层 | 名称 | 内容与职责 | 表面规则 |
|---|---|---|---|
| **L0** | 窗口底层 | Electron 窗口下方的系统桌面材质与应用底色，是所有应用 UI 的背景。 | macOS Vibrancy、Windows Acrylic 等平台材质由系统负责模糊；应用叠加主题色 tint。桌面 Shell 的 tint 目标为**最终 50% 不透明度**，颜色取当前主题的表面色。Renderer 根 Shell 不叠加 `backdrop-filter`，避免建立 backdrop root 后影响 L4 遮罩采样页面内容。最终 alpha 要按颜色通道计算，不能把半透明 token 再乘 50% 后误当成 50%。 |
| **L1** | 桌面全局 Chrome | 持续存在的主导航和顶栏，包括搜索、当前页操作、窗口拖动区域。 | 导航与顶栏共享 L1 几何，不额外铺不透明大面板；通过透明材质、细分隔和选中态建立可读性。顶栏拖动区域可跨到导航上方，交互控件使用 `no-drag`；导航项不得被拖动区拦截。 |
| **L2** | 页面工作区 | 当前路由的页面容器，承载 Web 复用页面及其工具栏、主内容、侧栏。 | 容器边界应清楚、滚动归属稳定。项目、日历、笔记和画布页面从统一 Shell 间距令牌取得外边距；具体业务布局沿用 Web 的成熟结构。 |
| **L3** | 内容表面 | L2 内具有独立信息分组的内容 glass，例如看板状态列、项目卡片、日历信息卡、笔记和画布元素。 | 复用 Web 的组件、状态、颜色及 `--surface-*` / `--project-card-*` 等令牌。L3 只在需要分组或承载交互时出现；不要给所有内容再套一层卡片。 |
| **L4** | 临时浮层（暂定） | 菜单、日期选择、搜索结果、对话框、上下文菜单等临时界面。 | 通过统一 overlay root 和公共弹层组件绘制，遮罩、焦点、Escape 和点击外部关闭遵循现有公共交互契约。未来可评估将部分浮层变成可拖动的独立面板；目前不要求独立窗口。 |
| **L5** | 咕咕球 / 助手浮层（暂定） | 全局助手入口与展开后的对话或任务面板，优先级高于页面内容和普通浮层。 | 未来可作为独立浮动层，让用户拖动和定位；需要单独确定窗口生命周期、置顶范围、跨屏、焦点和键盘行为。当前 L5 是预留设计层，不代表已有实现或默认置顶窗口。 |

### 层级关系

```text
L5  咕咕球 / 助手浮层（未来候选）
L4  菜单、弹窗、搜索和上下文浮层（当前统一 overlay；独立窗待定）
L3  项目、日历、笔记、画布等内容表面
L2  当前页面工作区
L1  顶栏 + 主导航
L0  系统窗口材质 + 应用背景 tint
```

L4/L5 若未来支持用户拖动，优先在产品交互明确后评估独立浮动面板或窗口；不能仅通过提高 DOM `z-index` 模拟跨窗口能力。普通弹层仍留在 L4 overlay root 中，避免每个弹层各自创建原生窗口。

## 3. 桌面间距规则

全局距离使用 `apps/web/src/assets/styles/tokens/primitives.css` 中现有 `--space-*` 令牌。桌面 Chrome 与页面容器的外层距离统一使用小距离令牌，页面内领域布局不因本规则被重排。

| 距离 | 规范 | 说明 |
|---|---|---|
| **L1 到 L0 窗口边缘** | `--space-sm`（8px） | L1 可视表面与 L0 窗口边缘保持一致的小间距。macOS 交通灯、Windows 系统按钮及窗口拖动安全区由平台 Chrome 保留，不压入交互控件。 |
| **L2 到 L1** | `--space-sm`（8px） | 页面工作区与顶栏、导航保持紧凑间距，避免项目页、日历页等分别写不同 margin。侧栏宽度变化不改变此间距。 |
| **L3 到 L2** | `--space-lg`（16px） | 页面工作区边缘到其中主要内容表面的默认间距，统一由 L2 内边距提供。若复用的 Web 页面已有清楚的容器内边距，不重复叠加；以最终可见间距为准。 |
| **L3 之间** | 默认 `--space-md`（12px），需要宽松分组时用 `--space-lg`（16px） | 网格、看板列间距和内容卡片间距优先使用现有页面令牌；密集控件可用 `--space-sm`。不使用未命名的零散像素值。 |

### 间距验收

- 主导航展开、收窄和图标模式下，L1 到 L0、L2 到 L1 的外层距离保持不变；仅导航列宽和内容可用宽度变化。
- 项目、日历、便签、画布及工作台开发页使用相同 L2 外边距；工作台的内部表单或测试组件可保留自己的领域间距。
- 页面滚动时，L0/L1 不随页面内容滚动；滚动容器边界应位于 L2 内。
- 弹层打开时，L4/L5 的视觉层级不能破坏 L1 导航、L2 页面内容的焦点与关闭行为。

## 4. 材质、对比度与主题

- L0 色相从 `--surface-card-solid` 等主题表面 token 取值，最终 alpha 单独控制为 50%；禁止固定写死浅色导致暗色主题发白。
- L0 背景模糊由平台窗口材质提供；Renderer 根 Shell 只绘制主题 tint，不额外重复模糊。L1 透明 chrome 通过 L0 材质获得背景玻璃感，按钮、选中态和搜索框仍使用各自现有组件 token。
- L2 页面容器使用统一页面表面 token；L3 业务内容保持 Web 的实际主题规则。不得在 Desktop Shell 上对整个 L2 内容叠加 opacity，否则文字和控件会一起变淡。
- L4 遮罩与浮层表面使用统一 popup/modal token。遮罩负责压低背景干扰，不能只依赖高 blur 让背景仍清晰可读。
- 每项材质调整都要检查 Aero/Mono、Light/Dark 和支持的色板，至少在浏览器开发预览中确认文字对比、层次和模糊实际渲染。

## 5. 实现边界

- 桌面 Shell：`apps/desktop/src/ui/shell/` 拥有 L0/L1/L2 桌面框架、间距和窗口拖动区域。
- 领域页面：`apps/desktop/src/ui/{project,calendar,workspace,...}/` 负责桌面装配；领域组件和业务行为优先复用 Web 实现，不在 Shell 复制卡片和弹层逻辑。
- 平台窗口材质：Electron Main 窗口配置只声明平台能力；最终颜色与透明层由 UI token 控制，不在 Main 和 Renderer 各叠一层不透明 tint。
- Overlay：普通弹层使用公共组件并挂到 L4 root；独立浮动窗口属于 L4/L5 后续平台能力，必须经产品交互与窗口安全边界评审后实施。
- 几何变更以 token 和 Shell 规则为主。页面临时覆盖必须说明例外原因，并保证 Web 入口不被桌面样式污染。
