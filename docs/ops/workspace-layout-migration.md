# 工作区目录布局迁移

本地存储统一采用 `users/<用户ID>/workspace/<目录段>/`。默认目录段为 `default`，英文命名工作区使用小写段名，例如 `qq`；无法生成有效段名或出现重名时使用 ID 区分。目录段创建后冻结，修改显示名不会移动文件或改变 Shell 路径。

旧默认目录中的全部内容（包括未登记的 Shell 文件）整体移入 `workspace/default`；旧命名工作区整体移入 `workspace/<目录段>`。同步更新目录元数据、文件及聊天附件的存储 key。个人文件和项目文件的原有物理根不变。

## 升级时执行

先备份数据库与完整存储目录，再停止使用该存储的 Web、Worker、Gateway、Shell/PTY 和沙盒任务。迁移锁只防止迁移进程互相竞争，不能替代停服。

裸机部署在数据库升级后、启动服务前执行：

```sh
cd backend
make workspace-layout-plan
make workspace-layout-migrate SERVICES_STOPPED=1
```

普通 `make migrate` 不自动移动文件，避免在服务仍运行时改名。下一版本镜像的 Web 启动入口会在数据库升级后、接收流量前调用同一迁移脚本；共享存储的其他旧服务和沙盒必须先停止。对象存储不执行本地目录迁移。

## 恢复与校验

迁移先保存带时间戳的原始元数据与移动计划，再通过同盘目录改名保留文件内容、权限和 inode。此计划不是完整的数据备份。源目录符号链接、路径越界、目标冲突或目录身份改变会停止迁移，不覆盖目标文件。

中断后保持停服，重跑同一命令即可续跑；不要手动删除迁移清单或暂存目录。完成后的重复执行不会再次嵌套 `default`。校验文件库读写、回收站还原及 Shell 默认/命名工作区后再开放服务。包含绝对路径的虚拟环境或自定义脚本可能需要调整路径。
