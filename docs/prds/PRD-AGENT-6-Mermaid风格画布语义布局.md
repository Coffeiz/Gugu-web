# PRD-AGENT-6：Mermaid 风格画布语义布局

> 状态：草案，待评审
> 创建：2026-08-31
> 关联文档：[`【已完成】PRD-AGENT-2-思维画布咕咕工具.md`](./【已完成】PRD-AGENT-2-思维画布咕咕工具.md)、[`思维面板/咕咕工具设计.md`](../product/_archibe/思维面板/咕咕工具设计.md)、[`思维面板/数据模型草案.md`](../product/_archibe/思维面板/数据模型草案.md)

## 版本阶段

### Phase 1：抽取布局引擎（本期）

目标是在不改变现有画布行为的前提下，先把当前分散在 Agent 工具和批处理流程中的自动排布逻辑抽成独立布局引擎。该阶段不引入 Mermaid DSL，也不自动重排已有画布。

范围：

- 统一 `auto`、`viewport_*`、`near_node` 等位置锚点解析；
- 统一节点类型的默认尺寸、有效尺寸和安全间距；
- 统一已有节点/同批节点的矩形碰撞检测与找空位策略；
- 统一单个创建、批量创建和引用节点创建的自动排布入口；
- 统一按卡片中心计算关系端点，避免模型根据节点 ID 或旧快照猜测左右；
- 输出可测试、可审计的布局结果和警告，但保持现有工具返回契约兼容；
- 保留用户明确提供的 `x/y`、手动拖拽和显式回环端点，不让自动布局覆盖它们。

交付边界：

- 新增独立的 `CanvasLayoutEngine`（建议位于 `backend/app/services/canvas_layout.py`）；
- `mind_canvas.py` 只负责工具参数校验、权限和流程编排；
- `mind_canvas_batch.py` 只负责事务与幂等，不再复制位置计算；
- 增加位置锚点、尺寸、碰撞、分页创建和连接端点的回归测试；
- 清理旧的重复常量、重复碰撞逻辑和要求模型自行计算端点的提示词。

验收标准：

1. 单项创建与批量创建在相同输入下得到一致的自动位置。
2. 自动位置不会与已有卡片或同批卡片重叠，并满足统一安全间距。
3. 普通连接不传端点时，左卡片使用 `right`、右卡片使用 `left`；节点 ID 顺序变化不影响结果。
4. 用户明确指定的位置和回环端点保持不变。
5. 现有画布 API、前端手动拖拽和历史数据无需迁移即可继续工作。

### Phase 2：声明式关系计划

在 Phase 1 稳定后，再引入 Mermaid 风格的关系 DSL、布局计划预览和确认应用流程。模型只输出关系、方向、层级和锚点意图，布局引擎负责生成最终坐标。

### Phase 3：增量布局与质量优化

在计划能力稳定后，再评估 ELK/Dagre 等分层布局策略、固定节点、连线交叉最小化、质量评分和局部重排。

## 1. 易读概述

### 1.1 要解决的问题

当前咕咕建立画布关系时，模型需要同时判断：

- 哪些节点应该连接；
- 节点在画布中的具体坐标；
- 节点的左右端点；
- 关系是否会穿过其它卡片；
- 整体布局是否拥挤或难以阅读。

这些职责混在一次工具调用中，模型容易把节点 ID 顺序误当成空间方向，也容易生成坐标合理但视觉混乱的画布。尤其是 `source_side`、`target_side` 属于渲染细节，不适合由模型直接决定。

### 1.2 方案摘要

采用 Mermaid 风格的声明式画布计划：

```text
模型：输出节点关系和布局意图
    ↓
布局引擎：根据关系、卡片尺寸和约束计算坐标
    ↓
画布 Runtime：渲染节点、端点和连接线
```

模型只描述“谁和谁连接、图从哪里开始、节点处于哪一层/哪一列”，不再直接输出像素级 `x/y` 或连接点。系统根据用户当前相机中心、已有节点和卡片实际尺寸生成最终布局。

## 2. 目标与非目标

### 2.1 目标

1. 让模型主要负责图的语义结构，而不是几何细节。
2. 让系统统一计算节点坐标、连接点和连线几何。
3. 支持以用户当前相机中心作为新增布局的锚点。
4. 支持模型表达中心节点、层级、方向、同层顺序和间距意图。
5. 保留用户已有的手动布局；没有明确整理要求时不得重排整张画布。
6. 减少卡片重叠、连线交叉和绕行过长的问题。
7. 保留同一端口连接多个不同节点的能力，并只对完全相同的连接去重。
8. 让布局计划可以在实际写入前被读取、展示和确认。

### 2.2 非目标

- 不直接把 Mermaid SVG 当作画布卡片渲染层。
- 不让模型继续输出最终 `x/y`、`source_side` 或 `target_side`。
- 不在用户没有要求时自动移动已有卡片。
- 不用自动布局覆盖用户手动调整过的节点。
- 不把复杂语义关系推断、知识图谱和画布布局绑定在一起。
- 不改变现有画布卡片、关系数据和前端拖拽交互的基本语义。

## 3. 核心设计原则

### 3.1 模型输出意图，系统输出几何

模型输出关系图和有限的布局约束；布局引擎负责将其转换为实际的 `MindCanvasItem.x/y`、连接端点和连线路径。

### 3.2 关系结构与视觉布局分离

关系结构是语义事实，例如 `A -> B`。卡片位置、端点和曲线路径是画布视图状态。重新布局不能改变关系语义，调整端点也不能改变关系语义。

### 3.3 以相机为局部锚点

“放在当前视野中心”使用用户最近保存的 `camera` 和 `viewport`，只作为布局原点或中心区域，不把屏幕坐标直接写入世界坐标。

### 3.4 已有布局优先

默认采用增量布局：

- 已有节点保持原位置；
- 新节点围绕指定锚点布局；
- 只有用户明确说“整理、重新排版、自动布局”时，才允许对指定范围重排；
- 用户手动拖过的节点需要有 `pinned` 或等价保护标记，自动布局不得覆盖。

## 4. Mermaid 风格画布计划

### 4.1 计划结构

模型生成内部结构化计划，不直接生成 Markdown 字符串：

```ts
type CanvasLayoutPlan = {
  canvas_id: number
  anchor: {
    type: "viewport_center" | "node" | "canvas_center"
    node_id?: number
  }
  direction: "LR" | "RL" | "TB" | "BT"
  layout: {
    rank_sep?: number
    node_sep?: number
    avoid_crossing?: boolean
    preserve_existing?: boolean
  }
  nodes: Array<{
    node_id: number
    rank?: number
    order?: number
    zone?: "left" | "center" | "right" | "top" | "bottom"
    pinned?: boolean
  }>
  relations: Array<{
    source_node_id: number
    target_node_id: number
    label?: string
  }>
}
```

`relations` 是 Mermaid 风格的图结构；`rank/order/zone` 是软约束，不是最终像素坐标。`pinned` 只能保护已确认的位置，不能让模型借此写入任意坐标。

### 4.2 典型示例

```json
{
  "canvas_id": 161,
  "anchor": {"type": "viewport_center"},
  "direction": "LR",
  "layout": {
    "rank_sep": 180,
    "node_sep": 80,
    "avoid_crossing": true,
    "preserve_existing": true
  },
  "nodes": [
    {"node_id": 525, "rank": 0, "order": 0},
    {"node_id": 526, "rank": 1, "order": 0},
    {"node_id": 527, "rank": 1, "order": 1}
  ],
  "relations": [
    {"source_node_id": 525, "target_node_id": 526},
    {"source_node_id": 525, "target_node_id": 527}
  ]
}
```

### 4.3 计划校验

服务端或布局适配器必须校验：

- 节点属于当前用户且位于目标画布；
- 关系两端均在计划节点集合中；
- 不允许自连接；
- `direction`、`anchor.type` 和布局参数在枚举/边界内；
- 不接受模型传入最终 `x/y` 或端点字段；
- 关系去重遵循现有 `related` 语义；同一端口连接不同节点不视为重复。

## 5. 布局引擎职责

### 5.1 输入

布局引擎读取：

- 画布计划中的节点、关系和软约束；
- 当前画布节点位置、实际/默认尺寸和保护状态；
- 用户最近保存的 camera/viewport；
- 画布安全间距和最小中心距离；
- 已有关系及其端点视图状态。

### 5.2 输出

布局引擎输出一个可审计的布局结果：

```json
{
  "anchor": {"x": 840, "y": 420},
  "nodes": [
    {"node_id": 525, "x": 716, "y": 346, "changed": false},
    {"node_id": 526, "x": 1140, "y": 346, "changed": true}
  ],
  "relations": [
    {
      "relation_id": 852,
      "source_side": "right",
      "target_side": "left",
      "crossing_count": 0
    }
  ],
  "warnings": []
}
```

系统负责：

- 按卡片矩形尺寸避让，而不是把节点当成无尺寸的点；
- 计算层间距、同层间距和安全边距；
- 根据节点中心位置选择相向端点；
- 对同侧连接、回环和多线保留显式关系，不强行改成默认方向；
- 统计连线交叉、过长绕行和节点重叠，作为布局质量指标；
- 在部分节点被固定时只调整未固定节点。

### 5.3 Mermaid、Dagre 与 ELK 的边界

Mermaid 风格语法适合作为模型和布局层之间的关系 DSL，但 Mermaid 本身不应成为现有画布的最终渲染器。实现时可优先评估 ELK.js 或现有布局 Runtime：

- Mermaid 兼容结构：便于模型表达和调试；
- ELK/Dagre 或现有 Runtime：负责不同卡片尺寸、固定节点、增量布局和交叉最小化；
- 现有 Vue 画布：继续负责拖拽、缩放、连接交互和最终渲染。

## 6. 工具与数据边界

### 6.1 读取

现有 `canvas_get` 继续作为事实读取入口，并提供：

- 全部或分页节点；
- 节点位置、有效尺寸和保护状态；
- 全部关系；
- 当前 camera/viewport；
- `relation_audit` 的推荐端点、当前端点和异常摘要。

当画布超过单页限制时，必须提供明确的 `total/truncated/next_offset` 或一次性的完整图摘要，不能把部分节点快照描述成全景状态。

### 6.2 计划与布局

建议新增只读计划工具和受确认保护的写入工具：

```ts
canvas_plan_layout(plan: CanvasLayoutPlan)
canvas_apply_layout(plan_id: string, confirm_token: string)
```

第一阶段可以先在现有 `canvas_batch` 之上实现适配器，不立即新增持久化表。计划应包含稳定 `plan_id`、输入快照版本和结果摘要，防止用户确认后基于过期画布覆盖新位置。

### 6.3 现有工具兼容

- `canvas_connect` 仍可处理用户明确指定的单条关系；模型自动布局流程优先使用计划工具。
- `canvas_update_anchor` 保留给用户调整或布局引擎写入端点，不再由模型直接猜测左右端点。
- `canvas_update_node` 继续支持用户明确指定的单卡移动；自动布局写入需带计划版本和变更范围。
- 现有 `MindRelation`、`MindCanvasItem` 和 `data_json.relationAnchors` 的存储语义保持兼容。

## 7. 交互与确认规则

### 7.1 只读评估

用户说“看看是否需要整理”“评估一下布局”“检查连线”时：

1. 只调用 `canvas_get` 或计划生成工具；
2. 输出节点数、关系数、截断状态和质量问题；
3. 只展示建议变更，不调用移动、改端点或删除工具。

### 7.2 明确整理

用户明确要求整理时：

1. 读取最新画布快照；
2. 生成布局计划和变更摘要；
3. 如果会移动已有节点或改变已有端点，先请求确认；
4. 应用计划；
5. 重新读取快照，逐项核对节点、关系、端点和警告。

### 7.3 不可声称未验证的结果

模型不得根据单条写入结果声称“整张画布已验证”“其它关系未受影响”。验证报告必须引用实际读取到的完整范围、快照版本和逐项结果。

## 8. 实施阶段

### Phase 0：协议与数据审计

- 确认 `canvas_get` 的完整快照、分页和关系端点返回契约；
- 清点前端测量尺寸、固定节点和现有布局状态；
- 明确 `canvas_batch` 与计划工具的事务边界；
- 输出 Mermaid 风格计划的 JSON Schema。

### Phase 1：声明式计划与本地布局

- 新增计划解析、校验和结果摘要；
- 接入现有尺寸和安全间距计算；
- 先实现 LR/RL 两种方向；
- 支持 viewport center、节点锚点和 preserve existing；
- 不改变现有手动拖拽路径。

### Phase 2：关系质量与增量布局

- 统计交叉数、绕行长度、重叠和超出视野；
- 支持固定节点和局部重排；
- 对同端口多线和回环保留显式布局；
- 增加计划过期检测和幂等应用。

### Phase 3：模型接入与人工确认

- 将模型的画布整理流程切换为“读取 → 计划 → 确认 → 应用 → 复查”；
- 在工具描述中只暴露语义结构和布局意图；
- 对旧版直接 `canvas_connect` 调用保留兼容；
- 完成 devserver 实际画布回归。

## 9. 测试与验收

### 9.1 协议测试

- 计划拒绝未知节点、跨画布节点、自连接和非法布局参数；
- 计划不接受模型直接传入 `x/y/source_side/target_side`；
- 同一端口连接多个不同节点不会被错误去重；
- 完全相同的关系和端点组合保持幂等。

### 9.2 布局测试

- 左右层级图默认生成相向端点；
- 节点 ID 顺序与空间左右顺序相反时仍按坐标布局；
- 不同尺寸卡片不会重叠；
- 固定节点位置不变，未固定节点可局部重排；
- viewport center 锚点转换为世界坐标正确；
- 回环和同侧端点不被自动归一成相向端点。

### 9.3 流程测试

- 只读评估不产生写操作；
- 应用布局前能看到变更摘要；
- 应用后重新读取并核对所有受影响节点和关系；
- 过期计划被拒绝，不覆盖用户之后的拖拽结果；
- 18、50、100 个节点的完整快照和分页结果不会被错误描述为“全景”。

### 9.4 人工验收

- 以当前相机中心创建一组 5–10 个节点的层级图；
- 验证左右、上下混排时连线不穿卡；
- 验证一张卡片同一方向连接多个节点；
- 验证已有手动布局在普通新增和只读检查中不被移动；
- 验证用户明确要求整理后，计划、确认、应用和复查四步均可见。

## 10. 风险与取舍

| 风险 | 处理方式 |
|---|---|
| Mermaid 布局能力不足以覆盖自由画布 | Mermaid 只作为 DSL；最终布局由 ELK/Dagre 或现有 Runtime 完成 |
| 自动布局覆盖用户精心摆放的卡片 | 默认 preserve existing，并增加 pinned/范围保护 |
| 大画布输入过长 | 分页读取 + 几何摘要 + 按需生成全景预览 |
| 模型仍输出旧版端点字段 | Schema 拒绝并给出修正提示，保留旧工具的显式人工调用兼容 |
| 计划生成后画布被用户修改 | 绑定快照版本，应用前重新校验，冲突时要求重新规划 |

## 11. 完成标准

- 模型的自动画布流程不再要求输出最终卡片坐标和连接端点；
- 布局引擎能根据关系结构、卡片尺寸、相机中心和约束生成可解释结果；
- 现有手动拖拽、缩放、关系保存和多线语义保持兼容；
- 只读检查不会修改画布；
- 布局应用前后都有可核对的计划和结果；
- 相关后端、前端和 devserver 回归通过。
