# PRD-AGENT-8：可组合上下文与子 Agent 运行时

> 状态：规划。创建：2026-11-17。
> 关联：`docs/refactor/Gugu-2.0-架构说明.md`、`docs/refactor/Gugu-2.0-迁移任务清单.md`、`docs/prds/PRD-AGENT-7-目标任务生命周期与续跑.md`。

## 1. 背景

2.0 的 Agent Runner 已通过 `ContextPort` 接收上下文，Core 有上下文准备、历史、快照和 RAG 等能力。当前 Web 主 Agent 的部分系统提示词拼装、记忆与业务概览格式化仍位于 Web Host，默认 builder 也将多种来源组合为一套流程。它们需要收敛到 Core，才能供桌面和未来的 Agent 类型复用。

用户希望主 Agent 和子 Agent 共享运行内核，同时按各自任务选择系统提示词、记忆、历史和其他上下文。子 Agent 应支持自定义系统提示词，默认没有长期记忆，专注执行父任务交给它的工作。

旧 Python Runner 在 `use_skill` 后根据 Skill 的 `related_tools` 将关联工具 Schema 注入后续上下文，并保留 `get_tool_schema` 单独发现工具。Node Core 已有 Skill 元数据及相关工具，但自动注入链和生产 Run 接线仍待核实和完成；Skill 关联关系不代表执行授权。

## 2. 目标和范围

- 提供可组合的系统提示词和上下文来源 API，允许 Agent 的创建方按需选择内容与顺序。
- 将跨端可复用的 Agent runtime、上下文规则及格式化逻辑放入 `packages/core/src/agent/`。各 Host 提供身份、授权、持久化、平台能力和生产装配。
- 主 Agent 保持现有 Python 后端的用户可观察行为；子 Agent 提供独立上下文和受限能力，复用同一个 Runner/Harness。
- 支持未来增加 Agent 方案，不要求每种 Agent 重写模型调用、工具循环、取消和恢复。
- 主 Agent 按需获取业务工具，短任务可自行执行；较长、上下文较多或适合并行的任务可委派子 Agent，减少默认提示词和工具 Schema 的负担。

首期聚焦上下文组合与单层子任务，不引入通用工作流引擎、跨设备调度、Agent 市场或可嵌套子 Agent。多 Agent 的用户界面和对外配置形式后续单独确定。本 PRD 不要求为实现这些目标暂停 N2/N3 或已在推进的生产 Run 装配。

## 3. 产品行为与功能要求

### 3.1 运行方案

每个 Agent Run 使用明确的上下文方案：系统提示词由一组有顺序的函数组合；上下文来源可以选择性启用、配置内容与预算。方案由可信 Host 或受其约束的创建方构造。Runner 调用组装器获取准备结果，不在核心循环中硬编码主 Agent 和子 Agent 的记忆分支。

首期至少提供主 Agent 和子 Agent 两种组合。系统提示词可包含基础规则、安全规则、角色、人设、自定义指令和工具说明；各端可选择适用内容。用户或父 Agent 提供的角色提示词不得修改可信安全策略或授予权限。具体配置入口与可编辑范围在落地时确定。

### 3.2 来源与记忆

长期记忆、会话历史、RAG、业务概览、本次任务和运行内消息分别选择与控制。记忆 API 应允许按可用类型选择需要的内容；是否存在的分类以实际记忆模型为准，不为示例字段新增数据模型。

子 Agent 默认不加载长期记忆、既有会话历史和 RAG，不创建长期记忆、反思或摘要任务。它可以读取父 Agent 明确提供且已授权的任务材料，并保留本次子 Run 内的消息和工具结果，以完成多步工作。为运行恢复而保存的子任务记录不自动成为长期记忆；用户数据保留期限遵循 Host 的既有策略。

主 Agent 的默认组合在重构前后保持旧版 Python 行为，包括提示词顺序、时间与语言、记忆选择、快照、RAG 和压缩边界；行为差异须单独记录和决策。关闭记忆不得被误解为自动关闭 RAG、IM 记忆或其他来源，各来源使用明确策略。

### 3.3 子任务与权限

父 Run 可创建独立子 Run，指定任务、自定义系统提示词、经授权的输入、允许的工具和运行预算。子 Run 具备独立身份、状态、运行内上下文、取消信号和最终结果，并记录父子关系。初期支持一个子任务、等待结果和取消；并发与更完整的恢复能力在后续阶段实现。

实际能力受父 Run 权限、子任务允许范围和 Host 可用能力共同约束；模型、提示词或传入工具名不能扩大授权。文件、网络、Shell 和危险操作沿用现有可信授权、隔离及确认边界。父 Run 取消时默认取消子 Run；子任务已提交的副作用和结果未知的操作不得盲目重放。

子任务向父任务返回完成、失败或取消状态、简短结果，以及可选结构化结果或已授权产物引用。父任务默认不接收完整内部工具输出；查看详情须符合 Host 授权及用户数据策略。

### 3.4 主 Agent、工具与子 Agent 预设

主 Agent 是用户的主要对话对象，负责理解目标、维护有权使用的长期记忆和会话上下文、决定直接执行或委派、协调任务和用户确认，并检查和汇总结果。主 Agent 保留子 Agent 创建、状态查询、通信、等待、取消等协调工具，以及 Shell、用户交互、时间和必要的基础查询能力；项目、日历、文件等业务工具可通过 Skill 按需获取，不要求简单任务也委派。

初期提供三个预设，均为同一子 Agent Runtime 的提示词、上下文和工具配置，不各建独立运行框架：

| 预设 | 职责 | 按需业务能力 |
| --- | --- | --- |
| Search | 查找网页及知识来源、分析整理证据与引用 | 搜索、网页读取和获授权的知识查询 |
| Workflow | 处理项目、日历、笔记、画布及定时任务 | 对应工作台领域的查询和写入用例 |
| File Management | 在授权范围内查找、读取、整理和处理文件 | 文件查询、读写与整理能力 |

主 Agent 和三个预设均包含 Shell 能力配置；实际使用由可信 Host 检查父任务授权、子任务工作范围、平台隔离后端及执行策略。不可用或未授权时明确拒绝；Linux 多用户隔离未验收不表示已经可以安全开放。Shell 与结构化业务工具共用现有沙箱、路径、网络、取消和危险操作确认规则。具备完整业务事务的项目、日历等操作优先调用对应业务用例。

Workflow 默认处理项目结构、状态和业务关联，File Management 默认处理授权项目范围内的文件内容和目录；职责是调度建议，不构成独立权限墙。涉及项目引用与物理文件的跨域操作由一个子任务调用完整业务用例，保持事务与失败处理，不拆成各自独立写入。主 Agent 对有依赖的操作串行交接项目标识、路径、修改与未完成事项；互不冲突的研究和执行可并行。并发安全由底层事务、版本或文件操作约束保障，不仅依赖提示词。

### 3.5 Skill 与工具 Schema 按需获取

主 Agent 默认只携带基础工具、子 Agent 协调工具和精简 Skill 目录；业务工具完整 Schema 按任务按需加载。读取 Skill 后，运行时参照旧 Python 行为解析可信 Skill 快照中的 `related_tools`，将当前可用且经授权的关联工具 Schema 加入后续模型上下文；保留 `get_tool_schema` 单独获取其他已授权工具。Skill 正文和元数据只用于发现，不授予权限；Schema 来源为可信注册表，执行前再次校验当前身份、授权与平台能力。

子 Agent 可按预设和父任务的范围使用相同机制。已加载工具集合及其版本、授权范围与上下文边界须纳入 Run 快照和恢复校验；默认按当前 Run 生效，释放或裁剪时应保持后续调用、恢复与权限撤销一致。若当前 Host 不支持某工具，不能因 Skill 关联而开放。减少上下文的验收应检查实际 Provider 请求不携带未启用业务工具的完整 Schema。

### 3.6 预算、快照和恢复

来源声明其顺序、用途、预算与稳定性，让组装器与既有上下文预算、缓存、快照和压缩机制协作。稳定系统前缀、动态时间、记忆、RAG 和运行内消息不得无差别拼接后丢失边界。来源未启用时不得读取该来源；需要的来源不可用时按该方案明确的错误语义处理。

启动时绑定方案标识、提示词版本或摘要、来源选择、可信授权范围及模型配置身份。恢复时验证绑定；配置或权限变化时由现有恢复策略决定拒绝或重新准备，不能静默复用不匹配的快照。不得把凭据或可识别的聊天正文写入可见日志。

## 4. 架构与接口方向

保留现有 `createAgentRunner` 和 `ContextPort` 作为运行内核边界；将当前主 Agent 的共享规则与格式化能力迁入 Core，在其上提供普通函数组合的上下文组装器和默认方案。平台 SQL、身份认证、文件根、Redis、模型凭据与平台生命周期留在相应 Host。桌面端以本地数据适配同一 Core 契约；Core 不直接依赖 Web 的 PostgreSQL 或 Redis 实现。

建议组织如下，最终名称随现有代码调整，不为目录树引入空文件：

```text
packages/core/src/agent/
├── core.ts                 # 通用 Runner
├── context/
│   ├── assembler.ts        # 来源选择、顺序与准备结果
│   ├── system/             # 系统提示词组合
│   ├── memory/             # 记忆选择与格式化
│   ├── sources/            # 任务、历史和业务来源组合
│   └── history/            # 既有历史与快照能力
├── profiles/               # 主 Agent 与子 Agent 默认组合
├── subagent/               # 子 Run 规格、结果与协调
├── tools/
└── providers/
```

接口应能表达系统提示词组合、来源选择、预算、可信身份和取消；主 Agent 与子 Agent 通过不同组合构建 Runner。具体类型以现有 `ContextPort`、快照和工具契约为基础，不保留仅用于内部目录迁移的兼容转发层。

## 5. 实施阶段

1. **公共化现有能力**：盘点 Web Host 的 Agent 代码，将跨端提示词组合、记忆/业务概览格式化和 runtime 规则迁入 Core；保留 Host 平台适配。对照 Python 和当前 Node 行为，继续生产 Run 装配。
2. **可组合上下文**：在现有 ContextPort 和快照基础上提供系统提示词与来源组合 API；用主 Agent 默认方案证明现有行为不变，覆盖独立禁用记忆、历史与 RAG。
3. **单层子 Agent**：实现自定义提示词、显式输入、独立运行上下文、按需工具、Shell 能力、结果返回和级联取消；提供 Search、Workflow、File Management 预设。对照 Python 补齐读取 Skill 后关联 Schema 自动注入与授权复核。
4. **并发与恢复**：根据产品需要增加并发/预算控制、持久恢复和运行事件展示；在相应 Host 完成真实依赖验收后开放。

## 6. 验收标准

- 主 Agent 迁移前后相同输入产生等价的来源选择、提示词顺序、权限与快照行为；已有 Python pytest 和 Node 回归不退化。
- 不启用某来源时，测试证明其加载器未被调用；子 Agent 默认无法读取或写入主 Agent 长期记忆、历史和 RAG，但本次 Run 的多轮工具结果可继续使用。
- 自定义提示词生效；越权工具、其他 owner 的数据及未授权文件不可通过提示词或模型参数获得。
- 主 Agent 读取 Skill 后关联工具 Schema 进入下一次实际 Provider 请求；未启用业务工具的完整 Schema 不被默认发送。单独获取 Schema、无权限、能力不可用、撤权及恢复后的工具集合均有行为回归，覆盖旧 Python 对应行为。
- 三个子 Agent 预设及主 Agent 均可在可信 Host 提供授权和就绪沙箱时使用 Shell；缺能力、越界和危险操作确认路径可验证。
- 项目整理后编辑文件等跨域任务可按依赖交接；跨项目与文件操作通过完整业务用例保持一致，并发冲突和失败不产生部分成功的虚假结果。
- 子 Run 状态、父子关系、结果、失败与取消可观察；父任务取消、确认、并发状态变化和结果未知的副作用符合既有运行契约。
- 快照和恢复覆盖方案或权限变更、过期身份、上下文预算和敏感数据边界；不得把合成端口回归记作真实 PG/Redis、模型服务或生产接入验收。
- Web 和桌面共享同一 Core 组合契约，各端以各自可信适配器接入；分别报告运行范围、通过/跳过与未验收项。

## 7. 待决定事项

- 子 Agent 自定义提示词由用户配置、主 Agent 动态提供，还是两者结合；对应的产品交互和管理权限。
- 默认模型选择、轮次/token/耗时和并发上限，以及预算耗尽后的用户提示。
- 子任务的历史可见范围、保存期限、详情展示和产物交付方式。
- 哪些写操作允许子 Agent 申请、确认交由父任务还是用户，以及未来是否开放多层子 Agent。
- 恢复时遇到模型配置或授权变化的具体产品策略，以及 Web、桌面各自的可用范围。
