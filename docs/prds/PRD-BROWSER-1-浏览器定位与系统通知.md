## 1. 背景与目标

咕咕目前运行在浏览器中，浏览器可以在用户授权后提供一次性设备定位，也可以把站内新通知转为操作系统通知。用户希望把这些能力作为统一的“浏览器能力”逐步提供给 Agent 和 Web 应用。

本 PRD 首版只包含：

- Agent 在用户明确提出位置相关需求时，按需获取一次当前位置。
- 用户可选择是否将新到达的站内通知同时显示为操作系统通知。

不包含：

- 持续或后台位置跟踪、位置历史、自动地理围栏。
- 自动反向地理编码为街道地址；浏览器定位工具只返回坐标、精度和采样时间。
- 页面关闭、浏览器退出或设备离线时的通知推送；不接入 Push API、VAPID 或推送订阅服务。
- 摄像头、麦克风、剪贴板、文件系统、屏幕共享、Web Share 等其他浏览器能力。
- 改变现有通知中心、通知气泡、邮件/IM 通知的事实源与投递规则。

## 2. 功能需求

### FR-BRW-001：按需获取当前位置

Agent 只有在当前请求确实需要用户位置时，才可调用“获取当前位置”工具。工具一次调用只采样一次，不启动 `watchPosition`，不在后台周期性刷新。

首次使用或站点尚未获浏览器授权时，咕咕必须先说明用途并等待用户在页面内确认；确认后再调用浏览器定位 API，由浏览器显示其原生权限提示。浏览器已有授权时仍需保留本次调用的咕咕确认，避免工具调用暗中读取位置。

成功结果只包含纬度、经度、精度半径和采样时间，不读取或返回海拔、速度、方向等无关字段。工具默认使用低功耗定位选项，并设置有限超时；超时、用户拒绝、浏览器不支持或页面非安全上下文时，返回可理解的失败原因，不伪造或推测坐标。

位置结果只用于当前请求，不写数据库、偏好、浏览器持久存储、遥测或可见日志。工具完成后不得复用上次坐标响应后续请求；若用户随后再次需要位置，重新经过调用及确认流程。

### FR-BRW-002：系统通知开关与浏览器权限

个人设置的“通知”分区增加“系统通知”开关。站内通知始终照常工作；开关只控制是否额外显示系统通知。

用户主动开启开关时，页面先说明系统通知用途，再通过用户点击请求浏览器通知权限。权限为 `granted` 时启用；为 `denied` 时保持关闭并说明需要在浏览器站点设置中恢复；为 `default` 或 API 不可用时展示相应状态，不得循环或在页面加载时主动弹权限提示。

开关偏好按当前浏览器/设备保存，不与账号设置跨设备同步；浏览器权限是站点级权限，由浏览器管理。用户可随时在 Gugu 设置关闭本地系统通知展示，关闭不得尝试撤销浏览器站点权限。

### FR-BRW-003：实时站内通知的系统展示

只有新收到的实时站内通知可以触发系统通知。通知来源复用当前 `live.ts` 收到的 canonical live stream 通知事件和 `ui` store，不为系统通知另建后端通知表或投递通道。

满足系统通知开关开启、浏览器权限已授予、页面已进入后台/不可见时，前端为该实时通知显示一条系统通知。页面处于前台可见时只保留现有站内呈现，避免重复打扰。系统通知不得改变站内通知是否持久化、是否弹气泡、未读状态或声音规则。

同一个通知 ID 在 SSE 重连、重复投递或前端重渲染期间最多显示一次。首次加载通知中心历史、登录后的历史补拉、刷新页面和上线补弹不得被误判为新系统通知。通知内容使用现有通知标题和简短摘要，不包含聊天正文、凭据或完整私密内容；没有安全摘要时使用通用提示。

用户点击系统通知后，若现有通知包含可验证的应用内目标，则聚焦/打开 Gugu 并导航到对应通知；没有目标时只打开通知中心，不推断或拼接不可信 URL。通知点击不自动将通知标记为已读，沿用现有站内已读操作。

本首版不承诺页面关闭后仍可收到通知。浏览器或操作系统屏蔽通知、权限被撤销、当前浏览器不支持相关 API 时，站内通知仍正常使用，并提供非阻塞状态提示。

## 3. 技术方案

### 3.1 浏览器定位工具边界

工具执行环境是用户浏览器，不能由后端直接调用 `navigator.geolocation`。应建立有超时、取消和请求归属校验的一次性浏览器操作通道：后端/Agent 发出待执行的定位请求，前端呈现本次用途及确认，确认后在页面调用浏览器 API，并把最小结果关联回原工具调用。请求必须绑定当前登录用户、活动会话和唯一 request ID；用户取消、会话切换、登出、超时或页面关闭时使请求失效，迟到结果不得交给其他会话或账号。

该工具不得绕过现有 Agent 工具注册、Schema 校验、权限过滤和确认机制。需要先验证现有流式工具调用生命周期能否安全等待一个前端回执；若需要新增协议，应使用短生命周期的请求/响应事件，不在数据库或 SSE 重放历史中持久化坐标，也不以定时轮询代替事件交互。

Geolocation API 要求安全上下文，并受浏览器权限和 Permissions Policy 约束。生产与测试验收需使用 HTTPS；不安全 HTTP 环境应明确展示不可用原因，而不是静默失败。仅 localhost 等浏览器认可的本地安全上下文作为开发例外。

### 3.2 系统通知接入

现有通知状态仍以 `ui` store 和后端通知接口为准。系统通知偏好存于当前浏览器本地；具体存储键应按账号隔离，登出/切换账号时不得把一个账号的开关状态套用到另一个账号。原生权限状态只读浏览器提供的状态，不在后端复制或推断。

实时新通知识别应在现有通知事件进入 `pushNotification` 的路径上完成，并区分实时事件与 `fetchNotifications`、`checkLoginBubble` 等历史/补弹路径。去重键优先使用通知 ID；无 ID 的瞬时通知不得跨刷新持久化去重标记。页面可见性切换和权限状态变化时应重新校验是否展示，通知调用失败不得影响通知中心和 SSE 消费。

当前通知中心在 `ProfilePreferencesPane.vue` 已有“通知”设置分区，系统通知开关放在该区，复用现有 ToggleSwitch、i18n 和偏好交互规范。首版不需要数据库迁移、服务端推送基础设施或新的通知投递 API。

## 4. 验证与上线

- 定位：覆盖用户确认、浏览器允许/拒绝、API 不支持、HTTP 非安全上下文、超时、用户取消、登出/切换会话后迟到响应丢弃；确认工具输出只有位置最小字段，数据库、日志及持久存储无坐标。
- 通知：覆盖开关关闭/开启、权限 `default`/`granted`/`denied`、页面前台/后台、实时事件与历史拉取、重复事件、无通知 ID、权限被撤销、浏览器 API 不支持和通知点击导航。
- 回归：已有通知中心列表、未读数、通知气泡、补弹、声音、SSE 重连和通知清除行为保持不变。
- 上线先在 HTTPS 环境验证。定位工具以功能开关控制服务端工具可见性；系统通知默认关闭，由用户主动开启。出现权限误触发、跨账号串用、重复通知或 SSE 受阻时，可分别关闭定位工具或系统通知开关，不需要数据库回滚。
- 页面关闭后通知、后台 Web Push、VAPID 订阅和推送服务属于后续独立评估，不以本首版验收结果暗示已支持。

## 5. 风险与待确认问题

| 风险 | 影响 | 对策 |
|---|---|---|
| Agent 工具在后端执行，而定位 API 在浏览器执行 | 工具无法仅靠新增后端 handler 完成，粗糙桥接可能卡住对话或串会话 | 先验证事件往返、取消和超时边界；请求 ID 绑定账号/会话；无法证明安全前不启用工具 |
| 坐标属于敏感个人数据 | 被日志、长期记忆或后续工具意外保留会造成隐私泄露 | 一次性授权、最小字段、仅当前请求可用、日志与持久层禁止落坐标 |
| 系统通知支持和权限受浏览器、系统设置影响 | 用户可能看不到系统提示或无法启用 | 展示能力与权限状态，保留站内通知为可靠路径，不反复弹浏览器权限框 |
| SSE 重连和上线补弹可能重放通知 | 系统通知重复或历史通知突然打扰用户 | 仅监听实时新增路径，按 ID 去重，不将历史补拉当新通知 |
| HTTP 部署无法使用定位/通知的安全上下文能力 | 功能不可用 | 上线必须通过 HTTPS 验收；非安全上下文给出明确提示 |

待确认：无。首版“浏览器通知支持”按页面运行期间的实时通知处理；用户明确要求页面关闭后也能收到时，再另行评估 Web Push 与 Service Worker。
