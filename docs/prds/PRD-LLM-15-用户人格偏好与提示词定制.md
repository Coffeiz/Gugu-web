# PRD-LLM-15：用户人格偏好与提示词定制

状态：规划中

## 0. 发布与解锁策略

- 托管服务由后台总开关控制，作为用户付费权益的一部分。
- 本地部署版本默认开启，不要求连接官方授权服务。
- 总开关关闭时，前端隐藏入口，后端 API 仍必须拒绝写入和生效。
- 关闭时保留已有配置，重新开启后恢复，不删除用户数据。

## 1. 背景与目标

允许用户定义咕咕的回答风格、称呼和互动偏好，同时保持系统安全规则、工具权限、确认门和上下文预算的权威性不变。

本功能是“用户偏好层”，不是开放式系统提示词编辑器。

## 2. 设计原则

- 系统规则永远高于用户偏好。
- 用户偏好不能授予工具权限、绕过确认或修改安全策略。
- Web、私聊、群聊使用同一份用户偏好语义。
- 固定注入位置和稳定序列化，避免每轮产生无意义的前缀断裂。
- 偏好为空、停用或读取失败时，不影响正常对话。

## 3. 上下文层级

```text
系统安全规则
→ Agent 基础人格
→ 用户人格偏好
→ 会话级临时偏好（如有）
→ 当前消息
```

用户偏好应作为稳定 snapshot 的一部分注入，不放在动态消息尾部。

## 4. 数据模型

建议复用用户配置体系，增加明确字段：

- `personality_preference`
- `personality_preference_enabled`
- `personality_preference_revision`
- `personality_preference_updated_at`

默认上限建议 4,000 字符；前端实时显示剩余字数，后端再次校验。

## 5. 产品交互

- 设置页新增“回答风格”区域。
- 支持编辑、启用/停用、恢复默认。
- 展示风险说明：不会改变工具权限、安全规则和确认要求。
- 保存成功后从下一轮请求生效，不回写历史消息。

后台管理增加“用户人格偏好”总开关，并显示托管服务付费解锁/本地部署默认开启的策略。

## 7. 验收标准

- 用户可以独立配置并停用人格偏好。
- 偏好不会改变工具可用性或确认门。
- 同一用户在三类渠道的稳定上下文内容一致。
- 偏好未变化时保持 provider cache 前缀稳定。
- 总开关关闭时前后端均不生效，重新开启后配置可恢复。
