## 1. 背景与目标

注册后用户已经拥有一组可浏览的示例项目、文件和日历内容，不需要再通过创建项目理解产品。当前缺少的是一条短路径，帮助用户先选择语言，再理解这些内容能做什么，最后完成模型和 IM 的必要配置。

目标是让新用户在 3～5 分钟内完成以下认知和配置：

- 选择并持久化界面与 Agent 使用语言。
- 通过已有播种数据理解项目、文件、日历、提醒和咕咕协作的关系。
- 确认使用系统模型，或完成自己的模型配置。
- 连接一个 IM 渠道，并知道连接后能获得什么效果。
- 中途离开后能继续，已完成步骤不重复打扰。

本 PRD 不包含：

- 不在引导中创建新的项目、阶段、文件或日历活动。
- 不重新实现模型 Provider、API Key、IM OAuth 或机器人连接逻辑。
- 不强制用户配置 BYOK 或连接 IM；系统默认模型和 Web 使用必须可跳过这些步骤。
- 不把引导文案写入 Agent system prompt，也不改变现有上下文注入策略。

## 2. 功能需求

### FR-ONB-001：首次进入条件

新用户完成注册并成功登录后，在首次进入主应用时展示引导。引导判定使用独立的引导完成状态，不使用“是否有项目”“是否连接过 IM”等业务状态推断。

已完成引导的用户不应在普通刷新、重新登录或切换页面时再次自动弹出。用户可以从用户菜单或设置中主动重新查看功能介绍和未完成配置。

### FR-ONB-002：语言选择

语言选择是引导第一步。页面展示受支持语言的原生名称，默认预选当前已持久化语言；新用户没有持久化语言时，根据浏览器语言预选。

用户选择后立即切换引导界面语言，并调用现有偏好更新能力持久化。后续功能展示、模型配置说明、IM 说明和成功/错误反馈均使用该语言。

语言保存失败时必须明确提示并允许重试，不得只更新前端内存状态后静默继续。

### FR-ONB-003：功能展示

语言选择完成后展示功能说明，不创建任何数据。展示内容使用当前用户已经播种的示例数据作为背景，至少包含：

| 场景 | 用户应理解的效果 |
|---|---|
| 项目与文件 | 项目包含阶段、待办和文件，咕咕可以帮助整理和推进。 |
| 日历与提醒 | 可以查看日程、创建事件并按时收到提醒。 |
| Web 对话 | 可以询问项目、文件和日历，并让咕咕执行可用操作。 |
| IM 协作 | 连接 IM 后，可以在聊天软件中接收提醒、查询信息和发起对话。 |

功能展示优先使用真实播种内容的名称和状态；如果某项播种内容缺失，展示仍必须正常，不得阻塞引导。页面提供“下一步”和“稍后设置”，不提供创建项目按钮。

### FR-ONB-004：模型配置引导

模型步骤展示当前模型状态，并提供两条清晰路径：

- 使用系统默认模型：显示可用状态，允许直接继续。
- 配置自己的模型：跳转或打开现有模型配置界面，完成后返回引导。

用户保存自定义模型后，引导应调用现有测试能力或读取已有验证状态，向用户展示“可用 / 配置但未验证 / 验证失败”。验证失败不应伪装成成功，也不应阻止用户稍后继续使用系统模型。

模型步骤需要说明模型实际用于聊天、文件理解、项目整理和工具操作；不在此处展示过多 Provider 高级字段。

### FR-ONB-005：IM 连接引导

IM 步骤展示 Feishu、QQ、WeChat 等现有渠道的连接入口和状态。每个渠道必须说明连接后的实际效果，包括接收提醒、查询项目或日历、私聊咕咕和必要的确认交互。

用户可以连接一个或多个渠道，也可以跳过。连接成功后优先发送一条低风险测试消息或提供明确的测试动作；授权取消、连接失败和权限不足必须显示可理解的状态与重试入口。

引导只负责调度现有连接流程，不直接保存平台凭据，不在前端日志、URL 或可见错误中输出密钥、Token 或授权参数。

### FR-ONB-006：完成、跳过与恢复

完成页展示语言、模型和 IM 的当前状态，并给出三个立即可尝试的动作：查看示例项目、查看今天的日程、向咕咕发送一条问题。

用户在任意步骤选择“稍后设置”时，记录当前步骤和已完成状态，关闭引导并进入主应用。下次主动打开引导时从未完成步骤继续；已经完成的步骤可查看但不要求重复操作。

用户选择“完成”后标记引导版本已完成。配置发生变化时不自动重开引导，只在配置清单中显示当前状态和入口。

### FR-ONB-007：配置清单入口

引导完成或跳过后，在用户菜单、首页或设置入口保留一张可关闭的配置清单，至少显示语言、模型和 IM 三项状态。清单支持直接跳转到对应设置，用户关闭后可以从设置重新打开。

## 3. 技术方案

### 3.1 状态与事实源

`onboarding_state.state` 继续作为引导自身状态的事实源，扩展为版本化 JSON，建议包含：

```json
{
  "seeded": true,
  "seeded_project_id": 123,
  "seeded_project_name": "示例项目",
  "guide_version": 1,
  "current_step": "features",
  "completed_steps": ["locale", "features"],
  "dismissed": false,
  "completed_at": null
}
```

用户语言仍以 `UserPreferences.data.locale` 为事实源；引导不得复制一份语言字段。模型状态以现有模型/BYOK接口返回为准，IM 状态以现有各渠道连接接口返回为准。

状态写入必须按用户所有权隔离，并通过现有 `onboarding` API 操作。未知字段需要保留，后续版本升级采用合并更新，不清空已有播种字段。

### 3.2 页面与组件边界

新增独立的引导容器和步骤组件，建议放在 `frontend/src/components/onboarding/` 或对应页面目录下；`useOnboarding.ts` 负责状态读取、步骤推进、跳过和完成，页面入口只负责展示和路由调度。

模型和 IM 连接应复用个人设置中已有组件或打开已有设置面板，避免出现两套表单、校验规则和授权流程。功能展示只读取项目、文件和日历现有数据，不额外创建演示数据。

所有用户可见文案必须进入现有 i18n 消息表，并保持 `zh-CN`、`en-US`、`ja-JP` 的 key 集合一致。播种数据本身仍由注册时语言决定，不因引导切换语言而重写已有项目内容。

### 3.3 API 与兼容性

在现有 `/api/v1/onboarding/state` 基础上增加受控的状态更新能力，至少支持更新当前步骤、完成步骤、关闭和完成版本。更新接口只接受有限枚举和布尔值，不接受任意 JSON 覆盖，避免客户端清空播种状态或写入未定义字段。

需要返回功能展示所需的播种摘要时，优先复用已有项目、文件、日历接口；不把完整业务数据复制到 `onboarding_state`。

旧用户没有引导状态或 `guide_version` 时，按已存在用户策略决定是否展示：默认只对注册后尚未完成引导的新用户启用；升级版本不得强制打断已有用户。

### 3.4 观测与隐私

可以记录步骤开始、完成、跳过和失败的结构化事件，但事件只记录步骤名、结果、版本和耗时，不记录聊天正文、文件名、邮箱、授权 Token 或 API Key。错误信息经过现有脱敏边界处理。

## 4. 验证与上线

验收需要覆盖：

- 新用户注册后能按“语言 → 功能展示 → 模型 → IM → 完成”顺序完成引导。
- 刷新、关闭浏览器和重新登录后能恢复到正确步骤，不重复播种数据。
- 中文、英文、日文界面没有缺失 key，长文案不会破坏布局。
- 系统默认模型路径无需配置 API Key 即可跳过；自定义模型验证失败显示真实失败状态。
- IM 连接成功、取消、失败和跳过路径均可完成或稍后恢复。
- 引导状态只能修改当前用户自己的记录，不能改变 `seeded_project_id` 或其他用户数据。
- 已完成用户不会被新版本自动打断；主动重新打开时能按当前版本迁移状态。

建议测试命令：

```bash
PYTHONPATH=backend backend/.venv/bin/pytest -q backend/tests/test_onboarding*.py
cd frontend && npm run typecheck && npm run test:run
```

上线先对新注册用户启用，保留版本开关和关闭入口。回滚时关闭自动展示即可，不删除 `onboarding_state`，也不删除已经播种的项目、文件和日历内容。

## 5. 风险与待确认问题

| 风险 | 影响 | 对策 |
|---|---|---|
| 引导重复实现模型或 IM 配置 | 两套状态和校验不一致 | 引导只负责编排，复用现有设置面板和连接流程。 |
| 播种数据被当成临时演示数据删除 | 用户已有内容丢失 | 引导只读播种内容，不提供删除或重播种操作。 |
| 语言切换后播种文案语言不一致 | 用户误以为引导没有生效 | 明确区分界面语言和注册时播种内容语言，不自动重写历史数据。 |
| 用户跳过模型或 IM 后不理解下一步 | 配置完成率低 | 完成页和配置清单显示实际能力差异，并提供直接入口。 |
| 引导状态被任意 JSON 覆盖 | 播种状态丢失或越权 | 后端只接受白名单字段和有限状态转换，并补所有权测试。 |
| 多端同时打开引导 | 步骤互相覆盖 | 更新使用版本或更新时间条件，冲突时重新读取服务端状态。 |

待确认事项：

- 功能展示是否采用纯静态卡片，还是使用播种项目中的真实名称做轻量动态演示。
- 完成后的配置清单默认展示多久，以及用户关闭后从哪个固定入口重新打开。
- 模型和 IM 是否需要在完成页显示“推荐配置”，还是只展示当前真实状态。
