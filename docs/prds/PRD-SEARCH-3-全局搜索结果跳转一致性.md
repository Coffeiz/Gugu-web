## 1. 背景与问题

全局搜索的查询和结果分组已有每类数量边界，但结果点击后的目标交接由多个页面各自实现。检查当前调用链发现，部分页面参数名不一致、目标状态由非当前路由消费，或目标只在已加载列表中查找；也有页面在展示搜索目标前等待与目标无关的数据。结果可能表现为点击无反应、没有打开目标、历史命中无法定位或等待时间过长。

已确认的待处理项：

| 类型 | 当前链路问题 |
| --- | --- |
| 便签 | 搜索写入 `pendingNoteId`，当前 `/mind/notes` 路由使用的 `NotesThreePaneView` 读取 `object_id`，没有消费该 pending 状态。 |
| 对话 | 目标消息只在当前已加载消息数组中定位；切换会话加载的最新一页不含较早命中时，定位函数直接返回。 |
| 画布便签 | 目标画布定位等待便签、画布和项目列表都加载完成后才开始。 |
| 定时任务 | 搜索传 `task` 查询参数，日程页读取 `object_id`，参数契约不一致；目标打开还等待任务列表加载。 |
| MCP | 搜索传入 `server` 查询参数，MCP 页面没有消费该参数并选中目标的逻辑。 |
| 技能 | 目标编辑窗口在技能列表加载完成后才打开；目标优先级和失败状态尚未统一。 |

日历按目标日期加载和项目卡片高亮没有发现相同的全量文件缓存依赖。客户搜索目前只提示客户页面尚未开放，属于未实现目的地，不在本 PRD 中改变产品状态。

## 2. 目标与非目标

### 2.1 目标

- 为每类全局搜索结果定义一致、可验证的目标标识及路由/状态交接方式。
- 点击结果后，目标页面能直接打开或定位到该实体；不能依赖目标恰好位于当前已加载列表页。
- 冷启动目标页时，先加载定位目标所需的最小数据；不相关列表数据不得阻塞目标打开。
- 对目标已删除、无权访问或无法加载的情况给出明确状态，并清理已消费的 pending target，避免后续误打开。
- 覆盖页面已打开时重复点击、直接打开带目标参数的链接、请求失败和快速切换目标等行为。

### 2.2 非目标

- 不改变全局搜索的匹配、分词、排序、索引或 `per_type` 数量边界。
- 不把文件/文件夹分页、位置解析或文件库缓存改造并入本 PRD；这些由 FS-8 负责。
- 不重做日历、项目、客户或技能/MCP 的页面视觉设计。

## 3. 功能需求

### FR-SEARCH-3-001：目标契约与消费一致

每种搜索结果定义稳定的目标类型和标识字段。结果生产端、路由参数/pending 状态和页面消费端必须使用同一契约；重复点击同一结果时，即使路由组件不重新挂载，也必须重新执行定位。消费成功、目标不存在、权限拒绝或加载失败后都要结束本次 pending 状态，不能让旧目标污染后续导航。

### FR-SEARCH-3-002：便签按实体 ID 定位

全局搜索便签结果进入当前正式便签视图后，必须按目标便签 ID 定位、选中并高亮。定位不能只依赖时间流已加载的首屏；可使用按 ID 读取或有界分页定位。目标缺失时显示明确提示，不得把正常搜索结果误报为不存在。

### FR-SEARCH-3-003：历史消息按消息 ID 定位

打开会话后，应按搜索命中的消息 ID/cursor 补载包含目标的历史页，再滚动到目标消息并高亮。目标不在当前消息数组时不得静默返回。补载应限定于目标会话，遵守现有用户归属校验和消息分页边界。

### FR-SEARCH-3-004：画布目标优先加载

点击画布便签结果时，先加载目标画布及目标节点定位所需的数据。项目抽屉、便签列表和其他非目标集合可以并行加载或延后加载，但不得阻塞目标画布激活和节点居中。节点缺失时显示明确结果并结束 pending 状态。

### FR-SEARCH-3-005：日程与 MCP 使用明确目标参数

定时任务和 MCP 搜索结果分别使用其页面实际消费的稳定目标标识。定时任务可按目标 ID 查询并打开编辑界面；MCP 结果需定位并选中对应服务器。不能出现只传查询参数但页面无消费者的情况。

### FR-SEARCH-3-006：技能目标加载与失败状态

技能目标打开应在技能列表返回后按稳定 Skill ID 选中并打开；加载错误、目标不存在或不可编辑时显示明确提示并清理目标参数。不得因路由参数保留导致刷新后意外重复弹窗。

## 4. 验收标准

- 各目标类型均通过冷缓存、热缓存和页面内重复点击三种路径验证。
- 便签结果能在目标不属于首屏数据时定位；历史消息结果能在目标早于当前消息页时定位。
- 画布搜索跳转不会等待无关便签或项目数据后才激活目标画布。
- 定时任务和 MCP 的搜索结果能打开对应实体，路由参数由实际目标页消费。
- 目标删除、越权、加载失败及快速连续点击时，不误开其他实体、不残留 pending 状态，并展示可理解的反馈。
- 请求仍限制在目标用户、会话、画布或资源 scope 内；不能通过扩大整表/全量列表读取解决定位问题。
- 测试验证用户可观察行为和目标隔离边界，不锁定无关实现细节或具体文案。
