## 1. 背景与目标

Desktop 已实际消费大量放在 Web 名下的代码。桌面 Vite 配置沿用 Web 的 `@` 别名和 Vue 配置，另将 renderer 入口指向 Electron 仓库目录。反向依赖也已存在，例如笔记 store、文件 API、日程和偏好会根据环境走 Desktop bridge。仅移动入口会原样保留这些耦合。

统一为一个 `apps/ui` 前端包，下面按 `src/shared`、`src/desktop`、`src/web` 分层。业务交互在已有共享的地方继续复用，应用外壳和宿主能力按平台分别装配。Web 主站、Admin、桌面工作台及其子窗口保有现行入口和业务契约。范围限于前端目录、依赖和构建接线。视觉改版、后端迁移、数据迁移以及业务功能合并均留在各自专项。

## 2. 功能需求

### FR-UI10-01：统一前端工作区

Web、Admin 和 Desktop renderer 使用同一份依赖清单和工具链，互相独立编译。共享模块只有一处维护，类型检查和测试覆盖各入口。

### FR-UI10-02：隔离平台能力

共享模块通过明确的领域接口访问会话、文件、资源和系统能力。平台入口提供实现，能力缺失时沿用既有禁用或错误反馈。Electron renderer 仍通过 preload 和 IPC 调用本机能力，浏览器预览仍经过受信代理。Web 保持现有登录、HTTP、SSE 和权限隔离链路。

### FR-UI10-03：保持跨端交互和入口

全局搜索、`@` 引用、笔记和画布跳转高亮、聊天工具卡片、主题与语言使用同一份共享交互。Electron 的新建窗口、文件预览、系统打开和拖入拖出由桌面适配实现。Web 保留原有路由、深链接、Admin 与静态资源地址。

### FR-UI10-04：开发和交付入口持续可用

本地 Web、Admin、Desktop 和桌面浏览器预览沿用现有启动能力。依赖安装和共享包编译成功后才切换运行版本。生产 Web 静态资源、独立 Web 镜像和桌面安装包各自消费明确的构建产物。

## 3. 技术方案

```text
apps/
├── ui/                              【新增】单一前端工作区
│   ├── package.json                 【新增】初期沿用 gugu-web 包名和命令
│   ├── src/
│   │   ├── shared/                  【新增】跨端组件、功能、主题、i18n 与领域接口
│   │   ├── desktop/                 【新增】桌面入口、壳层、窗口页面、IPC 与预览适配
│   │   └── web/                     【新增】主站及 Admin 入口、路由、布局、HTTP 与 SSE
│   ├── index.html、desktop.html     【新增】迁入现有入口
│   ├── admin/、public/              【新增】迁入 Admin 入口和静态资源
│   ├── vite.*、tsconfig.*           【新增】统一配置，保留各入口差异
│   ├── tests/、e2e/                 【新增】迁入前端测试
│   └── dist/、dist-desktop/          【生成】通过现有 Vite 构建命令生成
├── desktop/
│   ├── src/main/、src/preload/      【条件】仅调整渲染资源和纯契约接线
│   └── scripts/                     【修改】开发监听、预览和打包产物路径
└── web-host/
    ├── deploy/                      【修改】静态产物来源
    └── src/modules/                 【不改】业务 API 和 Agent 行为
packages/
└── core/                             【条件】需要被主进程和 renderer 共用的纯协议
```

### 3.1 模块归属

- **共享层**维护组件库、视觉令牌、图标、富文本、语言资源、拖拽运行时及经消费核对的共享功能。笔记、画布、GuguChat、全局搜索按功能保留聚合目录。可共享的项目、日历、文件及设置子模块由两端页面组合。
- **Desktop**承接整个 renderer 入口树，保留壳层、原生文件动作、托盘或窗口相关 UI、系统权限请求与本机聊天适配。主进程、preload、文件系统与 IPC 授权仍驻 `apps/desktop`。预览代理仅引入纯契约入口。
- **Web**承接主站、Admin、登录注册与公开页、Web 通知入口和 HTTP/SSE 适配。Admin 仍使用其独立构建与路由流程。按屏幕尺寸切换的布局归原功能模块。

### 3.2 依赖规则

`desktop → shared` 与 `web → shared` 是 UI 源码允许的跨层依赖。共享层可以依赖稳定的 Core 契约。平台目录之间不直接 import。Vite、TypeScript、Vitest 和 Playwright 使用同一套别名映射，迁移期间对尚未拆分的跨层 import 指明责任模块，收敛完成后移除临时映射。

沿用现有 Vue 注入模式，例如 `fileOpenAccessKey`、`mcpAccessKey` 和 `skillAccessKey`。按业务能力拆解 `services/api.ts` 内的平台分流，避免把整个 API 对象做成一个全局接口。Web 适配器维持 Cookie、请求取消和流重连契约，Desktop 适配器维持 IPC 身份、权限门、取消信号和事件生命周期。现有存储键、数据目录、SQLite、服务配置和日志策略延续。

### 3.3 构建与消费

保留前端包名 `gugu-web`，使现有 pnpm filter 可继续使用。迁移 `vite.config.js`、`vite.admin.config.js`、`vite.desktop.config.js`、TS 配置、测试入口、静态资源与 Docker 构建上下文。产物在新工作区内生成，Web 仍交付 `dist`，Desktop 仍交付 `dist-desktop` 并打包到安装包的 `ui` 目录。

已发现的消费者包括 `pnpm-workspace.yaml` 和 lockfile importer、`apps/desktop/scripts/dev.mjs` 与 `package.ts`、`apps/web-host/deploy/Dockerfile`、原 `apps/web/Dockerfile.prod`、`scripts/dev-restart.sh`、测试分层/元数据、质量扫描及发布 workflow。路径切换必须覆盖本地启动、容器 copy、安装包 staging 和测试报告上传。生成声明、构建产物和锁文件按相应工具生成。

## 5. 风险与待确认问题

| 风险 | 影响 | 对策 |
|---|---|---|
| 只搬目录，平台分流继续散落 | Web 和 Desktop 仍互相依赖 | 建立可执行的 import 边界检查，按领域移除临时例外。 |
| Vite 与发布脚本有不同路径假设 | 开发预览正常，生产 Web 或桌面包缺资源 | 每次切换同时验证真实消费链路，覆盖 Admin 与 Docker copy。 |
| 误把同名页面强行统一 | 丢失权限反馈、编辑状态或原生交互 | 以既有路由和跨端实际行为决定共享粒度，优先抽共用组件与接口。 |
| 桌面预览路由出现重复定义 | 预览请求被拒或行为漂移 | 延续路由单一来源，测试真实转发和未授权请求拒绝。 |
| 样式导入顺序或 Vue 解析路径变化 | 主题回归、弹层裁切、响应式或注入异常 | 保留入口样式顺序和 Vue 去重，覆盖窄屏 Web 与桌面预览。 |

待确认事项为后续是否改名 `gugu-web`。本次基线保留名称，目录边界、构建和验收均可独立推进。
