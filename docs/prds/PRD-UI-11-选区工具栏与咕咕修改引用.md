# PRD-UI-11 选区工具栏与咕咕修改引用

状态：选区引用与笔记写入已实现，文件条件写入与双端实机验收待完成
适用端：Web、Electron 桌面

## 目标

用户选中一段文字、代码或一个对象后，可以点「提出修改」，把来源和实际选中内容引用到咕咕聊天，再补充修改要求。用户能在发送前核对引用，咕咕能在获准写入时准确定位原文。

例如，选中 `config.yml` 第 18–26 行，点「提出修改」，输入「把请求超时改成 30 秒」。聊天显示文件名、行号及可展开的选中原文。

## 范围

| 来源 | 交付阶段 | 定位和处理方式 |
| --- | --- | --- |
| 代码与纯文本预览器 | 首版 | 工作区文件引用、相对路径、行列范围、选中原文和文件版本。具备写入能力时可修改源文件。 |
| 笔记与便签编辑器 | 首版 | 便签 ID、可稳定重定位的编辑器范围、选中原文和保存版本。未保存选区可引用，写入前需保存并重新定位。 |
| 渲染 Markdown | 首版 | 支持引用可见文字。有可靠源映射时可修改原文，其余场景提供改写建议。 |
| 项目、日程和画布对象 | 后续 | 使用对象 ID 和可编辑字段快照。多选时每个对象单独引用，通过对应领域工具修改。 |

首版覆盖鼠标选区和键盘选区。跨对象选区、系统级选区和后台自动采集留待后续评估。

## 交互流程

1. 在已接入的页面形成有效选区后，鼠标或触控拖选须等松手才在选区上方显示工具栏。键盘选区在选取后显示。浮层避开视口边缘。切换选区时更新位置，按 Escape、点击外部或离开来源页面时收起。
2. 点击「提出修改」时先保存当时的选区，再打开咕咕聊天。工具栏消失，输入焦点进入聊天编辑区。已有草稿、附件和引用继续保留。
3. 输入区显示引用卡，包含来源名称、定位和原文预览，并允许展开或移除。引用由用户手动发送。超过长度或数量上限时提示用户缩小选区，避免将截断片段误当作完整写入目标。
4. 桌面已有分体聊天时，将引用送入当前聊天窗口。窗口拖出或吸附之后，草稿与选区引用一起交接。
5. 用户明确要求应用修改后，咕咕通过对应工具核对来源、权限和最新版本，再返回实际修改结果。只读来源允许给出改写建议。

## 公共实现

- **来源适配器**负责从编辑器模型或对象选择状态提取选区，给出定位矩形和引用数据。代码范围来自编辑器，渲染后的 DOM 文本仅作为可见文字快照。
- **选区工具栏**复用公共浮层和交互规范，统一定位、焦点及收起规则。页面注册支持的选区和动作。
- **选区引用**复用 `ChatReference` 的稳定来源标识，扩展结构化快照。至少包含来源类型、对象引用、显示名称、选中原文、定位和可用的源版本。文件由工作区引用解析，相对路径用于用户展示。
- **聊天传输**将快照存入引用元数据，与用户正文分开保存。Web 和桌面只在解析到当前 owner 有权读取的来源后，才把选区和定位交给模型。用户气泡仍显示正文和来源胶囊，早期版本追加到正文里的已知上下文格式在渲染时隐藏。
- **写入**沿用现有文件和对象工具的 owner、工作区访问及确认规则。版本一致时校验指定范围，版本变化时重新读取。仅在能唯一定位并验证原文时写入。无法定位时提示重新选取；权限不足时提供建议。

## 验收标准

- [ ] Web 和桌面均可从代码预览器引用单行、跨行和含中文的选区，引用卡显示正确来源和原文。
- [ ] 笔记与便签选区可引用，未保存内容在写入前有明确提示。
- [ ] 点击工具栏后焦点进入聊天输入区，原草稿和引用仍在，消息不会自动发出。
- [ ] 切换会话、排队发送、窗口拖出和吸附后，引用仍对应原始消息及选区。
- [ ] 源文件改名、移除、版本变化或同段原文重复出现时，写入会重新核对定位，无法确认时保留源文档。
- [ ] 只读和无权限场景有明确反馈，其他普通选区动作仍可使用。

## 实施顺序

1. 确定选区引用契约，跑通预览器 → 工具栏 → 聊天草稿 → 发送与恢复。
2. 接入笔记与便签，验证来源适配接口可以覆盖文件和对象两种定位。
3. 验证真实写入、版本冲突、权限和分体窗口交接，再扩展 Markdown 与项目等对象来源。
