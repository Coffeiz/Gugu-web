# PRD-LLM-20：Agent 邮件发送工具

## 目标

复用 Admin 已配置的 SMTP，为咕咕提供一个受控的主动发邮件能力，用于给当前用户、客户或用户明确指定的收件人发送纯文本或 HTML+纯文本双格式邮件。

## Phase 1 范围

- 新增 `send_email` Agent 工具，复用 `app.services.email.send_email()` 和 Admin 的 SMTP 配置。
- 用户未指定收件人时，默认发送到当前用户的注册邮箱。
- 用户明确指定 `to` 时发送到该地址；指定 `client_id` 时读取当前用户所属客户的邮箱。
- `to` 与 `client_id` 不能同时传入；客户没有邮箱则拒绝发送。
- 发送前始终经过统一确认门，成功或失败都返回明确的结构化结果。

## 安全与边界

- Agent 不接触 SMTP 主机密码，不能修改 SMTP 配置。
- 收件人必须是单个合法邮箱，不接受批量地址、抄送或密送。
- 主题限制 200 字符，正文限制 20,000 字符；确认摘要不包含完整正文。
- 邮件正文和地址不写入可见日志，工具轨迹沿用现有脱敏规则。
- `body` 为必填纯文本 fallback；`html` 为可选 HTML 版本，发送前由公共邮件服务清洗危险标签、事件属性和链接。
- 工具标记为 `mutates=True`、`destructive=True`；不支持附件、群发和定时发送。

## 收件人优先级

```text
client_id（客户邮箱） ─┐
to（用户明确指定）     ├─ 互斥，需确认
未指定                 ─┘ → 当前用户注册邮箱，需确认
```

## 验收标准

- Schema 拒绝 `to` 与 `client_id` 同时出现、非法邮箱及超长主题/正文。
- 未指定收件人时只查询当前用户邮箱，不使用 Admin 的 `smtp.to_addr`。
- 客户查询使用当前用户归属校验，不能读取其他用户客户的邮箱。
- 未带有效确认凭证时不调用 SMTP；SMTP 失败时工具结果为失败且不泄露凭据。
- 覆盖默认收件人、显式地址、客户地址、确认拦截、配置失败和越权客户测试。
- 覆盖 HTML 双格式发送及危险 HTML 清洗，确认凭证必须绑定 HTML 内容。

## 后续

- 邮件模板、附件发送、发送记录、重试/频率限制和定时邮件。
