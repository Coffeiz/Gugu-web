# PRD-SHELL-2：共享协作终端

## 1. 文档信息

- 状态：Phase 0-4 已完成
- 目标：提供用户与咕咕共同可见、可切换、可接管的多终端工作台
- 依赖：`PRD-SHELL-1-工作区Shell沙盒`
- 首版平台：Web，复用现有 Shell 沙盒和工作区权限

## 2. 背景与目标

当前 Shell 主要以聊天工具气泡展示，用户无法持续观察长任务、查看完整输出，也无法区分咕咕正在使用哪个执行环境。需要增加一个独立终端页面，让终端成为聊天、Goal 和 Shell 工具之间的共享工作空间。

本 PRD 只定义终端会话的展示、生命周期和协作能力，不改变 Shell 沙盒的安全边界。终端页面不能授予新的 Shell 权限，也不能绕过工作区、网络、危险命令和用户隔离策略。

## 3. 核心体验

### 3.1 多终端

- 用户可以创建多个终端，以标签页或终端列表切换。
- 每个终端支持重命名、关闭和查看状态。
- 终端显示创建时间、所属工作区、来源（用户/咕咕）和最近活动时间。
- 刷新页面或暂时离开页面后，终端会话和已持久化输出仍可恢复。
- 关闭终端与终止进程分离：关闭只断开查看，终止才发送明确的终止请求。

### 3.2 咕咕使用中的终端

- 咕咕通过 `shell_exec` 执行命令时，自动关联一个终端会话。
- 如果当前 Goal 或会话已有对应终端，优先复用；否则创建新的咕咕终端。
- 终端顶部显示关联的聊天会话、Run、Goal 或工具调用入口。
- 用户可以从聊天工具气泡跳转到终端，也可以从终端回到对应 Run。
- 咕咕的命令、工具输出和用户输入必须有明确的来源标识。

### 3.3 用户协作

- 用户可以在已授权终端中输入命令，输入内容与咕咕输入使用不同样式区分。
- 用户只能操作自己有权访问的终端和工作区。
- 咕咕正在运行时，用户默认只读观察；是否允许用户接管由终端状态和后续权限策略决定。
- 终止任务、接管会话和关闭终端都需要明确的交互反馈。

## 4. 权限与可见性

终端页面使用与 Shell 工具相同的服务端有效权限判断：

```text
Admin Shell 总开关
        ↓
用户 Shell 权限
        ↓
当前会话与工作区范围
        ↓
终端会话访问权限
```

- Admin 关闭 Shell 总开关时，导航入口和终端页面隐藏。
- 用户没有 Shell 权限时，导航入口隐藏；直接访问路由也必须由后端返回无权限。
- 用户有 Shell 权限时，用户创建的终端不要求绑定聊天会话；输入仍按当前用户 Shell 权限、工作区和 system 范围重新判定。
- 开启 system 权限后，未绑定工作区的用户终端使用 system 范围；否则使用用户独立沙盒范围。
- Shell 权限被撤销时，已有终端立即停止接受新输入；正在运行的任务按现有 Shell 取消策略处理，终端页面同步变为不可用。
- 前端隐藏只是体验层，不能作为权限控制。所有终端查询、连接、输入和终止操作都必须在后端重新校验 owner、session、workspace 和 Shell capability。
- 终端不能访问其他用户、其他群组或未授权工作区的输出和历史。

## 5. 技术方案

```text
TerminalPanel
    ↓ WebSocket（交互与实时输出）
Terminal Session API / Manager
    ↓
PTY 或 ShellSandboxExecutor
    ↓
PRD-SHELL-1 的 sandboxd / Docker 沙盒
```

### 5.1 终端会话模型

终端会话至少包含：

```text
terminal_id
owner_id
session_id
workspace_id
source: user | agent
status: idle | running | waiting_confirm | exited | failed | terminated
shell_mode: sandbox | system
network_profile
command_count
created_at
updated_at
closed_at
```

命令和输出单独记录，不能把完整终端输出写入普通可见日志。输出持久化需要限制单条大小、总大小和保留时间，并对敏感内容执行现有脱敏策略。

### 5.2 实时传输

- 首选 WebSocket：支持用户输入、实时 stdout/stderr、窗口尺寸变化、终止和重连。
- 页面只观察时可以使用 SSE，但不能用 SSE 承担交互输入。
- 每个事件包含 `terminal_id`、单调递增序号和事件时间，重连时从最后序号继续请求，避免输出重复或乱序。
- 后端必须校验终端 owner 和访问范围后才建立连接。
- 断开连接不自动杀掉进程；显式终止、超时、配额耗尽或沙盒退出才改变运行状态。

### 5.3 安全边界

- 终端复用 `PRD-SHELL-1` 的 Shell capability、沙盒、网络 profile、危险命令确认、输出限制、超时和进程清理。
- 用户不能通过终端参数修改 `uid`、挂载、网络、能力、工作区根目录或容器安全配置。
- 终端会话不能成为绕过工具确认门的通道；咕咕发起的危险命令仍需经过现有确认策略。
- 禁止把宿主机 PTY、Docker socket 或未过滤的 shell 管道直接暴露给浏览器。
- 终端输出、命令和输入不得进入普通业务日志；诊断日志只记录指纹、长度、状态和错误类型。

## 6. 页面结构

- 导航入口：`终端`，仅在有效 Shell capability 可用时显示。
- 左侧终端列表：名称、状态、来源、工作区和最近活动时间。
- 主区域：终端输出、输入区、运行状态、工作区和网络 profile 摘要。
- 顶部关联条：聊天会话、Run、Goal、工具调用跳转。
- 操作区：新建、重命名、断开查看、终止任务、关闭终端。
- 无工作区时显示绑定工作区入口，不显示容易被误解为可执行成功的终端空白页。

## 8. 自动化测试覆盖

终端持久化和权限回归测试位于 `backend/tests/test_terminal_access.py`，使用隔离的
SQLite 测试库和双用户 fixture，不连接真实 Shell、Docker、网络或用户配置。当前覆盖：

- 终端契约、Admin Shell 总开关、用户 Shell 权限和无工作区终端访问。
- owner 隔离：跨用户终端查询、跨用户会话输入均返回拒绝，不泄露资源存在性。
- 事件序号严格递增，按 `after` 游标续传时只返回未确认事件。
- 用户/咕咕来源、Run 关联、失败状态、stderr 和退出码的持久化。
- 多终端事件流隔离，切换终端不会串入另一终端的命令输出。
- 终止、重开和刷新恢复：状态事件与命令历史均保留，重开不清空历史。

运行方式：

```bash
cd backend
PYTHONPATH=. .venv/bin/pytest tests/test_terminal_access.py -q
```

后续引入真实 PTY/WebSocket 后，再增加浏览器层的端到端测试，验证流式输出、断线
重连、输入发送和终止动作；当前一次性 Shell 执行器不把不存在的 PTY 行为伪装成
已覆盖能力。

## 9. 验收标准

- Shell 总开关关闭时，终端入口隐藏，直接访问和 API 请求均被拒绝。
- 用户只能看到并操作自己的终端及授权工作区。
- 同时存在多个终端时可以稳定切换，输出不会串台。
- 咕咕执行长任务时，用户可以实时看到命令和输出，并能定位到对应 Run。
- 浏览器刷新或短暂断线后可以恢复终端状态，不重复显示已确认的输出。
- 关闭终端不会误杀任务，显式终止才会停止进程。
- 超时、配额、权限撤销、沙盒退出和危险命令确认均有明确状态反馈。
- 自动化测试不产生真实用户终端输出、命令或配置文件。
