# QQ 表情本地缓存 PRD

> 状态：讨论稿，未开始实现
> 创建：2026-08-04
> 关联模块：`backend/agent/gateway/qq.py`、`backend/agent/im/parsers/qq.py`、`backend/agent/im/media_ingress.py`、`backend/app/core/chat_attach.py`
> 相关方案：[`【已完成】PRD-IM-1-im接入稳定性与qq自建websocket.md`](./【已完成】PRD-IM-1-im接入稳定性与qq自建websocket.md)

## 1. 背景

QQ 表情通常会以两部分到达：一段包含表情协议标记的文本，以及紧随其后的图片附件。协议文本中带有可复用的 `faceId`，例如：

```text
<faceType=6,faceId="0",ext="...">
```

当前实现会将协议文本转成 `[QQ表情]`，随后下载图片并按随机 `attach_id` 暂存。`faceId` 没有进入附件元数据，因此同一个用户重复发送相同表情时，系统会再次下载图片。

## 2. 产品目标

当同一个 QQ Bot 收到相同的 QQ 表情时：

1. 优先使用本地已有的表情临时文件。
2. 本地缓存不存在、过期或文件损坏时，再从 QQ 下载。
3. 不影响当前消息的独立附件记录、聊天展示、模型视觉输入和历史引用。
4. 不让不同用户、不同 Bot 的同 ID 表情互相复用。

## 3. 关键概念

### 3.1 `face_id` 与 `message_id` 的区别

| 标识 | 含义 | 用途 |
|---|---|---|
| `face_id` | QQ 表情本身的身份标识，同一表情可能在多条消息中重复出现 | 本地缓存命中键 |
| `message_id` | QQ 这条消息的唯一标识 | 消息去重、来源追踪、问题排查 |
| `attach_id` | 咕咕为当前附件生成的随机暂存标识 | 当前消息和工具调用引用附件 |

禁止使用 `message_id` 作为重复表情缓存键。它只代表一条消息，不代表表情本身。

## 4. 目标链路

```text
QQ raw event
  ↓
解析 faceType / faceId / ext
  ↓
等待或合并对应图片附件
  ↓
按 owner + bot + faceId 查询表情缓存索引
  ├─ 命中且文件可读 → 复用本地文件
  └─ 未命中/失效     → 下载 QQ 图片并写入缓存
  ↓
为当前消息生成独立 attach_id
  ↓
写入当前消息附件元数据，交给模型和前端
```

当前 QQ 表情的协议文本和图片可能是两条事件，必须保留现有的短时 pending 合并逻辑，不能因为增加缓存而把两条事件拆成两条聊天消息。

## 5. 缓存范围与隔离

### 5.1 推荐缓存键

```text
qq-face:{owner_user_id}:{bot_id}:{face_id}
```

- `owner_user_id`：隔离咕咕用户。
- `bot_id`：隔离不同 QQ Bot，避免同一个 `face_id` 在不同 Bot 下错误复用。
- `face_id`：QQ 表情身份。

这里的 `bot_id` 优先使用现有 payload 的 `channel_id`；如果后续确认 `channel_id` 不是稳定 Bot 身份，需要替换为稳定的 `user_bot.id` 或等价 Bot scope。

### 5.2 缓存元数据

缓存索引可放在 Redis，内容文件放在本地临时目录。建议保存：

```json
{
  "face_id": "0",
  "owner_user_id": "...",
  "bot_id": "...",
  "attach_id": "...",
  "storage_key": "...",
  "ext": "png",
  "mime": "image/png",
  "size": 12345,
  "source_message_id": "...",
  "created_at": "...",
  "last_used_at": "..."
}
```

`source_message_id` 只做来源追踪，不参与缓存命中。

### 5.3 本地文件边界

本需求的“本地缓存”指 QQ 表情专用临时文件，不进入用户文件库，也不应出现在文件搜索、配额统计或用户可见的文件列表中。

当前 `chat_staging` 使用统一 `StorageBackend`，切到 OSS 后可能把暂存文件写入 OSS。实现前需要二选一：

1. **推荐首期**：QQ 表情缓存使用独立本地目录，Redis 只存索引；即使全局文件存储切到 OSS，也保持 QQ 表情缓存本地化。
2. **简化方案**：复用 `chat_staging` 和统一 StorageBackend。实现量较小，但“本地缓存”会随全局存储后端切换，不完全符合本 PRD 的边界。

首期采用方案 1，除非部署环境明确禁止服务端本地临时目录。

## 6. 功能需求

### FR-1：保留表情身份

- 解析器从 QQ 协议文本提取 `face_id`。
- 文本展示仍使用已有的表情名称或 `[QQ表情]`，不能把协议串泄漏给模型和用户。
- `face_id` 随对应图片附件传递到 Worker。
- 多表情消息必须验证表情 ID 与图片附件的对应关系，不能默认把第一个 ID 绑定第一张图。

### FR-2：缓存命中优先

- Worker 处理 QQ 图片附件前，先查询 `qq-face` 索引。
- 索引存在时检查本地文件是否存在、可读且大小大于 0。
- 命中后跳过 QQ 下载，直接使用缓存文件内容。
- 当前消息仍创建自己的 `attach_id`，避免多个消息共用同一个消息引用标识。

### FR-3：下载回填

- 缓存未命中时按现有 URL 安全规则下载。
- 下载成功后写入本地表情缓存，并记录 `face_id`、Bot scope 和来源消息。
- 下载失败时保持现有附件失败行为，不伪造缓存命中。

### FR-4：缓存失效与清理

- Redis 索引与本地文件任一缺失，都视为缓存未命中。
- 缓存设置最长 TTL，并支持按 `last_used_at` 清理。
- 清理失败不能影响正常消息处理。
- 缓存不计入用户文件库配额；如需要单独监控，记录总文件数、总字节数和命中率。

### FR-5：并发去重

- 同一 `owner + bot + face_id` 同时首次到达时，只允许一个任务下载。
- 其他任务等待短时间后重新查询缓存；锁超时则允许一次受控回退下载。
- 不能因为缓存锁阻塞 QQ 消息主链路。

## 7. 非目标

- 不把 QQ 表情自动保存为用户文件库文件。
- 不改变 QQ 表情的发送协议和咕咕主动发送图片的逻辑。
- 不跨用户共享表情缓存。
- 不仅根据图片二进制 hash 推断表情身份；hash 只能作为后续完整性校验或无 ID 兜底。
- 不把 QQ CDN URL 作为长期缓存键，URL 可能过期或带临时授权。

## 8. 需要先验证的协议问题

实现前增加一次脱敏探针或专项测试，确认真实 payload：

1. `faceId` 是否始终出现在协议文本中。
2. 表情协议文本与图片附件是否稳定按顺序对应。
3. 一个消息包含多个表情时，图片数量和顺序是否一致。
4. 重复发送相同表情时 `faceId` 是否保持不变。
5. 不同 QQ Bot 是否可能使用相同 `faceId` 但返回不同图片。
6. 图片附件是否自带可用的表情 ID；如果自带，应优先使用附件字段而不是依赖顺序推断。

探针只记录字段名、`face_id` 的不可逆指纹、附件数量和类型，不记录 URL、图片内容、消息正文或用户 ID 原文。

## 9. 实施阶段

| 阶段 | 内容 | 状态 |
|---|---|---|
| Phase 0 | 真实 payload 探针，确认 faceId 与图片附件映射 | 🟡 探针已接入，待真实 QQ 消息验收 |
| Phase 1 | 解析器保留 `face_id`，payload/暂存元数据透传 | ⬜ 未开始 |
| Phase 2 | 独立本地缓存目录 + Redis 索引 + 命中复用 | ⬜ 未开始 |
| Phase 3 | 并发锁、TTL、清理和缓存统计 | ⬜ 未开始 |
| Phase 4 | 真实 QQ 重复表情验收，确认模型/前端行为无回归 | ⬜ 未开始 |

## 10. 验收标准

- [ ] 同一用户、同一 Bot、同一 `face_id` 连续发送两次，第二次不发起 QQ 图片下载。
- [ ] 删除或破坏缓存文件后，下一次发送能自动重新下载并恢复缓存。
- [ ] Redis 索引过期后，下一次发送能自动重新下载。
- [ ] 不同用户的相同 `face_id` 不互相命中。
- [ ] 不同 Bot 的相同 `face_id` 不互相命中。
- [ ] 表情协议串不会出现在聊天正文、模型上下文和前端展示中。
- [ ] 表情附件仍能正常显示、被模型识别、在需要时保存为正式文件。
- [ ] QQ 表情和普通图片、语音、引用附件的现有处理不回归。
- [ ] 并发发送相同表情不会生成大量重复缓存文件。
- [ ] 缓存清理不会删除用户文件库文件，也不会阻塞消息回复。

## 11. 风险与决策点

| 风险 | 影响 | 对策 |
|---|---|---|
| `faceId` 与附件无法稳定对应 | 误把表情缓存成另一张图 | 先做 Phase 0；多表情无法确认时不启用复用 |
| 不同 Bot 的 ID 空间重叠 | 表情内容串用 | 缓存键必须包含 Bot scope |
| 本地缓存被清理或磁盘不足 | 缓存命中下降 | 命中前检查文件，失败自动回源；限制总大小 |
| QQ CDN URL 过期 | 重新下载失败 | 不保存 URL 作为长期身份，只在当前消息使用 |
| 缓存锁异常 | 消息处理延迟 | 短 TTL、超时回退，不阻塞主链路 |
