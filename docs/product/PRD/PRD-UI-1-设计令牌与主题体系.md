## 1. 背景与目标

### 现状痛点

- `frontend/src/assets/styles/variables.css` 只有约 29 条 CSS 变量，覆盖玻璃拟态背景、5 个主题色、2 个文字色、3 档圆角、少量尺寸和字体族，命名风格是 `--类别-用途`。
- 实际调研统计：146 个 `.vue` 文件里有 **117 个（约 80%）** 在 `<style>` 块里直接写死颜色/rgba，而不是引用变量。高频硬编码值举例：
  - 主色 `#7b7fb2` 硬编码 140 次（同时也有 49 个文件在正确引用 `--color-primary`，是最该收敛的一项）
  - `rgba(255,255,255,0.1)` 64 次、`rgba(0,0,0,0.07)` 58 次
  - 圆角碎成 `8px`(105)/`6px`(77)/`10px`(64)/`7px`(56)/`9px`(55)/`20px`(43) 好几档，跟现有 `--radius-sm/md/lg`（10/14/18px）三档对不上
  - 字号碎成 `12px`(273)/`11px`(199)/`13px`(191)/`10px`(76)，还有 `12.5px`/`11.5px` 这类散点值
  - 成功/警告/错误语义色**完全没有变量**，且同一语义存在 4～5 种相近但不一致的具体色值（复制粘贴微调导致）
- `docs/development/design.md` 的"UI 设计规范"一节是纯文字写死数值，容易和代码实际值脱节（本次调研就是个例子：文档里的值和代码里散落的实际值对不上）。

### 目标

1. 建一套语义化（不是"颜色本身"命名，而是"这个值是干什么用的"）的设计令牌体系，覆盖颜色（含成功/警告/错误语义色）、字号、圆角、间距、阴影。
2. 做一个可视化的令牌展示页面，**替代** `design.md` 里"UI 设计规范"这一节——之后改令牌先改代码里的变量定义，页面直接反映最新值，不需要另外维护一份文字文档。
3. 把存量硬编码值替换成令牌引用（工作量大，允许分批推进，不要求一次性覆盖全部 117 个文件）。
4. 语义化命名要为 Phase 2/3 的多主题切换预留空间——即"这次先只做亮色一套值"，但令牌的**命名**必须是主题无关的（比如 `--surface-card`、`--text-primary`，不能是 `--white`、`--dark-gray` 这种描述具体颜色的命名），否则 Phase 2 暗色模式落地时又要把命名推倒重来。

### 不做的事（本 PRD 范围外，留给 Phase 2/3）

- 暗色模式的具体实现（CSS 覆盖、`data-theme` 切换机制）。
- 主题选择 UI（亮色/暗色/跟随系统三选一）和用户偏好持久化（数据库字段/API）。
- 除亮色外的第二套品牌配色主题。

## 2. 功能需求

### FR-UI-1：语义化令牌体系设计（🔲 待评估）

- 令牌分类：颜色（表面色 `surface-*`、文字色 `text-*`、边框色 `border-*`、语义色 `success/warning/danger-*`、品牌色透明度阶梯 `primary-08/12/18/...`）、字号阶梯（替换现在 12/11/13/10px 等散点值）、圆角阶梯（替换现在 8/6/10/7/9/20px 等散点值）、间距阶梯、阴影（`shadow-card`/`shadow-card-hover` 等语义命名，不按数值命名）。
- 每个语义色的"相近但不一致"的历史遗留值（比如成功色的 4～5 种绿色）需要先人工挑一个作为标准值，不是简单取众数。
- 命名规则、分层方式（是否需要 primitive/semantic 两层，还是直接语义化）待技术方案里定。

### FR-UI-2：令牌可视化展示页面（🔲 待评估）

- 替代 `docs/development/design.md` 的"UI 设计规范"章节，列出所有令牌分类、当前取值、用途说明、示例（比如颜色令牌显示色块，圆角/阴影令牌显示对应样式的卡片）。
- 页面本身直接读取运行时的 CSS 变量值渲染，不是手写文档里的数值——保证令牌页面和代码实际值不会脱节。
- 访问入口、权限（是否只对内部/开发环境可见）待定。

### FR-UI-3：存量硬编码值替换为令牌引用（🔲 待评估）

- 优先级：语义色（数量最少、不一致问题最明显）→ 品牌色透明度阶梯 → 圆角/字号阶梯 → 其余。
- 允许分批次提交，不要求一个 PR 全量替换完；每批次替换后需要过一遍视觉回归（人工或截图对比），避免"改了变量值但某处引用方式不对导致样式跑掉"。

### FR-UI-4（Phase 2，暂不启动）：暗色模式令牌

- 在 FR-UI-1 的语义令牌命名基础上，补一套 `data-theme="dark"` 覆盖值。

### FR-UI-5（Phase 3，暂不启动）：主题选择与持久化

- 亮色 / 暗色 / 跟随系统三个选项（不是"开关+自动"两套并行逻辑）；"跟随系统"时监听 `prefers-color-scheme` 变化。
- 用户偏好存数据库（具体字段/API 待 Phase 3 展开时定），前端读取后设置 `<html data-theme>`。
- 后续如果要支持第二套品牌配色主题，机制复用同一个 `data-theme` 属性，不需要新机制。
