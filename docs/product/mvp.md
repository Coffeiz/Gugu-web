## 易读概述

**这篇文档回答的问题**："咕咕做到什么程度可以对外找一批真实用户试用？"

MVP（最小可行产品）不是"功能齐全"，而是"核心主线能跑通、稳定不出大问题、能收到有效反馈"。这篇文档定义了：

- 内测要给谁用、成功的标准是什么；
- 哪些功能是内测前必须有的，哪些明确不做；
- 上线前要检查的技术清单（服务器、备份、密码、邮件通知等）；
- 内测开始后每个阶段该做什么。

**核实说明**：本文档原标注版本为 0.11.1，之后曾更新到 0.15.2，但仓库当前版本已到 1.0.1。期间已完成周视图、通知、新手引导、统一事件更新、交互式 PTY 终端、LoopScope、多用户安全加固和大量页面收口；后端当前仍以 Python/FastAPI 为主，TypeScript 仅用于 RAG worker 与 LoopScope Collector，不再按“TypeScript 后端迁移”描述。下方状态按当前代码和报告核实，涉及生产服务器、备份和真实用户运营的数据仍单独标记为待现场验收。

## 专业细节

### 一、MVP 定义

**目标用户**：有目标要推进、想做个人成长记录的个人用户（工作 / 创作 / 学习 / 生活皆可，创作者是重点群体之一）。

**MVP 成功标准**：
- 用户能独立完成「新建项目 → 归档文件 → 用咕咕管理进度 → 收到截稿提醒」完整主线
- 稳定运行 ≥ 2 周无服务中断
- 收到有效反馈 ≥ 20 条，能驱动下一个迭代方向

> 当前只能确认核心功能已具备；“稳定运行 2 周”和“有效反馈 20 条”需要内测运营数据确认，不能由代码仓库直接判定完成。

**MVP 不做的事**：
- 不追求完整功能覆盖（素材板、ToB 均不是 MVP 核心验收范围；思维记录和画布虽已存在，但不作为本轮主线门槛）
- 不追求极致性能优化（够用即可）
- 开放公开注册，并通过注册限流和账号管理控制滥用

### 三、上线前检查清单

> 以下清单为运维/安全类事项，与功能进度无关。当前仓库只能核对配置入口和启动脚本，不能代替生产服务器检查；未有现场证据的项目均保持待验收。

#### 3.1 基础设施

- [ ] **systemd 三服务**：`systemctl status gugu-web gugu-worker gugu-gateway` 均为 `active (running)`；`Restart=always` 已配置
- [ ] **开机自启**：`systemctl is-enabled` 三服务均为 `enabled`
- [ ] **nginx**：`/` 指向前端 dist、`/api/` 反代后端 8000、`/uploads/` **不对外暴露**（应由后端鉴权接口提供）
- [ ] **HTTPS**：SSL 证书有效，自动续签（Let's Encrypt）
- [ ] **防火墙**：8000 端口不对外暴露，只 nginx 内网转发

#### 3.2 数据安全

- [ ] **数据库备份**：`pg_dump` 每日定时任务，备份文件存异地（对象存储 / 另一台机器）
- [ ] **uploads 目录备份**：本地存储时 `uploads/` 同步到 OSS 或另一台机器；OSS 后端时开启 OSS 版本控制
- [ ] **数据库密码**：非默认值，`.env` 文件权限 `600`
- [ ] **Admin 密码**：已显式配置生产强随机密码
- [ ] **JWT Secret**：非默认，足够随机（≥ 32 字符）

#### 3.3 邮件 / 通知

- [ ] **SMTP 配置**：Admin → 系统配置 → 邮件系统 → 测试发送，确认能收到
- [ ] **反馈通知**：提交一条测试反馈，确认邮件送达
- [ ] **收件人地址**：`to_addr` 填的是真实能收信的地址

#### 3.4 存储

- [ ] **OSS 切换**（如准备好上线即用 OSS）：Admin 切 `backend=oss` → 上传一张图 → 确认 presign → PUT → confirm 完整链路
- [ ] **本地文件迁移**（如从本地切 OSS）：用 `ossutil` 将 `uploads/` 全量同步到 OSS 同名 key，再切后端
- [ ] **存储对账**：Admin → 数据库 → 存储对账，确认无幽灵/孤儿异常

#### 3.5 用户体验

- [ ] **空状态验收**：用新账号走一遍主线，检查无数据时各页面显示是否友好（新手引导已上线，但仍建议实测一遍首次体验）
- [ ] **移动端基础可用**：主要功能在手机浏览器可访问（不要求完美，但不能完全崩掉）
- [ ] **404 / 错误页**：已有咕咕风格 404 页，确认路由不存在时正常跳转

#### 3.6 监控 / 应急

- [ ] **日志可查**：`tail -f logs/gugu-web.log` / `gugu-worker.log` 能正常输出；Admin → 调试 → 系统日志可用（代码已支持关键词和 `trace_id`，生产可用性仍需现场确认）
- [ ] **磁盘空间**：确认服务器磁盘余量充足（uploads 目录会持续增长）
- [ ] **内存 / CPU 基线**：空载状态下确认三服务资源占用在预期范围内
- [ ] **应急预案**：知道怎么快速回滚（保留上一个可用的 git tag / docker image）
