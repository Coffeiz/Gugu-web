# 咕咕工具设计

> 状态：笔记 CRUD 工具已落地；关系与画布工具待实施
> 上游：[设计草案.md](设计草案.md)（产品）、[数据模型草案.md](数据模型草案.md)（数据）、[实现方案.md](实现方案.md)（阶段）
> 最后更新：2026-07-13

本文定义咕咕读写思维面板时的工具边界。目标不是让咕咕拥有一个自由 Markdown 编辑器或画布自动排版器，而是让它可靠地记录、读取、修改和关联用户已有的思考。

## 核心原则

1. **能力不超过 UI**：咕咕只能写入笔记编辑器已经支持、用户随后能稳定继续编辑的内容和样式。
2. **动作清楚，字段充分**：沿用现有 `create_*` / `update_*` / `delete_*` / `get_*` 工具风格；创建和更新一次带齐相关字段，避免拆成大量小调用。
3. **每个领域一组工具**：笔记、关系、画布各自独立；不做混合所有资源的总控工具。
4. **服务端是唯一写入边界**：网页和咕咕复用同一笔记领域服务，统一校验、序列化、索引状态、时区和乐观锁。
5. **显式意图才写入**：用户明确说“记一下”“把这条改成”等，咕咕才执行；归纳、改写、提炼先给草稿，用户确认后才落库。

## 当前能力

`MindSkill` 已接入默认咕咕工具集：

| 工具 | 状态 | 用途 |
|------|------|------|
| `mind_search` | 已完成 | 按标题和正文关键词搜索笔记/画布便签，并返回一跳关联摘要。 |
| `mind_get` | 已完成 | 按节点 ID 读取完整正文、来源对象和一跳关联。 |
| `create_note` | 已完成 | 使用受限块创建一条咕咕来源的笔记。 |
| `update_note` | 已完成 | 使用精确 ID 和版本更新标题、颜色、正文、追加内容或记录时间。 |
| `delete_note` / `restore_note` | 已完成 | 精确软删与恢复笔记。 |
| `undo_last_gugu_note` | 已完成 | 只撤销最近一条咕咕创建的笔记。 |

读取严格限制为当前用户的 live 节点；直接按 ID 读取必须走 `get_owned()`。工具不写节点、关系或画布数据。

## 笔记工具

### 检索与读取

```ts
mind_search({
  q: string,
  limit?: number,             // 默认 5，最大 10
  include_content?: boolean,  // 默认 false；true 时返回完整受限块内容
})

mind_get({
  node_id: number,
})
```

`mind_search` 默认只返回预览，避免多个长笔记挤满上下文。问题明显需要原文时，咕咕可在同一次检索中传 `include_content: true`；只有要对特定节点继续深读时才调用 `mind_get`。

两种读取结果都应包含 `node_id`、`version`、`title`、`color`、`captured_at`、来源摘要和一跳关联。这样咕咕找到笔记后，通常可以直接进入修改，不必额外查询版本号。

### 创建

```ts
create_note({
  title?: string,
  color?: NoteCardColor,
  blocks: MindNoteBlock[],
  captured_at?: string, // ISO 8601 且带时区；未传则采用当前用户时间
})
```

一次创建可以同时写标题、卡片颜色、正文和补录时间。服务端存储时把 `captured_at` 转为 UTC；用户说“昨天”时，咕咕按用户时区解析日期，不自行猜测 UTC 时间。

### 更新

```ts
update_note({
  node_id: number,
  version: number,

  title?: string | null,
  color?: NoteCardColor | null,
  blocks?: MindNoteBlock[],
  append_blocks?: MindNoteBlock[],
  captured_at?: string,
})
```

- `blocks` 是整篇替换，`append_blocks` 是在末尾追加，两者互斥。
- `title: null` 或 `color: null` 表示清空该字段、恢复默认展示。
- 修改必须使用搜索或读取结果中的精确 `node_id`；名称定位只由 `mind_search` 承担，不让更新工具做模糊匹配。
- `version` 来自搜索或读取结果；服务端用乐观锁避免覆盖网页或其他端刚刚完成的修改。

### 删除与恢复

```ts
delete_note({
  node_id: number,
  version: number,
})

restore_note({ node_id: number })
undo_last_gugu_note()
```

删除只做软删，因此不属于不可逆操作；`restore_note` 可恢复指定笔记。即便如此，`delete_note` 也**只接受已经确认的** `node_id` 和 `version`，不接受标题、关键词或日期定位：用户说“删除我的计划”时，咕咕必须先用 `mind_search` 列出候选、让用户明确指定，再执行删除。不能因为模糊匹配恰好命中一条就直接删。

`undo_last_gugu_note` 仅撤销当前用户最近一次由咕咕创建且尚未删除的笔记，内部至少限制 `origin='gugu'` 和 `deleted_at IS NULL`，绝不触碰用户自己创建的笔记。将来需要撤销更新笔记、创建关系等更多动作时，另建带持久 `action_id` / `undo_token` 的操作记录，并扩展为 `undo_last_gugu_action()`；不让当前的笔记撤销工具承担未实现的通用事务语义。

创建、更新、恢复成功后统一返回完整笔记和最新 `node_id` / `version`，使后续操作不需要额外读取。

## 受限内容协议

咕咕不直接提交任意 `content_md`，而是提交结构化块。服务端把块转换为现有受限 Markdown，并同步派生 `content_plain`。

```ts
type MindInline =
  | {
      type: "text";
      text: string;
      marks?: Array<
        | { type: "bold" }
        | { type: "italic" }
        | { type: "strike" }
        | { type: "code" }
        | { type: "link"; href: string }
      >;
    }
  | {
      type: "reference";
      ref_type: "project" | "file" | "event";
      ref_id: number;
      label: string;
    }

type MindNoteBlock =
  | { type: "paragraph"; content: MindInline[] }
  | { type: "heading"; content: MindInline[] }
  | { type: "bullet_list"; items: MindInline[][] }
  | { type: "ordered_list"; items: MindInline[][] }
  | {
      type: "task_list";
      items: Array<{ content: MindInline[]; checked: boolean }>;
    }
  | { type: "blockquote"; paragraphs: MindInline[][] }
  | { type: "code_block"; code: string; language?: string }
  | { type: "horizontal_rule" };
```

允许的呈现能力是当前笔记编辑器已经支持的：段落、单级标题、无序/有序列表、待办列表、引用块、代码块、分割线、加粗、斜体、删除线、行内代码、链接，以及项目/文件/活动引用。引用由服务端序列化为稳定的 `[[type:id|label]]` 标记；咕咕应先通过 `global_search` 找到业务对象 ID，不能编造引用。链接只允许 `http`、`https` 和 `mailto` 协议，行内代码不与其他文字样式叠加。

以下内容当前明确禁止：表格、图片、HTML、多级标题、任意 Markdown 扩展。将来只有网页编辑器、Markdown 往返、预览渲染都先支持并验证后，才可同步开放给咕咕。

## 卡片颜色

`NoteCardColor` 有五种稳定状态：`null`（默认纸色）、`amber`、`coral`、`blue`、`teal`：

- 后端拒绝任何不在这五种状态内的颜色。
- 不接受 CSS、HEX、渐变或咕咕临时生成的新颜色。
- 咕咕只可选择用户在现有卡片 UI 中已经能选择的默认纸色或四种自定义颜色。

## 写入服务与安全边界

笔记写入需提炼为网页 API 和工具共用的领域服务，负责：

1. 校验受限块、引用对象归属及颜色枚举。
2. 将块序列化为 `content_md`，并从中派生 `content_plain`。
3. 内容变化时重算 `indexed_hash`、清空 `indexed_at`。
4. 以用户时区解释输入时间、以 UTC 存储 `captured_at`。
5. 使用现有 `update_node_atomic()` 执行带版本的更新。
6. 所有节点、关系、画布读取与写入均走 `get_owned()`，不暴露跨用户资源是否存在。

咕咕不得传入或覆盖 `user_id`、`kind`、`origin`、`content_plain`、`indexed_at`、`indexed_hash`、`deleted_at`、`ref_type`、`ref_id` 等系统字段。可见日志不得记录用户笔记正文；沿用 `fingerprint()` 和脱敏日志边界。

## 笔记与画布的边界

思维页面保持一个一级入口，笔记与画布通过独立路由和工作区切换：笔记页是时间流，画布页是全屏空间。两者共享节点、关系、检索和归属边界，但不是同一种内容：

| 对象 | 节点 kind | 出现位置 | 工具状态 |
|------|-----------|----------|----------|
| 笔记 | `note` | 笔记时间流；可被放入画布 | ✅ CRUD 已完成 |
| 画布便签 | `canvas_note` | 只在画布；不进入时间流 | ⏳ 工具待实施 |
| 业务引用卡 | `ref` | 画布中的项目、文件、活动代理 | ⏳ 工具待实施 |

`create_note`、`update_note` 等笔记工具只操作 `note`，绝不创建画布便签。画布便签使用专用工具和专用删除语义，避免日常记录与空间草稿混为一谈。

## 画布容器工具（已接入 `mind_canvas`）

```ts
mind_list_canvases()
mind_get_canvas({ canvas_id: number })
mind_create_canvas({ title: string, project_id?: number })
mind_add_canvas_node({ canvas_id: number, ref_type: "project" | "file" | "event", ref_id: number })
mind_update_canvas_node({ canvas_id: number, item_id: number, x?: number, y?: number, w?: number, h?: number })
mind_remove_canvas_node({ canvas_id: number, item_id: number })
mind_search_placeable_nodes({ q?: string, queries?: string[] })
```

普通时间流 `note` 不属于画布可放置对象；`canvas_note` 是画布专属便签。移除节点只移除展示项，
不删除原始项目、文件、活动或引用节点。位置支持世界坐标和 viewport/near_node 语义锚点，
camera 与 viewport 由画布前端保存。

mind_update_canvas_note({

画布便签创建时必须选择四种自定义色之一，不允许默认纸色；它不进入笔记时间流。删除画布便签应同时移除它的画布展示项；这不同于 `mind_remove_from_canvas` 的“只从当前画布拿掉”语义。

- [ ] **全部允许格式**：分别记录待办、无序/有序列表、加粗、斜体、删除线、行内代码、链接、代码块、引用块、分割线；网页进入编辑并保存一次，确认内容不丢失、不变形。

- [ ] **修改与追加**：让咕咕给刚才的笔记追加待办，再一次修改标题、正文、颜色和记录时间；确认追加不覆盖旧正文，整篇替换能正确生效。
- [ ] **补录时间**：让咕咕把笔记记到昨天晚上，确认时间流归到昨天；尝试未来日期，确认明确拒绝且不创建记录。
- [ ] **删除与恢复**：存在多条相似“计划”笔记时发送“删除我的计划”，确认咕咕先列候选、不直接删除；指定一条后软删并恢复，确认时间流状态正确。
- [ ] **撤销范围**：网页手动创建笔记 A，再让咕咕创建笔记 B，执行“撤销刚才咕咕记录”；确认只删除 B，A 完全不受影响。
- [ ] **并发冲突**：网页编辑一条笔记后，让咕咕同时修改；确认版本冲突时咕咕提示重新读取，不静默覆盖网页内容。

### 引用生命周期回归

- [ ] **文件移动**：在笔记和画布中各引用一个文件，再将它移动到个人二级目录、项目目录和另一个文件夹；确认引用仍能打开同一文件，画布文件卡展示的是移动后的实时信息，不因路径变化变成墓碑。
- [ ] **项目删除**：在笔记和画布中各引用一个项目后删除该项目；确认笔记保留原名称并显示“已删除”、不可点击，画布保留快照卡但禁用打开与连线，不出现空的项目编辑窗。
- [ ] **文件删除**：在笔记和画布中各引用一个文件后将文件移入回收站；确认两处均保留快照并以墓碑样式显示，不能打开预览或下载；恢复文件后刷新页面，引用应恢复可用。
- [ ] **活动删除**：在笔记和画布中各引用一个活动后删除该活动；确认画布活动卡显示“已删除，仅保留快照”，笔记引用显示删除状态，点击均不弹出空活动编辑窗。
- [ ] **网络异常不误判**：在活动引用可见时临时断网或使请求失败；确认引用不会被标成“已删除”，恢复网络后仍可正常打开。
