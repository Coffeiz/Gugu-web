## P0 — 图层地基（迁移 + 空跑通）✅ 已完成

**目标**：三表 + 约束建好、模型能增删查、归属和乐观锁机制就位；无 UI。

> 落地记录：模型三 class + `User` 三条 relationship、迁移 `20260710000002_add_mind_nodes`、
> `app/core/mind.py`（`update_node_atomic` / `upsert_relation` / `content_hash`）、
> `tests/test_mind_p0_model.py` 23 个测试全过（含并发插入撞车走 SAVEPOINT 回查那条分支）。
> 另核验过：迁移可重复执行、downgrade 干净、迁移建出的表与模型 `create_all` 无列/约束漂移、
> 两个 CheckConstraint 在迁移库里确实拦得住。
>
> 代码审查加固（2026-07-10）：`update_node_atomic` 两处收口——① 内容变更时 `indexed_hash`
> 无条件按新 `content_plain` 重算，调用方只给 `content_md` 时服务层兜底推导，杜绝哈希与正文脱钩
> 导致 P3 漏索引；② 原子 UPDATE 的 WHERE 加 `deleted_at IS NULL`，堵住"读到 live→并发软删→
> 编辑写进墓碑"的 TOCTOU。各补一个针对性测试（故 21→23）。

后端：
1. `models/__init__.py`：加三个 class（连 `UniqueConstraint`/`CheckConstraint`，`CheckConstraint` 记得进 sqlalchemy import）；`User` 上补三条 `relationship`（`cascade="all, delete-orphan"`）；`MindMap` 语义注释更新（`project_id` 降级为可选关联、`files.mind_map_id` 标历史字段）。
2. 迁移：`create_table` 三张 + 唯一约束 `uq_mind_node_ref`/`uq_canvas_node`/`uq_mind_relation` + 检查约束 `ck_mind_node_ref_shape`/`ck_mind_relation_no_self` + 索引（各 `user_id`、`mind_nodes.captured_at`、`mind_nodes.deleted_at`、canvas_item 的 `canvas_id`/`node_id`、relation 两端）。idempotent（`IF NOT EXISTS` 风格同现有迁移）。
3. `app/core/mind.py`（新）：沉淀两个公用函数——
   - `update_node_atomic(db, node_id, user_id, client_version, fields) -> bool`：一条 `UPDATE … WHERE id AND user_id AND version=:v`，返回 `rowcount==1`；`False` 让路由抛 409。
   - `upsert_relation(db, user_id, a, b, rel_type="related", origin="user")`：`related` 先按 id 归一（`src<dst`），命中唯一约束就返回已有边（`ON CONFLICT DO NOTHING` 后回查），保证幂等。

验收：`pytest` 里直接调模型/函数——建 note、建 ref、连 relation、原子 UPDATE 版本冲突返 False、自环被 CheckConstraint 挡、跨用户 `get_owned` 返 None、`related(A,B)` 与 `related(B,A)` 落同一行。

## P2 — 画布可用（自由画布 + 纸条/贴纸 + 拖拽 + 详情栏）

**目标**：自由画布，便签纸条 + 系统对象贴纸，拖动/缩放/连普通关联，右侧详情栏。

后端：
1. `MindNode` 的 `ref` kind 启用：`POST /mind/nodes/ref`（幂等，命中 `uq_mind_node_ref` 返已有）、创建时抄 `title` 快照。
2. 画布容器复用 `mind_maps`：`GET/POST /mind/canvases`（`project_id` 仅作可选筛选）。
3. canvas item：`GET /mind/canvases/{id}/items`、`POST`（过双 `get_owned`：canvas 和 node 都归当前用户，见 schema"跨用户不变量"）、`PATCH`（位置/尺寸/层级/折叠，最后写赢，无 version）、`DELETE`（只删展示项）。
4. relation：`POST /mind/relations`（`upsert_relation`，两端过 `get_owned`）、`DELETE`；本期 `rel_type` 只接受 `related`。

前端：
1. `views/Mind/CanvasView.vue` + `components/MindCanvas.vue` + `useMindCanvas.ts`：无限画布（平移/缩放，节点绝对定位 + transform；节点多时视口裁剪/虚拟化）；`CanvasToolbar.vue` 工具栏、`CanvasSidebar.vue` 画布列表。
2. `NoteSticker.vue`（纸条材质）、`EntitySticker.vue`（复用玻璃卡语言 + 项目色/图标/摘要）、`RelationLayer.vue`（连线渲染 + 命中，默认细浅灰紫、选中才强调）、`NodeInspector.vue`（右侧详情：完整内容/关联/来源）。
3. 拖拽/连线由 `useMindCanvas.ts` 内部接 `usePhysicsDrag`（`tilt:0`、轻 lift、吸附）；从边缘拖出连线落到另一节点建 `related`（P2 只有默认类型，不建 `RelationPicker`）。
4. 删除规则前端呈现：软删的节点渲染成"墓碑"贴纸；`ref` 指向的业务对象没了也显示 `[已删除]+快照名`。

验收：一节点可加进多张画布、跨项目连线成立；删贴纸不删节点、删便签变墓碑、关系不断；重复连线/重复落同一对节点只有一条 `related`。

## P3 — 检索与咕咕（召回 + 图谱邻居 + 来源回跳 + 只读分析）

**目标**：咕咕能"读懂"面板并附来源；先关键词召回 + 图谱邻居扩展，向量化留接口不急上。

后端：
1. 检索：先"关键词召回（`content_plain`）+ 沿 `mind_relations` 扩一跳邻居 + 回带原始节点/来源链接"。`embedding` 作为可选增强：`indexed_at`/`indexed_hash` 已就位，起一个补索引 worker（按 `indexed_at IS NULL` 捞增量），不阻塞主链路。
2. 咕咕工具（`agent/tools/mind.py`，注册进 `agent/tools/__init__.py`）：**只读优先**——`mind_search`（召回 + 邻居）、`mind_get`（取节点 + 关系 + 来源）。写入类（建节点/建关系/提取待办）走"生成建议、用户确认"，默认 `status=suggested`、`origin=gugu`，不直接落 confirmed。
3. `mind_relations` 的 `origin=gugu`/`status=suggested` 正式启用。

前端：详情栏/时间线显示来源回跳；咕咕建议以"待确认"态呈现，一键确认→`status=confirmed`。

验收：咕咕回答"这个结论来自哪"能列出来源并跳回原始便签；改便签正文后 `indexed_at` 被清、会被重新召回/索引。

## P4 — 丰富能力（语义类型 + suggestion 节点 + 版本/图片）

- 关系：开放少量高价值 `rel_type`（`supports`/`derived_from`/`verifies` 等），连线后弹 `RelationPicker.vue` 选类型；`related` 仍是默认。
- `suggestion` 节点：加节点级 `status`（`pending`/`accepted`/`dismissed`，见 schema 草案），咕咕建议贴纸**沿用纸条材质 + 待确认角标/虚线紫边**，不引入第三套玻璃材质。
- 块编辑器扩展图片块；节点版本历史（`version` 已在，补历史读取接口）。
- 主题底板：需要时单开 `mind_canvas_boards`（画布内矩形区域 + 标题），不塞进 canvas_item。
