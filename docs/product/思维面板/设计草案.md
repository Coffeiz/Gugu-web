## 易读概述

思维面板不是另一套笔记功能，而是把用户日常留下的零碎想法、现有项目、文件和日历活动组织到一起的长期上下文层。它由两个独立但互通的界面组成：**笔记**负责快速捕捉，**画布**负责空间化思考。

### 笔记：按时间留下生活与工作的线索

笔记页是按日期排列的时间流，重点是低负担地写下内容，而不是立刻分类或排版。一条记录可以是一句想法、会议后的感受、链接、图片或待办；需要时再轻量关联到项目、文件或日历活动。

记录以 Markdown 保存正文，但不要求用户直接书写 Markdown 语法——**编辑器不做任何 Markdown 输入规则**（打 `#`、`-` 等前缀不会触发格式转换），格式一律通过工具栏按钮设置；页面始终以可读的排版呈现。触发键只保留两个：`@` 呼出对象引用面板（项目/文件/活动），`/` 预留给呼唤咕咕（P3 点亮）——「@ 指名词、/ 发动作」，因此**本编辑器永久不做 Notion 式的 `/` 插入菜单**，这个键位已被咕咕占用。

### 画布：把思考贴在一张桌面上

画布是用于项目拆解、方案比较和决策推演的空间化工作台。内容以可自由拖放的“贴纸”呈现：短想法、问题、结论、项目、文件、活动、图片和咕咕的建议都能贴上去。

画布应保留个人的摆放痕迹，不强迫用户整理成传统思维导图。节点之间可以连线、分组或贴在同一片半透明主题底板上；连线默认弱化，仅在选中或聚焦时强调，避免画面变成难读的蜘蛛网。

日常记录和画布共享内容，不共享界面。用户可将一条记录“贴到画布”生成引用贴纸；从画布打开贴纸则回到原始记录及其发生时间。

视觉上，用户自己写下的 Markdown 便签采用轻薄纸条质感，成为画布中的思考焦点；项目、文件和日历活动等系统对象沿用咕咕现有的玻璃卡语言。这样“纸条”表示人的思考，“玻璃”表示系统中的真实对象，主题底板与工具栏则只承担组织和操作，不与节点争夺注意力。

### 让咕咕读懂，而不只是搜索到

面板最重要的能力是为咕咕提供可信、可追溯的上下文。除了保存对象本身，还需要表达对象之间的关系，例如“这场会议为项目做准备”“这份文件支持该结论”“这个任务验证某个假设”。

咕咕基于这些关系，才能回答“项目为什么改变方向”“下次会议前还有哪些未解决问题”“这份文件影响过哪些决定”，并把回答链接回对应的原始内容。咕咕可以建议关联、归纳主题或提出待验证问题，但不应未经用户确认地改动画布布局或把推测写成事实。

## 专业细节

### 产品边界

| 能力 | 记录 | 画布 |
|------|------|------|
| 主要场景 | 随手捕捉、按时间回顾 | 整理复杂问题、推进项目 |
| 内容组织 | 日期流 + 轻量关联 | 自由位置 + 分组 + 关系 |
| 输入方式 | 快速创建 Markdown 便签 | 引用已有内容或新建贴纸 |
| 推荐终端 | 桌面端网页；碎片时间走 IM 对咕咕说 | 桌面端、较长专注时段 |

> **手机端范围（2026-07-10 定）**：思维面板（记录 + 画布）第一期**只做桌面端网页**，不为手机做任何适配或降级布局。未来手机端不走"响应式凑合"，而是**所有页面统一单独设计移动版**，届时再一并纳入。
>
> **碎片时间的捕捉路径是对咕咕说**（"记一下：xxx"→ 咕咕调工具写入记录流 → 回执"记好了，已记到 X 月 X 日"），不是手机网页。`record_note` 是普通工具、走现有对话→工具管线，**天然渠道无关**——IM 和网页聊天框都能用（网页端因此有两条记录入口：底部捕捉条自己写、聊天框让咕咕记/总结，互补不冲突）。这条路径的四条契约：
> ① **聊天 ≠ 记录**——只有显式意图（"记一下/帮我记/记到昨天"）才写入；咕咕可以主动建议"要不要记下来"，但必须用户确认才写（同"不未经确认把推测写成事实"原则），否则记录流会被聊天噪音淹掉；
> ② **写什么用户要先知道，按加工程度分两档**（2026-07-10 改，总结也是合法的记录）——写入内容≈用户原话（"记一下：xxx"）→ 直接写入，但回执必须**完整回显写入内容**（不是光说"记好了"）；写入内容是咕咕加工的（总结/提炼/改写）→ **先出草稿、用户点头再写**。两档共享安全网：撤销/修改最近一条必须有，它是"直录不确认"成立的前提。记录不是 destructive 操作、不挂硬确认门（删除记录才挂）。写入工具层须对 LLM 输出做 Markdown 硬规整（clamp 单级标题、拍平嵌套列表——低层输出习惯提示词治不了，只能工具层兜底）；
> ③ **同一条写入路径**——复用 `core/mind.py` 的写入逻辑（content_plain / indexed_hash 同事务），不为咕咕开旁路，避免"网页记的搜得到、IM 记的搜不到"；
> ④ 最小工具集 `record_note(content, captured_at?)` + 撤销最近一条；`captured_at` 支持补录（"记到昨天"），回执天然带日期。
| 视觉语言 | 时间排列的小纸条 | 可拖拽、带轻微物理感的贴纸 |

画布不承担日记式的连续输入；笔记页也不承担自由排布。两者通过同一条记录或同一个业务对象建立联系，而不是复制数据。

### 内容对象

思维面板中的内容分为三层：

1. **原始业务对象**：现有的项目、文件、日历活动、任务等实体，仍由各自页面和数据模型负责。
2. **思维节点**：用户创建的 Markdown 便签，以及问题、假设、结论、决策等可表达思考过程的节点。
3. **语义关系**：对象和节点之间带有明确含义的连接，用于界面展示和咕咕理解上下文。

第一层和第二层都可直接打开和编辑；第三层应可由用户手动维护，也可由咕咕提出建议后确认写入。

### 贴纸类型

| 类型 | 典型内容 | 画布表现 |
|------|----------|----------|
| 便签 | 零碎想法、问题、提醒 | Markdown 摘要和可选颜色 |
| 项目 | 项目状态、目标、阶段 | 项目图标、名称、状态摘要 |
| 文件 | 文档、图片、附件 | 缩略图、名称、内容摘要 |
| 日历活动 | 会议、日程、截止日 | 时间、参与者或关联项目摘要 |
| 图片 | 截图、灵感素材、白板 | 可缩放的图片贴纸 |
| 咕咕建议 | 归纳、问题、待确认结论 | 明确标注为建议，支持确认或移除 |

### 视觉与布局

画布本体铺满内容区，不再用一层大卡片包住无限画布。背景沿用现有灰蓝渐变，可叠加极淡的点阵或细网格帮助定位；画布列表、工具栏和选中节点的详情栏才使用克制的玻璃面板。

| 层级 | 外观 | 用途 |
|------|------|------|
| Markdown 便签 | 半不透明纸条、短阴影、可选低饱和颜色 | 用户的想法、问题、结论与提醒 |
| 系统对象贴纸 | 现有玻璃卡语言，保留图标、项目色与摘要 | 项目、文件、日历活动等真实对象 |
| 咕咕建议 | 淡紫灰玻璃贴纸 | 可确认的归纳、关联和待验证问题 |
| 主题底板 / 工具栏 | 轻量玻璃面板 | 圈定主题、组织和操作 |

贴纸使用普通小圆角，不使用大面板的 squircle。拖动只提供轻微抬起、短阴影和对齐吸附，不使用会改变文字渲染的 3D 后仰效果。

### Markdown 便签与编辑器

便签以 Markdown 保存原始内容，画布只保存其展示状态，例如位置、尺寸、颜色、层级和折叠状态。Markdown 是便签的可移植存储格式和咕咕可读取的结构化内容，不是普通用户必须掌握的编辑方式。

编辑器使用所见即所得的固定内容块，第一期支持以下类型：

| 内容块 | 创建方式 | 编辑体验 |
|------|----------|----------|
| 正文 | 直接输入 | 普通文本和自然换段 |
| 标题 | 工具栏文字样式 | 单级标题（薄卡片里多级标题无意义） |
| 待办 | 工具栏勾选图标 | 可点击完成的任务项 |
| 列表 | 工具栏列表图标 | 无序条目（平铺不嵌套） |
| 引用 | 工具栏引用图标 | 用于摘录、结论和提醒 |
| 图片 | 图片插入操作 | 独立内容块，可打开原图 |
| 对象引用 | `@` 触发补全面板 | 搜索项目、文件和日历活动后插入可读标签 |

**不做 Markdown 输入规则**（2026-07-10 定）：所见即所得编辑器里"看到的是排版、却要敲语法改排版"是自相矛盾的，行首 `#`/`-`/`[]` 等前缀一律不触发格式转换，格式只走工具栏（TipTap 关 `enableInputRules` 一个开关）。存储仍是 Markdown（`content_md`）——它不露脸，但 `to_plain_text`/搜索召回/咕咕读写/导出全靠它，改存节点树是零收益重写。存量便签里的多级标题（`##` 等）在用户下次编辑保存时 clamp 成单级，**不做批量迁移**（爆炸半径保持单条）。代码块可在后续按实际需求加入，不作为日常便签的第一期重点。

对象引用用 `@` 触发（行首或前面是空白才弹面板，挡住邮箱地址等误触；连续无结果自动关闭）：输入时补全项目、文件和活动，选择后显示为可读的对象标签。`@` 只是触发键，写进 `content_md` 的仍是 `[[project:7|某项目]]` 这类稳定锚点，后端的 `REF_PATTERN`、`to_plain_text`、搜索召回不受影响。

在便签中输入 `/` 呼出咕咕（P3 点亮），对当前便签及其已关联上下文发起协作请求，例如归纳、补充问题、提取待办或检查论据。咕咕的输出应首先以可确认的建议贴纸或草稿呈现。「`@` 指名词（引用对象）、`/` 发动作（呼唤咕咕）」是本编辑器的触发键总纲，`/` 不再另作他用。

### 语义关系

关系不仅是视觉连线，也应持久化为可供检索和推理的结构化数据。第一期可限定为以下关系类型：

| 关系 | 含义 | 示例 |
|------|------|------|
| 属于 | 内容归入某个项目或主题 | 便签属于“新手引导”项目 |
| 来源于 | 内容由某次活动、文件或记录产生 | 结论来源于一次访谈 |
| 支持 | 某对象为结论或假设提供依据 | 数据文件支持留存假设 |
| 反驳 | 某对象与结论或假设相冲突 | 用户反馈反驳原方案 |
| 待验证 | 任务或活动用于验证假设 | 访谈任务待验证需求假设 |
| 导致 | 一个决定或事件推动另一个变化 | 决策导致项目方向调整 |
| 后续行动 | 结论或活动产生明确下一步 | 会议纪要产生跟进任务 |

节点从边缘的连接点拖出连线，落到另一个节点后选择关系类型；尚未分类时可先建立普通“关联”，再在详情栏补充语义。连线默认是细而浅的灰紫色，不遮挡便签内容；选中节点、点击连线、筛选某类关系或向咕咕提问时，才突出相关路径。

关系应记录创建者、创建时间、来源和置信状态。由咕咕推断的关系默认标为“待确认”，不能与用户确认的关系混为一谈。

### 交互原则

- 贴纸拖动时有轻微抬起、阴影和对齐吸附，传达“贴在桌面上”的感觉；拖拽使用 pointer 模式，不采用原生 HTML5 拖拽。
- 双击贴纸进入内容编辑；单击打开右侧详情，查看完整内容、关联、历史和来源。
- 允许用主题底板圈定区域，但不强制网格或自动排版。
- 节点边缘可拖出连线；建立连线后优先选择关系类型，也允许先以普通关联落下再补充。
- 从记录加入画布时创建引用，不复制 Markdown 正文；删除画布贴纸不删除原始记录。
- 从项目、文件、日历等现有页面可直接“贴到画布”，并预填对应业务对象的摘要。

### 咕咕协作边界

咕咕可以读取用户授权范围内的记录、画布、项目、文件和日历活动，并在回答中附带对应来源。面板内的协作行为分为两类：

- **只读辅助**：概括主题、梳理时间线、寻找相关内容、指出矛盾或未解决问题。
- **需确认写入**：新增贴纸、建立关系、提取任务、修改便签或项目关联。

任何涉及用户内容的摘要或推断都应保留来源链接与生成时间；不确定的信息应明确为假设或建议。涉及文件和日历活动时，复用现有权限和归属校验，不能因面板关联而扩大访问范围。

### 分期（详见[实现方案](实现方案.md)）

- **P0 图层地基**：三表 + 约束 + 归属/乐观锁机制就位，无 UI。
- **P1 记录可用**：时间流 + 窄口径块编辑器（正文/标题/待办/对象引用四种块）+ 便签可被 global_search 搜到；关系只写默认 `related`。
- **P2 画布可用**：自由画布、纸条便签、系统对象贴纸、拖拽/缩放、详情栏；连线默认普通关联。
- **P3 检索与咕咕**：关键词召回 + 图谱邻居扩展 + 来源回跳；咕咕只读分析优先，写入走确认式；embedding 留接口不急上。
- **P4 丰富能力**：少量高价值语义关系类型、suggestion 节点自身状态、块编辑器图片/版本历史、主题底板单开表。
