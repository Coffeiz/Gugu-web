# Gugu 2.0 Web Host Shell 工具设计

状态：Linux Agent Shell 和用户终端已接入，并在独立 Linux 环境验证。范围为 Linux/NAS 自部署 Web Host，Windows 桌面继续使用 MXC。Python 后端是行为参照，2.0 的执行路径使用 Node 与 Bubblewrap。通用文件工具只有在对应能力验收后才逐项退役。

## 目标与现状

Agent 用受授权的 Shell 操作本地文件，支持列目录、读取、搜索、创建、编辑、复制、移动和重命名。默认 sandbox 不暴露宿主系统目录或宿主配置，只提供独立、可控的运行环境和授权文件；只有显式 `scope=system` 且通过独立授权后才允许访问服务所在系统环境。文件正文以本地 FS 为真源；Shell 不直接操作业务数据库。附件读取、展示和发送仍走独立消息接口。删除、覆盖及批量写入必须由执行边界落实确认策略，不能只依赖提示词或命令分类器。

已有 `packages/core/src/agent/security/shell-policy.ts` 的策略、风险分类，`packages/sandbox` 的授权执行接口和 MXC 适配，以及 `apps/web-host/src/modules/terminals/` 的目录解析、授权复核、取消和终端事件可供复用。Linux 接线现已复用这些能力，并以目录句柄建立虚拟挂载目标。具体验收范围见文末。

## 分层与代码位置

```
Agent ToolRegistry → Core shell 工具 → Host per-lease 执行服务
  → 策略/确认/目录计划 → @gugu/sandbox Executor → Linux Bubblewrap
  → 结果、终端事件和派生数据失效
```

| 位置 | 职责 |
| --- | --- |
| `packages/core/src/agent/tools/shell.ts`（新增） | 模型 Schema、参数约束、工具结果、动态危险判定；只依赖 Host 注入的端口，不接触 OS、数据库和用户路径。 |
| `packages/core/src/agent/security/`（现有） | 复用风险和策略规则；补齐 Agent 与定时主体所需事实，分类不是隔离或完整确认的证明。 |
| `apps/web-host/src/modules/agent-sessions/tools/agent-shell.ts`（新增） | 从可信 dispatch lease 取 owner/session/run/主体，接确认与恢复、输出及终端记录；不接收模型传入的身份和挂载授权。 |
| `apps/web-host/src/modules/terminals/`（现有，按需提炼共享服务） | 复用 owner 目录查询、目录句柄固定、执行期间授权复核、沙箱启动和终端事件；避免 Agent 伪造 HTTP 终端请求或复制一套安全逻辑。 |
| `packages/sandbox/src/`（扩展） | 公共授权和执行契约保留根目录，`linux/bubblewrap/` 存放直连 Bubblewrap 后端，`mxc/` 存放 SDK 适配；Windows 桌面继续使用 MXC。受信任挂载计划和 OS 强制隔离不能由字符串校验代替。 |
| `agent-tool-registry.ts` 和 `main.ts` | 仅在自部署且服务端能力可用时按 lease 注入端口；SaaS 不装配。 |

先抽出 Agent 和终端确实共用的执行服务；确认交互和主体授权各自保留，不把终端自身授权当成 Agent 授权。路径仅是建议的实现落点，修改前仍需核对工作区中其他进行中的改动。

## 工具契约

对照 Python `ShellSkill`，模型参数为 `command`（必填）、`cwd`（默认 `.`）、`timeout`（秒）、`max_output_chars` 和 `scope`；网络、owner、工作区、确认凭证均不由模型提供。省略 `scope` 为 sandbox；`scope=system` 必须显式选择，且需要管理员和用户双侧开启、逐调用授权及危险命令确认。system 指 Web Host 服务所在环境，使用服务进程权限；容器部署时不等同于容器宿主机。定时任务不得使用 system。system 的授权、审计、撤权和执行器需独立实现并验收；未完成时明确拒绝，不能回退或自动切换。一个调用执行一次非交互命令，复合命令与管道由受限执行环境中的 shell 处理，不把参数拼进宿主 shell 的启动命令。

默认超时 30 秒、输出 12000 字符。Python Schema 上限分别为 3600 秒、120000 字符；现有 `executionPolicy` 授权超时上限 300 秒、输出上限 1 MiB，首版 Schema 应与实际后端限制一致（超时最多 300 秒），不得默默放宽。字符与字节限制同时生效，截断或输出超限须明确报告；当前 MXC 输出超限会终止并抛错，不能声称已经具有 Python 的截断语义，需实现并测试明确的结果语义。结果至少区分 `ok`、`exit_code`、`stdout`、`stderr`、`timed_out`、`truncated`、取消/授权撤销、执行环境和网络状态；启动前拒绝与启动后结果未知必须可区分。

每次调用以服务端生成的唯一 request ID 标识，绑定 owner、session、run、round、tool call 和租约。保留 Python 同会话默认串行语义；并行需要明确的调度约束，危险命令不能因并行绕过确认。确认只由服务端签发、绑定完整命令、cwd、主体、工作区和策略版本并单次消费，模型不能自称已确认。定时任务使用独立主体与绑定，不允许等待交互确认的命令；自动模式若支持必须沿用服务端确认门，不能简单跳过校验。

## 目录与挂载

Host 在每次调用依据可信 owner 查询活动工作区和授权，构建只读/可写挂载计划；模型的 `cwd` 只选取计划内的目录，不能扩大授权。Python 的目标语义如下，作为新执行后端需要验证的契约：

| 情况 | 默认 cwd 与权限 |
| --- | --- |
| 未绑定工作区 | 用户默认 Workspace；没有可安全解析的默认根时拒绝。 |
| 绑定目录、项目或文件夹 | 对应活动根作为默认 cwd 和可写范围；不挂载整个用户存储父目录。 |
| 未获得完整用户沙箱写授权 | 只写当前工作区；个人/项目空间按原版只读提供，前提是能强制实现精确只读及路径隔离。 |
| 获得完整用户沙箱写授权 | 在 owner 限定下增加该用户的个人、项目和活动 Workspace 根；仍禁止其他用户及服务敏感目录。 |

逻辑视图期望沿用 Python 的 `/workspace/<目录>` 及个人/项目规范路径；项目或文件夹绑定沿物理空间映射生成目标，不用显示名作为权限依据。绑定根内相对 cwd 必须拒绝穿越、绝对路径越界、符号链接逃逸和替换竞态；如支持其他已授权挂载的绝对 cwd，必须在执行器按挂载计划解析，而不是在 Host 做字符串前缀判断。

目前 `prepareTerminalMounts` 使用 Linux `O_NOFOLLOW` 逐级固定目录并持有 `/proc/.../fd/...`，仅接受主工作区内相对 cwd；MXC 接口只有源路径读写列表，没有 source→target 映射。Linux 使用 Bubblewrap 的源路径到目标路径挂载实现上述虚拟路径，并用实际进程验证目录句柄固定和跨挂载访问。未实现前拒绝要求这些能力的执行，不暴露宿主绝对路径给模型，也不把字符串替换伪装成挂载。重叠的只读/可写根、目录重命名、根替换和链接攻击须以真实进程测试确定权限实际生效。

## 隔离、生命周期与数据

- MXC 1.0.1 Linux Bubblewrap 默认只读暴露宿主 `/etc` 和部分 `/usr`、`/bin`、库及解析器目录，因此直接使用默认后端不满足 sandbox 隐藏宿主系统目录的要求。需要受控的独立 root filesystem 和必要工具/库，并以 OS 级隔离只挂入授权用户目录；沙箱内的 `/bin`、`/usr` 等如存在，应来自独立运行环境而非宿主对应目录。禁止凭路径黑名单或提示词声称满足此边界。Linux 采用直接调用 Bubblewrap 的后端实现最小 root 和 source→target 映射；后端不可用时不降级为默认 MXC。见 [MXC 1.0.1 Bubblewrap 后端](https://github.com/microsoft/mxc/blob/v1.0.1/docs/backends/bwrap/bubblewrap-backend.md)。
- 授权按调用重新读取管理员、用户、主体、工作区、完整沙箱授权和执行后端能力；启动前再次复核，运行期间以独立短事务持续复核，撤权、取消或租约失效终止进程树。执行期间不持有数据库事务或连接。等待确认期间再次校验所有绑定。
- Linux Bubblewrap 必须实测账号间文件隔离、只读与越界、链接和竞态、进程树回收、CPU/内存/进程数/临时空间限制以及网络隔离；静态 capability 标志或 SDK 存在不等于安全验收。后端不可用、策略无法强制或检查失败时拒绝，不回退普通 `spawn`、宿主 shell 或旧 Docker。
- 网络由管理员策略决定：默认断网；受控 egress 仅在代理及绕过防护经实测后开启，不能接受模型指定代理、凭据或网络授权。环境变量白名单、固定可执行入口和工作目录由 Host/执行器提供，禁止继承服务密钥及注入变量。
- 复用用户存储配额的可信账本及短事务：启动前检查已超额状态，执行后记录/刷新实际使用量；旧 Python 本地方案允许单次执行越过额度，后续调用才阻断，并非硬配额。若要求单次写入不得越限，必须增加经验证的 OS 硬配额，不得声称账本检查实现硬限制。
- Shell 直接操作 FS，不保证旧 `delete_file` 的回收站、Undo、CAS 或批量原子语义；危险确认也不自动提供恢复。退役前需明确产品行为、提供经验证的恢复方案或获得对行为变化的确认。派生索引与 UI 缓存需失效/可重建；watcher 仅优化，不能成为数据正确性前提。旧 DB 文件身份迁移及引用变化需独立验收。
- 命令可能已产生副作用：启动后超时、取消、进程崩溃或记录失败都不得自动重放。持久记录启动前预留、启动中/完成/结果未知；恢复只读取结果或报告未知，不能把未知当作未执行。终端输出和历史按 owner 隔离，敏感输入不写普通日志；审计使用指纹及脱敏结果，终端历史保存失败要保留真实执行结果并提示。

## 实施顺序与验收门

1. **执行后端可行性**：隔离测试环境实测 Linux Bubblewrap 目录映射和多用户、网络、资源、进程树隔离；补足不可实现项，能力不可用时保持关闭。先明确虚拟路径映射与 FD 生命周期，不能以模拟测试替代真实 OS 测试。
2. **共享执行边界**：从现有终端实现提取确有共用的挂载、授权复核、取消与执行端口；验证既有终端行为不变。扩展可信授权、输出、资源及结果契约，不接受来自模型的授权字段。
3. **Agent 工具切片**：接入 Core Schema、per-lease Host、危险命令确认、同会话串行、事件和未知结果恢复；覆盖 Web Agent 真实 registry → 确认 → 执行 → 续轮。定时任务使用独立主体单独接线和验收，未完成前不注册。
4. **文件行为验收**：在临时真实文件系统执行读写、移动、重命名、删除、并发、链接攻击、取消、超时、撤权、配额、刷新和失败恢复；明确回收站/Undo 与历史引用迁移。使用两个独立 owner 及真实 Linux 后端验证跨用户拒绝。
5. **逐项退役文件工具**：盘点 Schema、注册、权限白名单、技能、历史与附件消费者、测试及数据引用；满足对应替代和迁移条件后移除通用 CRUD。附件、展示和投递保留独立接口。SaaS 不以此方案承诺本机 Shell。

上述任一安全能力未通过时，只能报告设计或部分实现，不能宣称 Shell 可用于多用户生产或据此删除旧文件工具。

## 当前实现状态（2026-11-19）

Linux 的咕咕 Shell 和用户终端由 `packages/sandbox/src/linux/bubblewrap/` 直接启动 Bubblewrap。MXC 的 SDK 适配、平台探测、执行器和 PTY 位于 `packages/sandbox/src/mxc/`，供 Windows 桌面和 Linux MCP stdio 等现有调用方使用。原有包导入路径保持兼容。

Web Host 命令终端与 Agent Shell 已接入同一个断网命令执行器。Host 逐级固定目录并把描述符传给子进程，Bubblewrap 使用 `--bind-fd` 或 `--ro-bind-fd` 完成绑定。临时 Linux 虚拟机验证了工作区写入、项目只读、宿主配置及未授权目录不可见、网络命名空间分离、命令启动后不再持有挂载句柄，以及超时和取消。

测试虚拟机通过仅匹配 Bubblewrap 可执行文件的 AppArmor 配置授权创建用户命名空间，系统全局限制仍开启。开发服务器尚未安装同等配置。直接引用 Web Host 的 `/proc/<pid>/fd/<fd>` 在该测试环境被拒绝，不能用这条路径替代句柄传递。

PTY 走 Linux `forkpty` 启动器。控制管道处理终端尺寸更新，挂载句柄在子进程启动时继承。一次性命令和 PTY 运行在 systemd 用户 scope 下，限制 CPU、内存、交换空间和进程数。已在独立 Linux 环境使用签名校验构建的 Debian 运行根通过命令与 PTY 的集成用例，覆盖实际资源上限和关闭后 scope 回收。Web Host 已实测使用临时工作区试运行命令与 PTY 判定就绪，缺运行根时保持关闭。Agent 未确认的命令以只读权限挂载用户文件，避免以命令文本分类充当文件写入边界。安装步骤见[Linux 沙盒部署说明](../../apps/web-host/deploy/bubblewrap/README.md)。

在 Node 26 的 Linux 虚拟机上，认证 WebSocket 已连接真实 PTY，验证了异主访问拒绝、动态工作区挂载、输入和尺寸调整、撤权退出。挂载目标由沙箱自己的临时文件系统提供，挂载完成后父目录转为只读。Web Agent 通过生产注册器、隔离 PostgreSQL 的可信确认和真实 Bubblewrap 验证了未确认不写入、确认后执行一次、参数篡改与重放拒绝、账号停用拒绝，以及授权绝对路径。该测试使用合成的确认提交记录。

隔离 PostgreSQL 与 Redis 下，生产确认服务消费用户选项令牌并从恢复队列继续同一个 Agent Run。合成模型的第二轮收到了真实 Shell 工具结果。显式 `scope=system` 经双侧启用及每次确认后，使用 Web Host 服务账号读取了沙盒外的合成文件。该执行路径清空命令环境并记录脱敏审计指纹。

用户侧栏从工作区接口读取终端可用性。终端策略「自动」随已保存配置生效，入口还要求 Bubblewrap 就绪及当前账号的 Shell 权限。当前 Linux 后端仅提供断网执行，沿用旧版 `egress` 策略时需先切换到 `none`。

Chromium 中实际渲染了终端组件。浏览器键盘输入经 Vite 和认证 WebSocket 到达 Linux PTY，并收到真实执行结果和工作区提示符。终端页面的新建和删除没有纳入这次组件验收。

devserver 尚未安装运行根、PTY 启动器或加载专用 AppArmor 配置。MCP stdio 仍走原有独立路径。
