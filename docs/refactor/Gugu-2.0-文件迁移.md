# 2.0 文件路径存储

文件与目录共用授权磁盘树中的相对路径作为定位方式。文件读取、移动、回收、还原和目录遍历都从当前 owner 与授权根目录解析路径；子目录不需要单独的数据库身份。

`files` 表只保存文件元数据，以 `(user_id, path)` 为主键。目录内容、文件名、大小和正文以磁盘为准；数据库不维护 `folders` 表，也不保存文件数字 ID、目录外键或独立 `storage_key` 列。`path` 是相对于存储根的授权路径，不是可绕过授权检查的凭据。

项目和工作区可以有自己的根目录元数据，用于解析授权根。根目录之下的文件和子目录仍按相对路径访问。聊天附件的 `storage_key` 属于独立的临时附件存储，不是 `files` 表的文件身份。

数据库迁移 `0041` 至 `0043` 将历史聊天/定时任务文件引用转换为路径，并将 `files` 主键切换为 `(user_id, path)`。这些有序迁移保留为数据库升级历史。旧数字 ID 索引、旧回收项导入器和迁移演练脚本已删除；Mind 与 Undo 的一次性旧数据转换只服务数据库升级，不参与服务启动或运行时读写。

路径回收站把文件或整棵目录移入 owner 私有的 `.gugu-trash`，记录原授权范围、相对路径和删除时间。还原时重新解析授权根；目标冲突时保留回收项。Shell 新建或移动的内容通过目录遍历直接进入文件列表，无需导入文件记录。
