# 2.0 文件统一迁移

项目详情、文件库和 Shell 共享同一份授权目录。目录、文件名、大小和内容以磁盘为准。2.0 文件列表和日常读写无需登记 `files` 或 `folders`。项目、账号等业务数据有各自的持久化边界。

## 迁移范围

| 旧来源 | 迁移目标 |
| --- | --- |
| 个人文件、项目文件、工作区的实体文件及空目录 | 已在对应授权目录内的文件原地采用。导入区和历史存储路径中的文件校验后复制到所属目录，保留空目录与现有 Shell 文件。 |
| 项目阶段标签及旧文件、目录 ID | 生成一次性旧 ID 到授权路径的映射。将阶段标签等业务信息转成可持久读取的文件元数据，普通目录列表直接读磁盘。 |
| 聊天与笔记附件、画布引用、全局搜索和工作区文件夹绑定 | 将消费者从旧 ID 切换为受授权的文件引用。搜索索引用磁盘重建，索引可丢弃和重建。 |
| 回收站 | 保留实体内容、原目录、删除时间、还原命名冲突和保留期。应用管理回收元数据，并与普通 Shell 挂载隔离。 |

旧记录的 `storage_key` 不是授权凭据。按当前可信 owner、项目和工作区解析目标，任何超出归属的记录列入异常清单。附件引用必须在切换后仍能打开。文件名冲突、缺失内容和无法解析的原目录要显式处理，禁止静默覆盖。

## 预检与切换

1. 用只读脚本统计各空间的原地文件、待归位文件、缺失内容、无效路径、大小差异、阶段标签和旧目录绑定。该统计仅覆盖旧记录。正式导入还需扫描授权目录，以识别 Shell 或磁盘写入的文件和现有目标冲突。
2. 从同一个时间点备份旧记录和磁盘，生成导入清单以及旧引用映射。先恢复到隔离目录演练。优先原地采用，确需归位的文件在临时路径校验字节后无覆盖发布。记录已完成项，以便中断后重跑。
3. 在暂停旧文件写入后复查差异，切换附件、搜索、工作区绑定和回收站消费者。验证三类入口、旧附件、阶段信息和回收站还原，并确认 Shell 新文件在 UI 可见。
4. 完成验证后停用旧文件写入、路径保护查询和依赖旧表的读路径。保留备份及回滚记录，旧表和原文件的清理由独立维护操作执行。

### 运行只读预检

在已安装依赖的 Linux Web Host 环境，从仓库根执行。使用当前运行环境已有的配置或为本次命令提供配置，脚本的标准输出只有聚合计数。

```bash
cd apps/web-host
node --import tsx scripts/check-file-migration.ts
```

`inPlace` 表示文件存在且位于当前授权目录，`needsPlacement` 表示内容可读但需要确定目标路径。缺失或不安全路径是迁移阻塞项。大小差异需按实际内容核验。预检读取旧表和文件元信息，不执行导入或停用旧表。

需要核对逐项来源时，使用 `--manifest <仓库和运行数据目录之外的新绝对路径>` 导出 JSON Lines 清单。文件以只允许当前用户读取的权限发布，已存在的目标会被拒绝。清单包含旧文件与目录标识、数据归属、旧路径、阶段标签、删除状态和已有目标路径。将其与对应时点的文件备份一起保管。

### 隔离演练

使用同一份清单，在相同 Host 环境执行：

```bash
node --import tsx scripts/rehearse-file-migration.ts "<清单绝对路径>"
```

演练只读取来源文件，将内容复制到系统临时目录。按旧文件 ID 验证字节摘要。对回收项，使用清单里的授权目录和相对路径，导入磁盘回收站，验证同一清单可重跑、列表有且仅有一份回收项及还原后的内容校验。找不到实体、无法解析原位置和需要重新归位的条目都会计入 `blocked`，命令返回非零。目录记录单独计数，目录 ID 和工作区绑定需要独立校验。演练完成后清理临时目录。

### 切换状态

- Linux Web 的全局文件和文件夹搜索读取个人文件、项目文件和默认工作区授权目录。搜索结果直接按路径进入文件库，Shell 新文件可被发现。Agent 和笔记引用建议仍使用原搜索来源，直到相关消费者支持路径结果。
- 历史版个人文件可通过私有磁盘索引继续按数字 ID 定位和读取。迁移项在回收期间不可从历史下载入口读取。还原后，文件即使在个人空间内被移动或改名，仍按实体身份解析，旧路径被另一个文件占用时会拒绝把它当成原件。
- devserver 已备份并迁入唯一的旧个人回收项，核对了文件字节和历史还原位置。清除了已由磁盘承载的旧文件、目录索引和两条旧测试撤销的可执行状态，`files` 和 `folders` 存量均为零。还原入口位于文件库的磁盘回收站。
- 停用 `files` 和 `folders` 表前需验证各入口在旧表不可写且运行时无旧表读权限的环境仍正常工作。仍有旧表调用的入口包括 Agent 文件及清空回收站工具、数据导出、定时任务邮件附件、部分笔记与画布引用、非默认工作区、配额、旧文件写入 API 和项目生命周期。

路径视图的复制在目标目录暂存内容，然后原子发布，拒绝覆盖既有目标。回收时通过原子移动把文件或整个目录转到用户私有的 `.gugu-trash`，记录原授权范围、相对路径及删除时间。还原重新解析当前授权范围，冲突时保留回收件。Web 回收页只读磁盘条目，支持选择、逐项及批量还原、永久删除与清空。Linux Web Host 每小时按磁盘元数据清理满 30 天的条目。旧批量清空任务表仍供未迁移的 Agent 路径使用。
