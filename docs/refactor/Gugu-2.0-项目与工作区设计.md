# 咕咕 2.0 项目与工作区设计

状态：设计待实现。本文件描述桌面端目标行为，不表示当前产品已支持。

## 概念与关联

项目负责组织目标、阶段、待办和文件入口；文件工作区登记用户选择的真实文件夹。同一项目可以关联多个工作区，同一工作区可以关联多个项目。关联不复制文件，也不把工作区的所有权转交项目。Web Host 和桌面端采用各自的可信文件边界；本方案首先实现桌面端，不能把桌面本机路径当成 Web Host 路径。

项目已有托管文件夹继续作为独立文件根。项目文件界面应列出该文件根和所有已绑定工作区，进入后显示对应真实文件。咕咕读取项目文件范围时返回同一组工作区与可定位路径；多个工作区时调用方须指定目标或使用用户明确设置的默认工作区，不根据列表顺序猜测。

## 设置工作区

项目编辑卡提供多选已有工作区和新建工作区入口。新建复用文件库选择文件夹、检查真实路径及登记工作区的能力。关联记录以项目 ID 和工作区 ID 为键，支持多对多并持久化；目录不可用时保留关联并提供重新定位，不悄悄切换目录。

首次关联时，若项目托管文件夹含文件，询问是否移动。选择移动时，将该目录迁入用户选定的一个目标工作区，使用「项目名 #项目ID」作为目录名，保留子目录结构。选择不移动时仍建立关联，原目录保持可访问。多选时必须明确选择迁移目标；已关联项目再次新增工作区不重复搬迁。

迁移记录至少绑定项目 ID、工作区 ID、实际目录标识和相对位置，并区分迁移目录与用户自行创建的同名目录。项目重命名、目录改名及重新定位不能仅靠名字猜测归属。目标冲突时提示并允许选择新名称或取消，不覆盖现有文件。

## 解除关联

解除关联前读取可信迁移记录并核对目录身份。存在该项目迁入的目录时，提供移回项目文件夹、保留在工作区并解除关联、取消三种选择。移回时保留目录结构，若项目文件夹已有冲突先提示，不能覆盖。目录已移动、替换或无法确认身份时，停止自动移动并提示用户处理；不能仅凭名称中的项目 ID 移动文件。

删除项目或解除关联不能删除外部工作区及其他项目共享的内容。项目软删、恢复和永久清理仅管理咕咕托管的项目目录；外部目录的处理须遵循用户在解除关联时明确选择的结果。

## 一致性与安全

迁移必须校验工作区根目录及项目归属，拒绝符号链接逃逸、目录嵌套冲突和路径替换。跨磁盘移动采用复制到隔离临时目录、完整校验、无覆盖发布、持久记录及引用切换；仅在新目录和引用确认可用后清理源文件。操作应有持久阶段记录和幂等恢复，崩溃、取消或清理失败时保留可恢复副本并明确显示状态。失败不能报告为完成，也不能在不确定时自动重试有副作用的步骤。

文件引用、项目上下文、Agent 文件工具、预览和搜索必须共用相同的工作区身份和相对路径解释；迁移时原有引用须经持久映射更新或兼容解析，不能因目录移动悄然失效。日志和诊断不得记录文件正文、用户输入或凭据。

## 验收

- 同一工作区可关联两个项目，一个项目可关联多个工作区；取消关联或删除项目不删除共享文件。
- 绑定时分别验证移动、不移动、取消、名称冲突及跨磁盘迁移；解除时验证移回、保留和取消。
- 覆盖文件引用、Agent 文件工具、目录重命名/替换、授权撤销、崩溃恢复与无覆盖边界。
- 验证已有项目和未绑定工作区的行为，以及无效/已删除项目和其他用户数据隔离。
