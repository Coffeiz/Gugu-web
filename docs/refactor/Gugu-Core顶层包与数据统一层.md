# 顶层 Core 包与数据统一层

> 状态：已实现并完成本轮回归；PR 目标仍为独立 `v2.0`。
> 代码内容基线：`main` 的 `c7f3f6de`（1.7.9 squash merge），与 `dev` 的 `11757f15` 文件树一致。

## 1. 目录与产品边界

`gugu-core/` 是顶层可独立安装的 Python 包，源码位于 `src/gugu_core/`。原来的 `backend/gugu_core` 已迁出，`backend/pyproject.toml` 仅保留现有测试质量工具配置。前端继续保留 `frontend/`。

桌面验证宿主已放入 `gugu-desktop/`，后续云宿主命名为 `gugu-saas`。SaaS 未来可迁入私有仓库，由宿主实现账号、租户、订阅、同步入口和部署装配；Core 不导入 SaaS 代码，独立构建不需要云服务源码。本次没有修改仓库许可证或拆出私有仓库。

现有 `backend/` 暂时承载 Web/NAS 兼容宿主，不为了目录命名搬动用户运行配置、存储目录或全部业务模块。Agent 与其他业务域继续按切片迁移，不把目录搬迁当作完成全部重构。

## 2. 已统一的数据底座

| 契约 | 职责 |
| --- | --- |
| `DataRuntimeConfig` | 显式选择 SQLite/asyncpg 驱动、连接池和 SQL 调试选项，不读取宿主环境配置；默认不输出 SQL |
| `DataContext` | 宿主鉴权后提供的所有者 UUID，不包含登录凭据或隐式管理员 |
| `SqlDataRuntime` | 管理自己创建的连接池和 Session；关闭后拒绝继续使用 |
| `DataServices` | 项目、联系人用例门面，输出脱离 ORM 的快照 |
| `DataModels` | Web 注入保留用户外键的映射；本地使用不依赖用户表的共享映射 |
| `bind_services` | 借用现有 Web 请求事务，不自行开始第二个事务或提交 |
| `LocalRuntime` | 单用户本地身份、文件库初始化、打开及显式升级 |

项目与联系人现共用同一事务、身份上下文和 SQL 后端。一次用例编排可以创建项目并更新联系人；第二步出错或请求取消时，前面的写入一起回滚。项目沿用版本比较，联系人沿用原有资料更新语义，不给所有领域强行套用一种冲突规则。

PostgreSQL 的池配置、连接健康检查和空闲事务超时由 Core 工厂维护；Web 的事件循环检测、会话取消清理、迁移编排和诊断仍由 Web 宿主维护。它们具有不同职责，不为抽取重复创建两套连接池。

## 3. Web 兼容与权限

Web 项目更新和联系人服务接入统一装配，现有调用方仍可使用原来的 ORM 服务接口。单条 Web 读取继续通过 `get_owned()`；Core SQL 查询、更新和删除都限定上下文所有者。上下文必须来自已验证的宿主身份，不能直接信任请求中的 UUID。

用户外键、列名、可空性和现有表结构保持兼容。撤销、幂等、通知、文件目录和 destructive 工具确认门仍按原有入口编排。本次不执行 Web 数据库迁移，也不删除 Linux/NAS 多用户或首版 SaaS 的 FS 能力。

## 4. 本地 schema 与升级

新库为版本 `2`，增加联系人表。打开版本 `1` 时明确拒绝隐式升级；宿主停止相关运行时后显式调用 `LocalRuntime.migrate(path)` 或 CLI 的 `migrate` 命令。

升级持有 SQLite 写锁，用只读连接执行一致性备份，备份名包含 UTC 时间戳和随机后缀。然后在同一数据库事务内创建联系人表与索引、推进 schema 版本。故障时回滚 DDL 与版本，旧项目、身份和备份保留。不接受未知版本或异常表结构，不自动覆盖修复。

本地数据库文件和备份是数据后端内部存储，不是用户文件工作区，不使 SaaS 获得通用 FS 能力。任何用户运行配置均不属于本轮迁移输入或输出。

## 5. 安装、制品与更新

从仓库根安装 `./gugu-core`，PostgreSQL 宿主使用 `./gugu-core[postgres]`。Web 的 `make deps`、部署依赖步骤和手动 CI 安装步骤已同步；直接 pip 安装的命令见根 README 和 Core README。

生产镜像把独立 Core 包安装到单独制品目录，再与应用源码一起组装进应用包；因此现有应用包更新会同步携带匹配的 Core 和分发元数据。开发镜像和 Compose 使用仓库根构建上下文，顶层 Core 独立挂载，Web/Worker 热重载监听其 `src`。

Core 的 wheel 只包含 Core 源码与分发元数据，发布不需要 Web、前端或 SaaS。完整宿主镜像和桌面安装包仍是不同验收项目，不能以 Core wheel 构建替代。
