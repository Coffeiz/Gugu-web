## 二、可统一的「骨架」

第 1、3、7、8、10 号（以及部分 2）共享同一形状，可被 `optimisticMutation` 覆盖：

```
备份选中项 → 乐观改缓存(remove/update) → loadContents()
→ try { await API } catch { 用备份回滚 → loadContents() → console.error(前缀, e) }
```

## 三、**必须保留、不能被包装抹平的差异**

1. **成功副作用不一致**：只有 `ctxDelete` 删文件后 `fetchStorage()` 刷用量，`deleteSingleFile`/`deleteSelected` **没刷**
   → 这其实是**现存不一致（疑似 bug）**：删文件都应更用量。包装时**不能默认全加或全不加**；要么显式传 `onCommit`，
   要么先单独修齐这处不一致再抽（**建议：先修，后抽**）。
2. **刷新策略分两类**：多数靠自己的缓存乐观改动即是真相源（只 `loadContents`）；但 `restoreFile`/`restoreSelected`
   （文件从回收站回到文件库，本页 loadContents 不会重填库缓存）和 `deleteFolder` 失败（子结构未知）**必须 `cacheStore.refresh()`**。
   原因是 SSE 回声对「本页自己发起的变更」被抑制，这些改动缓存没覆盖到 → 得显式重取。包装**不能统一成只 loadContents**。
3. **回滚完整度不同**：`deleteSelected` **只回滚文件、不回滚文件夹**（失败时夹已从视图消失却不还原）；`deleteFolder`
   **根本无法回滚**（改走 refresh）。一个「统一对称回滚」的包装会**改变**这两处语义（前者算修 bug、后者做不到）——
   属行为变更，须显式决策，不能默默吸收。
4. **await vs fire-and-forget**：`commitRename` 用 `.catch()` **不 await**（函数立即返回、重命名后台跑）；其余 `await`。
   若包装统一 await 会改变调用时序（重命名当前是「立即关输入框、后台落库」）。
5. **非乐观的一类（11–16）**：copy/回收站还原/永久删/清空都是 **API 先行**，不套乐观壳；`optimisticMutation` **不该**覆盖它们。
   回收站三个永久操作各自带 `confirm()` 门，属另一条语义。

## 四、建议边界

- `optimisticMutation` **只**覆盖第三节「骨架」那 5 处纯对称乐观（1/3/7/8/10），签名需暴露 `onCommit?`（成功副作用，如 fetchStorage）
  与 `refresh` 策略（`loadContents` | `loadContents+cacheStore.refresh`）两个钩子，**不写死**。
- 先**单独**修齐删文件的 `fetchStorage` 不一致（第三节 1），再抽——不把「修 bug」混进「抽公共件」。
- `deleteSelected` 的夹回滚缺口、`deleteFolder` 的无回滚、`commitRename` 的 fire-and-forget、回收站 API-先行组
  —— **本轮不并入**包装，保持原样，各自单独评估。

## 五、补记：ProjectModal.vue（2026-07-17）

本盘点当初只覆盖 `Files/index.vue`，`ProjectModal.vue`（项目文件区）当时是完全独立的一份实现，
没有跟着这轮盘点走。之后陆续发现它的 `commitRename`/`commitFolderRename`/`movePmFilesInto`/
`movePmFoldersInto` 都还是「先 await 接口成功了才改缓存」的旧写法——网络稍慢或响应丢失时，
拖拽/重命名落地后视图不会跟着变，只有手动刷新才会显示最新状态，且不稳定必现（跟等接口的
时序特征吻合）。已改成跟 `Files/index.vue` 对应函数一致的乐观更新（`commitRename` 走同款
`.catch()` fire-and-forget，`movePmFilesInto`/`movePmFoldersInto` 复用 `optimisticMutation`）。
`ProjectModal.vue` 没有 `loadContents()` 概念，视图/计数全部从 `fileCacheStore` 现算，
`afterMutate` 传空函数即可。
