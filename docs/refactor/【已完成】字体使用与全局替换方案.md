# 字体使用与全局替换方案

> 状态：已完成
>
> 清点日期：2026-08-23
>
> 本文定义字体资源、设计 token 和迁移边界，并记录已完成的全局迁移。

## 1. 清点结论

### 1.1 字体资源

字体位于 `frontend/public/fonts/`，当前包含 7 个 Source Han Sans（思源黑体）OpenType TTC 字体集合：

| 文件 | 字重语义 | TTC 内含中文地区字体 | 约大小 |
|---|---:|---|---:|
| `SourceHanSans-ExtraLight.ttc` | 200 | SC / TC / HC 等 | 16M |
| `SourceHanSans-Light.ttc` | 300 | SC / TC / HC 等 | 17M |
| `SourceHanSans-Normal.ttc` | 400 | SC / TC / HC 等 | 18M |
| `SourceHanSans-Regular.ttc` | 400 | SC / TC / HC 等 | 19M |
| `SourceHanSans-Medium.ttc` | 500 | SC / TC / HC 等 | 18M |
| `SourceHanSans-Bold.ttc` | 700 | SC / TC / HC 等 | 19M |
| `SourceHanSans-Heavy.ttc` | 900 | SC / TC / HC 等 | 19M |

字体目录同时包含 `LICENSE.txt`，内容为 SIL Open Font License 1.1。字体文件总量约 125MB，不适合无选择地全部加载。

### 1.2 当前 token 与全局入口

当前字体 token 位于 `frontend/src/assets/styles/tokens/primitives.css`：

```css
--font-sans: -apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI",
  "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
--font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

`frontend/src/assets/styles/global.css` 通过 `var(--font-sans)` 应用于 `html`、`body` 和 `#app`，因此这是主应用的有效全局入口。当前代码中约有 110 处直接消费 `var(--font-sans)` 的声明。

### 1.3 字体族使用分类

对 `frontend/src` 中 Vue/CSS/TS 文件进行完整扫描后，发现 22 种 `font-family` 表达式，主要分为以下几类：

| 类别 | 当前情况 | 处理原则 |
|---|---|---|
| UI 无衬线 | 约 110 处 `var(--font-sans)` | 统一由字体族 token 控制 |
| 日历/日期组件旧栈 | 约 24 处 `PingFang SC + Segoe UI` 变体 | 迁移到 UI token，保留日期组件的字号/行高 |
| 等宽代码 | `SF Mono`、`Fira Code`、`JetBrains Mono`、`ui-monospace` 等多套 | 统一到 `--font-family-mono`，代码编辑器可有明确产品例外 |
| 继承字体 | `inherit` | 保留，不强行覆盖父组件 |
| 系统/第三方回退 | `system-ui`、`-apple-system` | 只作为 fallback，不作为产品主字体 |

当前明确写死 UI 无衬线栈的重点位置包括：

- `frontend/src/components/common/DatePicker.vue`
- `frontend/src/components/common/DateSpanPicker.vue`
- `frontend/src/views/Calendar/index.vue`
- `frontend/src/views/Dashboard/components/CalendarPanel.vue`
- `frontend/src/components/common/AppSidebar.vue`

当前代码编辑/预览相关的等宽字体重点位置包括：

- `frontend/src/components/common/viewers/TextViewer.vue`
- `frontend/src/components/common/MarkdownView.vue`
- `frontend/src/views/Mind/components/mind-content.css`
- Admin Debug、SystemLogs、AuditLog、StorageAudit 等日志页面

### 1.4 字重清点

代码中实际出现的主要字重为 `400`、`500`、`600`、`700`，另有少量 `650`、`750`、`800` 和 `900` 风格值。现有基础 token 已定义 regular/medium/semibold/bold 四个语义字重，但仍存在少量直接数字值。

字体迁移时不应为每个数字值加载一个文件。推荐将产品 UI 收敛为 400、500、700 三个真实字体文件；`600` 使用相邻权重匹配，`650/750/800` 视为局部视觉例外，先不新增资源。

## 2. 目标字体 token 设计

### 2.1 字体族 token 分层

保留现有兼容别名，同时增加职责明确的字体族 token：

```css
:root {
  --font-family-body: "Source Han Sans SC", "Source Han Sans", var(--font-system-sans);
  --font-family-ui: var(--font-family-body);
  --font-family-heading: var(--font-family-body);
  --font-family-mono: "SFMono-Regular", "Fira Code", Consolas, var(--font-system-mono);

  /* 兼容现有组件，迁移完成前不能删除。 */
  --font-sans: var(--font-family-ui);
  --font-mono: var(--font-family-mono);
}
```

其中 `--font-system-sans` 和 `--font-system-mono` 只承载平台回退栈，不再在业务组件里重复书写。

### 2.2 字体角色

| 角色 token | 用途 | 默认族 |
|---|---|---|
| `--font-family-body` | 正文、卡片、表单内容 | Source Han Sans SC |
| `--font-family-ui` | 导航、按钮、标签、弹窗控件 | body |
| `--font-family-heading` | 页面标题、卡片标题 | body |
| `--font-family-mono` | 代码、日志、技术标识、文件路径 | 系统等宽栈 |

字体族与字号/字重分离。组件不得因为换字体而重复定义字号、行高或字重。

## 3. 字体资源加载方案

### 3.1 不直接把 TTC 当作最终 Web 资源

TTC 是字体集合，单个文件内含多个地区字体。为了避免浏览器对集合内字体选择不一致，以及避免加载无关的日文/韩文/繁体字形，正式接入前应从 TTC 中提取 `Source Han Sans SC` 的单字体版本，并转换为 WOFF2。

建议产物：

```text
frontend/public/fonts/web/source-han-sans-sc-regular.woff2  (400)
frontend/public/fonts/web/source-han-sans-sc-medium.woff2   (500)
frontend/public/fonts/web/source-han-sans-sc-bold.woff2     (700)
```

TTC 原文件可以继续作为许可证对应的来源归档，但不应由页面直接请求。

### 3.2 `@font-face` 的职责边界

`@font-face` 属于字体资源加载层，不属于 design token 定义本身。建议单独放入：

```text
frontend/src/assets/styles/fonts.css
```

再由全局样式入口引入。字体 token 只引用字体族名，不在组件或页面里写 URL。

推荐资源加载规则：

- `font-display: swap`，确保字体加载失败时页面仍可用；
- 首屏只声明 400、500、700；
- 不预加载全部字体；
- 只有确认存在首屏标题渲染闪烁时，才考虑预加载 400；
- 代码编辑器继续使用等宽字体 token，不与正文 Source Han Sans 混用。

## 5. 设计约束

1. 组件不得直接写 `Source Han Sans` 文件 URL。
2. 组件不得自行创建新的中文 UI 字体栈。
3. 字体族、字号、字重、行高是四个独立 token 维度，不因局部错位直接调整字体文件。
4. Runtime 拖拽代理必须继承或复制最终字体 token；字体迁移后要回归检查卡片换行和 landing 尺寸。
5. 不把字体文件全部内联，不在日志、接口响应或用户数据中暴露字体路径。
6. 每次修改字体 token 都必须检查项目卡、文件卡、画布卡、聊天气泡和弹窗的布局稳定性。
