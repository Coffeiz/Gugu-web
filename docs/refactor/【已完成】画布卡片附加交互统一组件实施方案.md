# 画布卡片附加交互统一组件实施方案

## 1. 文档状态

| 项目 | 内容 |
| --- | --- |
| 状态 | ✅ Phase 0–4 已完成 |
| 范围 | 画布页面卡片附加交互 |
| 目标 | 统一项目、文件、便签和贴纸的按钮与连接点外观 |
| 非目标 | 不修改 Runtime 卡片主体生命周期，不处理抽屉卡片 |

## 2. 背景

画布侧已经有 `CardActions.vue` 和 `CardConnDot.vue`，但便签、项目、文件等卡片仍保留部分独立的附加交互样式和 hover 状态。后续继续增加编辑、删除、更多操作或连接点状态时，容易出现尺寸、层级、显隐和落地揭示行为不一致。

本次在业务侧新增一个全局通用组件，Runtime 只负责卡片主体的拖拽、landing 和 reveal；附加按钮与连接点继续由业务组件提供语义和事件。

## 3. 目标与非目标

### 3.1 目标

- 新增全局 `CardAffordances.vue`，统一附加交互的容器、状态和基础样式；
- 支持操作按钮、连接点两个独立插槽；
- 统一 hover、connecting、connection-target、dragging、revealing 状态传递；
- 先迁移画布项目卡、文件卡、贴纸和便签；
- 保持现有事件、权限判断、按钮图标和用户流程不变；
- 未来可以继续接入文件库卡片，而不复制画布专用实现。

### 3.2 非目标

- 不把按钮注册到 Runtime；
- 不让通用组件理解“删除项目”“编辑文件”等业务语义；
- 不修改抽屉项目卡的展示和拖拽逻辑；
- 不在本次重构中统一所有卡片的内容布局、颜色或尺寸；
- 不改变连接线和业务 action 的实现。

## 4. 目标结构

```text
frontend/src/components/common/
└── CardAffordances.vue       # 全局附加交互容器

frontend/src/views/Mind/components/
├── CardActions.vue            # 迁移期兼容层，最终删除或改为薄封装
├── CardConnDot.vue             # 迁移期兼容层，最终删除或改为薄封装
├── ProjectRefCard.vue
├── FileRefCard.vue
├── EntitySticker.vue
└── NoteCard.vue
```

推荐使用方式：

```vue
<CardAffordances
  :hovering="isHovering"
  :connecting="connecting"
  :target-side="connectionTargetSide"
>
  <template #actions>
    <button type="button" title="从画布移除" @click="onRemove">...</button>
  </template>

  <template #connect>
    <!-- 连接点语义和事件由业务组件提供 -->
  </template>
</CardAffordances>
```

组件只统一容器和状态 class，例如：

```html
<div data-card-affordances data-affordances-state="hovering">
```

## 5. 组件职责

### 5.1 `CardAffordances.vue`

负责：

- 附加交互的绝对定位和层级；
- `actions`、`connect` 插槽；
- 操作按钮的尺寸、间距、透明度和 hover 反馈；
- 连接点容器的显示状态和交互状态 class；
- 在 `dragging`、`landing`、`revealing` 状态下统一隐藏或冻结附加交互。

不负责：

- 创建按钮或图标；
- 调用删除、编辑、连接等业务函数；
- 查询 Store 或判断权限；
- 维护卡片的业务 hover 状态来源。

### 5.2 卡片业务组件

各卡片继续负责：

- `mouseenter`/`mouseleave` 或已有 composable 提供的 hover 状态；
- 操作按钮的语义、图标、tooltip 和事件；
- 是否展示某个按钮；
- 连接点的业务回调和连接目标状态；
- 卡片自身特殊的编辑态或墓碑态。

附加交互统一限制：卡片进入 runtime 的 dragging、landing、revealing 或 regrab 生命周期时，
`CardAffordances` 统一隐藏并关闭命中；抓起、landing
和 regrab 不再由各业务卡片分别控制按钮或连接点。

### 9.2 新组件接口

`CardAffordances.vue` 位于 `frontend/src/components/common/`，提供：

- `hovering`、`connecting`、`targetSide`、`dragging`、`landing`、`revealing` 状态 props；
- `actions` 和 `connect` 命名插槽，以及 `overlay`、`inline`、`float` 三种操作区布局；
- `nodeId` 与 `connectDragStart` 事件，保留连接点的命中区域、tooltip 和左右 active 状态；
- `data-card-affordances` 与 `data-affordances-state` 稳定 DOM 标记，供后续测试和排查使用。

### Runtime 生命周期接入

附加交互的显示时机由对象类型注册字段统一声明，Runtime 不渲染按钮，也不依赖业务组件 class：

```ts
runtime.registerObjectType('mind-canvas-object', {
  defaultVisualMode: 'detach',
  affordances: { selector: '[data-card-affordances]' },
})
```

`selector` 可以是一个选择器或选择器数组。Runtime 会在 `dragging`、`landing`、`revealing`
阶段为匹配节点添加 `runtime-affordances-hidden`，回到 `idle` 后移除；业务侧只需要提供稳定
DOM 标记并自行决定隐藏、过渡和按钮样式。未声明 `affordances` 的对象不会被 Runtime 处理。

Phase 0–1 只新增组件和测试，不替换消费者；Phase 2 已将四类画布卡片切换到 `CardAffordances`。`CardActions.vue`、`CardConnDot.vue` 仍是迁移期兼容层，待 Phase 3 确认没有其他消费者后再处理。

## 7. 验收标准

- 所有画布卡片的附加按钮尺寸、间距、层级和 hover 反馈一致；
- 连接点的显示、命中范围和 active 状态与现有行为一致；
- 卡片拖拽和 landing 期间不出现按钮残影或 hover 阴影跳变；
- 业务组件仍能独立决定按钮是否存在及其 action；
- Runtime 源码没有新增附加按钮或连接点业务逻辑；
- 文件库后续可以直接复用该组件，不需要复制画布侧 CSS。
