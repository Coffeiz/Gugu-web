## 2. 背景与判断

当前定时任务页面仍集中在一个 `index.vue` 中，已经同时承担以下职责：

- 任务列表和任务卡片展示；
- 新建/编辑任务弹窗；
- 重复规则表单和渠道选择；
- Cron 生成、解析和展示文案；
- 加载、实时刷新、保存、试运行、启用/停用和删除；
- 页面和弹窗样式。

它还没有达到必须立即拆分的“巨型页面”程度，但已经违反页面入口只负责编排的约定。后续继续增加任务类型、投递渠道、执行历史或失败状态时，继续堆在入口文件会让表单、纯逻辑和异步流程互相影响。

本次采用渐进式拆分，只移动职责，不改变接口、数据结构、视觉样式或用户流程。

## 3. 目标与非目标

### 3.1 目标

- `index.vue` 主要负责页面布局、列表组合、弹窗开关和事件转发；
- 新建和编辑共用一套表单组件；
- Cron 规则转换成为可独立测试的纯函数；
- API 加载和任务操作从页面模板中收口；
- 继续复用 `BaseModal`、`DatePicker`、`TimeInput`、Toast 和 Live Refresh；
- 保持现有任务卡、弹窗、渠道选项和交互动画不变。

### 3.2 非目标

- 不修改后端定时任务模型、API schema 或调度器；
- 不修改 Cron 的存储格式和兼容语义；
- 不新增 Store；
- 不把定时任务和日历活动强行合并；
- 不在本次重构中增加执行历史、失败重试或批量操作功能；
- 不顺手重做页面视觉样式。

## 4. 目标目录结构

```text
frontend/src/views/Schedules/
├── index.vue                         # 页面编排、列表和弹窗状态
├── components/
│   ├── ScheduleCard.vue              # 单个任务卡片展示与操作事件
│   └── ScheduleFormModal.vue         # 新建/编辑共用表单弹窗
├── composables/
│   └── useScheduledTasks.ts          # 加载、实时刷新和任务操作流程
└── utils/
    └── scheduleCron.ts               # Cron 解析、生成和展示文案
```

### 4.1 `index.vue`

负责：

- 页面容器和新建按钮；
- `ScheduleCard` 列表组合；
- `ScheduleFormModal` 的打开、关闭和编辑对象传递；
- 将表单保存事件交给 `useScheduledTasks`；
- 页面级空状态。

不再负责卡片内部模板、表单字段细节和 Cron 算法。

### 4.2 `ScheduleCard.vue`

负责：

- 任务名称、启用状态、重复规则、渠道、payload 摘要和上次运行时间；
- 发出 `toggle`、`run`、`edit`、`remove` 事件；
- 当前任务卡片的 scoped CSS。

组件不直接调用 API，不持有页面任务集合，也不决定操作后的刷新策略。

### 4.3 `ScheduleFormModal.vue`

负责：

- 新建/编辑共用的表单 UI；
- 重复模式、间隔预设、自定义日期、时间和渠道选择；
- payload 高度调整；
- 表单校验和保存/取消事件；
- 当前弹窗样式。

组件接收 `show`、`task` 和可用 IM 渠道，向父级发出 `close` 与 `save`。编辑任务时保留已有 `enabled` 状态，不在表单组件内部调用 API。

### 4.4 `useScheduledTasks.ts`

负责：

- `scheduledTasksApi.list/create/update/run/delete` 的调用；
- `loading`、`busy`、任务列表和操作错误状态；
- `useLiveRefresh('scheduled_tasks', load)`；
- 保存、启停、试运行、删除后的刷新；
- 对外提供稳定的任务操作函数。

它不负责表单字段状态和页面 DOM，也不把 API 细节下沉到展示组件。

### 4.5 `scheduleCron.ts`

负责纯函数：

- `parseCron(cron)`；
- `buildCron(input)`；
- `cronLabel(cron)`；
- 重复模式和解析结果类型；
- 日期格式化所需的无副作用辅助函数。

需要保留并测试以下格式：

- `*/N * * * *` 间隔任务；
- 每日、工作日和周末任务；
- `@once:YYYY-MM-DDTHH:mm` 单次任务；
- 非法或未知格式回退到现有默认展示语义。

## 7. 风险与回滚

- 每个阶段独立提交，不混入后端行为或视觉改版；
- Phase 1 优先完成并单独验证，作为后续拆分的稳定基线；
- 表单拆分时重点防止 `ref`、`nextTick`、textarea 高度和弹窗关闭时机回归；
- composable 拆分时重点防止实时刷新重复注册、保存后重复加载和 `busy` 状态丢失；
- 任一阶段出现行为回归时，优先回滚该阶段提交，不回滚前面已验证的纯函数或展示组件拆分。

## 8. 完成定义

当以下条件全部满足时，视为本次重构完成：

- `index.vue` 只保留页面布局和流程编排；
- 新建/编辑表单只有一份实现；
- Cron 逻辑有独立类型和测试；
- API 和实时刷新流程集中在 `useScheduledTasks`；
- 页面 UI、交互和后端请求语义与重构前一致；
- typecheck、单元测试、构建和手工验收全部通过。
