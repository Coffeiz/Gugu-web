## 0. 范围（写死，防越界）

**现在做（Web 1.0，Local 还要用几个月）**：
- `StorageBackend` 抽象——**把 `upload/` 当成一种后端实现，而不是整个文件系统**。
- `KeyStrategy` 接口——**现在保留 `PathMirrorStrategy`（存量数据零迁移）**，opaque 留作未来可换实现。
- 文件夹**生命周期一致性**（DB 状态 ↔ 磁盘状态）：修当前的丢失/幽灵/不可恢复。
- `File Service`——**REST 与 Agent 共用同一套文件语义**。
- 文件夹**软删 + 整体恢复**；埋 `storage_backend / version / updated_at / deleted_at` 字段（含 `storage_backend`，为快速切 OSS 留好通道）。

**OSS 到来时才做**（几个月后，或需求突增时；字段已就位、可快速切）：
- `OSSStorageBackend`（**阿里云 OSS**，已定）；**OSS 切 `OpaqueStrategy`**（已定，`{uid}/blobs/{uuid}.{ext}`）。
- lazy 双后端：新文件→OSS/opaque、旧文件留本地慢慢迁——**迁移既换后端也换 key 方案**（path-mirror→opaque，逐个 re-key）。

**更以后再决定**：
- 桌面端 / 双向同步 / 冲突 / operation log。

> 原则：**现在把「文件操作入口」收紧就够了；不为未来把生产文件系统提前重写。**
> **别为未来桌面端把后端写成同步系统；但今天的后端不能挡住未来。**

## 1. 现状诊断（当前要修的 root cause）

`Folder` 是纯 DB 行（无 storage_key/物理路径，`app/models/__init__.py:156`）；物理存在只靠文件 key 内嵌路径 + 业务代码直拼 `/upload`。当前**生产在跑**的三个数据完整性问题：
- **空文件夹不上盘**：建文件夹从不 `mkdir`，只在写文件时隐式建（`storage/__init__.py:113`）。
- **rename 留幽灵目录**：`rename_file`（`:130`）建新父但**不删空旧目录**；`delete`（`:119`）只清一层 → 移动/改名后残留（如两个 `adr`）。
- **删文件夹无法恢复**：`delete_folder` 硬删文件夹行（`db.delete`）。

**根因**：文件夹缺物理生命周期 + 业务层直接拼路径、无统一入口。**这三个是当前线上真实风险**，与 OSS 无关，先修。

## 2. 目标抽象（现在就落）

```
                REST API        Agent 工具
                    \             /
                     File Service          ← 唯一文件语义入口（REST 与 Agent 共用）
                    /            \
             FolderTree      StorageBackend
             (领域层)          (字节层)
                 |                |
             SQLAlchemy    LocalStorageBackend → /upload   （未来加 OSSStorageBackend）
                                  |
                             KeyStrategy = PathMirror（现在）  （未来可换 Opaque）
```
> **当前实现** = PostgreSQL + Local(`upload/`) + PathMirror；**未来** = PostgreSQL + OSS + Opaque。
> 换的是最底下两层（StorageBackend / KeyStrategy），**上层 REST / Agent / FileService / FolderTree 不变**——这就是这套抽象的全部意义。

- **`File Service`**：建/移/删/改名/软删/列举的**唯一实现**，REST 与 Agent 都调它 → 天然一致。
- **`FolderTree`**：文件夹树的 Web 后端领域层（`getFolder/getChildren/createFolder/moveFolder/deleteFolder/resolveLogicalPath`），当前实现 = SQLAlchemy。**保持为接口**（未来桌面端可另给实现，白捡；非当前目标）。
- **`StorageBackend`**：只管字节。现在只有 `LocalStorageBackend`（包 `upload/`）。**未来 OSS 是加一个实现,不动业务层。**
- **`KeyStrategy`**：现在 `PathMirrorStrategy`（`{uid}/项目文件/.../file`，存量数据不变、可挂盘浏览）。**OSS 到来时切 `OpaqueStrategy`（已定）**；Local 保持 path-mirror。

> **YAGNI**：现在只实现 `Local` + `PathMirror` 一条。`OSSStorageBackend`（阿里云）+ `OpaqueStrategy` 只留接口、不写实现，等 OSS 到来。
> **接口前向兼容**：`KeyStrategy.build_key(ctx)` 的 `KeyContext` 只放存储字段（`user_id/file_id/name/ext/logical_path`），PathMirror 取 `logical_path`、Opaque 取 `file_id`，**加 Opaque 不改签名**。业务命名（项目/年月/文件夹→路径）拆到 `compose_logical_path` 纯函数，不进存储层。**冻结签名见附三。**

## 3. 文件夹生命周期一致性（当前主线）

**要求**：`Folder DB 状态` 与 `磁盘状态`始终一致。因为 Local 还要用几个月，这是**当前主要交付、不是过渡投入**：
- 建文件夹 → `mkdir` 真目录（修「空文件夹不上盘」）。（Local 空目录用真 `mkdir`，不用 `.keep`，避免污染用户可见文件。）
- 纯改名 → `rename_dir`（整目录 `mv`，原子、不留孤儿）。
- 移动 → 目录/文件同步，**逐级清空的旧祖先目录**。
- 删文件夹 → 物理搬子树进 trash 前缀（配合 §5 软删）。
- 修 `rename_file`/`delete`：清空后**逐级 rmdir** 旧祖先。
- **一次性清幽灵**：对账工具 diff DB 树 vs 磁盘，补缺失目录、报告孤儿（非空目录人工确认后清），治现存 `adr`/123。**由管理员在后台入口触发（扫描→报告→确认清理）+ 低频兜底，不做小时级常驻扫描。**

> 未来若切 opaque（文件夹变纯 DB 行、无物理目录），这套生命周期会大幅简化甚至消失——但那是未来；**现在就是要把 Local 修对**。

## 4. Agent / REST 一致（当前价值最高之一）

Agent 的 `_create_folder`/`_delete_folder`/移动等，**全走同一个 `File Service`**（现在各写一套：REST 走 `folders.py`，Agent 走 `tools/files.py`，语义容易漂）。一致靠共用实现 + 对称测试（沿用 projectStages / agent 工具模式，不合并成单一代码源）。

## 5. 软删：回收站 + Agent 执行安全

`deleted_at` 软删 + 整体恢复：
- **回收站**：文件夹可整体恢复（修 §1 第三个 bug）。
- **Agent 执行安全层**：咕咕删目录 = 可撤销 tombstone，是「安全操作真实世界」的信任底座（与 P2-b、confirm-gate 同一条可靠性主线，见 [[gugu-agent-reliability]]）。
> （将来还能当同步删除墓碑——白捡的未来价值，现在不为它设计。）

## 6. 现在埋的字段（低成本，不实现未来系统）

Alembic 加列、nullable/带默认、不回填即安全：
```
File:   storage_backend(默认 'local')  version  updated_at  deleted_at
Folder: version  updated_at  deleted_at
```
- `storage_backend`：**现在就加**（默认 `'local'`，所有现存+新文件都是 local，零行为变化）。目的是**给「需求突增直接切 OSS」留好快速通道**——真要切时不必再卡一次 schema 迁移，直接上 `OSSStorageBackend` + 路由。加列 ≠ 建系统。
- `version`/`updated_at`：当前用于乐观并发（延伸现有 409 并发锁）；未来同步冲突裁决白捡。
- `deleted_at`：软删（§5）。
> **只加字段，不建** SyncEngine / ConflictResolver / OperationLog。`OSSStorageBackend` 实现 + lazy 迁移逻辑仍等 OSS 到来再写（字段就位 ≠ 系统建好）。

## 附二：迁移 vs 同步的边界（防混淆）

「OSS→本地」和「同步到客户端」共用一块地基，但**不是同一个功能**：

| | OSS→本地迁移（运维） | 客户端双向同步（桌面端·围栏外） |
|---|---|---|
| 在哪 | 服务端 | 每台用户设备 |
| 方向 | 单向（换权威后端） | 双向（两副本收敛） |
| 复杂度 | 低——切 OSS 按钮的镜像，`migrate(oss, local)` | 高——分布式，需冲突解决/墓碑/version |
| 归属 | 本 PRD 的 P4（方向无关作业顺带出） | **围栏外的未来大件（SyncEngine）** |

**共用地基**：两者都要「把 DB 树 + 文件**物化成真实本地目录**」这个原语 = `LocalStorageBackend` + `local/tree.py`。
- OSS→本地：服务端「读 OSS 后端 → 写 Local 后端」。
- 客户端同步：客户端「从 API 拉树 → 写本机 FS」，**同一套物化逻辑，上面再叠双向同步**。

> 所以现在（P0/P1）把服务端 Local backend + 目录物化做扎实，一箭双雕：治 today 的同步 bug + 铺客户端本地镜像引擎的地基。但**「客户端双向同步」本身不在本 PRD**——它是围栏外的分布式大件。

**KeyStrategy**（瘦身：只放存储需要的数据，不放 `project_year/mind_map_title` 等业务字段）
```python
@dataclass
class KeyContext:
    user_id: UUID
    file_id: int | None       # Opaque 用；PathMirror 忽略（可 None）
    name: str
    ext: str
    logical_path: str = ""    # 已由上层解析好的「可浏览逻辑路径」，如 项目文件/2026/07/P #3/设计

@dataclass
class ResolvedKey:            # 冲突改名后 key 与 name 都变，两者都要落库（storage_key + display_name）
    key: str
    name: str

class KeyStrategy(Protocol):
    def build_key(self, ctx: KeyContext) -> str: ...
    async def resolve_conflict(self, storage, base_key, display_name, ext) -> ResolvedKey: ...
    @property
    def move_semantics(self) -> Literal["relocate", "db-only"]: ...
```
- **`compose_logical_path(space, project, folder_path, …) -> str`**：业务命名（可浏览树布局）从 `_build_key` 拆出、放近 FileService 的纯函数；KeyStrategy 只吃结果 `logical_path`。
- `PathMirrorStrategy`：`{uid}/{logical_path}/{safe_name(name)}.{ext}`；`move_semantics="relocate"`。
- `OpaqueStrategy`(P4)：`{uid}/blobs/{file_id}.{ext}`（忽略 logical_path）；`move_semantics="db-only"`。**加它不改签名。**

**FolderTree**（只管元数据 DB，`get_owned` 语义；**绝不含 `os.rename`/mkdir**）
```python
class FolderTree(Protocol):
    async def get(user_id, folder_id) -> Folder | None                       # 未拥有→None
    async def get_children(user_id, *, project_id, parent_id) -> list[Folder]  # 根传 None（渲染 IS NULL）
    async def resolve_folder_path(user_id, folder_id) -> str | None          # 文件夹名链（如 设计/评审）；坏链/越权→None
    async def descendants(user_id, folder_id) -> list[int]                   # 含 root
    async def create(user_id, *, name, parent_id, project_id) -> Folder      # raise NotFound(项目)/Conflict(重名)
    async def rename(user_id, folder_id, new_name) -> Folder                 # raise NotFound
    async def move(user_id, folder_id, new_parent_id) -> Folder              # raise NotFound/Invalid（循环/跨空间）
    async def soft_delete(user_id, folder_id) -> None             # P2
    async def restore(user_id, folder_id) -> None                 # P2
# 实现微调（acb3961）：resolve_logical_path→resolve_folder_path（返文件夹名链，喂 compose_logical_path）；
# get_children 取 project_id+parent_id；mutation 校验失败抛领域异常、返 Folder（非 Optional）；只 flush 不 commit。
```

**StorageBackend**（现有 + 新增；**物理动作由 backend 自决，FileService 不 `if local`**）
```python
class StorageBackend(Protocol):
    async def put/get/delete/exists(...)          # 现有
    async def copy(src, dst) -> None              # 新增（OSS rename=copy+delete 的基元）
    async def rename_file(old, new) -> None       # 无原生 rename 的后端默认 copy+delete
    async def stat(key) -> StorageObjectInfo      # 新增：size/checksum/mtime（迁移校验用）
    async def list_prefix(prefix) -> list[str]; def presign(...)
    # 文件夹生命周期钩子（Local 真 mkdir/mv/rm；OSS no-op）：
    async def ensure_folder(logical_path) -> None
    async def move_folder(old_path, new_path) -> None
    async def remove_folder(logical_path) -> None
    async def remove_empty_ancestors(key) -> None   # Local 清孤儿
```

**FileService**（薄门面，`FileService(db)` 构造；抛**领域异常**不抛 HTTPException）
```python
class FileService:                # get_file_service(db) 一处装配：FolderTree(db)+get_storage()+get_key_strategy()
    # 文件：create_file / read_file / rename_file / move_file / delete_file(软删) / list_files
    # 文件夹：create_folder / rename_folder / move_folder / delete_folder(软删+trash) / restore_folder
```
- `create_folder` = `FolderTree.create()` + `storage.ensure_folder(path)`（无 `if local`，backend 自决）。
- `move_folder` = `FolderTree.move()` + `storage.move_folder(old,new)`（认知 vs 物理分离）。
- **领域异常放 `app/core/errors.py`**：`NotFound / NotOwned / Conflict` = P2-b 的 `ExpectedError` 子类（**两 PRD 合流，不建两套**）。REST 映射 HTTPException、Agent 映射 `{"error"}`。
- **返回 DTO/schema，不泄漏 ORM**：`FolderTree`（内部）返 ORM，`FileService`（公开）在边界映射成 `FileDTO/FolderDTO`（或复用现有 `FileResponse/FolderResponse` schema）→ REST/Agent/桌面端都不绑 SQLAlchemy Model。
- **create 顺序**：PathMirror（现在）key 不依赖 id → 先算 key 再 insert；Opaque（P4）需 id → insert → build_key → upload → 回填。**P4 不止把 `storage_key` 改 nullable，还加 `storage_status`（pending/uploaded/failed）**——「insert 成功、upload 失败」是必然，NULL key 无法区分「上传中/失败/垃圾」，有状态才能清理与重试。（P0 不需要。）
