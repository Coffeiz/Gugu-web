# 文件同步内核溢出修复 A/B

## 改动范围

- Linux 通过独立 Python 标准库进程直接读取 inotify，明确识别 `IN_Q_OVERFLOW`，继续使用现有 sidecar JSON 协议、Python supervisor、数据库投影与持久任务队列。
- 其他系统继续使用 TS watcher；不增加外部依赖或用户配置开关。
- 新监听进程仅处理路径和元信息，不读取文件正文。目录用 `O_NOFOLLOW` 打开，并验证已打开描述符的实际归属，避免跟随越界符号链接。
- 普通文件删除直接移除对应索引项，不为每个文件遍历整棵追踪树；目录删除才枚举后代。
- 内核、TS 输出、Python 缓冲和路径缓冲溢出均作为可核对缺口。已知溢出原因不会被后续 ready 擦除。
- 只有已知溢出且保留了监听根身份时，自动任务才允许通过完整扫描软删除缺失记录。没有根身份依据的历史缺口仍保持人工确认。
- 根设备和 inode 身份保存在已有任务 JSON 元数据中，进度更新不覆盖；入队后根替换和扫描期间根替换均停止修复。无需 schema 或运行配置迁移。
- 扫描有权限排除、空根无法证明历史内容确实删除等情况，不自动删除。既有路径存在性、对象版本、扫描完整性和用户归属校验继续保留。
- 同绑定已有任务时不改变当前任务的删除权限，保留根身份供后续补偿；周期补偿只复用已记录且仍匹配的身份，不拿替换后的新根冒充旧根。

## 实验隔离

使用 devserver 临时目录和临时 SQLite，全部文件、身份和正文为合成数据。监听停顿仅作用于实验子进程；不暂停运行服务，不修改内核参数。A/B 测试阶段没有调用真实工作区的批量删除接口。

## A/B 1：真实内核事件链路

A 显式调用原 TS watcher 构建制品；B 调用新 Linux 原生入口。两者使用同一诊断脚本、相同文件数量和操作顺序：预置文件、等待 ready、Shell 删除、恢复消费、观察最多 45 秒，再写哨兵验证监听仍活跃。

| 场景 | A 原 TS watcher | B Linux 原生 watcher |
| --- | --- | --- |
| 正常删除 100 项 | 100/100，哨兵正常 | 100/100，哨兵正常 |
| 正常删除 5000 项 | 5000/5000，哨兵正常 | 5000/5000，哨兵正常 |
| 暂停监听并删除 24000 项 | 16384/24000，无缺口通知 | 16384/24000，明确发出 1 条 `kernel_event_queue_overflow` |
| 停顿后写入哨兵 | 可继续收新事件 | 可继续收新事件 |

最终 B 复测仍为：100/100、5000/5000；停顿场景 16384/24000 且收到内核溢出通知，哨兵正常。

B 没有声称能够恢复已经被内核丢弃的精确事件；修复点是可靠检测并触发后续完整核对。上述事件数不等于数据库最终收敛结果。

```bash
cd backend
PYTHONPATH=. .venv/bin/python scripts/diagnostics/filesync_delete_pressure.py --driver baseline --repeats 1
PYTHONPATH=. .venv/bin/python scripts/diagnostics/filesync_delete_pressure.py --driver native --repeats 1
```

该命令运行完整矩阵，包含其他压力对照；表中列出配对比较的三种场景。单次耗时不作为正式性能基准结论。

## A/B 2：持久化修复到数据库最终状态

该层使用 64 个合成文件加一个保留文件，先通过实际 initialize 任务建立文件库，再从磁盘删除 64 个文件，故意不提交精确删除事件。使用真实任务入队、claim、完整扫描、投影、journal 和健康状态收尾；不假冒真实内核产生了 64 项溢出。

| 版本 | 已软删除记录 | 活动残留 | 结果 |
| --- | ---: | ---: | --- |
| A：原非删除修复 | 0 | 64 | 任务结束，留下 64 条冲突 |
| B：已知溢出自动补偿 | 64 | 0 | 任务成功，保留文件仍存在，缺口清除 |
| B：入队后替换根目录 | 0 | 64 | 任务失败并报告根不可用，替换目录中的文件保留 |

运行入口：

```bash
cd backend
PYTHONPATH=. .venv/bin/pytest -q -s tests/storage/filesync/test_filesync_runner.py -k overflow_recovery_ab
```

这两层分别证明“真实内核溢出能被捕获”和“丢失事件后完整修复能收敛”；没有把 24000 项事件实验写成 24000 项数据库端到端收敛实验。

## 其他回归与限制

- 文件同步目录完整回归：先后 185、186、189 项通过（不累加为独立用例数）。
- 最后调整后，原生入口、真实 Shell、sidecar 与周期调度定向复测 13 项通过；数据库 A/B 与逐批根替换保护复测 4 项通过。
- 最终原生根变更通知、符号链接隔离与缺口去重复测 7 项通过。
- Linux 原生入口额外覆盖递归删除、解除监听、符号链接隔离；周期补偿覆盖无身份、根替换和前序非删除任务延后恢复。
- 不保证任意负载下精确事件永不丢失；保障是缺口显式可见，满足安全条件时完整核对可恢复。
- 未知原因缺口、无法验证根身份或已有人工冲突的对象仍需人工处理，不能用自动删除掩盖不确定状态。
