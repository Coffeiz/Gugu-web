# AUDIT：前端重复功能审查、清理与行为复查

> 审查日期：2026-10-19
> 对象：前端源码、Vitest 测试与相关 Playwright 夹具
> 版本基准：`33c26a740` 加本轮未提交修改
> 目的：审查重复功能与旧实现，合并职责相同的逻辑，保持既有行为并补充回归验证。

## 1. 结论与范围

完成项目、日历、Dashboard、文件库、预览、聊天、Mind、个人设置、定时任务、技能及 Admin 的横向盘点，对确认共享契约的重复实现进行集中清理。没有按名称删除存量兼容，也没有强行合并仅外观相似的业务。

最终全量 Vitest **175 个文件、913 项通过**；Vue/TS、strict 检查与生产构建验证通过。本轮开始时为 170 个文件、859 项。结果支持本轮测试覆盖的契约保持不变，不构成所有浏览器状态或外部系统零回归的证明。真实浏览器 E2E 本轮未执行。

工作区同时存在其他任务的后端、部署、主题、BYOK 默认值及预览文件位置信息修改；未重置它们，也不计入本轮成果。因此不以整个脏工作区的文件数、净删除行数衡量本轮清理。

## 2. 方法与静态证据

综合使用功能入口盘点、全域引用检索、调用关系、TypeScript 未使用诊断、规范化函数体相似度、Vue SFC 脚本补充解析和实际 diff 阅读。生成类型及翻译目录不作为业务函数去重目标。删除项另查实际消费者，抽取项对照状态所有者、请求、返回、失败和卸载路径。

静态工具初始检出 114 对候选、76 个合并簇、约 3.9% 函数体重复行比例；最终为 94 对、67 个簇、约 3.4%（926/27572 行）。这些是包含测试的可解析函数体近似指标，不是产品重复率或性能收益。调用图有 525 个无语法覆盖文件，不能用零调用直接证明 Vue 代码无用；另以 Vue 编译器与 TypeScript 解析脚本区、引用搜索补足。

### 3.1 复查纠正的细节

无待办项目的头部与卡片公式数学等价，浮点中间值却有差异。只读比较 1–512 阶段共 131328 个位置，发现 45 处舍入差异：40 阶段的第 23 阶段为头部 58%、卡片 57%；72 阶段的第 27 阶段为头部 37%、卡片 38%。因此共享函数增加可选回退回调，头部仍传原阶段公式；两个例子均补测。这是有意的兼容签名扩展，不宣称所有签名未变。

Runtime 未直接换成上游通用 hook，因为它缺少应用所需的 generation 更新检查、指针处理和 post-flush 交接契约。只抽取应用内一致部分。

浮窗一项旧源码字符串断言绑定边界公式写法。先增加真实组件挂载、鼠标事件及最终位置测试，覆盖边界/最大化/恢复，再移除被其替代的结构断言；没有放宽边界或跳过失败测试。

DEV 旧重定向 `/dev/notes-three-pane` 最终保留，路由文件无本轮 diff。旧报告的“删除入口”“没有改测试”“未跑 Vitest”结论已由本报告替换。

## 4. 审查后保留的实现

- 聊天 Markdown 与 Mind：引用序列化、分块、空白及流式责任不同，共享基础消毒，不合并整个渲染器。
- 文件库导航与文件夹栈：初始游标、深浅复制、历史裁剪与回调不同，不制造通用历史管理器。
- IM 侧栏与聊天绑定：过期时分别关闭二维码或保留重试，不合并状态机。
- 文件/文件夹写入：版本、所有权、缓存键、递归与刷新不同，不能只按集合操作相似度合并。
- 字体与表格缩放偏好：默认值、范围、键不同；保留领域接口。
- `NotesView.vue` 仍由开发时间线使用；当前 Mind 与 DEV 控制器都有入口，不按旧名称删除。
- 旧凭据清理、历史文件名规范化、日历旧类型与笔记 Markdown 规整仍服务存量数据，保留。
- 短标签、年份展开、节假日缓存包装以及不同编辑器的能力判断无需为几行相似代码引入万能框架。

### 4.1 质量工具告警处置

最终 `quality-delta` 非零：12 条告警，其中 5 条阻断级。`resetDeepResearch` 实际作为保存后回调；`stopDrag` 由事件和卸载调用；Mermaid 标签函数由 Vue 使用，且属于并行修改。四条阻断重复告警来自 `moveProject`、`setStage` 与 `updateProject` 的短包装形状，纯转换职责不同，真正重复的应用/持久化已集中到 `applyTransition`；不为清零指标进一步隐藏领域逻辑。其余五条为短期修改频率提示。

没有写豁免或重设基线来获取绿色。质量门禁不宣称通过，保留人工判断理由；静态图不足以判定回调无用。
