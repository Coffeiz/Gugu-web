# TEST：注意力连续对话字符法与 IDF 法 mock 回放报告

> 测试日期：2026-10-30
> 测试环境：devserver
> 测试对象：`0.5C + 0.5P` 字符匹配、100 条窗口的方向性 IDF 匹配
> 测试目的：使用真实 Session 消息建立 IDF 词频窗口，在其后追加合成对话，比较不同情境、候选数量和时间间隔下的相关性分数与计算耗时。

---

## 1. 摘要

从测试账号拥有的一个 QQ 群 Session 中读取最近 100 条非空消息，作为 IDF 的初始语料。该 Session 共 1,066 条消息。真实正文只在远端进程内读取和计算，没有写进本报告、测试结果文件或数据库。

随后在内存中追加合成的咕咕回复、第三者消息及用户消息。模拟 10 种对话情境，分别将目标咕咕回复与当前用户消息的间隔设为 5、60、180、600、1,800 秒，共 50 组情境与时间回放。每组分别在最近 1、10、30 条已接受的合成咕咕回复中选最高分。所有合成候选都先于当前用户消息，未使用未来消息。

本报告中的“已接受”是 mock 事实，不代表平台真实发送收据。没有向真实群聊发消息，也没有修改数据库。

主要结果：

- IDF 在 30 个候选时的均值为 0.374，字符法为 0.339；两者都随候选池增大而上升，IDF 的零分比例较高，但非零 IDF 分数并未普遍接近 1。
- IDF 能提高共享多个关键项的续接分数，例如 Redis TTL 执行反馈；但共享术语也会让换话题消息得到分数。IDF 不能单独判断“在谈什么”与“在对谁说”。
- 时间间隔对这两种文本相似度分数没有影响，因为本次公式不含时间衰减。时间作为回放维度记录，不应把“间隔变长”误解为分数应该变化。
- 分词器首次加载是冷态主要耗时，约 925 ms；热态读取、分词与评分约为数十毫秒级，IDF 分数扫描自身低于 1 ms。

## 2. 数据范围、隔离与限制

### 2.1 数据范围

- Session 总消息数：1,066。
- IDF 初始语料：按时间排序后的最近 100 条真实非空消息。
- 真实消息在此处只作为统计语料；不展示其正文、账号标识、Session 标识或群标识。
- 10 个情境各追加 30 条合成已接受咕咕候选，包含目标回复和干扰回复；再追加合成的第三者插话及待评分用户消息。
- 在 mock 事件时间线上，每追加一条事件，IDF 使用最近 100 条消息滚动窗口。
- 不存在数据库写入；合成消息不持久化。

### 2.2 可信边界

本测试的标签由场景构造者预先定义，并非人工盲标，也不是线上真实 ACCEPTED 出站收据回放。测试验证的是：给定这些输入时，两个文本相似度算法如何计分、候选池如何改变最大分、计算各阶段耗时多少。它不代表真实群聊准确率、误接话率或注意力门控最终放行率。

本测试只比较文本相似度分数。DIRECT、硬拒绝、对话归属、时间 TTL、主动额度及 Agent 的最终静默判断不在分数公式内，也没有把相似度分数直接换算成注意力总分。

## 3. 算法定义

### 3.1 字符法 `0.5C + 0.5P`

先对两段文本做 Unicode NFKC 与大小写归一化，移除空白及标点。

- `C`：用户消息有效字符中，与咕咕候选回复匹配的非重叠片段长度占比。
- `P`：最长连续匹配片段长度的平滑值：`P = 1 - exp(-max(0, L - 3) / 4)`。
- 最终分：`sim_char = 0.5 × C + 0.5 × P`。

该实现不使用人工领域词表或分词；匹配以规范化文本字符序列为基础。

### 3.2 IDF 法

使用仓库现有 `agent.rag.cython_tokenizer.tokenize_raw` 分词。窗口大小 `N=100`，每条消息作为一个文档：

`idf(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))`

对每个候选咕咕回复与当前用户消息计算词频：

- `Wshared = Σ idf(t) × min(tf_user(t), tf_reply(t))`
- `Wnew = Σ idf(t) × max(0, tf_user(t) - tf_reply(t))`
- `sim_idf = Wshared / (Wshared + 0.3 × Wnew)`；分母为 0 时分数定义为 0。

这是用户消息方向的覆盖式相似度：咕咕回复里没有被用户复述的其他词不会进入分母。报告中的 IDF 分数与权重均为该定义的结果，`λ=0.3` 是本轮实验参数，不是已校准最优值。

### 3.3 候选池与排序

每个情境构造 30 个已接受的合成候选。`K=1`、`K=10`、`K=30` 分别在最近 1、10、30 个候选内逐一计算相似度，并报告最高分。候选池增加只会保持或提高最高分，因此不能把 K=30 的最大值直接与 K=1 的最大值当成同等条件下的独立预测。

## 4. 时间回放与分数

间隔集合为 `5 / 60 / 180 / 600 / 1,800 秒`。每个情境每种算法均完整回放这五个间隔。下表每格的分数向量在五种间隔下相同；每个情境对应五个回放，而不是只运行一次。

格式：字符法为 `C / P / sim_char`；IDF 法为 `Wshared / Wnew / sim_idf`。分值保留三位小数，权重保留三位小数。

| 阶段 | 耗时 | 口径 |

### 6.2 端到端解释

本次没有测 Provider HTTP、Agent Run 或真实 IM 收发，因此不能称为“发消息到算法完成”的产品级 HTTP 端到端耗时。可以复核的本地热态路径由数据库采样、分词和算法计算组成：用表中热态历史分词、合成输入分词、数据库读取和一次 IDF 扫描粗略相加约 26.1 ms。各阶段数据来自独立计时，因此该加总是分阶段近似，不是单个统一事务的 wall-clock 实测。

冷态路径的主要卡点是 jieba 词典加载，约 0.925 秒；热态最大的单阶段是 100 条历史的重新分词，约 19 ms。IDF 的窗口维护和候选扫描远小于分词成本。工程上应优先复用已分词窗口或增量维护 `df`，而不是优化 IDF 除法或候选遍历。

### 6.3 连续滚动窗口：全量重算与增量更新

为回答“每来一条消息时是否要把滚动窗口内 100 条都重新分词”，另取同一真实 Session 中连续 300 条消息做热态回放：前 100 条建立窗口，后 200 条依次作为新到消息。正文未输出。先预热分词器，再对每条新消息比较两种路径：

1. **全量路径**：每次拼出当前 100 条窗口，将 100 条全部重新分词，并重建 `df`。
2. **增量路径**：只分词新消息；缓存每条消息的 token set，窗口移出最旧文档并从 `df` 扣减其 token，再把新文档及 token 加入窗口和 `df`。

| 滚动处理方式 | 每条消息 P50 | 每条消息 P95 | 200 条累计 |
|---|---:|---:|---:|
| 每次重新分词 100 条并重建 `df` | 17.029 ms | 32.503 ms | 3,583.454 ms |
| 仅分词新消息 | 0.155 ms | 0.787 ms | — |
| 增量更新窗口 `df`（分词之外） | 0.020 ms | 0.052 ms | — |
| 仅分词新消息 + 增量更新 `df` | 0.183 ms | 0.813 ms | 54.542 ms |

因此连续滚动时**无需每条消息重分词整个 100 条窗口**。复用 token set 并增量维护词频后，200 条回放的累计时间约为全量重算的 1/65.7；每条消息 P50 约快 93 倍。该结果是热态算法路径计时，不包含数据库取下一条消息、Provider 请求、持久化或并发锁等待。首次词典加载另计，冷态约 1.023 秒。

上一小节中 `0.0016 / 0.0048 ms` 的滚动维护结果只计了已分词 token set 上的 `df` 扣减与增加，未计新消息分词；本小节是将新消息分词纳入后的完整滚动算法对比。两组数字口径不同。

## 7. 结论与后续建议

1. IDF 方向性相似度在多概念反馈（S06、S09）上比字符法更能体现共享关键信息；短追问、单值回答仍会因没有词项重叠而得零分。
2. 共享一个术语就可能让另起话题的消息非零（S04、S05）。扩充候选池也会让无关候选夺得最高分（S02、S08、S10）。单纯改进分词或 IDF 参数无法解决发言归属问题。
3. 连续聊天应把“文本话题关联”和“谁在回应谁”的结构性对话事实分开：原生引用、同成员可信出站锚点、时间窗口、明确结束或转向等信息需要独立进入决策；相似度仅作为其中一类证据。
4. 若将 IDF 纳入后续算法候选，应保留 100 条窗口逐条时间切片，按每条待评分消息只使用它到达前的历史与已接受回复；并使用人工标注的相关/不相关样本评估误接话、漏接话，尤其覆盖短追问、纯数字回答、共享术语换题、第三者加入和候选池扩大。
5. 本测试没有证明 IDF 更准确，只证明其在当前 mock 情境下有不同的分数分布和较低的评分内核耗时。`λ=0.3`、阈值及候选取最大策略都尚未校准。

## 8. 补充：完整注意力分与最终判定

原报告没有给“最后总分”，原因是前面的字符法和 IDF 法只输出文本相似度；测试时没有把它们接入完整 scorer，也没有为每个场景提供全部关系、群忙、转向和出站来源事实。直接把相似度说成注意力总分是不正确的。为补足口径，下面分别给出**控制变量下的公式投影**与**当前 v2.5.4 scorer 实跑结果**；两者不可混为同一组 A/B 数据。

### 8.1 公式投影：将实验相似度放入本人执行反馈通道

仅对预先标为本人执行反馈的场景，把实验相似度作为 `sim_local` 代入 PRD 的反馈分支。固定合成条件为：自然模式、目标回复是发给同一成员并已 ACCEPTED、无第三者占用历史（`B=0`）、无转向冲突（`X=0`）、主动额度可用。本人回复衰减采用 `h=360 秒, H=600 秒`。公式为：

```text
g(t) = (2^(-t/360) - 2^(-600/360)) / (1 - 2^(-600/360))，0≤t<600；否则为 0
link = 0.65 + 0.35 × sim
R = min(0.98, 0.98 × g(t)^0.25 × link)
S = 100 × 0.85 × R
```

这是明确固定输入后的“完整公式分”，不是完整历史群忙重放，也不是当前 production scorer 对字符/IDF 两种算法的 A/B。`5/60/180/600/1800 秒`五个间隔的投影结果如下：

| 场景 | 字符法最终分 | IDF 最终分 | 自然档 70 分门槛（B=0 基线） |
|---|---|---|---|
| S01 同一成员执行反馈 | `73.42, 70.55, 64.09, 0, 0` | `71.21, 68.43, 62.16, 0, 0` | 字符法 5/60 秒通过；IDF 仅 5 秒通过 |
| S02 多轮短追问 | `94.73, 91.03, 82.69, 0, 0` | `94.73, 91.03, 82.69, 0, 0` | 两者 5/60/180 秒通过 |
| S03 单值回答 | `93.75, 90.09, 81.83, 0, 0` | `93.75, 90.09, 81.83, 0, 0` | 两者 5/60/180 秒通过 |
| S04 共享术语但另起话题 | `73.80` × 5 | `73.80` × 5 | 两者在 B=0 下均通过；由 open 通道得到，与 sim 无关 |
| S05 第三者独立提到相同术语 | `0` × 5 | `0` × 5 | 不通过；没有本人续接或公开问句关系 |
| S06 第三者插话后原成员续聊 | `71.85, 69.04, 62.72, 0, 0` | `75.45, 72.51, 65.86, 0, 0` | 字符法仅 5 秒通过；IDF 5/60 秒通过 |
| S07 多轮技术追问 | `73.80` × 5 | `73.80` × 5 | 两者在 B=0 下均通过；由 open 通道得到，与 sim 无关 |
| S08 结束当前话题并转向 | `73.80` × 5 | `73.80` × 5 | “谢谢，解决了”后有新天气问句，按新 open 候选计算；不视为整条消息结束 |
| S09 长间隔后回到原话题 | `64.68, 62.15, 56.45, 0, 0` | `72.37, 69.55, 63.17, 0, 0` | 字符法均未过；IDF 仅 5 秒通过 |
| S10 第三者提出不相关新问题 | `73.80` × 5 | `73.80` × 5 | 两者在 B=0 下均通过；由 open 通道得到，与 sim 无关 |

向量顺序均为 `5 / 60 / 180 / 600 / 1800 秒`。非执行反馈的 S02/S03 使用结构性续接 `link=1`，所以最终分不依赖字符或 IDF 相似度；公开问句按 `I=.90, R=.82, B=0, X=0` 计算为 73.80；无合格关系的场景为 0。若 `B>0`，open 通道还会乘以 `1−0.45B`，因此 73.80 不是任意群忙程度下的最终值。

### 8.2 当前 v2.5.4 scorer 实跑

另外在 devserver 对同一组 mock 正文调用当前 `decide_attention()`，自然模式阈值 70，额度可用；目标回复以已接受的 DIRECT 事实定向给 A 或 B。快照不提供其他历史群聊消息，所以 `B=0`；没有原生 @ 或转向事实。每格为 `最终分 / 获胜关系 / 判定`，间隔顺序同上：

| 场景 | 当前 v2.5.4 scorer 五间隔结果 |
|---|---|
| S01 | `69.65/last/PASSIVE; 59.53/last/PASSIVE; 48.13/member/PASSIVE; 0/PASSIVE; 0/PASSIVE` |
| S02 | `94.73/member/CONTINUE; 91.03/member/CONTINUE; 82.69/member/CONTINUE; 0/PASSIVE; 0/PASSIVE` |
| S03 | `93.75/member/CONTINUE; 90.09/member/CONTINUE; 81.83/member/CONTINUE; 0/PASSIVE; 0/PASSIVE` |
| S04 | `73.80/open/PROACTIVE` × 5 |
| S05 | `0/no relation/PASSIVE` × 5 |
| S06 | `0/no relation/PASSIVE` × 5 |
| S07 | `73.80/open/PROACTIVE` × 5 |
| S08 | `73.80/open/PROACTIVE` × 5 |
| S09 | `0/no relation/PASSIVE` × 5 |
| S10 | `73.80/open/PROACTIVE` × 5 |

这个实跑使用的是仓库当前 v2.5.4 scorer，不是候选字符法或 IDF 法。S06 的“我改成……现在正常”和 S09 的“还是没过期，我查到……”未命中当前 `_FEEDBACK` 续接表达，故被判为无关系；S01 的 5/60 秒结果由 `last` 通道获胜。这些结果说明当前实现与场景的人工语义标签之间还存在差异。该实跑也只用空的忙群历史，不能替代真实 `B` 特征回放。

### 8.3 对结果的解释

- 完整注意力分由 `I、R、B、X` 及获胜关系共同决定；相似度只在部分反馈关系中作为次级 link 证据。它不会自动代表“最终总分”。
- 两种相似度算法的公式投影显示，S06、S09 在低间隔下会影响是否跨过自然档门槛，但只有在消息已被识别为本人执行反馈且有可信本人锚点时才适用。
- 当前 scorer 实跑显示，若消息未命中反馈意图，IDF 分数再高也不会产生 member 总分；反过来，独立公开问句可能由 open 通道获得 73.80，与其和上一条咕咕回复是否相关无关。
- 因而 A/B 比较应同时报告文本相似度、意图类别、获胜关系、完整总分和最终判定；下一轮如要评估 IDF 是否提升“连续对话”，需先把它接入明确的反馈 link，并对同一批 fixture 固定其他事实后重放。

## 9. 测试脚本与复现信息

- 独立仓库脚本：无。本轮的 IDF 回放、滚动窗口性能计时及当前 `decide_attention()` mock 实跑均通过 SSH 向 devserver 的 Python 进程传入临时脚本执行，未将探针或临时产物留在仓库。
