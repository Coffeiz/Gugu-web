# docs/reports

一次性排查/测试报告的存放目录：验证某个第三方能力的边界（如 `TEST-LLM-*`）、定位某个线上问题的根因（如 `OPS-*`）。跟 `docs/devlog` 的区别是——devlog 记的是"改了什么、为什么改"，这里记的是"测/查出了什么结论"，本身不一定对应一次代码改动。

## 命名

`<CATEGORY>-<主题>.md`，`<主题>` 用中文/英文均可，简短说明测的是什么。

已用过的 `CATEGORY`：

| CATEGORY | 用途 |
|---|---|
| `TEST-LLM` | 某个模型/API 能力边界的验证测试（如传输模式、参数限制） |
| `OPS` | 线上环境（服务/中间件/第三方依赖）问题的排查报告 |

新增分类时如果已有的都不贴切，直接起一个新的大写单词即可，不用改这份 README（自然增长，不强求穷举）。

## 文件头格式

参考现有文件，开头统一是标题 + 一段引用块的元信息，字段按报告类型选取（不是所有字段都必填）：

```markdown
# <CATEGORY>：<标题>

> 测试/排查日期：YYYY-MM-DD
> 测试/排查环境：...
> 测试/排查对象：...
> 测试/排查目的：...

---

## 1. ...
```

正文结构不强制统一模板，但建议至少包含「现象/过程」和「结论」两块——报告的价值主要在结论，过程是为了让结论可信、可复现。
