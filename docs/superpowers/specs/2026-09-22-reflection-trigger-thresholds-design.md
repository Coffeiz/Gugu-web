# 反思触发阈值统一设计

## 背景与目标

网页/私聊与群聊目前使用多条反思调度路径：普通 Owner 私聊使用配置阈值，QQ 普通私聊对象可能逐回合创建 `private-owner` 任务，群级反思走活跃时间窗口，群友批反思走 50 条消息阈值，群内 Owner 又使用私聊 Owner 配置阈值。目标是统一成清晰的私聊与群聊两套触发规则，避免私聊每回合反思，并让群内路径遵循群聊阈值。

## 已确认的行为

- 网页和所有私聊对象（Owner 与非 Owner）共用一个可配置阈值。
- 达到私聊阈值时反思；未达到时，最后一轮后空闲 3 分钟则收束待处理内容。
- 所有群聊反思（群级、群友批量、群内 Owner）统一由同一群累计的 50 条消息事件触发；群内 Owner 缓冲不另数 50 个 Owner 发言。
- 群内未到 50 轮的剩余内容在最后一条群消息后空闲 3 分钟时收束。
- 反思继续使用对应主对话的完整历史前缀；保留持久任务的幂等和失败重试语义。

## 设置命名与旧配置兼容

- 将 `reflection_threshold` 更名为 `web_private_reflection_threshold`，管理界面显示“网页/私聊反思触发阈值”。
- 默认值保持 10，输入范围保持 1–100。
- 旧配置中若只有 `reflection_threshold`，加载时将其映射为新字段；显式新字段优先。运行配置文件属于用户数据，不由本功能直接改写。
- 群聊阈值保持代码常量 50，不新增群聊阈值配置；群内 Owner 缓冲改为使用该统一群聊阈值，不再读取私聊配置。

## 调度设计

- 普通 Owner 网页/私聊继续走现有 Owner 反思缓冲，但读取 `web_private_reflection_threshold`。
- QQ 私聊 `platform-user` scope 在每个已完成 Agent 回合更新持久游标和 `pending_agent_count`。达到私聊阈值时预留一批并创建覆盖自上次反思后全部消息的持久任务，并复用当前主会话快照；未达阈值不调用模型。若任务入队失败，3 分钟 idle 扫描仍可根据反思游标恢复完整未反思范围。
- 私聊闲置收束仍由现有 3 分钟 cursor 扫描处理；它只处理尚未反思的消息范围，复用相同幂等键，避免与阈值任务重复。
- 每个私聊 scope 独立累计，不跨平台、bot 或联系人合并；待反思轮数保存在持久游标，进程重启不丢计数。
- 群消息累计到 50 条时，同时允许群级任务和群友批任务进入处理，并冲刷同群已累计的群内 Owner 反思缓冲；群内 Owner 消息到达该边界时先入缓冲再冲刷，其他成员到达边界时冲刷已有 Owner 缓冲。
- 群级反思不再以 1 小时活跃窗口单独触发；不足 50 条时由 3 分钟空闲收束补处理。群友与群内 Owner 的 3 分钟空闲收束保持。
- 反思完成后推进对应游标；失败任务沿用持久重试，不提前推进已反思游标。

## 兼容与验证要求

- 新私聊阈值缺失时默认 10；只有旧 `reflection_threshold` 时继承旧值；显式新字段不被旧值覆盖。
- 运行配置文件不得由迁移或代码直接重写。
- 更新 PRD-IM-11 对触发条件和空闲收束时间的说明，使其与实现一致。
- 验证至少覆盖：网页/Owner 私聊阈值、QQ 非 Owner 私聊阈值、未达阈值时无模型调用、达到阈值触发一次、3 分钟闲置收束一次、不同私聊联系人计数隔离、旧配置兼容、群级与群友 50 条同时触发、群内 Owner 50 轮触发、群聊空闲收束、重复 idle 扫描不重复反思。

## 范围外

- 不改变记忆文件格式、反思提示词、主对话历史快照组装策略和 3 分钟闲置时间。
- 不改变不同私聊联系人、群聊和不同 bot 之间的数据隔离。
