# 对话默认问候 · 生成方案

> 把 GuguChat 打开时那条**默认欢迎消息**从写死改为咕咕自己生成（暖、像朋友、可代入记忆）。
> 状态：**已实现**（§5 决策为最终落地版）。进入全新对话时生成、打开对话框时打字机动画显示、不计精力。

## 1. 背景

- 现在 GuguChat 无历史时显示一条**写死**的首条 AI 消息：
  「你好！我是咕咕，可以帮你查项目进度、搜索文件、查看截止日期和近期排期，随时问我吧 ✦」（`GuguChat.vue` 约 852 行）。
- 这条本身就是刚在 `persona.md` 里禁掉的「报功能菜单」——干、像念提示词。改成生成正好治本。

## 2. 目标 & 硬约束

- **自己生成**：咕咕写这句话，不是从固定文案里挑。
- **快**：打开对话框要**秒出**，绝不在「显示」这一下等模型。
- **简单**：不堆复杂提示词、不走完整 agent 循环。
- **可代入记忆**：有记忆时能带一点个性化（「最近在忙 X 吧？」），新用户无记忆就给通用暖句。

## 3. 核心原则：生成与显示解耦

**绝不在「打开对话框」的热路径上调 LLM**（那必慢）。做法：

```
进应用 / 刷新
  └─ GuguChat 挂载：sessionStorage 有 SESSION_KEY？
       ├─ 有（恢复老会话，loadSession 拉回历史）→ 不显示默认问候 → 不生成
       └─ 无（全新对话）→ 后台异步生成一条问候 → 写内存 ref（仅本次页面生命周期）
打开对话框（全新对话、无历史）
  └─ 取那一刻最新的问候，打字机逐字显示 —— 不在「显示」这下等模型
       └─ 还没生成好 / 失败 → 从静态兜底池随机取一条（同样走打字机）
```

- runtime（开对话框）只读内存里已生成好的那条 → 不等模型；LLM 延迟全在后台预取，用户无感。
- 这条默认气泡只在**全新对话**才显示，所以**只在进入全新对话时生成**——刷新常停在老会话（`SESSION_KEY` 仍在），那时问候根本不显示，生成纯属空跑、白费 LLM。
- **不在缓存里跨刷新留存**：问候放内存 ref，刷新即重置；每个真正的新会话一版，保持新鲜、不重复。

## 4. 实现要点（草案）

### 4.1 后端：轻量问候生成
- **不走完整 agent 循环**，用轻量直连调用（参照 `adapters/web._generate_title`：非流式、小 `max_tokens`）。**模型用默认 `settings.ai`**（成本暂不考虑）。
- **提示词极短**，要点：
  - **不自我介绍**——用户已经认识咕咕了，别说「你好，我是咕咕」这种，直接像熟人/老朋友打招呼。
  - **别报功能清单**、暖、像朋友、**emoji 极简**（守 persona）、≤30 字左右。
  - 把话交回用户（「想做点啥、想理清啥，直接说」）。
- **代入的记忆上下文**（喂给提示词，截短）：
  - **fact 类记忆**（`agent.memory.store` 的 `facts` / `memory.md` 长期事实）；
  - **最近 7 天的项目活动 + 提醒**（7 天内有动静的项目：名/进度/阶段，查库按 `updated_at`；+ 该窗口的日历事件/提醒）；
  - **最近 7 天的 daily 记忆**（`daily.md` 里近 7 天、带日期的对话提炼要点；`store.load` 返回的 `daily` 按日期筛）。
- 出口：小端点 `GET /agent/greeting`，返回 `{ text }`。失败/超时返回空，由前端兜底。
- **不计精力 / 配额**：该调用是独立直连，不经 `web.stream`/`runner` 那条记 `AgentUsage` 的路 → token 不写 `AgentUsage`、不扣配额。

### 4.2 前端：预生成 + 内存 ref + 打字机 + 兜底
- **生成时机 = 进入「全新对话」时**（不是每次刷新）：问候放**内存 `ref`**（`useGreeting.js` 的 `greeting`），仅本次页面生命周期、不跨刷新缓存。生成不再由 `DefaultLayout` 无条件触发——**`GuguChat` 挂载时据 `SESSION_KEY` 判断**：有可恢复会话（`loadSession` 拉回历史、不显示问候）→ 不生成；无（首次访问 / 关过标签页 / 清过会话）→ 才 `prefetchGreeting()` 后台 `fetch /agent/greeting` 写入 ref（fire-and-forget）。这样刷新停在老会话时不空跑生成。
- **GuguChat 初始消息**：无历史时，首条 AI 消息是**占位空消息**；**打开对话框时**（`watch(open)` → `animateGreeting()`）取那一刻最新问候，逐字打字机显示（走 `streaming`/`renderMdStream`，与咕咕回复同源），每条只播一次。生成没好/失败 → 取**静态兜底池随机一条**，**兜底同样走打字机**。
- **问候纳入对话**：默认问候只是前端展示，不在 DB 历史里——用户回复它时，后端新建会话只有那条用户消息，模型会当成「对话刚开始」又重新打招呼。修法：用户回复问候（新会话首条消息）时把已显示的问候随消息发给后端（`ChatRequest.greeting` → `AgentRequest.greeting`），`web.stream` 两步处理：
  1. **入库为本会话首条 `assistant` 消息**（先 flush、`created_at` 早于用户消息）——供会话回看时显示那条开场白；仅写一行 `ConversationMessage`、不碰 `AgentUsage`，**仍不计精力**。
  2. **新会话首轮把问候作为「对话开场」注入 system prompt**——⚠️ 不能只靠上面那条前导 `assistant` 历史：`agent/sanitize.py` 的 `sanitize_messages` 有「开头必须是 user」规则（Anthropic/MiniMax 不许前导 assistant），会把它**每轮都剥掉**，模型永远看不到 → 一直重新打招呼。注入 system 后模型「知道」自己已说过开场白，顺着接、不重复寒暄。（首轮之后有真实上下文，前导 assistant 被剥也无害，故只在 `is_new_session` 注入。）
- **大窗「新对话」不放问候**（`newSession`）：问候只在打开小窗时出现；大窗点「新对话」是干净起手、空白开始（`messages = []`）。
- **静态兜底池**（不自我介绍、不报菜单、emoji 极简，体量贴近生成文案；随机取一条；改文案动这里）：
  1. 回来啦。\n这阵子忙的事，有进展就一起往前推，卡住了也别自己扛。\n想先理清点啥、推进点啥，还是随便聊聊？都行。
  2. 咕咕在呢。\n该做的我帮你盯着，容易忘的我帮你记着，别让事情悄悄跑丢。\n今天想从哪件开始？不急也没关系。
  3. 嘿，在的。\n不管是要推进的事、要理清的念头，还是想找个人说说，我都在。\n你说，我听着。
  4. 来啦~\n手头那些要做的、要记的、要想明白的，交给我一起整。\n想先弄哪样，直接说就行。
  5. 等你半天啦。\n这地方会慢慢攒下你做过、想过、聊过的东西。\n今天，想先做点啥、聊点啥？
- 打字机由 GuguChat `animateGreeting()` 实现（逐字 ~22ms/字，到末尾转正式 markdown）；与通知气泡打字机同思路。

### 4.3 文件结构

问候用到 LLM + 记忆，属 agent 范畴，放 `backend/agent/` 下（不像 onboarding 那样单独成包）。

```
backend/
├── agent/
│   ├── greeting.py            # ← 新建：组装记忆上下文(fact + 近7天项目/提醒 + 近7天 daily)
│   │                          #          + 轻量 LLM 直连(参照 _generate_title) → 生成问候
│   ├── memory/store.py        #   复用：load() 取 facts / daily（按日期筛 7 天）
│   ├── llm_select.py          #   复用：选模型/客户端（默认 settings.ai）
│   └── adapters/web.py        #   参照：_generate_title 的轻量直连写法
└── app/
    ├── api/v1/agent.py        #   加 GET /agent/greeting → 调 agent.greeting.generate(user_id, db)
    └── models/__init__.py     #   复用：Project / CalendarEvent（查 7 天项目活动 + 提醒）

frontend/
└── src/
    ├── composables/
    │   └── useGreeting.js     # ← 新建：内存 ref（刷新即重置）+ DefaultLayout 挂载预取
    │                          #          + 兜底池(5 条) + 取问候的入口
    ├── services/api.js        #   加 agentApi.greeting()
    ├── layouts/DefaultLayout.vue        #   挂载时后台预取写入 ref（fire-and-forget）
    └── components/common/GuguChat.vue   #   占位空消息 → 打开对话框 animateGreeting() 打字机显示
```

- **后端只 2 处新增/改动**：新建 `agent/greeting.py`（核心）+ `app/api/v1/agent.py` 加一个端点；记忆/LLM/模型全复用。
- **前端**：新建 `composables/useGreeting.js`（内存 ref + 兜底池一处收口）；api.js 加方法、DefaultLayout 触发预取、GuguChat 接初始消息 + 打字机动画。
- **兜底池**放 `useGreeting.js`（前端常量，生成失败即用，不依赖后端）。

## 5. 已定决策（最终落地版）

1. **生成时机**：✅ **进入「全新对话」时生成一次**（`GuguChat` 据 `SESSION_KEY` 判断；内存 ref、不跨刷新缓存）。刷新停在老会话时不生成（问候那时不显示，生成纯属空跑）。
2. **记忆深度**：✅ **fact + 最近 7 天的项目活动和提醒 + 最近 7 天的 daily 记忆**。
3. **兜底**：✅ 生成没好 / 失败 → 从静态兜底池随机取一条（§4.2，永不慢、永不空）。
4. **模型 / 成本**：✅ 用默认 `settings.ai`，成本暂不考虑。
5. **内容约束**：✅ 问候**不自我介绍**（用户已认识咕咕）、不报功能菜单、emoji 极简。
6. **显示方式**：✅ 打开对话框时**打字机动画**逐字显示（生成版 + 兜底都走），每条只播一次。
7. **精力**：✅ 该生成**不计入精力 / 配额**（不写 `AgentUsage`、不扣额度）；问候入库同样不计。
8. **纳入对话**：✅ 用户回复问候时，问候①入库为首条 `assistant`（供回看显示）②新会话首轮注入 system prompt（让模型知道已打招呼，绕开 `sanitize` 剥前导 assistant），避免重复寒暄。
9. **大窗新对话**：✅ 不放问候，干净起手（问候只在打开小窗时出现）。
