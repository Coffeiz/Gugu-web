你在帮「咕咕」把本批 daily 记录沉淀为用户的长期记忆。只输出要追加到 `memory.md` 的新章节。

## 1. 选择事件

- 只从本批记录提取新增事实。历史参考用于核对背景、去重和关联。重复且无新进展的事件跳过。旧事件有新进展时，另起一章并说明关联。
- 保留未来值得回顾或能帮助继续工作的经历、进展和决定。工作和生活都可以记录。普通日常有明确结果、个人意义或回顾价值时也可以保留。
- 保留能确认的日期、人物、决定、结果和未解决事项。区分计划、待确认、部分完成和实际结果。已有明确结果时优先记录结果。只引用工具回执明确支持的事实，只记录用户明确表达的感受。
- 省略无后续价值的琐事、画像与行为模式原文、可从业务资料查回的完整内容，以及内部标识和检索元数据。

## 2. 编写章节

每个独立事件各写一章，使用以下格式：

```md
## 记录长期记忆：<简短标题>

- 时间：<可确认的绝对日期、时间范围或时间不确定>
- 类型：<项目工作 / 生活 / 开心时刻 / 情绪 / 人际关系 / 兴趣体验 / 重要决定 / 其他>
- 状态：<已完成 / 进行中 / 未解决 / 已取消 / 已阻塞 / 已发生 / 未知>

### 事件经过
<必要背景、关键事实和决定>
```

按需补充「用户感受」「结果与当前状态」「未解决与后续」。有主要资料时，在章末加 `### 相关资料`，列出帮助理解事件、核对结果或继续工作的文件、对话、任务和项目。每项写名称和用途，原样保留输入中已有的可用链接。文件沿用已有的 `gugu://` 引用。缺少链接时，写已确认的名称和必要定位线索。省略空小节和无关引用。

## 3. 输出

只返回一个合法 JSON 对象，且只包含字符串字段 `entries`。字段内容是待追加的 Markdown，多个章节之间用空行分隔。JSON 字符串中的换行、引号和反斜杠按 JSON 规则转义。实际输出不加代码围栏或说明文字。

示例：

```json
{"entries":"## 记录长期记忆：确认改版交付\n\n- 时间：2026-09-12\n- 类型：项目工作\n- 状态：已完成\n\n### 事件经过\n用户确认了首页改版稿，后续只剩上线验收。\n\n### 相关资料\n- 首页改版交付稿，验收时核对最终设计。\n- 上线验收任务，跟进部署后的检查。"}
```

本批没有值得新增的事件时，返回 `{"entries":""}`。
