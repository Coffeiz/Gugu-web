# 图片分析技能

## 什么时候使用

- 用户要求辨认角色、物体、场景或图片内容。
- 用户要求比较多张图片的共同点、差异、版本或风格。
- 用户要求核对搜索结果是否符合目标，而不是只要图片链接。
- 用户要求找同款、相似图、类似图片或相近风格。

## 标准流程

### A. 用户要辨认、找同款或核对出处

1. 消息包含用户图片且用户要辨认角色、物体、出处、同款、相似图或来源时，加载本技能后，第一个业务工具必须调用 `similar_image_search`。使用当前图片的 `attach_id` 或网络图片的 `image_url`，不要先把视觉猜测当作事实。
2. 每次以图搜图必须独立，只使用当前图片的 `attach_id` 或 `image_url`；上一轮猜出的角色名、作品名、标题和候选结论只能作为待验证线索，不能作为搜图输入。
3. 候选返回后，使用 `web_search` 核对候选标题、来源页与出处。只对当前可见的图像描述视觉细节。

### B. 用户只要描述当前图片

4. 用户只要求描述当前附图时，直接分析对话里可见的图片。需要比较历史附件时，请用户重新附上相关图片。

### C. 通用判断规则

5. `similarity` / `score` 只用于排序，不是事实置信度，也不是“相似度 X/5”。分数达到 2 或以上的候选是重要参考，但仍需结合标题、来源页、网页内容、候选图和用户线索核对；低于 2 也不能直接判定无关。
6. 如果用户要查出处的文字资料、角色背景或购买信息，使用 `web_search`；如果用户想按关键词找当前上下文中没有的图片，说明当前没有可用图片作为相似图搜索输入；可先用 `web_search` 查找网页线索。
7. 简单判断默认读取 2～5 张；只有用户要求全面比较时才扩大数量，单次最多 20 张。
8. 先逐图描述可观察事实，再给出跨图比较和结论。

## 输出要求

- 明确区分“图片中直接可见的事实”和“基于事实的推测”。
- 比较时按统一维度组织：主体、构图、颜色、文字、动作/姿态、相同点、差异点。
- 不能仅凭搜索标题、文件名、来源页或缩略图推断图片内容。
- 图片模糊、遮挡、加载失败或角度不足时，直接说明不确定，不要补猜。
- 需要引用某张图时使用 `result_id` 或标题标识，避免把不同候选混淆。
- `similar_image_search` 的 `similarity` / `score` 只是服务端排序等级，不是百分比、置信度或“相似度 X/5”；其中 `score >= 2` 的候选属于重要参考，但仍需核实。即使分值低，只要标题、来源或图像内容与用户线索吻合，也不能直接判定结果无关；证据不足时使用“可能相关”，不要武断否定。

## 成本与安全

- 只读取能影响结论的图片，不要默认读取全部搜索结果。
- 图片下载仍由工具执行 URL 安全校验、格式校验和大小限制；技能层不要绕过这些限制。
