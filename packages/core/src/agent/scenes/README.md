# Agent 场景组装

默认 Runtime 通过通用上下文和能力端口组装本轮已授权、已启用的内容。场景目录只承载特定运行或渠道需要的自定义规则。Web Host 和 Desktop 负责验证入口和身份，提供当前设置、可用能力与读写端口。通用 Agent 层负责模型调用、工具执行、确认、持久化和恢复。

## 目录约定

| 文件 | 职责 |
| --- | --- |
| `index.ts` | 场景对外入口。导出场景的组装函数及调用方需要的类型。调用方通过入口接入。 |
| `context.ts` | 数据来源、读取范围与生命周期，系统指令、快照与本轮片段，以及输入输出的场景投影。 |
| `tools.ts` | 场景工具授权、可见性、技能目录和派发前复核。场景没有工具策略时省略此文件。 |

场景入口接收可信运行材料。模型生成的工具参数、聊天正文和历史快照中的字段只用于当前业务输入，不能授予权限。预备阶段的能力快照用于生成模型声明。执行、确认与恢复仍须按当前可信授权重新检查。

## 场景与渠道

| 目录 | 组装内容 |
| --- | --- |
| `im/` | IM 渠道的工具和技能权限、私聊及群聊上下文、提示词屏蔽与原生交付约束。 |
| `greeting/` | 问候的来源选择、读取顺序、提示词和轻量生成。Host 提供数据、模型与缓存端口。 |
| `task/` | 定时任务触发输入、任务上下文、工具定义约束及运行租约授权。业务调度和实际投递由定时任务服务处理。 |
| `reflection/` | 反思证据与模型请求投影。记忆作用域、证据获取和持久化由反思调用方提供。 |

本轮入口选择渠道规则。QQ 群消息在默认运行组装上应用 IM 渠道规则。从 App/Web 打开同一群会话发起的运行使用 App/Web 渠道规则。定时任务向 QQ 投递时，任务场景仍负责模型运行，投递端口负责实时验证 IM 目标。当前持久渠道标识保留 `default` 与 `im`，随已有指纹参与快照和恢复校验。

共享的历史来源角色投影保存在 `source-policy.ts`。新 IM 运行通过 `im/index.ts` 提供的主体策略核对当前绑定。

## 依赖方向

Host/Gateway → 默认 Runtime → 上下文、能力和执行端口。有自定义要求时接入对应场景入口。场景可复用片段编译、工具注册和提示词格式化。片段编译器、通用运行循环和 Provider 适配器消费组装结果，渠道选择与限制由场景规则提供。

新增场景时先确定身份与数据来源，再声明系统、快照和本轮片段，并验证发现、执行与恢复使用相同的工具规则。专用模板和静态限制保存在场景内。通用工具实现、危险确认、历史解码和协议发送遵循 [Agent 目录职责](../README.md)。
