# 媒体生成工具设计

本目录规划 Agent 发起图片和视频生成的共享工具契约。当前文档是设计约定，不表示工具、供应商适配器、任务持久化或生产入口已经实现。

## 目标

- Agent 使用稳定的生成意图调用工具，不直接拼接 MiniMax HTTP 请求。
- 首批接入 MiniMax-H3-Image 图片模型与 MiniMax-H3 视频模型。
- 图片和视频生成结果作为当前对话的附件返回，消息中可预览；附件提供下载操作。
- 保存到用户文件空间是显式的后续操作，不与对话附件混为一谈。
- 供应商凭据、异步任务、授权和文件落盘由可信 Host 端口提供；Core 维护可复用的输入/结果契约。

## 工具规划

### `generate_image`

用于文生图和基于参考图的编辑。

| 字段 | 必填 | 约束/说明 |
| --- | --- | --- |
| `prompt` | 是 | 生成或编辑要求；限制长度，错误和日志不得回显用户正文。 |
| `reference_attachments` | 否 | 当前用户有权访问的对话附件引用；首批最多 16 张，实际校验以供应商限制为准。 |
| `aspect_ratio` | 否 | 受支持的宽高比。 |
| `width` / `height` | 否 | 可选输出尺寸；与 `aspect_ratio` 的冲突规则需在 Schema 中固定。 |
| `count` | 否 | 输出数量，首版设置小而明确的上限。 |
| `output_format` | 否 | 支持格式由供应商适配器声明；不支持时给出校验错误。 |

首批供应商适配器：MiniMax-H3-Image。文生图与图像编辑走同一模型能力，根据是否提供参考附件确定模式；不把供应商特有参数直接扩散到通用工具 Schema。

### `generate_video`

用于文生视频和首帧/尾帧引导的视频生成。

| 字段 | 必填 | 约束/说明 |
| --- | --- | --- |
| `prompt` | 是 | 视频画面、动作或声音要求；限制长度，错误和日志不得回显用户正文。 |
| `first_frame_attachment` | 否 | 当前用户有权访问的图片附件引用。 |
| `last_frame_attachment` | 否 | 当前用户有权访问的图片附件引用；若使用，需遵守供应商模式约束。 |
| `duration_seconds` | 否 | 首批限制在 MiniMax-H3 当前支持的时长范围内。 |
| `aspect_ratio` | 否 | 支持的画幅比例。 |
| `resolution` | 否 | 首批使用基础分辨率；高分辨率重生成另行评估。 |

首批供应商适配器：MiniMax-H3。多模态参考模式（参考图片/视频/音频集合）不纳入第一版工具输入，避免一次暴露复杂且模式相关的字段组合。

## 执行与结果

- 图片或视频生成是有外部副作用且可能计费的写操作；调用前校验当前 Run、owner、工具权限、供应商能力和额度策略。
- Host 适配器负责供应商请求、异步任务查询、取消/超时语义、结果下载及附件创建。Core 工具不接受任意 URL 作为未经验证的结果落点。
- 视频调用必须支持持久任务状态与恢复查询，不能依赖单个长时间 HTTP 请求维持任务生命周期。图片调用也应统一返回可追踪的任务/结果状态，避免不同媒体工具有不一致的结果协议。
- 结果进入 Gugu 管理的附件存储，返回稳定的附件引用、媒体类型、文件名和必要的预览元数据；不把供应商临时 URL 或 Base64 媒体直接放进模型上下文。
- 当前对话回复引用附件，前端按 MIME 类型显示图片预览或视频播放器，并提供下载。附件保留策略复用现有对话附件策略。
- “保存到文件空间”是用户明确提出或后续调用独立保存能力时执行的操作；不得因生成成功而静默复制到下载目录/用户文件空间。
- 若供应商生成成功但下载或写入 Gugu 附件失败，状态必须保留为可诊断的部分失败/未知结果，不得报告完整成功或自动重复创建生成任务。

建议的统一结果形状：

```ts
type GeneratedMediaResult = {
  status: 'completed'
  media: Array<{
    attachmentId: string
    mediaType: 'image' | 'video'
    mimeType: string
    fileName: string
  }>
}
```

进行中、失败、取消和未知提交结果应沿用 Agent 持久 Run/工具交互的规范表示；不得将伪造的 `attachmentId` 或临时供应商链接作为完成结果。

## 权限与安全边界

- 参考附件必须由可信 Host 在当前 owner 和对话范围内解析；不能以模型提供的附件 ID 直接跨用户读取。
- 供应商 API Key 从现有加密凭据/配置端口读取，不进入工具输入、任务可见日志、消息内容或 URL。
- 供应商返回的下载 URL 按外部请求安全规则校验；禁止自动跟随未经校验的重定向。下载响应需限制大小、MIME 类型和读取时长。
- 错误对用户使用统一脱敏映射；原始异常、提示词、附件名和凭据不得写入常规日志。
- 任务的创建、状态恢复和结果读取始终重新检查 owner 与当前 Run/任务授权；取消只影响该用户有权访问的任务。
- 计费/未知返回不得自动重发生成请求。只有供应商提供可靠幂等能力并有持久提交凭据时，才可设计安全恢复。

## 目录与接入边界

共享工具定义与参数校验放在本目录。MiniMax API 适配、密钥绑定、网络出口和任务持久化属于 Node Host/provider 层；通用媒体附件契约优先复用 Core 现有附件能力。Web 与 Desktop 的实际入口、工具权限配置和消息附件渲染均需在实现阶段逐一接通并核对，不以 Core 注册成功代表功能交付。

实现前需进一步确认：

1. 现有 Agent 持久 Run 是否支持可恢复的后台生成任务和进度事件，若不支持需先定义最小共享状态协议。
2. 对话附件现有容量、保留和下载授权能否覆盖生成结果，视频大文件是否需要独立媒体附件策略。
3. 用户 BYOK 与管理员供应商凭据如何选择，以及额度、并发和任务清理策略。
4. 第一版支持哪些 H3-Image 输出尺寸/格式及 H3 视频时长/画幅，并在适配器中校验供应商能力。
